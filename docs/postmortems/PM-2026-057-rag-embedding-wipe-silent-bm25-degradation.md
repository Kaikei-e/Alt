## サマリー

2026-08-02、embedding モデルの世代交代（768 次元 → bge-m3 1024 次元）のための migration が `rag_chunks.embedding` を `USING NULL::vector(1024)` で全行 NULL 化した。この設計は「後で backfill が再充填する」前提だったが、**その backfill は一度も実行されなかった**。破壊側の migration は毎デプロイ自動実行される compose サービス（`rag-db-migrator`）であるのに対し、復旧側のランチャーは git 追跡外のローカルシェルスクリプト（接続先ハードコード・最終更新は 7 ヶ月前）であり、両者の運用強度が非対称だった。

結果として、ベクトル検索の対象は新着記事の増分（全 57,058 文書中 1,105 件 = **1.94%**）だけとなり、Ask Augur は約 1 ヶ月間、実質 BM25 単独 + 上位 10 件の rerank 窓で動作し続けた。この間、エラーは 1 件も出ず（NULL embedding は `ORDER BY distance` の `NULLS LAST` で無音に最下位へ沈む）、embedding カバレッジを見る監視は存在せず（PM-2026-018 の未実装アクションアイテム）、検知は 2026-09-01 の品質調査による偶然の発見だった。直近 18 会話のサンプル判定は良好 5 / 取りこぼし 4 / 的外れ引用 5 / 浅い回答 3 / 索引汚染 1 で、体感されていた品質不満の主因はこの障害である。

なお 08-02〜08-08 の間、この障害は「NULL を non-nullable 型に Scan して panic」という形で大声で壊れていた。08-08 の修正 commit `d0f5da20a` はこれをデコードバグとして修復し検索を無音化したが、**データ消失としては扱われず、backfill は起票されなかった**。

- **影響を受けたユーザー数/割合:** 全ユーザー（単一ユーザーのセルフホスト構成）
- **機能への影響:**
  - **ベクトル検索:** 対象文書が 57,058 件中 1,105 件（1.94%）に縮退。2026-08-09 以前に取り込んだ全記事（約 98%）が dense 検索から不可視
  - **回答品質:** 直近 18 会話のサンプルで問題あり 13 件（取りこぼし 4 / 的外れ引用 5 / 浅い回答 3 / 索引汚染 1）。記事指定モードは 7 会話中 5 件で対象記事を引用できず（別バグ PM 外・ADR-000987 で修正済みの article-scoped 経路欠陥と複合）
  - **鮮度の体感:** 引用が 08-09 以降の新着記事に偏り、「最近の記事しか出ない」体感を生成
- **影響を受けなかった機能:** BM25（tsvector は全行無傷）、記事取り込み（`rag_document_versions` は正常に増加、取り込みラグ約 4.6 時間）、要約・タグ付け・検索インデックス等の他パイプライン

## 検知

- **検知方法:** 品質調査中の手動発見（アラートではない）
- **検知までの時間 (TTD):** 約 30 日
- **検知の評価:** 機能していない。以下が独立に検知を殺していた。
  1. **無音に沈む失敗モード。** `ORDER BY (embedding <=> $1)` は PostgreSQL 既定で `NULLS LAST` のため、NULL 行はエラーなく最下位に並ぶだけ。ベクトル検索は「0 件」ですらなく「上位に新着だけが並ぶ成功」として観測される
  2. **カバレッジ監視の不在。** rag-db のチャンク品質監視（PM-2026-018 AI#3）と backfill 後の品質スモーク（同 AI#4）は 5 ヶ月間未実装のままだった。eval ハーネス（12 golden case）は存在したが CI / Makefile に未接続
  3. **08-08 の修正が兆候を消した。** panic という唯一の大声シグナルが「デコードバグ修正」で除去され、以降の状態を表すシグナルが存在しなくなった
  4. **品質履歴の楽観バイアス。** fallback 回答（「情報が見つかりません」系）は DB に永続化されない実装だったため、最悪の回答ほど履歴から消えた

## 根本原因分析

### 直接原因

migration `20260802120000_widen_embedding_to_bge_m3.sql` が `rag_chunks.embedding` を `USING NULL::vector(1024)` で全行 NULL 化したが、対応する再充填（backfill）が実行されなかった。

### Five Whys

1. **なぜ Ask Augur の品質が劣化したか？** — コーパスの 98% がベクトル検索から不可視になり、retrieval が実質 BM25 単独 + rerank 窓 10 件に縮退したため。
2. **なぜ 98% が不可視になったか？** — 次元変更 migration が全 embedding を消去し、再充填が一度も走らなかったため。
3. **なぜ再充填が走らなかったか？** — 破壊側（migration）は毎デプロイ自動実行なのに対し、復旧側は git 追跡外・接続先ハードコード・手動起動のローカルスクリプトだったため。ADR-000620 が定めた 3 手順のうち、自動化されたのは手順 1 と 3 だけで、人間が担う手順 2（backfill 実行）が脱落しても何も止まらなかった。
4. **なぜ 30 日間誰も気付かなかったか？** — 失敗モードが構造的に無音（NULLS LAST）であることに加え、embedding カバレッジ・retrieval 品質の SLI/アラートが存在せず（PM-2026-018 の未実装アクションアイテム）、唯一の大声シグナル（panic）は 08-08 に「バグ修正」として除去され、fallback 回答の非永続化が品質履歴を楽観側に歪めていたため。
5. **なぜ同じ型の障害が再発したか？** — PM-2026-018（chunker v9 backfill の停滞）と同型: (i) バージョン列で再処理を*可能*にし、(ii) 手動起動の backfill に依存し、(iii) 担当者・期限・完了確認機構がない。前回の学び「バージョニングを embedder 変更にも応用する」は適用されたが、**「バージョニングは再処理を可能にするだけで、スケジュールも完了保証もしない」という欠陥ごと再生産**された。PM-2026-018 自体が Draft のまま、アクションアイテムは担当者なしで放置されていた。

### 寄与要因

- migration コメントが実在しない "backfill playbook" を参照しており、レビューで運用手順の不在を検出できなかった
- 全 embedding 消去という不可逆操作を承認した ADR が存在しない（commit message の括弧書き 1 行のみ）
- backfill CLI は `rag_jobs` キューを経由しない設計だったため、キュー滞留の監視も効かない位置にあった
- HNSW index を migration が即時再作成したため、事後の backfill は「HNSW 存在下で INSERT 約 5 倍遅」（ADR-000620 実測）の不利な条件に置かれる構造だった

## 対応の評価

### うまくいったこと

- **append-first / バージョン刻印の設計により、失われたものが「再計算可能な派生物」だけに限定された。** 記事本文・チャンク・バージョン履歴は無傷で、復旧は純粋な再計算問題に還元される
- 検知後の調査は read-only の並列調査（DB 採掘 / git 考古学 / ログ集計）が同日中に根本原因と証拠チェーンを確定した
- 恒久対策（rebuild CLI・カバレッジ監視・ガード）を検知同日に実装・テスト完了まで到達した

### 運が良かったこと

- tsvector（BM25 アーム）が全行無傷だったため、完全停止ではなく品質劣化で済んだ
- 単一ユーザー構成であり、外部影響がなかった

### 改善が必要だったこと

- 08-08 の panic 対応が症状（デコード失敗）だけを見て原因（データ消失）を掘らなかった。「なぜ NULL になったのか」を 1 段掘れば 8 月上旬に発見できた
- 過去ポストモーテムのアクションアイテムが Draft のまま放置され、まさにその未実装項目が本障害の検知を殺した

## 教訓

- **バージョニングは再処理を「可能」にするだけで、「実行」も「完了保証」もしない。** 再処理可能性を復旧計画と呼んではいけない。破壊と復旧は同じ運用強度（自動 vs 自動、または両方に完了ゲート）で対にする。
- **破壊は自動・復旧は手動、という非対称はいつか必ず片方だけ実行される。** 特に migration は「デプロイのたびに必ず走る」最強の自動化であり、そこに手動手順を前提として埋め込んではならない。
- **無音に縮退する失敗モード（NULLS LAST 等）は、専用のカバレッジ計測がなければ観測不能。** 「エラーが出ていない」ことは何の証拠にもならない。
- **症状の修正がシグナルの除去になっていないかを問う。** panic を黙らせる変更は「なぜその状態が生じたか」の調査とセットでなければ、障害を無音化するだけである。
- **ポストモーテムのアクションアイテムは、実装されるまで教訓ではなく予言である。** 本障害は PM-2026-018 の未実装項目が予言どおりに再演されたものだった。
