## 2. パターン

混入フェーズは、バグがコードや設定に入った地点である。検知が何日も遅れるのは、多くの場合その後の運用である。

頻度の目安:

- **広い** — Context の 8 分割レビューのすべて、またはほぼすべてで同型が複数本あった
- **中程度** — 複数の時期と複数サービスにまたがるが、上より本数は少ない
- **局所** — 本数は少ないが、停止日数やデータの規模が本文に数字で残っている

### 2.1 失敗を成功・空・healthy に写す

**説明.** 失敗を `return nil`、空配列、`Ok(())`、HTTP 200、`/health` 200、チェックポイント前進、degraded の無言継続に変換する。防御的な nil ガードは「意図的に無効」と「配線し忘れ」を同じ形にする。プロセスは生きて見え、仕事は止まっている。

**混入フェーズ.** 実装が主。DI の付け忘れは結合。検知の遅れは運用（ヘルスとメトリクスが業務結果を見ていない）。

**影響.** rag-orchestrator、knowledge-sovereign、alt-backend、recap-subworker、recap-worker、pre-processor-sidecar、auth-token-manager、pki-agent、search-indexer、compose。

**典型的帰結.** 機能がゼロのまま数日〜十数日、緑のまま進む。append-only の行は空のまま残り、後から埋められない。

**頻度.** 広い。8 分割のすべてに同型がある。下表は原典で確認した代表。

| ADR | タイトル | 本文が述べていること |

### 2.2 境界の片側だけを新契約にする

**説明.** 移行・分割・フィールド改名で、書く側・読む側・REST と RPC・proto の package・環境変数・リスナの片方だけが新契約に載る。呼び出しは 200 や空文字で成功し、画面は「効いていない」「常に false」「ゼロ件」「404」になる。

**混入フェーズ.** 実装（対になる経路を同じ変更で書き換えない）。一部は配備（migration 未適用、compose の env 未注入、リスナの載せ違い）。

**影響.** alt-backend、pre-processor、search-indexer、knowledge-sovereign、proto、alt-frontend-sv、alt-butterfly-facade。Knowledge Home の link / Why / review reason に集中する。

**典型的帰結.** 成功応答のまま機能が欠ける。再投影すると、片側のキーで全件が空になる。

**頻度.** 広い。分割レビューのすべてで複数本。バケット 0（125 本）だけでも、この型と読めたものが 17 本あった。

| ADR | タイトル | 本文が述べていること |

### 2.3 投影の部分更新と、誤ったデータベースへの着地

**説明.** 投影の upsert が、イベントが変えるつもりのない列に Go のゼロ値（空文字、nil slice → JSON `null`）を書く。merge SQL はそのゼロを本物の更新として採用する。別の形では、再投影が最新状態や別キーを見て確定済みの dismiss を戻す、チェックポイントだけ進めてイベントを落とす、テーブルを所有者でない DB に作る。

**混入フェーズ.** 実装（merge SQL、dedupe key、payload のゼロ値）。設計（read model をどの DB に置くか）。配備後の再投影操作で被害が全件に広がる。

**影響.** alt-backend、knowledge-sovereign、tag-generator、migrations-atlas、acolyte 系。

**典型的帰結.** dismiss が戻る、ready の要約がスケルトンに戻る、タグが数千行 `null` になる、再投影で URL が全件空になる、修正コミットが死んだコピーに入る。

**頻度.** 広い。2026-03 の Knowledge Home と、2026-04 以降の再投影・DB 所有で繰り返す。

| ADR | タイトル | 本文が述べていること |
|---|---|---|
| `000529` | タグ削除とタグ生成スタック | `Tags` 未設定の nil slice が `"null"` になる。`'null'::jsonb != '[]'::jsonb` が真なので既存タグを上書き。projection_version 2 に **13,386** 件 |
| `000465` | ready の summary_state を保護 | 非要約イベントで `summary_state` が空文字に戻り、空文字が既存の `ready` を上書きした |
| `000457` | dismiss を後続 upsert で巻き戻さない | 2026-03-18 の運用で、dismiss 後のリロード再表示が続いた。`dismissed_at` は `NULL` のまま |
| `000433` | ArticleCreated の dedupe 統一 | `article-created:` と `backfill:` が別イベントになり、加算系の投影が二重に数える |
| `000944` | projector を sovereign へ | タグ版の取得に失敗してもログだけで空タグのまま続行し、チェックポイントが進んでイベントが落ちる。要約版の経路は hard fail で、非対称 |
| `000940` | Loop を Trail へ retire | 実装中に、Trail の CREATE が `migrations-atlas`（`alt_db`）にあり、動く sovereign は別 DB だと分かった。projector も read handler も runtime で落ちる。PR で混入し main に入っていた |
| `000960` | 孤児テーブルの DROP | acolyte の表は専用 DB を決めたあとも alt-db に古いコピーが残った。2026-07-18 のインデックス追加は、クエリが飛ぶ側ではなく **死んだコピー** に入った。`schema.hcl` は 10 表、実 DB は 27 表 |

`000535` の「reproject が常に旧パス」と `000867` の「再投影が全件空 link」は、この型と 2.2 の交差である。

### 2.4 ローカル LLM の入出力契約とトークン予算

**説明.** 思考レベル、チャット区切り、`num_predict`、JSON/XML の文法、few-shot、検証器が、実際のモデル出力と一致しない。思考トークンが予算を使い切り、本文が空になる。検証器は妥当な日本語を棄却する。呼び出し側は空・fallback・degraded を完了として通す（2.1 と重なる）。

**混入フェーズ.** 実装（プロンプトと検証）。モデル差し替えの結合で一斉に顕在化する。

**影響.** rag-orchestrator、news-creator、pre-processor、acolyte-orchestrator、recap-worker。

**典型的帰結.** 空回答、全件 hard-stop、別トピックへの引きずり、要約品質の崩壊、存在しない事実の生成。

**頻度.** 広い。2025-12 の最初の推論レベル変更から、2026 年の Gemma 移行と Acolyte まで途切れない。

| ADR | タイトル | 本文が述べていること |
|---|---|---|
| `000024` | 推論レベルの動的選択 | `000023` で `Think: "medium"` にしたあと「システムが正常に動作しなくなった」。クエリ拡張は `response_length: 0`。思考が短いタスクのトークンを食う |
| `000640` | Gemma 4 のチャットテンプレート一括置換 | 旧 `<start_of_turn>` のまま。Gemma 4 の停止トークンと違い、`num_predict` 上限までゴミ出力。Recap 品質が「劇的に悪化」 |
| `000608` | キーワードカバレッジの誤検知 | 直近の回答が `stream_short_answer_hard_stop` で棄却され、サービス停止に等しい。日本語は `strings.Fields` で 1 トークンになりカバレッジ 0% |
| `000632` | Gemma 4 構造化出力 | `000630` の配線後、golden が 6/12 から 1/12。`should_clarify: true` の乱発でほぼ全クエリが空回答 |

### 2.5 終端しない失敗と、外側が先に切れる待ち

**説明.** タイムアウト、403、参照先の欠落、upsert の再通知を「未完了」に戻す。処理できない項目が候補の先頭に残り、有効な仕事が飢える。反対側では、クライアントやプロキシの期限がサーバの処理より短く、リトライが待ち行列を増やす。セマフォとタイムアウトの組み合わせが同じ増幅を起こす。

**混入フェーズ.** 実装（リトライと状態機械）。設計（窓の大きさがキュー容量を超える、レート制限の単位が仕事の単位と違う）。運用（負荷試験の残骸が本番キューに残る）。

**影響.** pre-processor、news-creator、recap-worker、alt-backend、rag-orchestrator。

**典型的帰結.** GPU の空転、全ジャンル失敗、新規要約が処理されない、未要約の一覧が永久に同じ記事で埋まる。

**頻度.** 広い。2025-09 に顕在化した冪等性の欠如から、2026-11 の enqueue sweep まで同じ飢餓が形を変えて残る。

| ADR | タイトル | 本文が述べていること |
|---|---|---|
| `000008` | コンテンツ処理パイプライン | 同じ記事が複数回処理され重複データが発生。一部が失敗しても全体が止まらず、再試行もされない、と 2025-09 の課題として記録 |
| `000096` | 最大コンテンツ長 | 188KB 超で要約が 300 秒を超え、同じ記事が無限リトライして GPU を塞ぎ、他記事が止まる |
| `000296` | 403 のバックオフ | `000290` が 403 を persistent から外したあと、403 フィードへ無限にリクエストし続けた |
| `000504` | ゴーストジョブの掃除 | k6（3/5–3/13）のあと pending **1,913,832**。`article not found → failed → pending` のループ。毎分約 120 件のエラー。有効な新規ジョブが処理されない |
| `000512` | lifecycle event の分離 | upsert でも `ArticleCreated`。要約済みでも再びキューに積まれる |
| `000184` | 7-day Recap の停止 | 下流キューの飽和とタイムアウトで全ジャンルが失敗した |
| `001013` / `001014` | enqueue sweep と placeholder | ガードで永久に弾かれる記事が未要約一覧の枠を使い切る。`001013` はページを進めて緩和し、`001014` は終端の記事に版を作らない placeholder を書いて候補から外す。`001013` 自身が、件数がページ上限を超えると遅延が再発する、と負債を残している |
| `000752` | can-i-deploy の selector | これはキューではないが同じ「外側のゲートが中身とずれる」形。provider テストは 18 pass / 0 fail なのに、`can-i-deploy` が 14 本中 11 本で unknown、exit 10。`Latest: true` だけでは本番 consumer との組が broker に無い |

`000121`, `000137`, `000145`, `000185` はセマフォ・タイムアウト・リトライの増幅、`000146`, `000330`, `000386` はクライアント期限がサーバより先に切れる型として、同じ時期の Context に並ぶ。

### 2.6 デプロイ単位が実行時の依存を外す

**説明.** Compose 単体では正しいパターンが、サービス単位の rolling deploy（`000826` が書く `docker compose up <service> --no-deps` 相当。`--no-deps` は `depends_on` の相手を起動も create もしない）では一度も動かない。フラグの無い `docker compose up <service>` は依存を起動するので、この経路とは別である。init container、名前付き volume の populate、restart policy 無し、死んだ netns を掴む sidecar、マウントされていないルールファイルが、この型に入る。

**混入フェーズ.** 設計と配備。単体の compose レンダリングと unit test は通る。

**影響.** compose、recap-subworker、pki-agent、search-indexer、prometheus のルール、CI。

**典型的帰結.** コンテナは healthy に起動し、データやリスナが空。下流は 0 件や connection refused。

**頻度.** 中程度。2026-04 に連続し、`000826` がレビュー手続きにしたあとも、イメージと netns の形で残る。

| ADR | タイトル | 本文が述べていること |
|---|---|---|
| `000826` | rolling deploy との整合を必須チェックに | `PM-2026-036` の **9 日間**の 3days Recap 停止のあと、`000825` は init container で volume を埋める設計にした。同日夕方のデプロイ後、手動キックが再び 0 件で失敗。`--no-deps` 相当の経路は `service_completed_successfully` の init を起動しない。compose 上は healthy、volume は空（`PM-2026-037`） |

### 2.7 検証が本番の失敗形を見ない

**説明.** CI の `|| true`、空の SARIF、スタブした route に対する pact、ヘルスの安い成功、片方の経路だけのテストが、失敗を緑にする。逆に、selector が狭すぎるとテストは緑なのにデプロイゲートだけが止まる（`000752`）。

**混入フェーズ.** 結合（CI と broker）。テストが node 環境に `matchMedia` を持たない、といった実行環境の差も含む。

**影響.** ci-cd、pact、recap-subworker、tag-generator、alt-backend、alt-frontend-sv、govulncheck。

**典型的帰結.** 本番の 401・502・分類不能が緑のまま進む。または、契約が無いセルのために SHA を上げるだけでデプロイが止まる。

**頻度.** 広い。2026-04 の Pact 整備と、2026-11 の ci-gate 再定義まで。

| ADR | タイトル | 本文が述べていること |

| `000616` | Pact CI の再構成 | recap-subworker と tag-generator の provider 検証が `\|\| true`。失敗しても CI は green。16 pact 中 5 が broker に届かない。alt-backend の provider テストは CI に無い |
| `000736` | Pact の残ギャップ | `PM-2026-025`。acolyte-orchestrator の consumer pact が `X-Service-Token` を assert せず、**24 時間のサイレント degradation**。search-indexer はその pact を intentionally excluded |

### 2.8 局所修正と決定の置換が、同じ穴を戻す

**説明.** 直前の修正が、隣の不変条件を壊す。あるいは、正しい理由で前の制御を外したあと、その制御が塞いでいた穴が別の形で開く。設計を重ねても、保持できないモデル（多軸の状態）が単軸に潰れる、という形もある。

**混入フェーズ.** 実装（局所修正）。設計（モデルが実装者と利用者の両方の作業記憶を超える）。決定の置換そのもの。

**影響.** alt-frontend-sv、alt-backend、knowledge-sovereign、認証境界（pre-processor、search-indexer を含む mTLS 化）。

**典型的帰結.** 直した画面の隣が壊れる。閉じたはずの認証境界が「到達できれば通る」に戻る。read 表層を ADR で重ねた末に、表層ごと捨てる。

**頻度.** 中程度。本数より、置換の連鎖が長い。

| ADR | タイトル | 本文が述べていること |
|---|---|---|
| `000226`（`000222` と `000224` を置換） | 検索の追加ロードでスピナーが残る | `000224` が `$effect` 内の `isLoading` ガードを外したあと、追加ロードのスピナーが止まらなくなった。`000224` 自身は、`000221` の `$effect` 移行後に初回スピナーが永続した、という修正だった |
| `000320` | Tag Trail のリクエスト雪崩 | `$effect` が `new Set` の再代入で再発火。1 記事あたり毎秒約 30 回。5 分でストリーム開始 9,181、Redis pool timeout 24 |
| `000954` | backend / harvester / data-hub 分割 | `000717` は内部 API にアプリ層認証を付けた。`000743` の mTLS 一本化でその層は撤去され、内部リスナーは再び「到達できたら通る」。本文は「同じ欠陥クラスが 2 度発生している」と書く。`000743` 自体は、共有秘密の二重管理が `PM-2026-025` 型のサイレント劣化を生む、という理由で正しい、とも書く |

### 2.9 識別子と所有の取り違え

**説明.** 利用者から見て一つのものが、保存キーでは別物である。URL と記事 ID、feed と article、`(url, user_id)` の一意性を SELECT が無視する、テナント述語が無い、proto の package が経路そのものなのに片側だけ違う。所有 DB の取り違え（2.3 の `000940` / `000960`）も、識別子が「どのデータベースの表か」まで含めて一意でないときに起きる。

**混入フェーズ.** 実装。設計で「同一物」の定義が層ごとに違うまま進む。

**影響.** alt-backend、pre-processor、search-indexer、alt-frontend-sv、proto。

**典型的帰結.** 他人の要約が出る、既読が落ちる、404、空の Open、誤った DB への修正。

**頻度.** 広い。2.2 と重なるが、機構は「欠落」ではなく「別の実体を同じ名前で指す」ことである。

### 2.10 契約グラフの修復が、現行契約を落とす

**説明.** ADR の `supersedes` を一括で直したとき、退役と無関係な決定まで `superseded` になり、`docdag query --binding` と編集前の ADR ブリーフから消える。不変条件はコードと CI に残っていても、次の変更者が「現行の契約」として読めなくなる。

**混入フェーズ.** プロセス（文書の一括編集）。影響はそれ以降の設計と実装。

**影響.** docs/ADR 全体、knowledge-sovereign の migration 規約、pre-processor-sidecar の取り込み監視、CI の sparse-checkout と `atlas.sum`。

**典型的帰結.** 一度障害から得たルールが、binding 一覧から脱落する。本文は append-only なので、辺を静かに外せず、新しい ADR で契約を立て直すことになる。

**頻度.** 局所。事象は 2026-10-24 の 1 回だが、反転した ADR は 54 本と本文が数えている。

| ADR | タイトル | 本文が述べていること |
|---|---|---|
| `001011`（`000877` を引き継ぐ） | View 列順・sparse-checkout・atlas.sum を再確定 | 2026-10-24 の 979 件の frontmatter 修復で、`000940` の `supersedes` が 6 件から 60 件になり、54 件が `accepted` から `superseded` へ反転した。`000877` は Knowledge Loop と無関係な CI / migration の規約だった。原契機は 2026-05-01〜02 の三障害。その一つは `CREATE OR REPLACE VIEW` の列順で PostgreSQL `42P16` になり、migration コンテナが止まったこと |
| `001012`（`000895` を引き継ぐ） | Inoreader のサイレント停止検出を再確定 | 同じ一括修復で `000895` も binding から落ちた。中身の監視契約は有効なまま、グラフ上は退役扱いになっていた |

`001011` は、列順の専用 lint は今も無く、検出は全 migration を実 PostgreSQL に適用する統合テストに依存する、とも書いている。ルールの再確定と、実行時の検査の欠落は別の層である。

### 2.11 文書の床が、コードの床になっていない

**説明.** リポジトリのルールや ADR が「最低 5 秒」「列は末尾に足す」「`atlas.sum` を追跡する」と書いていても、検証がそれを拒まない期間がある。違反は設定値やレビューの記憶に依存する。

**混入フェーズ.** 実装（validation が規約より緩い）。プロセス（専用 lint が無い）。

**影響.** alt-backend の外部取得、migrations、CI。

**典型的帰結.** 規約どおりだと思っている間隔やスキーマ操作が、実行時には別の値で通る。

**頻度.** 中程度。`001011` の三ルールと、レート制限の床が同じ構造。

| ADR | タイトル | 本文が述べていること |
|---|---|---|
| `000982` | 記事本文取得の間隔を 7.5 秒に | 5 秒ルールは書いてあったが、validation は 1 秒超を通していた。床を守らせていたのは配布時の設定値だけだった、と本文が書く。本 ADR で 5 秒の床をコードで執行する |
| `001011` | 三つの CI 不変ルール | `CREATE OR REPLACE VIEW` の列順を見る専用 lint は無い。`atlas.sum` の追跡漏れは、過去に CI とデプロイを止めた三障害の一つとして再掲されている |

## 4. 再発を止めるための推奨

優先度は、無言の期間の長さと、既存のガードをすり抜けた記録があるかどうかで付けた。すでに ADR やリポジトリの規約にあるものは「文書がある」で終わらせず、実行時に拒む形へ寄せる。

### P0 — 成功に見える停止を、業務結果で落とす

対象: 2.1、2.6、2.7。

- producer、projector、resolver の未配線は、空を返して続行しない。起動ログに `*_enabled` または `*_disabled` を出し、業務経路で未配線の枝に入ったら停止する。`000928` が記録した「nil なら no-op」を、意図的な無効と区別できないまま残さない。`000943` は、この型が 2026-07 に全域で再発したと書いている。
- `/health` が 200 でも業務が止まっている事例が、Recap 8 日（`000825`）、Inoreader 3 日（`000895`）、pki-agent の connection refused（`000784`）、search-indexer 不在 36 時間（`000703`）で繰り返している。ヘルスは、そのプロセスが果たす依存（listener の bind、分類器の初期化、トークンの実体、直近成功時刻）を見ない限り成功にしない。`000980` が書いている cheap health の穴を、依存ごとに閉じる。
- チェックポイントは、投影の書き込みが成功したあとだけ進める。`000593` と `000944` は、ログを出して進めた結果、再試行が永久に消えたと書いている。

### P0 — 契約の両側と、すべての書き手を同じ変更に含める

対象: 2.2、2.9。

- フィールド名、proto package、REST と RPC、書き手と読み手の変更は、producer の CDC（Pact）が赤の状態から始める。`000867` は、修正した経路が 1 本で、live の `map[string]any{"link": ...}` が 2 本残っていた。変更の完了条件は「そのフィールドを書く箇所の一覧が、新しいキーだけになっていること」にする。
- `(url, user_id)` のように複合で一意なものは、読む SQL に同じ述語が無ければテストが失敗するようにする（`000552`）。
- feed と article、URL と UUID を同じ引数で渡せる関数を残さない（`000027`, `000040`, `000158`）。

### P0 — 投影はゼロ値で上書きしない。表は所有者の DB にしか置かない

対象: 2.3。

- merge SQL は、空文字・JSON `null`・未設定を「変更なし」として扱う。`000529` の `'null'::jsonb != '[]'::jsonb` と `000465` の空文字上書きを、回帰テストの入力にする。
- 再投影のテストは、本番に残っている payload の形（キー無し、`"link"`、`"url"`）を全部食わせる。`000867` は Full Reproject のあとで全件空になった。
- migration の適用先 DB を、その表を読むプロセスの DB と一致させるテストを CI に置く。`000940` は表が `alt_db` にあり sovereign が落ち、`000960` は修正が死んだコピーに入った。`000961` が「リンカの依存グラフを断言する」形を既に alt-backend の import 境界で使っている。同じ形を「この migration ディレクトリの適用先」に広げる。

### P1 — LLM の予算と出力契約を、空成功の外側で固定する

対象: 2.4。

- `num_predict` と思考トークンの合計が、本文の下限を残すことを golden で見る。`000024` と `000640` と `001000` は、予算の使い切りが空やゴミになる、と書いている。
- モデルを替えた PR は、チャット区切りと停止トークンの差分をテストが持っていること。テンプレートの一括置換（`000640`）を、文字列の残りで検出する。
- 日本語の分割に ASCII 空白を使わない（`000608`, `000304`）。カバレッジ 0% で全件棄却する検証器は、サンプル文で赤になるようにする。
- degraded と空回答は完了にしない。`000888` は JSON パース失敗を genre の drop と degraded に畳み、実在しない文章が出た。

### P1 — 永久失敗は候補から外し、期限は内側より外側を長くする

対象: 2.5。

- リトライ不能（403 の継続、article 不在、品質削除の上限、dead-letter）は pending に戻さない。`000504` の 191 万件と `000296` の無限 403 と `001014` の placeholder は、同じ「終端が候補に残る」問題である。`001014` の「版とイベントを作らない」は、Home に偽の完了を出さないための条件なので、終端の実装はそこを崩さない。
- 負荷試験のジョブは本番のキューに混ざらない識別子を持つ（`000504`）。
- クライアント、プロキシ、JWT の期限は、下流の処理時間より短くしない。短い側が切れるとリトライが増幅する、という記録が 2026 年春の複数 ADR にある。
- 外部呼び出しの間隔の床は、設定値ではなく validation が拒む（`000982` が 5 秒床をコードで執行した、という決定を他の床にも使う）。

### P1 — rolling deploy で動かない Compose を、CI が拒む

対象: 2.6。

- `000826` のチェック（`depends_on` の `service_completed_successfully`、`restart: "no"` の init、名前付き volume の populate 責務）は、テンプレートの自問で終わらせず、compose ファイルに対する lint にする。`000826` 自身が、compose 単体のテストは通ったと書いている。
- 常駐サービスに restart policy が無い状態を CI が落とす（`000703`）。
- 起動時に、分類器・ルールファイル・証明書リスナの実体が無ければプロセスを終了し、その終了をアラートする。fail-closed にしたあと、終了そのものが見えないと `000952` のようにデプロイ後に初めて分かる。

### P1 — 緑の定義から `|| true` とスタブ経路を除く

対象: 2.7。

- ワークフロー内の `\|\| true` と、失敗を空 SARIF に変える処理を禁止する。`000616` と `001004` は、それが「検出 0」「CI green」になったと書いている。
- Pact は実在する route だけを検証する。`000952` はスタブした clustering route で緑だった。consumer が要求するヘッダ（`000736` の `X-Service-Token`）を assert しない pact は未完成として扱う。
- `can-i-deploy` の selector は、デプロイ済み consumer との組を含む（`000752`）。テストが 18 pass でもゲートが unknown なら、selector が本番の行列を見ていない。

### P2 — 制御を外す決定は、塞いでいた穴の回帰テストを残す

対象: 2.8。

- `000743` が共有秘密を外した判断は `000954` が正しいと書いている。同時に、`000717` が塞いでいた「到達できれば通る」が戻った。制御を撤去する ADR は、撤去後も閉じていなければならない条件をテスト名で残す。allowlist 未設定で起動を続ける経路は、ログではなく終了コードで拒む（`000954` が死蔵 allowlist を問題にしている）。
- UI のリアクティブ修正は、直した画面の隣接状態（初回、追加ロード、回転、件数一致）を同じ PR のテストに含める。`000221` → `000224` → `000226` と `000320` は、`$effect` の依存の読み方が隣を壊すと書いている。
- 保持できない多軸モデルを read の正本にしない。`000940` は、3 軸が単軸に潰れ続けたので表層を捨てた。新しい read model は、欠けると行が存在できない列（Trail の four-tuple）で退化を構造的に拒む、という `000940` の決定を、次の表層でも先にスキーマへ置く。

### P2 — `supersedes` の一括編集は、無関係な binding を落とした時点で失敗とする

対象: 2.10、2.11。

- `supersedes` を広げる変更は、退役の本文が名指ししている ID 以外が `accepted` から落ちたら CI が失敗する、という検査を `docdag` に置く。`001011` は、54 件の反転が `000877` を binding 一覧から消したと書いている。append-only なので、あとから辺を静かに戻せない。
- 障害から得た不変条件（view の列順、`atlas.sum`、取り込みの最終成功時刻、5 秒床）は、ADR の status が落ちてもコード側のテストが残る場所に置く。`001011` は列順の専用 lint がまだ無いと書いている。統合テストの間接検出に加え、列の挿入位置そのものを見る検査を足す。

## 5. この分析の限界

- 一次資料は ADR の Context である。ポストモーテム本文、チャット、メトリクスの生データは突き合わせていない。ADR が数字を書いていない被害は、数字として書いていない。
- 684 という本数は「Context が既発の誤動作を述べている」という分類の合計である。深刻さと、開発中に直した表示の不具合が混ざる。`bugfix` タグ 362 本とは集合が違う。
- `superseded` 107 件を「失敗した決定」の件数としては使えない。`000940` の 60 辺のうち、本文が退役の対象として述べている Loop の read 表層と、2026-10-24 の一括修復で付いた無関係な辺が混ざっている（`001011`, `001012`）。
- パターンは排他ではない。`000928` は未配線（2.2）であり、nil の無音（2.1）であり、e2e が緑（2.7）である。
- 2026-06 以降は ADR の月間本数が減っている。失敗が減ったのか、記録が ADR 以外に寄ったのかは、このコーパスだけでは分からない。
