調査日: 2026-11-15。一次資料は `docs/ADR/` の本文と frontmatter。件数はファイル一覧との照合結果。

## 2. 方法と限界

各 ADR について、決定、応答している問題、本文が述べる原因、置換関係、影響サービス、バグが入った局面をノートにした。`responds_to_failure` は、Context または Decision が実際の不具合、回帰、障害、データ消失、本番または CI の失敗、あるいは直前の決定が実地で失敗したことを書いている場合だけ真とした。Consequences にしか無い想定リスクは数えていない。

この分類に当たった ADR は **708 / 1013**。frontmatter の `bugfix` タグは 362 件で、そのうち 356 件がこの 708 に含まれる。残る 352 件はタグが無くても、性能劣化、無音停止、契約が本番で破れた記録として本文が失敗を述べている。

信号タグ（`silent_fallback` など）は読解ラベルである。隣接する症状を含むので、パターンの「頻度」はタグ件数を広がりとして示し、主張の根拠は引用した ADR 番号に置く。存在しない障害は書いていない。

局面の内訳（708 件）:

| 局面 | 件数 | 割合 |
|---|---|---|
| 実装 | 308 | 44% |
| 結合（サービス境界、FE/BFF/proto） | 175 | 25% |
| 運用（キュー、再試行、稼働中の劣化） | 153 | 22% |
| デプロイ | 55 | 8% |
| 設計そのものが実地で失敗 | 17 | 2% |

失敗対応 ADR の `affected_services`（1 件が複数サービスを持ち得る）の上位は、alt-backend 292、alt-frontend-sv 233、pre-processor 92、rag-orchestrator 84、news-creator 82、recap-worker 67、knowledge-sovereign 56、acolyte-orchestrator 53、search-indexer 49、tag-generator 43、alt-butterfly-facade 42。

## 3. パターン

### 3.1 無音の成功

防御的な `nil` 判定、空配列、`.ok()`、`|| true`、プロセス生存だけの health が、未配線・欠落・失敗を成功と同じ形にする。

本文で確認した例:

- [[000928]] Ask Augur の neighbor searcher が DI で渡されず、`related_citations` は空のまま。CI は e2e 313 件が通り、ログに警告も無い。原因は `if neighborSearcher == nil { return nil }` が「意図的に無効」と「配線忘れ」を区別できないこと。
- [[000273]] `ImageProxy.Enabled` の既定は true だが secret が空で usecase は nil のまま、画像プロキシは本番で一度も動かなかった。
- [[000535]] Sovereign 経由の dismiss などが、ペイロードを読んだあとリポジトリへ委譲せず no-op だった。
- [[000616]] recap-subworker と tag-generator の Provider 検証が `|| true` で、失敗しても CI が green だった。
- [[001004]] govulncheck が Go の版ずれで失敗し、`|| true` と空の SARIF で「検出 0」になっていた。
- [[000825]] と [[000826]] は、名前付き volume が空のままコンテナが healthy になり、3days Recap が 8 日から 9 日止まった（[[PM-2026-036]] / [[PM-2026-037]]）。

広がり: 失敗対応ノートのうち `silent_fallback` 180、`nil_guard` 24、`di_wiring` 44。三つは重なる。帰結は「画面が空、件数 0、CI 緑」で、利用者報告かログの手作業まで検知が遅れる。影響は rag-orchestrator、tag-generator、recap-worker、knowledge-sovereign、CI。

### 3.2 局所修正が次の欠陥を露出する

一つの本番症状を塞ぐと、同じ経路の次の前提が壊れて別の ADR になる。バグは最初の修正の時点で隣に既にあることが多い。

確認できる連鎖:

- 検索の追加読み込み。[[000222]] と [[000224]] は [[000226]] が supersede している。スピナーが残るたびに `$effect` と sentinel を直し、修正が次のスピナー固着を作った、と [[000226]] の題が「追加ロード時のスピナー永続表示バグ修正」として二つの先行 ADR を置換している。
- 要約キュー。待ち時間、タイムアウト、予約スロット、モデル切替、7 日バッチの飢餓が月をまたいで別 ADR になる（例: [[000140]] の TTFT 平均 211 秒、[[000185]] の待ち 3668 秒、[[000551]] の要約不可記事 63 件が 1349 ジョブを再投入）。
- GPU スロット。[[000601]] から [[000606]]、[[000610]]、[[000612]] は、返却先の推測がプリエンプション、遅延 `set_result`、キャンセル待ちの順で別のリークを残した、と各 ADR が直前の ADR を名指ししている。
- LLM の出力形式。[[000672]] の QuoteSelector を [[000675]] が降格し、[[000683]] の JSON 経路を [[000698]] が XML に替え、[[000699]] が残った FactNormalizer を閉じる。成功率が 0/10 や 3/30 のまま形式だけが替わる。

広がり: 置換辺 110 のうち、実地の失敗を理由に少数を置き換えるものはこの型。帰結は同じユーザー症状（スピナー、空要約、枠の消失）が週単位で再発すること。影響は alt-frontend-sv、news-creator、rag-orchestrator、pre-processor。

### 3.3 境界で識別子と契約がずれる

片方のサービスが「ID」と呼ぶ値が、隣では別テーブルの主キー、別フィールド名、別の URL 種別である。コンパイルも単体テストも通る。

本文で確認した例:

- [[000300]] [[000299]] の修正が `feed_links.id` を `feeds.id` として返し、`articles.feed_id` の外部キー違反で新規記事が保存されなくなった。
- [[000027]] は三層で `article_id` が欠け、要約が URL を UUID として渡して SQLSTATE 22P02 になった（バッチノートの引用は本文のエラー文字列と一致）。
- [[000306]] は要約保存が 6 時間で 287 件失敗・成功 0。`user_id` が proto に無く、ジョブは完了扱いになり得た。
- [[000865]] を [[000867]] が置換。再投影のあと記事リンクが空になり、live の producer は `url` ではなく `link` を書き続けていた。
- [[000942]] は admin JSON が PascalCase のまま、altctl が零値で成功した。

広がり: `missing_contract` 184、`api_contract_break` 84、`boundary_mismatch` 94。帰結は 404、401、FK 違反、空リンク、別記事の表示。影響は alt-backend、pre-processor、proto、knowledge-sovereign、BFF。

### 3.4 投影がイベント以外を見る

read model がペイロードではなく最新行、`time.Now()`、後続 upsert のゼロ値を使う。checkpoint は失敗のあとも進む。再投影すると当時の事実が消えるか、二度と戻らない。

本文で確認した例:

- [[000447]] `SummaryVersionCreated` が `summary_version_id` を無視し `GetLatestSummaryVersion` を見ていた。過去イベントを再投影すると最新本文で上書きされる。
- [[000457]] 後続 upsert が `dismissed_at` を NULL に戻し、dismiss したカードが戻る。
- [[000468]] projector の `time.Now()` が再投影を非決定にし、Recall の `next_suggest_at` がすべて未来になった。
- [[000598]] swap 後に checkpoint をリセットせず、Home から 326 記事が欠け、1947 件の `summary_state` が古いままだった。
- [[000922]] recall スコアが再投影のたびに時刻で変わり、同じ event log から別の行が出る。
- [[000869]] ArticleCreated の dedupe が URL backfill を `success=true / event_seq=0` の no-op にした。

広がり: `projection_drift` 78、`immutable_violation` 15、`clock_time` 20。帰結は Home が空、dismiss が戻る、再投影のたびに別の画面になること。影響は knowledge-sovereign と alt-backend の projector。

### 3.5 設定と未再ビルドがコードより勝つ

ソースの意図と、実行中の env、イメージ、マイグレーション適用状態が別物である。起動は成功する。

例:

- [[000499]] `.env` が compose の既定モデルに勝ち、存在しないモデルで RAG が謝罪フォールバックした。
- [[000571]] `.env` が [[000567]] のセマフォ配線を上書きし、RAG Chat の 60% がタイムアウトした。
- [[000614]] 未再ビルドのバイナリが古い `gemma3` 名を送り、Ask Augur が 2 回失敗した（[[PM-2026-016]]）。
- [[000189]] `altctl up` が `.env` を渡さず、全サービスが空の DB 設定で起動した。
- [[000273]] secret 未設定で機能ごと nil（3.1 と同一）。
- [[000895]] OAuth token ファイルが空のまま Inoreader 取り込みが 2026-05-05 から 3 日凍結した。[[001012]] がこの検知契約を現行のものとして置き直している。
- [[000059]] `article_summaries` への `user_id` 追加マイグレーションで全データが消失した（2026-01-08）。
- [[000040]]（withdrawn）既読テーブルへの付け替えで、article の無い feed 約 7000 件の既読が消えた。

広がり: `config_drift` 104、`schema_migration` 63、`dependency_upgrade` 37。帰結は無音フォールバック、全件削除、起動はするが仕事をしないプロセス。影響は compose、alt-backend、news-creator、pre-processor-sidecar、マイグレーション。

### 3.6 rolling deploy と cheap health が障害を healthy に変える

per-service の `compose up --no-deps` は init container を起動しない。healthcheck はプロセスか証明書の鮮度だけを見て、モデルファイル、netns、配送先を見ない。

本文で確認した例:

- [[000826]] `--no-deps` は `depends_on` の init container を起動も create もしない。compose 上は healthy で、volume は空。同 ADR が deploy-model のセルフチェックを ADR 雛形へ入れた。
- [[000825]] は同じ空ディレクトリで 2026-04-14 から 8 日間 Recap が失敗し、コンテナは healthy だった。初期の init container 案は rolling と非互換なため host 直 bind に戻している。
- [[000784]] を [[000802]] が置換。loopback probe と自己 exit では sidecar の netns 孤立を治せなかった。
- [[000782]] 親の force-recreate のあと sidecar が旧 netns に残り、acolyte が 502 になった。
- [[000980]] `/health` の 200 が依存の死と旅程の破壊を page から隠した。
- [[000969]] アラートは firing したが配送先が無く、証明書失効の検知に 7 時間 21 分かかった。
- [[000871]] migrator の apk 取得でデプロイが 73 分 hang した。

広がり: `deploy_order` 37、`orchestration` 62。帰結は「緑のコンテナのまま機能が数日止まる」。影響は recap-worker、pki-agent、acolyte、compose、監視。

### 3.7 テストが本番の経路を見ない

単体テストはコピーやモックを叩き、E2E は存在チェックや path skip で緑になり、CDC は DI の配線漏れを見ない。

本文で確認した例:

- [[000928]] proto、migration、handler、e2e は正しく、壊れていたのは DI の 2 段の未配線だけだった。
- [[000616]] と [[001004]] の `|| true`（3.1）。
- [[000931]] path skip の Hurl が共有の回帰を緑で通した。
- [[000957]] が Hurl 導入 ADR 11 件を置換。`event_seq` 0 や未実行スイートが緑のままだった、と置換理由が題と本文にある。
- [[000193]] 実ハンドラーではなくコピーをテストしていた。
- [[001011]] は、CI 不変ルール自体がグラフ操作で binding から落ちた事例（3.10）。

広がり: `test_gap` 92。帰結は「CI 全 pass の当日に本番だけ空」。影響は e2e、Pact、rag-orchestrator、CI ワークフロー。

### 3.8 観測が止まるか、最初から無い

TraceId がゼロ、アラートの UID が実体と違う、ルールは firing しても届かない、取り込みが 0 件でもエラーにならない。

例:

- [[000098]] ログの約 74% が DB ノイズで、TraceId はすべてゼロだった。[[000124]] を [[000125]] が置換したあとも、[[000127]] と [[000128]] でポート、未初期化 logger、専用フィールドから fields へ戻さない変換が残った。
- [[000134]] と [[000135]] は pre-processor と search-indexer で TraceID がゼロのまま、後者は約 322 箇所が残ったと本文が数えている。
- [[000286]] Grafana の統合アラートが UID とテーブル名の不一致で全滅した。
- [[000895]] の 3 日凍結（3.5）。誰も気付かなかったことが、この ADR の主題である。
- [[000969]] の未配送アラート（3.6）。

広がり: `observability_gap` 103。失敗対応ノートとの共起では `silent_fallback` と 51 件重なる。帰結は原因調査がログの不在から始まること。影響は rask、Grafana、pre-processor、search-indexer。

### 3.9 部分失敗を完了と記録し、再投入が雪崩になる

0 件保存、スキップ、短い本文、要約不可を成功または失敗の無限再試行にする。キューは同じ仕事で埋まる。

例:

- [[000149]] 保存 0 かつ 55 ジャンル失敗のジョブが Completed のまま閉じた。
- [[000076]] feed_id 欠損のスキップを失敗と数え、60 秒ごとに再試行した。
- [[000551]] 要約できない 63 記事が placeholder を書かず、1349 回再投入された。
- [[000504]] k6 由来のゴースト pending が約 191 万件残り、有効な要約が処理されなかった。
- [[000276]] `BatchUpsertArticleTags` が 101 回連続で失敗し、同じ 75 件を再抽出し、CPU 1683% になった。
- [[000320]] `$effect` が自分の Map 更新で再発火し、1 記事に毎秒約 30 回、5 分でストリーム開始 9181 回になった。
- [[001013]] 終端記事が 1 ページを埋め、enqueue 0 のまま要約が約 1 時間半遅れた。[[001014]] が版なし placeholder で未要約一覧から外す。

広がり: `partial_failure` 103、`retry_storm` 31、`idempotency` 59、`ui_state` のうち effect 再入は [[000279]] と [[000320]] と [[000441]]。帰結は GPU とキューの占有、完了に見える未処理。影響は pre-processor、tag-generator、news-creator、alt-frontend-sv。

### 3.10 一括 supersede が隣の契約まで外す

失敗した設計を退けること自体は記録として正しい。壊れるのは、置換リストが対象外の決定まで `superseded` にし、binding 一覧から消すとき。

本文で確認した例:

- [[000940]]（2026-06-11）は Knowledge Loop の read 表層を Knowledge Trail へ退け、loop 用の表を DROP して event log から再射影する。frontmatter の `supersedes` は 60 件。
- [[001011]]（2026-11-15）が経緯を書いている。2026-10-24 の frontmatter 一括修復が、本来 6 件だった [[000940]] の置換リストを 60 件へ広げ、54 件を `accepted` から `superseded` へ反転させた。[[000877]] の CI 三ルール（view 列順序、sparse-checkout、`atlas.sum` 追跡）は Loop と無関係なのに binding から落ちた。確定済み ADR は append-only のため、[[000940]] の辺は残したまま [[001011]] が契約を再確定している。
- [[001012]] は同じ一括修復で [[000895]] の無音取り込み検知が binding から落ちたため、その検知を現行契約として置き直している。
- 実地の廃止として本文が理由を述べているものは別にある。[[000533]] は自動全文取得（[[000486]] [[000487]] [[000488]]）を、収集の肥大と外部障害時の全体停止を理由に廃止。[[000743]] は共有 `X-Service-Token`（[[000719]] [[000720]] [[000735]]）を外して mTLS に一本化。[[000957]] は Hurl 11 件を Playwright へ退役。[[001007]] は Tag Verse の 5 件を WebGL 再実装で置換し、キャッシュウォーマーが分割後に届かず毎回コールドだったことを理由に含む。

帰結は二種類ある。設計の退役は read model の作り直し。一括修復の巻き込みは、障害の再発防止ルールが preflight に出なくなること。

## 5. 再発を止める優先策

優先は、すでに本文が「次も同じ形で壊れる」と書いており、かつ検知が利用者依存になっているものから。

1. **無音の成功を起動時とテストで別物にする。** 未配線の依存は `*_enabled` / `*_disabled` の起動ログを出し、業務経路で nil のまま呼ばれたら panic する。空配列を「無効」と「0 件」の両方に使わない。`|| true`、失敗を握る `.ok()`、side effect 失敗後の checkpoint 進行を CI で禁止する。対象は [[000928]] [[000535]] [[000616]] [[001004]]。
2. **health は仕事の前提を見る。** プロセス生存、TLS の鮮度だけでは pass にしない。モデルファイルの非空、sidecar の netns、アラートの配送先、外部トークンの非空を probe にする。`restart: "no"` の init container を `--no-deps` の rolling と組み合わせない。[[000826]] の deploy-model セルフチェックを、compose を変える ADR の必須項目として空欄のまま merge しない。対象は [[000825]] [[000826]] [[000802]] [[000980]] [[000969]]。
3. **投影の再実行テストを、projector を触る変更の入口にする。** 同じ event log を二度投影して行が一致すること。`time.Now()` と `GetLatest*` を projector から排除すること。checkpoint は永続化が成功したあとだけ進めること。dismiss や URL などの列を、後続 upsert のゼロ値で消さないこと。対象は [[000447]] [[000457]] [[000468]] [[000598]] [[000922]]。
4. **境界の ID は型と CDC で固定する。** `feed_id` と `feed_link_id`、`url` と `link`、記事 URL と RSS URL を同じ関数の戻り値にしない。producer がフィールドを足す変更は、Pact の失敗テストを producer の実装より先に入れる。「proto が生成できた」と「DI が渡している」を同じ緑にしない。[[000928]] 型の回帰は、nil を許すテストではなく、配線されたコンテナで 1 件 emit されるテストにする。対象は [[000300]] [[000306]] [[000867]] [[000942]]。
5. **実行中の設定を起動ログに 1 行で出す。** 採用したモデル名、secret の有無（値は出さない）、バイナリの revision、マイグレーション版。`.env` が compose の既定を上書きしたら、そのキー名を起動失敗か明示ログにする。未設定の必須 secret は exit 非ゼロ。Go と Rust の変更は再ビルド無しでデプロイしない。対象は [[000499]] [[000571]] [[000614]] [[000189]] [[000059]]。
6. **キューは 0 件保存を完了にしない。** スキップ、要約不可、終端記事は別状態で一度だけ記録し、同じ Idempotency-Key の失敗を再利用しない。外部 429 と内部の待ちを同じ再試行に混ぜない。`$effect` が自分の書いた state を依存に取る循環は lint で落とす。対象は [[000149]] [[000551]] [[000504]] [[000320]] [[001013]]。
7. **置換リストは対象を 1 件ずつ確認する。** `supersedes` を機械的に広げるコミットは、各 ID について「この決定の本文を置換しているか」を diff に残す。Loop と無関係な CI ルールや取り込み検知が binding から落ちた事実は [[001011]] と [[001012]] が既に補正している。次の一括修復では、binding 一覧の差分を PR の必須チェックにする。
8. **修正 PR は、直前の ADR が残した隣の失敗をテスト名にする。** 検索スピナー、GPU スロット、LLM の format は、直した経路の次段（ハートビートの次のフェーズ、返却の次のキャンセル、JSON の次のノード）が赤のまま残った。連鎖の 2 件目以降は、新しい設計ではなく欠落テストとして扱う。
