# ADR-000994: ADR-000993 の事後レビュー指摘に対する追補修正と本番 DB 修復計画を確定する

## Status

Accepted

## Date

2026-10-15

## Affected Services

- knowledge-sovereign (Go)
- alt-backend (Go)
- alt-frontend-sv (TypeScript / Svelte)
- knowledge-sovereign-db (PostgreSQL、read-only 調査および修復計画)

## Context

[[000993]] で実装した Knowledge Home / Your Trail のスリム化と `/feeds` 相互同期について、2026-10-15 に事後レビューと本番 DB の read-only 調査を実施したところ、以下の不具合・不変条件違反・計画差分が判明した。

- **knowledge-sovereign の branch 提案上書きと junk 候補による上位枠占有**:
  - `knowledge_trail_branches` の `ON CONFLICT (branch_key)` が `anchor_item_key`・`why_json`・`status`・`created_at` を上書きしていたため、2026-10-14 の計画外 `knowledge_event_dedupes` 削除の直後に再提案された 5 件の `trail.branch_proposed.v1` イベントで既存の branch 行（解決状態・生成時刻・anchor）が上書きされた。
  - cluster 候補 SQL が `LIMIT` の後に Go 側の `tagclean.CleanDisplay` でタグを正規化・除外していたため、junk タグや空タイトルの記事が SQL の上位枠を占有して有効な候補を締め出す（ロックアウト）経路が残っていた。また anchor を選ぶ LATERAL サブクエリも clean 共有タグの一致を条件にしていなかった。
- **alt-backend の同期 hook 無言スキップと `open` 時の過剰な既読化**:
  - Home↔`/feeds` 同期 hook に `!= nil` ガードによる無言スキップが入っており、[[000928]] で禁じた「DI 配線漏れを nil ガードで隠す」パターンに該当していた。また `FetchArticleByURL` のエラーログに URL 原文が含まれていた。
  - `open` アクションすべてで無条件に `MarkArticleAsRead` を呼んでいたため、`/feeds` 一覧での詳細展開やモバイルスワイプ面（[[000948]] の遅延既読フラッシュ + UNDO）でも即座に既読化され、スワイプの UNDO 契約を壊していた。
  - Trail branch を `taken` にした際に BE 側でも `open` を自動発行しており、遷移先の読書面（`/articles/[id]`）が記録する `open` と二重になっていた。
- **alt-frontend-sv の `open` 二重記録・`$effect` 契約違反・計画差分**:
  - Home カードをクリックして `FeedDetailModal` を開くと、カード側とモーダル側の双方が `open` を送信していた。Mobile `FeedDetails` も `articleId` 未確定時に Inoreader ID へフォールバックして `open` を送っていた。
  - `/articles/[id]` で `ArticleVisit` と `+page.svelte` が `$effect` 内で RPC 再取得・訪問記録を発火させていた。
  - Home ヘッダに「Your Trail」導線が残っており、in-place reader（`FeedDetailModal`）には記事末尾の end branches と `/articles/[id]` への導線が無く、lens 削除にも確認 UI が無かった。
- **本番 DB の状態**:
  - 2026-10-15 の read-only 調査により、(1) `knowledge_event_dedupes` から `trail.branch_proposed.v1` の 40 キーが欠落（2026-10-14 の計画外 DELETE 45 件のうち 5 件が再提案で埋まり 40 件が残存）、(2) Trail read model で `projection_version` 1 と 2 が混在し削除済み branch 6 件が欠落、(3) Home は v7 が active で実ユーザの 1,342 記事が v7 に欠落していることを確認した（recall の重複は 0 件、checkpoint 遅延も 0）。

[[000993]] は既に `origin/main` で `accepted` として確定しているため、追記専用規則に従い本 ADR で追補決定と修復計画を記録する。

## Decision

**[[000993]] の設計を以下のとおり追補修正し、本番 DB の修復手順を確定する。**

### knowledge-sovereign

- **`knowledge_trail_branches` の先勝ち upsert**: `ON CONFLICT (branch_key) DO UPDATE` は `projection_version = EXCLUDED.projection_version` のみを更新し、`anchor_item_key`・`why_json`・`status`・`resolved_at`・`created_at` を上書きしない。これにより重複した `trail.branch_proposed.v1` イベントが再生されても最初の提案内容と解決状態が保持される。
- **cluster 候補 SQL の `LIMIT` 前正規化と matched anchor 制約**:
  - 候補クエリ内の CTE で、Unicode 空白トリム・非 ASCII 句読点除去・小文字化・junk 語除外・長さと文字種フィルタを `LIMIT` 前に適用し、空タイトルの target 記事も除外する。
  - anchor を選ぶ LATERAL サブクエリでも、target と同じ clean 共有タグを持つ直近の engaged 足跡（`read` / `asked` / `listened`）だけを選ぶ。
  - 実 PostgreSQL に対する統合テストで、junk 候補による上位枠占有が起きないことと先勝ち upsert の挙動を検証する。
- `knowledge-sovereign/CLAUDE.md` の記載を実装（engagement verb 3 種、最小共有タグ数 1）に合わせて修正する。

### alt-backend

- **同期 hook の fail-fast 配線**: Home↔`/feeds` 同期 usecase（`TrackHomeActionUsecase` / `DismissKnowledgeHomeItemUsecase` / `UpdateFeedStatusUsecase` / `RegisterFavoriteFeedUsecase`）のコンストラクタおよび呼び出し時から nil ガードによる無言スキップを撤廃し、必須依存が nil の場合は panic して配線漏れを即座に検出する。`FetchArticleByURL` 失敗時は URL 原文を出さず構造化エラーログを記録する。
- **`open` 時の `/feeds` 既読化 allowlist**: `TrackHomeActionUsecase` が `MarkArticleAsRead` を呼ぶのは、`actionType == "open"` かつ `metadataJson` の `source` フィールドが `"home_card"`・`"article_page"`・`"favorite"` のいずれかである場合に限る。不正な JSON や非オブジェクトの `metadataJson` はエラーとして拒否する。これにより `/feeds` 一覧展開やモバイルスワイプ面（[[000948]]）の未読状態と UNDO を保護する。
- **branch `taken` 時の BE 側 `open` 自動発行の廃止**: `ResolveTrailBranchUsecase` から `homeActionTracker` 呼び出しを削除し、遷移先の読書面（`/articles/[id]`）が記録する `open` に一本化する。

### alt-frontend-sv

- **`open` 二重記録の解消**: Home から `FeedDetailModal` を開く際は `trackOpen={false}` を渡してカード側の `"home_card"` 記録のみに統一し、モーダル内の Next / Previous 移動時は Home 側のハンドラで移動先記事の `open` を 1 回だけ記録する。Mobile `FeedDetails` は解決済みの `articleId` が確定したときのみ 1 回だけ `open` を記録する。
- **`/articles/[id]` のイベント駆動化**: `ArticleVisit.svelte` と `src/routes/(app)/articles/[id]/+page.svelte` から `$effect` による訪問記録・end branches 再取得を撤廃し、`onMount` + `afterNavigate`（および単調増加トークンによる stale 応答破棄）で駆動する。
- **Home in-place reader の導線と lens 確認付き削除**:
  - Home ヘッダから「Your Trail」リンクを削除する。
  - `FeedDetailModal` で `showHomeReaderLinks={true}` のとき、記事本文末尾に `ArticleEndBranches` と URL エンコード済みの `/articles/[id]` リンクを表示する。
  - `LensSelector` に lens ID 単位のインライン削除確認 UI（Confirm / Cancel、確認ボタンへの初期フォーカス、削除対象の lens 名を含むアクセシブル名）を導入し、`useLens.remove()` で RPC 失敗時はロールバックのうえエラーを再送出して成功トーストの誤表示を防ぐ。
- **テストとクライアント呼び出しの整備**:
  - `EpisodeCard` の複数 footprint 既定展開に合わせて `tests/e2e/integration/knowledge-trail.spec.ts` を更新する。
  - `trackHomeActionClient` からテスト環境判定分岐（`import.meta.env?.MODE === "test"`）と動的 `import()` を除去し、静的 import と Vitest `{ spy: true }` モックで検証する。

### 本番 DB の修復計画（メンテ時間帯に承認を得て実行）

修正版のデプロイ後、書き込みを伴う各手順の実行直前に SQL・コマンドを提示して承認を得たうえで、以下の順序で修復する。

1. compose override で branch planner を一時停止する。
2. `knowledge_event_dedupes` の欠落 40 件（`trail.branch_proposed.v1:cluster:%`）を `knowledge_events` から補填する。
3. `knowledge-trail` read model を rebuild し、`projection_version` の混在と欠落 branch 6 件を解消する。
4. `knowledge_home` の v7→v8 reproject swap を実行し、v7 に欠落している 1,342 記事を回復する。

### 検討した代替案

- **[[000993]] を直接編集する**: `origin/main` で既に `status: accepted` となった ADR の変更は `docdag validate --immutable-since origin/main` の追記専用不変条件に違反するため却下した。
- **branch `taken` 時に BE 側と FE 側の双方で `open` を送り dedupe に任せる**: `HomeItemOpened` の dedupe key は操作単位で生成されるため二重イベントを防げず、contactCount の水増しを招くため却下した。

## Consequences

### Pros

- 重複した `trail.branch_proposed.v1` イベントが再生されても、先勝ち upsert により最初の branch 提案と解決状態が守られる。
- cluster 候補 SQL が `LIMIT` 前に正規化・junk 除外・anchor 一致を行うため、junk タグや空タイトル記事による候補枠のロックアウトが解消される。
- Home↔`/feeds` 同期の配線漏れが起動・呼び出し時に即座に検出され、モバイルスワイプ面（[[000948]]）の遅延既読フラッシュと UNDO が壊れなくなる。
- Home in-place reader・Mobile `FeedDetails`・`/articles/[id]` での `open` 記録が 1 閲覧あたり 1 回に揃い、`/articles/[id]` の再取得もナビゲーションイベント駆動になる。

### Cons / Tradeoffs

- **knowledge-sovereign（単体テストと pg 統合テストの役割分担）**: 先勝ち upsert を検証する projector 単体テストはフェイク同士の比較であり、実 SQL の先勝ち挙動は pg 統合テストが担保する。
- **knowledge-sovereign（SQL タグ正規化の境界とコスト）**: 空白判定と `[[:alpha:]]` は DB ロケールに依存する（本番・テストとも `postgres:16-alpine` で同一挙動）。SQL 側では複数形の単数化を行わないため単複ペアで共有タグ数が二重計上されうるほか、候補クエリで行ごとに `regexp_replace` を 2 回呼ぶ CPU コストが増える。
- **alt-backend（既存 port の nil ガード）**: 今回のスコープ外である既存の `!= nil` ガード（`dismissPort` / `recallSignalPort` / `featureFlagPort` / `articleURLLookupPort` / `tagHotspotPort`）は残存している。
- **alt-frontend-sv（既存 `$effect` と lens 削除ロールバック粒度）**: `/articles/[id]` には以前からある `$effect` ベースの取得が 2 箇所（source URL 解決と本文の自動取得、今回スコープ外）残っている。また `useLens.remove()` のロールバックは配列全体のスナップショットを戻すため、2 件の削除が重なり先行分が失敗した場合にサーバ側で削除済みの lens が画面上に戻りうる。
- **本番の追記専用ログ**: 重複して発行された `trail.branch_proposed.v1` イベント 5 件は追記専用の `knowledge_events` に永久に残るが、先勝ち upsert により投影への影響はなくなる。
