# ADR-001031: knowledge-sovereign の投影安全コアに Tauto による CAS checkpoint・欠番放棄モデルと適合テストを導入する

## Status

Accepted

## Date

2026-11-27

## Affected Services

- `knowledge-sovereign` (Go: `projection_gap` / `sovereign_db` CAS checkpoint 適合テスト・ゴールデンベクタ配置および 3 projector 横断整合対象)
- `specs` (`specs/tauto/sovereign-projection/` 配下の形式仕様・機械検証済み定理・ベクタ出力ドライバ)

## Context

`knowledge-sovereign` のイベントログ再生・チェックポイント前進・欠番（sequence gap）処理は、Alt の不変データモデル（Append-first / Reproject-safe / Disposable projections、[[000447]]・[[000468]]・[[000944]]）の要であり、投影カーソル周りで 2 件の重大障害が発生している。

- **`PM-2026-010` と [[000967]]**: `PM-2026-010` では V3 reproject swap 時のチェックポイント未リセットにより約 4 日間・326 記事欠落・1,947 件の `summary_state` 停滞が発生した。さらに [[000967]] の統合テスト新設時に、単一トランザクション化した `RebuildProjection` に対しても in-process projector の無条件 `UpdateProjectionCheckpoint` が古いバッチの `last_event_seq` を後から上書きして同じ欠落状態を再発させる競合が判明し、[[000967]] で 3 要素 read token（`Exists`, `LastEventSeq`, `UpdatedAt`）による Compare-and-Set（CAS）を導入して `0 -> 0` ABA と初回起動競合を含め閉じた。
- **`PM-2026-064`**: `knowledge_events.event_seq`（`BIGSERIAL`）の欠番を扱う `projection_gap` で、`reading_projector` が 0 から約 113 万行（約 1.07 万〜1.09 万個の burned hole）を再生する際、欠番ごとに tick を打ち切って追いつきに約 30 時間掛かる状態となり、Read Today キューが 4 時間 15 分表示されなかった。

本 ADR 策定前の 3 projector（`knowledge_home_projector` / `knowledge_trail_projector` / `reading_projector`）横断監査により、現行実装にも以下 4 項目の構造ギャップが確認された（FP-03 / FP-05 / FP-07）。

1. **`PM-2026-064` の同一 tick 追いつき修正が `reading_projector` のみに留まる**: `reading_projector/projector.go:139-141,181-193`（`MaxBatchesPerTick = 40`）は `hole.Open()` で `continue` し、実行中 Tx が無ければ同一 tick 内で 2 回目の `ReadSequenceGapFrontier` を実行する。一方 `knowledge_home_projector/projector.go:206-208,219-239` と `knowledge_trail_projector/projector.go:203-205,216-236`（`MaxBatchesPerTick = 4`）は旧実装のまま `return nil` で tick を打ち切っており、rebuild 時に同じ約 30 時間停滞リスクが残っている（`PM-2026-064` AI #1 未着手）。
2. **`reading_projector` のテスト用 CAS モックが `Exists` / `UpdatedAt` を検査していない**: `reading_projector/projector_test.go:100-110` の `fakeReadingRepo` は `LastEventSeq` のみ比較し `Exists`・`UpdatedAt` を無視している（`home` / `trail` のフェイクは 3 要素すべて検証）。また実 PostgreSQL での projector 対 rebuild の CAS 統合テストは `knowledge_home_projector/projector_pg_test.go` にしか無く、`trail` / `reading` には無い。
3. **CAS 証人 `updated_at = now()` の暗黙前提と `ContiguousPrefix` の暗黙境界**: `read_infra_checkpoints.go:117-118` が示す通り `now()`（マイクロ秒精度 `transaction_timestamp()`）の厳密単調性を前提にしており、同一マイクロ秒更新や NTP 巻き戻しでは `0 -> 0` ABA が閉じ切れない（単調増加 `BIGINT` 世代列で完全閉鎖可能）。また `projection_gap.ContiguousPrefix`（`gap.go:44,49-58`）は `afterSeq >= 0` かつ狭義単調増加を暗黙前提としており、前提を破ると `First > Last` の逆転 hole を返す。
4. **3 projector 間のエラー処理・Rule 8 配線ログの非対称性および `EvaluateReadRuleV1` の二重実装**: `EvaluateReadRuleV1` は `alt-backend/app/domain/reading_event.go:39-53` と `knowledge-sovereign/app/usecase/reading_projector/rule.go:28-42` に完全重複しており、[[001018]] の閾値改訂時に片側修正ドリフト（FP-02）を起こす構造になっている。

事前プロトタイプ（`Hihaheho/tauto` v0.1.0、8 `inductive enum` / 23 純粋 `fn` / **40 `pub theorem`**）では、`tauto --offline check --fresh --summary` が **`71 ok, 0 failed, 0 incomplete; 0 skipped; axioms: none`**（カーネル検証 `0.314s`、コールド wall-clock `2.92s`）で通過し、21 本の決定論的適合ベクタ（`8 CAS + 9 GAP + 4 PREFIX`）を `tauto --offline run` で出力できることを実証した。

## Decision

**[[001029]] で確定した Tauto 形式仕様基盤を用い、[[000967]] の CAS checkpoint 競合プロトコルおよび `projection_gap` の欠番放棄・同一 tick 再プローブ規則を `specs/tauto/sovereign-projection/` として形式化し、本番 Go ランタイム依存ゼロの適合テストオラクルを `knowledge-sovereign` に導入する。**

本決定は [[000965]]（実 PostgreSQL 統合層）・[[000967]]（CAS checkpoint 前進）・[[001029]]（配置規約・CI ゲート・撤退基準）を前提・拡張とし、既存 ADR を置換しない。単一行 `knowledge_home_items` の SQL マージ則および `EvaluateReadRuleV1` のクロスサービス共有オラクル化は別判断とし、本 ADR のスコープ外とする。

### 1. 形式モデルと機械証明する不変条件

`specs/tauto/sovereign-projection/`（`src/` と `vectors/` 分離、[[001029]] 規約準拠）において、以下 2 部構成を無制限の `Nat`・`List(Nat)` に対し **公理ゼロ・hole ゼロ** で証明する。

#### Part A: CAS Checkpoint + Rebuild 並行プロトコル（[[000967]] 拡張）

1. **初回起動 `Absent` 競合の安全性**: 未競合の `Absent` は `Present(to_seq, write_ts)` へ前進し、並行 rebuild が先に `Present(0, rebuild_ts)` を作成済みの場合は `Absent` トークンが必ず拒否されて `(0, rebuild_ts)` を保持する（`ON CONFLICT DO NOTHING` 意味論）。
2. **`0 -> 0` ABA および rebuild 後旧トークンの拒否**: `tok_ts < rebuild_ts` の下で、rebuild 後の旧トークンおよび 2 重 rebuild による `0 -> 0` ABA は必ず拒否され、イベント `1..M` がスキップされないこと。
3. **`UpdatedAt` / `Exists` の必要性反例**: `LastEventSeq` のみ比較し `Absent -> 0` に畳むナイーブ CAS が `0 -> 0` ABA および初回起動競合で誤って `applied = true` を返しチェックポイントを飛ばす反例を定理として固定する。
4. **2 アクター間プロトコル終端と単調前進**: in-flight バッチ（`Present` / `Absent` 双方）に対して rebuild が先行した場合の終端状態は常に `Db(Present(0, rebuild_ts), true)` であること、wire RPC 無条件 upsert（`UpdateProjectionCheckpoint`）後の旧トークンが拒否されること、一致トークンが単調前進し再利用できないこと。

#### Part B: `projection_gap` + `ContiguousPrefix` + 同一 tick 再プローブ

1. **欠番放棄の 5 安全性質**: `HoleOpen = false` なら絶対に放棄せず `EmptyTracker` へ戻すこと、初見の穴は絶対に放棄しないこと、境界が変わった穴は旧観測を引き継がないこと、`xmin < prev_ceiling` なら実行中 Tx をスキップしないこと、放棄確定時は `EmptyTracker` に戻り再出現した穴をゼロから判定し直すこと。
2. **`PM-2026-064` 同一 tick 2 回プローブの安全性**: 実行中 Tx が残っていれば 1 回目で待機し、2 回目の読み取り前に書き手がコミットして穴が閉じた場合は放棄せず、burned hole かつ実行中 Tx 不在のときのみ 1 tick で通過すること。
3. **`ContiguousPrefix` の帰納法安全性**: すべての `events: List(Nat)` と `after_seq: Nat` に対し、`OpenHole(first, last)` で停止したとき返却プレフィックスの全要素 `x` が `x < first` を満たすこと。

### 2. Go 適合テストオラクルと実 PostgreSQL 統合層（[[000965]]）との責務分担

- **ゴールデンベクタと 2 層適合テスト**: `tauto --offline run` の出力を `knowledge-sovereign/app/usecase/projection_gap/testdata/projection_safety_vectors.txt` へコミットする。
  - 通常の `go test ./...`（Docker 不要・`tauto` 不要）が `PREFIX|*` / `GAP|*` / `CAS|*` を再生し、`projection_gap.ContiguousPrefix`・`Tracker.MayAbandon`・同一 tick ヘルパ・インメモリ CAS モックを検証する。
  - `//go:build integration` 配下の `driver/sovereign_db/cas_conformance_pg_test.go` が同一の `CAS|*` ベクタを `pgtest.NewDB(t)` 上の実 PostgreSQL（`ReadProjectionCheckpointForAdvance` / `AdvanceProjectionCheckpointIfUnchanged` / `RebuildProjection` / `UpdateProjectionCheckpoint`）へ流して突合する。
- **実 PostgreSQL 統合層（[[000965]]）が引き続き担う境界**: モデルは MVCC やストレージを抽象化しているため、以下は引き続き `pgtest` 統合テスト（`gap_pg_test.go`・`read_infra_pg_test.go`・`rebuild_projection_pg_test.go`）で担保する。
  - 単一 SQL 文内の MVCC スナップショット原子性（`pg_current_xact_id`・`pg_snapshot_xmin`・`NOT EXISTS`）
  - 書き手側の `dedupe INSERT` 先行による xid-before-seq 順序および `BIGSERIAL CACHE 1`
  - `RebuildProjection` の単一トランザクション `TRUNCATE` 原子性・`FOR UPDATE` ロック・FK 整合性
  - `now()` のマイクロ秒精度時刻制約（モデルでは `tok_ts < rebuild_ts` を前提とするため、同一マイクロ秒衝突・NTP 逆行を完全排除するには後続マイグレーションでの単調 `BIGINT` 世代列導入が必要）

### 3. 段階的実装順序（Phase 1 / Phase 2）と PM アクション対応

1. **Phase 1（形式仕様 + 適合テスト追加）**: [[001029]] の基盤整備と合わせて `specs/tauto/sovereign-projection/`・`testdata/projection_safety_vectors.txt`・ユニットおよび `//go:build integration` 適合テストを追加する。Phase 1 完了時点で本 ADR を `accepted` へ更新する。
2. **Phase 2（3 projector 横断整合のハードニング PR・別 PR、TDD 先行）**:
   - `knowledge_home_projector` と `knowledge_trail_projector` を、証明済み同一 tick 追いつき仕様に合わせて `reading_projector` と統一する（`PM-2026-064` AI #1 をクローズ）。
   - `reading_projector/projector_test.go` の `fakeReadingRepo` に欠落している `Exists` / `UpdatedAt` 検証を追加し、`CAS|*` ベクタで 3 projector のテストフェイク挙動を揃える。
   - `knowledge_trail_projector` と `reading_projector` にも実 PostgreSQL での rebuild 対 projector CAS 統合テストを追加し、Rule 8 の起動配線ログ・`repo == nil` 検査を 3 projector 間で統一する。
   - なお `knowledge_projection_checkpoints` の単調 `version BIGINT` 化（時刻非依存化）、`EvaluateReadRuleV1` の共有オラクル化（[[001018]]）、および `PM-2026-064` の観測性アラート項目（`#3` 等）は独立した別 ADR / PR として扱う。
   - 本実装ブランチ（`feat/tauto-formal-specs`）では Phase 1（`specs/tauto/sovereign-projection/`：53 `pub theorem`・`107 ok, 0 failed, 0 incomplete, 0 holes, 0 skipped, axioms: []`、30 ゴールデンベクタ＋ユニット/`pgtest` 適合テスト）と Phase 2（`Tracker.ProbeAndEvaluate` 共通化・3 projector の同一 tick 追いつき統一・`fakeReadingRepo` 3 要素検証・`trail`/`reading` 実 PG CAS 統合テスト・Rule 8 配線ログ/nil panic 統一）を一括実装・検証済みのため、本 ADR を `accepted` とする。

### 4. 検討した代替案と却下理由

- **Go ユニットテスト + `rapid` PBT のみで継続する案**: 現行ユニットテストでは `reading_projector` の `fakeReadingRepo` が `Exists`/`UpdatedAt` 検査を落としていても気付けず、`home`/`trail` と `reading` の仕様乖離も防げなかった。また `rapid` は有限サンプリングかつ **MPL-2.0**（[[000988]] 許可リスト外）であるため主系には採らない。
- **`pgtest` 統合テストの拡充のみで対処する案**: MVCC や SQL 実行の検証には不可欠だが、無制限の `List(Nat)` / `Nat` に対する `ContiguousPrefix` や `0 -> 0` ABA の網羅証明はできないため、形式仕様の代替ではなく必須の補完層（[[000965]]）として位置づける。
- **Tauto の Rust / WASM 出力を Go (`knowledge-sovereign`) へ組み込む案**: Go サービスに WASM ランタイムや cgo 境界を持ち込む複雑さが純粋ロジック規模に見合わず、本番ランタイム依存ゼロの方針（[[001029]]）にも反するため却下した。

## Consequences

### Pros

- `PM-2026-010` / [[000967]] の CAS ABA 防止と `PM-2026-064` の欠番放棄・同一 tick 再プローブを、無制限のシーケンス番号・イベント列に対する公理ゼロの機械証明として固定できる。
- `knowledge-sovereign` の本番バイナリ・Docker イメージ・通常 `go test ./...` に `tauto` 依存を一切持ち込まず、単一の検証済み仕様を 3 projector（`home` / `trail` / `reading`）の共通ベースラインにできる。
- 監査で判明した `home` / `trail` の約 30 時間 rebuild 停滞リスクと `reading_projector` CAS モックの検証欠落を、証明済み仕様を基準に迷わず是正できる。

### Cons / Tradeoffs

- `tauto` は `tok_ts < rebuild_ts` を前提として CAS 安全性を証明するため、PostgreSQL `now()` の同一マイクロ秒衝突・時刻逆行リスクは単調 `BIGINT` 世代列を別マイグレーションで導入するまで残る。
- 仕様ファイルは約 1,200 行（カーネル検証 `0.314s`）の保守対象となり、`projection_gap` や checkpoint SQL の契約変更時は `.taut` 仕様・証明・`testdata/` ベクタの同期更新が必要になる（[[001029]] の CI ゲートで強制）。
- wire RPC `UpdateProjectionCheckpoint`（`SwapReproject` 経路）の無条件 upsert 自体は [[000967]] と同様スコープ外であり、本モデルでは「wire upsert 後の旧 in-process トークン拒否」までを扱う。
