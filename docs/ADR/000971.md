# ADR-000971: Recap の人間向け出力を「一画面・一示唆」に縮退させる形式実験を行い、文書の第一読者を人間から機械へ移す判断材料を得る

## Status

Superseded by [[000975]]

**Web / code 調査後の判定（2026-08-11）: 実験設計の後継 ADR が必要。** 現行の 3 日 Recap は
「3 日ごと」ではなく 3 日窓を毎日 JST 02:00 に生成するため、D1/D4 の「4 サイクル ≈ 12 日」が
実装事実と一致しない。また `EmitTrailOutcome` / `trail.act_outcome.v1` は taken branch の帰結専用で、
Recap 接触計測へ流用できない。本 ADR の Decision は実装根拠にせず、[[000975]] を正とする。

## Date

2026-08-11

## Affected Services

- recap-worker (Rust) — 一示唆カード出力の追加（中間成果・フル文書生成は無変更）
- alt-frontend-sv (TypeScript) — 着地画面の変更と計測イベント
- knowledge-sovereign (Go) — 計測イベントの受領

## Context

### 1. 観測された事実: Recap は生成コストに対して読まれていない

運用者自身の観測として、直近 3 日を窓にした Recap は生成しているが読んでいない。実装は
`DailyCadence` による JST 02:00 の日次バッチであり、「3 日ごとに 1 回生成」ではない。原因の仮説は
強い順に「読みにくい ＞ 価値を感じづらい構造 ＞ 品質が低い ＞ 構想の敗北」と推定されているが、
どの仮説も未検証である。仮説の検証コストは前者ほど低く、後者ほど高い。したがって最も安い仮説
（形式）から棄却を試みる方向は合理的だが、観測単位は「配達」または非重複窓として定義し直す必要がある。

### 2. 読書行動の研究は「形式仮説」を最有力として支持する

Nielsen Norman Group の 2008 年の調査では、平均的なページ滞在時間から読める語数の上限を 28%、
現実的には約 20% と推定している（https://www.nngroup.com/articles/how-little-do-users-read/ ）。
1997 年の小規模 lab 調査では、79% がページをスキャンし、逐語的に読んだのは 16% と報告された
（https://www.nngroup.com/articles/how-users-read-on-the-web/ ）。一段落一アイデア・逆ピラミッド・
語数削減という処方箋と、scannable / concise 条件での usability 改善（各 47% / 58%）は形式仮説を
質的に支持する。

ただし、これらは 1997 / 2008 年の汎用 Web ページや観光サイトの task usability を対象とし、
2026 年の単一ユーザー向け Recap の読了・遷移率を直接予測する研究ではない。47〜58% は本実験の
効果量や D4 の閾値の根拠として使わず、「長文より scan 可能な形式を先に試す」順序の根拠に限定する。

### 3. Recap の計算は文書が読まれなくても無駄ではない

recap-worker は多段の決定論的処理（日本語形態素処理、文単位 XXH3 による近似重複排除、
genre 分類の一部 rescue 経路における疎行列ラベル伝播）を持ち、通知は自 DB の
`notification_outbox`（`src/store/dao/notification_outbox.rs`）から relay
（`src/notification/relay.rs`）で data-hub に転送している。これらの中間成果は「直近 3 日に
ユーザーが追っていた問いの束」の機械可読表現であり、[[000973]] の branch 候補生成の入力として
価値を持つ。つまり検討すべきは「Recap を廃止するか」ではなく「Recap の第一読者を誰にするか」である。

### 4. 本 ADR が決めないこと

フル文書の廃止・縮退の最終判断は本 ADR では行わない。それは実験データが決める。本 ADR が決めるのは実験の設計・計測・判定規則のみである。

調査後の制約として、D3 の「同じ計測方式」は Page Visibility による visible-time 計測手法の再利用だけを
意味し、Trail RPC / event の再利用を意味しない。`EmitTrailOutcome` は `branch_key` を要求し、
`trail.act_outcome.v1` は branch taken 後の first-write-wins outcome である。Recap カード接触を
この語彙へ混ぜると Trail の語彙最小・closure 契約を壊す。実験用イベントの namespace、dedupe、
retention、分析期間を後継 ADR で固定する。

## Decision

**次の 4 サイクル（約 12 日間）、Recap の人間向け出力を二形態並走させる形式実験を実施し、事前に固定した判定規則で文書の扱いを決めることを採用する。**

### D1. 二形態の並走

- **フル文書**: 現行のまま生成し、アーカイブとして保存する（検索・Augur の grounding 対象としての役割は維持）。
- **一示唆カード**: 同じパイプラインの最終段に追加する新出力。構成は「その期間の最重要の示唆 1 つ（3 文以内）＋未回収の問い 1 つ」に固定する。一画面に収まらない量を禁止する（Context §2 の処方箋の適用）。

### D2. 通知は変更しない、着地を変更する

`recap_ready` の通知 kind・payload・トリガー性（コンテンツを運ばない）は一切変更しない。変更するのはタップ後の着地画面で、一示唆カードを先に表示し、フル文書へのリンクを card 下部に併置する。

### D3. 計測

既存イベントストリームに以下を記録する: (1) カード表示、(2) カードからの文書遷移、(3) 文書上の可視滞在（dwell、Page Visibility 準拠 — `EmitTrailOutcome` と同じ計測方式）、(4) カード上の問いから検索・Augur への遷移。新しい計測基盤は作らない。

### D4. 判定規則（事前固定）

4 サイクル終了時点で:

- カード接触がありながら文書遷移が 4 サイクル中 1 回以下 → **形式仮説を採択**。人間向け Recap は一示唆カードを正とし、フル文書は生成継続するが UI 上はアーカイブ（検索経由）に格下げする。
- 文書遷移が半数以上のサイクルで発生 → 形式仮説を棄却し、次順の仮説（構造）の検証を別 ADR で設計する。
- カード自体に接触がない → 形式よりも上流（通知そのもの・生活動線）の問題であり、[[000970]] のバッジ導線の効果と合わせて再診断する。

単一ユーザーの自己実験であり統計的検定は成立しないが、本システムの真実はその単一ユーザーの行動のみであるため、これを判断材料として十分とみなす。

### D5. 中間成果の機械読者への公開（方向づけのみ）

recap-worker の中間成果（クラスタ、ジャンルラベル、重複排除済み文集合)を planner から参照可能にする配線は、本 ADR では方向として記録するに留め、実装は [[000973]] 側の候補生成設計で扱う。

### 検討した代替案と却下理由

**(a) フル文書の即時廃止 — 却下。**
形式仮説は最有力だが未検証であり、廃止は不可逆に近い（生成停止期間のアーカイブ欠損）。並走実験なら検証コストは 1 出力の追加だけで済む。

**(b) 要約品質の改善から着手 — 却下。**
仮説順位で品質は 3 番手である。読まれていない文書の品質を上げても、読まれない原因が形式なら効果は観測されず、投資順序として誤り。

**(c) 生成頻度の削減（3 日→7 日）のみ — 却下。**
コストは下がるが形式仮説を何も検証しない。頻度は実験結果が出た後の変数として残す。

**(d) 通知本文に示唆を直接載せる — 却下。**
トリガー専用原則の変更であり、本実験の変数を増やす。コンテンツ搭載の是非は [[000973]] の rich preview 節に集約する。

## Consequences

### Pros

- 最も安い仮説から順に、事前固定の判定規則で検証でき、「なんとなく読んでいない」が言語化される。
- 実験に失敗がない: どの結果でも次の一手（採択 / 次仮説 / 上流再診断）が確定する。
- フル文書の生成は継続するため、アーカイブ・grounding 資産に欠損が生じない。
- 「一画面・一示唆」という出力単位の規律が、[[000973]] の Beacon 本文設計の先行検証を兼ねる。

### Cons / Tradeoffs

- 4 サイクルの間、出力が二形態になり recap-worker の最終段が一時的に複雑化する。
- 判定規則 D4 は行動データのみに依存し、「読んだが価値を感じなかった」を区別できない。構造仮説の検証は別設計が必要になる。
- 単一ユーザー実験のため、生活リズムの変動（旅行・繁忙）がノイズとして乗る。実験期間中の異常週は判定から除外する運用とする。
- baseline も形式の反転もない 4 観測では、形式変更と示唆内容・新奇性・生活リズムを分離できない。D4 の結果は因果的な採択ではなく次の運用仮説に留める必要がある。
- 「異常週」は事後裁量で除外すると判定を恣意化する。除外条件と、除外後に必要観測数を割った場合の延長規則を実験開始前に固定する必要がある。
- Recap 計測を既存 hot-retention の user-event 面へ置く場合、baseline と intervention の全期間を比較できる retention を先に保証しなければならない。
