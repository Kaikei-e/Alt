# ADR-001037: VERIFY-01〜06 の動的検証層と pstack 準拠の実機検証スキルを alt-harness へ統合する

## Status

Accepted

## Date

2026-11-27

## Affected Services

- `scripts/altharness`, `scripts/verify`, `scripts/harness/corpus`, `scripts/agent-harness/templates` (Go 単一バイナリ検証サブコマンド・テンプレート・コーパス)
- `.claude/skills/verify-alt`, `.claude/skills/maintain-verification-skill`, `.agents/skills/`, `.agents/rules/rule-ledger.md` (検証スキル・Feature Map・規則台帳)
- `alt-backend/app`, `auth-hub`, `pre-processor/app`, `rag-orchestrator`, `docker/inference-proxy`, `alt-backend/sidecar-proxy`, `proto/tools/protovis` (VERIFY-03 実効設定ゴールデン・VERIFY-05 Flaky 修正)
- `recap-subworker`, `news-creator`, `plecto`, `recap-worker` (VERIFY-02 分割同値性テスト・VERIFY-04 実機プローブ・VERIFY-06 ABI/Clippy 証拠)

## Context

[[001028]] により Alt のエージェントハーネスは単一の標準ライブラリ専用 Go バイナリ（`scripts/altharness/alt-harness`）へ統一され、層 1（`ARCH-01〜06`）と層 2（`CHECK-01〜07`）および `CORPUS-01`（22/22 捕捉）が稼働している。しかし層 3（実物による動的検証 `VERIFY-01〜06`）には以下の未完ギャップが残っていた。

1. **VERIFY-01 の残差**: `alt-harness packet verify-sequence` で `--packet` から `base_commit` / `behavior_preserving` を自動読込できておらず、コーパス `C-06`・`C-15` に特性テストが未接続だった。
2. **VERIFY-02（長大関数分割の差分試験）**: `recap-subworker` の学習エントリポイント 5 本のうち `train.py` 以外の 4 本や補助分割スクリプトについて、`git show <base>:<path>` による分割前後の乱数入力差分試験と不変条件プロパティテストが未整備だった。
3. **VERIFY-03（実効設定ゴールデン）**: Echo v5 移行対象 4 サービスおよび `inference-proxy`・`sidecar-proxy`・`protovis` の組み上がった実効設定（ルート × ミドルウェア順・タイムアウト・BodyLimit・CORS・転送ヘッダ・出力ファイルモード）を JSON ゴールデンで固定する仕組みがなく、`C-11/12/14/15` の再発をランタイム設定層で検出できていなかった。
4. **VERIFY-04（実機検証スキルと Feature Map）**: `C-07`（`aclose()` 例外時に SSE が終端せずハングする問題）や境界値・認証・プロキシ転送を、本番 `-p alt` のポート・DB・ボリュームから完全隔離した実機プロセスで動かして証拠を残す検証スキルと Feature Map 保守ループが未実装だった。
5. **VERIFY-05（不安定テストの再現と修正）**: `pre-processor/app` で発生していた間欠失敗を `-shuffle=on -race` シード付きで再現・特定するランナーと根本修正が未完了だった。
6. **VERIFY-06（主張ごとの検証証拠）**: 実装報告の「影響ゼロ」等の包括主張を機械拒否し、`plecto` WASM Component Model の `wasm-tools component wit` 比較および `recap-worker` の `cargo clippy` 警告ゼロ証拠を再実行可能に検証する仕組みが未配線だった。

## Decision

[[001028]] の単一純 Go 標準ライブラリ方針（`scripts/altharness/go.mod` の外部依存ゼロ）を維持したまま、`VERIFY-01〜06` すべてを `scripts/altharness/alt-harness` のサブコマンド・コーパス・メタゲートおよび検証スキルへ統合する。

1. **VERIFY-01 補完**: `internal/packet` の `verify-sequence` が `--packet` から `base_commit` / `packet_id` / モードを自動解決するようにし、コーパス `C-06`・`C-15` に特性テストを接続して `C-06`・`C-15`・`C-18` 全 3 件の 2 コミット目失敗を実証する。
2. **VERIFY-02（`alt-harness verify-diff`）**: `git show <base>:<path>` を隔離一時ディレクトリへ展開して分割前後を乱数入力で比較し、`.harness/evidence/verify-02/` および `guards.AppendDecisionToFile` 経由で LOOP-03 正準結果語彙（`info`/`mismatch`）の `decisions.tsv` へ通過記録を書き出し、一時足場の残存を `check-clean` で禁止する。`recap-subworker` の未確認分割箇所すべてに決定論的シード付き不変条件プロパティテストを恒久化する。
3. **VERIFY-03（`alt-harness verify-golden`）**: 7 サービス（`alt-backend/app`, `auth-hub`, `pre-processor/app`, `rag-orchestrator`, `docker/inference-proxy`, `alt-backend/sidecar-proxy`, `proto/tools/protovis`）の実効設定を正規 JSON ゴールデンとしてコミットし、`C-11/12/13/14/15` の改変で確実に差分が出ることを単体テストおよび `CORPUS-01`（`VERIFY-03`）で検証する。あわせて CI メタゲート向けに高速・オフライン安全な `--check-files-only` 検査を配線する。
4. **VERIFY-04（`alt-harness verify-live` + `verify-alt` / `maintain-verification-skill`）**: 本番 `-p alt` をハード拒否する隔離不変条件のもと、`127.0.0.1:0` 実機ループバックプローブ（`sse` / `body-limit` / `auth-hub` / `inference-proxy`、実生産配線関数呼び出し）と `C-07` SSE 終端ハング検知を実装し、`.claude/skills/verify-alt/`（現行ルート整合済み Feature Map 5 ファイル含む）および `.claude/skills/maintain-verification-skill/` を `.agents/skills/` シンボリックリンク込みで整備する。SSE probe の実行環境検証と CI での実実行は [[001036]] の契約（実ハンドラ import 検査・fail-closed・スキップ禁止）に従い、CI メタゲートでは書き込み非依存の `doctor --hygiene-only` を実行する。検証スキル・Feature Map・保守ループの概念設計は Cursor プラグイン `pstack`（MIT License, https://github.com/cursor/plugins/blob/main/pstack/docs/guide/README.md ）を参照し、Alt 固有の要件に合わせてクリーンルーム実装する。
5. **VERIFY-05（`alt-harness flaky-hunt` + `scripts/verify/flaky-hunt.sh`）**: Go（`go test -json -count=N -shuffle=on -race`）と Python（`pytestrand`）のシャッフルシード抽出・証拠保存ランナーを実装し、`pre-processor/app` で再現した 2 件の実 Flaky（`ProxyMetrics` nil logger 汚染 + `totalRequests` 競合、`TestLoggingPerformance_MemoryUsage` の `uint64` アンダーフロー）をシード固定回帰テスト付きで修正する。
6. **VERIFY-06（`alt-harness verify-claims` + 報告書テンプレート）**: 実装報告の「主張 / 証拠（コマンドと出力保存先）」表を必須化し、裏付けのない包括主張やプレースホルダを機械拒否する。あわせて `plecto` の `wasm-tools component wit` / `.wasm` SHA-256 比較および `recap-worker` の `cargo +1.99.1 clippy` 警告ゼロ証拠を実測台帳として固定する。
7. **統合配線**: 5 新規サブコマンド（`verify-claims`, `verify-diff`, `verify-golden`, `verify-live`, `flaky-hunt`）を `main.go`・`selfcheck`・`corpus`・`meta` ゲート・`.agents/rules/rule-ledger.md` へ配線する。

検討して却下した案:
- **検証スクリプトを個別の Python / Bash スクリプトとして追加する案**: [[001028]] の単一 Go バイナリ・二重正本根絶方針に反するため却下した。
- **本番 Compose（`-p alt`）共有ポートで VERIFY-04 を動かす案**: 単一マシン運用の本番コンテナ・DB・ボリュームを汚染する危険があるため却下し、`127.0.0.1:0` 隔離ループバックを標準・`-p alt-verify-*` 隔離 Compose を任意モードとした。

## Consequences

### Pros

- 静的解析・構文木スクリーナに加えて、コミット順・分割同値性・実効設定ゴールデン・実機ループバック・Flaky 再現・主張別証拠の層 3（`VERIFY-01〜06`）がすべて機械実行可能になる。
- `pre-processor/app` に潜んでいた nil logger パニックと `uint64` アンダーフローの 2 件の Flaky 要因がシード再現のうえで根本解消される。
- `verify-alt` スキルと Feature Map・保守ループにより、AI エージェントが自己申告ではなく実機証拠（`.harness/evidence/<task>/`）に基づいて動作を証明できる。

### Cons / Tradeoffs

- `verify-golden` や実機プローブの維持コストが増えるが、設定変更時の PR レビューを差分読みから成果物確認へ置き換えられるため総合コストは下がる。
- `docs/review/` 配下の実測証拠台帳は `.gitignore` 対象のため、意図的にバージョン管理する台帳のみ明示追跡する運用となる。
