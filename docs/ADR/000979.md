# ADR-000979: Compose の file-bind / pre_start / init-edge / OSU 予算を CI で凍結し create_host_path:false と Compose 5.4 以上を契約にする

## Status

Accepted

本 ADR は CI と本番 include チェーン上の予算契約を記録する。ホスト Compose のアップグレードや本番反映は行っていない。[[000825]] / [[000826]] / [[000809]] を **supersede しない**。

[[000825]] の置換境界は compose-init 層だけである。残る: Pydantic validator と `Path.is_file()`。obsolete: named-volume + SCS init-container（`recap-subworker-artifacts-init`）。rolling `--no-deps` でその init は走らない（[[PM-2026-037]] / [[000826]]）。現行の fail-closed mount は directory bind + `create_host_path: false`（本 ADR D1）であり、[[000825]] が directory-bind を既に決めたわけではない。

## Date

2026-08-19

## Affected Services

- `compose/compose.yaml` の include チェーン（本番）
- `.github/workflows/compose-audit.yaml`
- `scripts/compose-*-audit.py` / `scripts/ops-surface-inventory.yaml` / `scripts/ops-surface-baseline.json` / `scripts/compose-feature-gate.report.json`
- オペレータホストの Compose バージョン前提

## Context

P2 の構造移行は「サービスを足すな」ではなく「足すときの会計と fail-closed を機械的に固定する」ことが目的だった。人手のレビューだけでは次が再発する。

- [[PM-2026-036]]: 短形式ファイル bind は欠落 source を空ディレクトリにし、`Path.exists()` を素通りする。recap-subworker は 8 日間 healthy のまま分類を返さなかった。
- [[PM-2026-037]] / [[000826]]: `depends_on: service_completed_successfully` の sibling init は rolling `--no-deps` で起動されない。
- [[000809]]: `service_healthy` の先に healthcheck が無いと `up --wait` が abort する。
- Wave 0 実機は Compose v5.0.0 で `pre_start` を reject した。再測定は v5.5.0 で `pre_start.ok=true` かつ `create_host_path_false.ok=true`。契約の床は **Compose 5.4.0**（`pre_start` サポート）。フラグ無しの long-syntax は短形式と同じく空ディレクトリを作る。
- 運用面（OSU = 本番 include の long-running サービスキー）は、[[000978]] の sidecar 退役後に **declared 91→77、long-running 77→63、accidental OSU 30→16**。ephemeral oneshot 10 + profiled 4。init-edge allowlist は **22**（migrator / `step-ca-bootstrap` / `oauth-token-init`）。cap は上げない。

名前の正本は compose。inventory YAML を第二の手書きリストにすると F1 が沈黙する。

## Decision

**本番 compose の file-bind / pre_start / init-edge / operational-surface 予算を CI の fitness function として凍結する。欠落ホスト path は `create_host_path: false` または `configs:` / `secrets:` で fail-fast する。オペレータホストは Compose 5.4 以上を契約し、v5.5 系で `create_host_path:false` が no-op でないことを committed probe で pin する。**

### D1. file-bind

短形式のファイル / socket / artefact-directory bind は禁止。静的 git 管理ファイルはトップレベル `configs:`。ホスト専用ファイルは long-syntax bind + `bind.create_host_path: false`（原則 `read_only: true`）。joblib 個別ファイル bind は禁止（ディレクトリ + `Path.is_file()`）。監査は `scripts/compose-file-bind-audit.py` が 0 件で exit 0。

### D2. pre_start と init-edge

chown-only の 2 本（`news-creator-backend`、`knowledge-embedder-local`）と Wave 4 の 14 親 cert chown は、sibling init ではなく **消費者の `pre_start`** に置く。残る `service_completed_successfully` エッジは allowlist 22 と一致しなければならない。新しい SCS エッジは baseline 行と理由が無いと CI が落ちる。

### D3. OSU 会計（F1–F5）

| ID | 失敗条件 |
|---|---|
| F1 | long-running compose 名が inventory に無い、または stale 行がある |
| F2 | accidental OSU（例外なし）が cap 16 を超える |
| F3 | 新しい long-running に `offset_of` も未期限切れ exception+sunset も無い |
| F4 | exception の sunset 欠落 / 不正 / 今日以前 |
| F5 | `kind: sidecar-*` の親が live compose に無い |

`--write-baseline` は機械的カウントを更新するだけで、`accidental_osu_baseline` と `long_running_osu_baseline` は上げない。accidental の残りは `*-logs` のみ。pki-agent ワークロードを accidental として戻すことは禁止（[[000978]]）。

### D4. Compose バージョン契約

- `pre_start` の床: Compose **5.4.0**
- オペレータホストの committed 測定: `scripts/compose-feature-gate.report.json`（現 pin は v5.5.0、`pre_start.ok` かつ `create_host_path_false` が欠落ファイル / 欠落ディレクトリを refuse）
- CI は live docker probe をせず、parser テストと committed report を印字する。report を「効いている」と偽って commit してはならない。

### 検討した代替案

| 案 | 却下理由 |
|---|---|
| サービス追加のたびに cap を上げる | 予算が装飾になり、P2-14 の freeze が消える |
| inventory YAML を名前の正本にする | compose と二重管理。F1 が「YAML を直しただけ」で緑になる |
| chown を oneshot init + SCS に戻す | rolling `--no-deps` で init が走らない（[[000826]]） |
| `create_host_path: false` をバージョン確認なしに信じる | v5.0 系では no-op に見える。効くことは live refuse で示す |
| 全 long-running に healthcheck を強制する | [[000809]] と同じく abort しない subset への過剰。本 ADR の対象は bind / init / OSU |

## Consequences

### Pros

- PM-036 / PM-037 クラスの回帰が PR 時点で落ちる。
- 新しいプロセスは offset か期限付き例外なしに merge できない。
- `configs:` と fail-fast secret が「欠落なのに healthy」を構成から排除する。
- Compose 機能の可否がホスト anecdata ではなく committed report になる。

### Cons / Tradeoffs

- **CI GREEN ≠ 全オペレータホストが Compose ≥5.4。** 古い Compose で `pre_start` を含むファイルを `up` すると reject される。ホスト側のアップグレードは本 ADR の外。
- allowlist 22 の oneshot は rolling 非互換のまま残る（migrator / bootstrap / oauth-token-init）。新しい責務をここに足してはならない。
- accidental 16 は logs sidecar。forwarder 統合は別決定。
- feature-gate report はオペレータホストの測定スナップショットであり、CI runner の Compose 能力そのものではない。
- 本番 include 外（staging overlay の Kratos ファイル bind など）は監査対象外。対象を広げない限り別系統の足場が残る。

## Deploy-model 整合性セルフチェック

新設 compose service なし。予算は既存チェーンの freeze。chown は消費者 `pre_start`（Compose ≥5.4）。SCS oneshot は allowlist 以外に増やさない。

- [x] 新設 compose service が `depends_on` で他 service を gate するか？ — 新設なし
- [x] 新設 compose service に `restart: "no"` の one-shot init container を含むか？ — 新設なし
- [x] 新設名前付き volume を populate する責務はどこにあるか？ — 該当なし。artefact は directory bind + `create_host_path: false`（本 ADR D1）+ アプリの `is_file()`（[[000825]] の validator 層。named-volume + SCS init は使わない）
