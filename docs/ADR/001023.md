# ADR-001023: 読んだ記事だけを原典にし、記事末で過去に読んだ記事と埋め込みの近さでつなぐ

## Status

Accepted

## Date

2026-11-18

## Affected Services

- rag-orchestrator (Go): 候補記事集合に絞った近接探索 API、評価コマンド (`cmd/eval-connections/`)、2 記事の要約に基づく理由文の生成を新設する
- knowledge-sovereign (Go): `trail_planner` の `cluster` branch 提案を停止し、接続イベントの fold と read model `reading_connections` を新設する
- alt-backend (Go): 読了後の接続取得・記録と 1 タップ判定 (`Connected` / `Not connected`) の窓口を提供する
- alt-frontend-sv (TypeScript / SvelteKit): 評価基準を満たした場合に限り、記事末領域へ最大 3 本のつながり表示と 1 タップ判定 UI を追加する
- proto: 読書接続イベントおよび内部 RPC 契約を追加する

## Context

持ち主は 2026-11-18 に、製品の目的を「読むこと、読ませること、読んだ情報が血肉になること」と定めた ([[001015]])。「血肉になる」とは、持ち主の言葉で「過去に読んだものとつながること、つまり情報が構造化・結晶化されること」を指す。その形として「読んだ記事だけを原典にした wiki」を選び、本 ADR では記事末で過去に読んだ記事とつなぐ部品 (段階 R3) を決める。テーマごとのページ生成は [[001024]] で扱う。

2026-11-17 時点の本番データを読み取り専用で計測した結果、現状の関連提案とデータには次の問題がある。

- **タグによる接続が成り立たない**: 開いた記事は 523〜667 本 (`knowledge_user_events` の `open` で 523 本、`knowledge_trail_footprints` の `read` で 667 本) あり、全件に本文・要約・タグがあり、本文長の中央値は 6,424 文字である。しかし開いた記事のタグは 2,950 種類にのぼり、うち 2,175 種類 (74%) は 1 記事にしか付いていない。上位タグも配信元名や一般語 (「ニュース」、年、英語の機能語など) に偏る。
- **Knowledge Trail の `cluster` branch が機能していない**: 既存の `trail_planner` (`knowledge-sovereign/app/usecase/trail_planner/planner.go:141-178`) は、`DeriveTrailClusterCandidates` (`knowledge-sovereign/app/driver/sovereign_db/read_trail_candidates.go:104-186`) で直近 30 日以内の未接触記事と共有タグ 1 個以上で `cluster` branch を提案している。本番では 45,055 本の branch (うち 43,838 本が 2026-10-12 の週に生成、`open` の `cluster` branch が 44,583 本、1 起点あたり最大 4,642 本) が作られた一方、採られた branch は 9 本にとどまる。
- **Recall 候補も接点を作れていない**: 現状の `knowledge_home_projector` (`folds_lifecycle.go:56-68`) は `HomeItemOpened` ごとに固定スコア `0.5`・理由 `opened_not_revisited` の recall 候補を作るだけで、記事同士の関係は示していない。
- **埋め込み表現の分布が表現ごとに大きく異なる**: 開いた記事 523 本のうち `rag-db` に埋め込みがあるのは 268 本 (667 本換算では 411 本) で、索引登録が 2026-11-03 から止まっている ([[001017]] で復旧する)。`rag-db` 全体は 84,367 文書・約 207 万チャンクである。埋め込みのある開いた記事どうしで類似度を測ると、先頭チャンク同士では最近傍との類似度の中央値が `0.554` で `0.80` 超は 4% である一方、チャンク平均同士では最近傍の中央値が `0.833`、全対の中央値が `0.604`、99 パーセンタイルが `0.841` であった。表現によって分布が大きく変わるため、数値の分布だけからしきい値を決めることはできない。
- **既存 RAG 検索に候補集合限定の接点探索が無い**: `rag-orchestrator` の `SearchNeighbors` (`hybrid_search_repo.go:145-152`) は `seedArticleIDs` を除外する全記事検索である。`SearchWithinArticles` (`rag_chunk_repo.go:245`) は `articleIDs` で対象を絞るが、単一ベクトルのチャンク距離を返すのみで、記事間の表現選択やしきい値評価を扱う経路ではない。

## Decision

1. **原典を「読んだ記事」だけに限定する**: 候補の母集団は [[001018]] の `reading_sources` read model に限る。読んでいない記事は候補に出さない。理由: 読んでいない記事とつないでも、持ち主が読んだ記憶は残らないためである。
2. **過去に開いた記事を最初から原典に含める**: 既存の `HomeItemOpened` イベントから `reading_projector` で `reading_sources` へ射影し、[[001018]] の新規則とは `read_rule_version` で区別する。バックフィル用の新規イベントを後から足すことはしない。理由: 過去分を入れないと、つながりが出始めるまで数週間の空白が生じるためである。
3. **接続軸を埋め込みの近さとし、タグを使わない**: 記事間の近さはベクトル埋め込みで測り、タグの一致は使わない。理由: タグの 74% が 1 記事にしか付いておらず、上位タグも配信元名や一般語であるためである。
4. **候補集合を受け取る近さ問い合わせ API を `rag-orchestrator` に新設する**: 呼び出し側が起点記事 ID と候補記事 ID の集合を渡し、候補が空なら空を返すエンドポイントを `rag-orchestrator` に新設する。理由: 未読記事が候補に混入しないことを、検索実装の内部条件ではなく API の型と契約で保証するためである。
5. **評価コマンドを新設し、48 組の採点結果で表現としきい値を決める**: `rag-orchestrator/cmd/eval-connections/` を新設し、持ち主が採点する 48 組 (2 表現からの最近傍 20 組と 12 組、5〜15 位の 10 組、無作為 6 組を順序混合・類似度非表示で「つながる / つながらない / 判断できない」の 3 値採点) に対して、先頭チャンク・チャンク平均・最寄りのチャンク対・要約ベクトルの 4 表現を比較する。コマンドは採用表現、最小類似度、しきい値の版を出力する。理由: 表現ごとに類似度分布が大きく異なり、数値だけではしきい値を選べないためである。
6. **合格基準を 6 割とし、未達なら UI を作らない**: 提案の 6 割以上が「つながる」と採点されることを合格線とする。どの表現でも 6 割に届かなければ、記事末のつながり UI は実装しない。運用時も、候補が無い記事では何も出さず、空の枠も表示しない。理由: 根拠の薄い提案を常設して読書体験を損なわないためである。
7. **記事末に最大 3 本出し、理由文は正常な要約のみから生成する**: [[001019]] で統合する記事リーダーの記事末領域に、最大 3 本まで表示する。各項目は題、読んだ日、両記事の要約から生成する 1 行の理由を持つ。現状は保存済み要約の一部に生成失敗の定型文が混ざっているため、要約が定型文である記事は理由文の生成に使わない。理由: 記事末という注意の解放点に最小限の文脈だけを置き、壊れた要約の伝播を防ぐためである。
8. **1 タップの判定操作を置き、しきい値見直しに使う**: 各提案に `Connected` / `Not connected` の 1 タップ判定を置く。機械が提案し、持ち主が確かめる形を採る。理由: 自分で構造を作る場合と機械が与える構造を読む場合の学習効果の差は一次資料で確認できていないため、確かめる操作を残し、蓄積した判定を将来のしきい値見直しに使うためである。
9. **イベント 3 種と read model `reading_connections` を新設する**: `reading.connection_proposed.v1` (起点、相手、類似度、表現、しきい値の版、理由)、`reading.connections_evaluated.v1` (候補なしの結果も記録し再計算を防ぐ)、`reading.connection_judged.v1` を新設する。`knowledge-sovereign` にこれらを fold する read model `reading_connections` を新設する。理由: append-first と reproject-safe の不変条件を保ち、候補なしの結果も残して同じ計算を繰り返さないためである。
10. **Trail の `cluster` branch の新規提案を止める**: `trail_planner` によるタグ重なりベースの `cluster` branch 提案を停止する。既存のイベントは消さず、[[000949]] の他の決定 (episode spine の `tagChainWindow = 14d` / `minSharedTags = 2`、patch-exit、`continuation` branch など) は維持する。理由: 未読記事を大量に提案し、45,055 本のうち 9 本しか採られなかった仕組みを止め、読んだ記事どうしの接続に一本化するためである。
11. **索引登録の復旧を前提にする**: 本決定の本番稼働は [[001017]] による `rag-orchestrator` の索引登録復旧を前提とする。理由: 開いた記事の半数近くに埋め込みがないままでは、読んだ記事どうしをつなげないためである。

### 検討した代替案

- **タグの共起でつなぐ**: 開いた記事タグの 74% が単一記事のみに出現し、タグの重なりで作った既存の branch も 45,055 本のうち 9 本しか採られなかったため却下した。
- **エンティティのグラフを作る (GraphRAG, Edge ら arXiv 2404.16130)**: エンティティグラフとコミュニティ要約はコーパス全体への大域的な質問に向く方式であり、数百本の既読記事同士を記事末でつなぐ目的には抽出と保守の費用が見合わないため却下した。
- **全記事を候補にする**: 未読記事が候補に混入し「読んだ記事だけを原典にする」方針に反するため却下した。
- **類似度の分布からしきい値を決める**: 表現ごとに中央値や 99 パーセンタイルが大きく変わり、数値分布だけでは人間の納得感と対応付けられないため却下した。
- **想起クイズを作る**: 持ち主が定めた「血肉になる」の定義は「過去記事とつながること」であり、記憶テストではないため却下した。

## Consequences

### Pros

- 未読記事を除外した API 契約により、接続先が必ず「自分が読んだ記事」になる。
- 48 組のブラインド評価と 6 割基準により、品質が伴わないまま UI を作り込む失敗を防げる。
- `HomeItemOpened` からの既存履歴射影により、段階 R3 着手直後から接続候補を得られる。
- 失敗要約の除外と `reading.connections_evaluated.v1` により、定型文混入と重複評価を防げる。

### Cons / Tradeoffs

- `rag-db` の埋め込みに依存するため、[[001017]] の索引復旧と欠損記事の再索引が完了するまで網羅率が落ちる。
- 4 表現の最終選択・最小類似度・しきい値の版は、`cmd/eval-connections/` による 48 組採点の結果が出るまで未確定であり、本 ADR では決めない。
- 評価が 6 割に達しなかった場合の代替手段 (理由生成なしの類似タイトル表示のみにするか、接続機能を閉じるか) は本 ADR では決めない。
- 理由文生成に使う正常要約の判定条件 (失敗定型文の具体的な判定パターン) は実装時に詰める必要があり、本 ADR では決めない。
