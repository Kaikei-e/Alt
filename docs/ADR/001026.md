# ADR-001026: Evening Pulse と 7-day Recap の残りを廃止し、呼び出し側から順に削除する

## Status

Accepted

## Date

2026-11-18

## Affected Services

- alt-frontend-sv — `/recap/evening-pulse` ルート、ナビ項目、`TodayBar` の Pulse 導線、関連コンポーネント・テスト・`/recap` の 7-day 切替と未リンクルートを削除する
- alt-butterfly-facade — `proto` 変更に伴う生成コード再生成（透過プロキシのため固有実装なし）
- alt-backend — `GetEveningPulse`・`GetSevenDayRecap` の Connect-RPC ハンドラ / usecase / port / gateway / domain と `TodayBar` 向けフラグ配線を削除する
- proto — `RecapService.GetEveningPulse` と `GetSevenDayRecap`、関連メッセージを削除する
- recap-worker — Pulse 生成パイプライン、`/v1/pulse/latest`、`/v1/recaps/7days` 系、Pulse DAO、関連設定と `recap.evening_pulse_generated.v1` 発行を削除する
- recap-migration-atlas — `pulse_*` の 3 テーブルと 3 ビューを DROP するマイグレーションを追加する
- knowledge-sovereign — `recap.evening_pulse_generated.v1` の fold・認可ポリシー・liveness 監視と `today_digest_view` の Pulse 関連列を整理する
- compose — `compose/recap.yaml` と `compose/compose.staging.yaml` の `PULSE_*` / `RECAP_FRESHNESS_EVENING_PULSE_HOURS` 環境変数を削除する

## Context

持ち主が 2026-11-18 に製品の目的を「読むこと、読ませること、読んだ情報が血肉になること」と定め、ほとんど開かれていない Evening Pulse については「廃止してもよい」と述べた（[[001015]]）。

2026-11-17 時点の本番データを読み取り専用で計測した結果、直近 15 日の RPC 呼び出し回数は `GetEveningPulse` が 0 回、`GetSevenDayRecap` が 0 回、`GetThreeDayRecap` が 9 回、`GetTopicCards` が 3 回、`GetLatestLetter` が 4 回だった。`/recap/evening-pulse` への遷移も 0 回である。

ポストモーテム `docs/postmortems/PM-2026-062-recap-surfaces-stale-and-placeholder-output.md`（L176）のアクションアイテム 12 番（期限 `2026-11-20`）は「製品判断を記録する。(a) 3 日 Recap 画面の既定表示を Topic Cards に切り替えるか、(b) Evening Pulse を作り直すか、Topic Cards に統合するか、廃止するか。決定は ADR に残す」を求めている。同書（L47, L128-135）と [[001003]]（L52, L57, L104）は、Evening Pulse が全 269 回の生成で品質判定 `"ok"` が 0 件だったこと、スコア・エンティティ・埋め込みを空のまま選定器に渡していたため構造上 `"ok"` に届かず空白区切りの類似度も日本語に効かないこと、3 トピック出力 263 回中 148 回で同一記事が重複し定型見出し・固定理由文が出ていたこと、Alt-Paper 基準からも外れていることを記録している。本 ADR は同 12 番の (b) に「廃止する」と答える（(a) は本 ADR の対象外）。

コードベース上で Evening Pulse と関連資産の所在を確認した結果は以下のとおりである。

## Decision

1. **Evening Pulse を廃止する。** 理由は、直近 15 日で RPC 呼び出し・遷移ともに 0 回であり、持ち主が廃止可と述べ、さらに [[PM-2026-062]] が記録した構造上の欠陥（空の信号入力、日本語で機能しない類似度計算、重複選出、UI 基準逸脱）を直す費用が見合わないためである。
2. **削除は呼び出し側から順に行う。** 順序は、フロントエンド（ルート・ナビ項目・コンポーネント・E2E）→ BFF と `alt-backend` → `proto` → `recap-worker` の生成ステージと API・環境変数 → `knowledge-sovereign` の fold・認可ポリシー・liveness 監視 → `recap-db` のテーブルとビューの DROP とする。Pact の interaction も consumer 側（`alt-backend`、`recap-worker`）から先に外す。理由は、移行途中のどの時点でも呼び出す側が先に居なくなっている状態を保ち、デプロイ順で 404 や契約不整合を起こさないためである。
3. **Knowledge Home 側の導線と可用性フラグの依存を先に切り離す。** `TodayBar.svelte:52-67` の Pulse リンクと `evening_pulse_available` / `pulse_refs_json` の参照・書き込みを外してから、`recap.evening_pulse_generated.v1` の発行と fold を止める。Morning Letter は Evening Pulse の生成物を入力に使っていないため切り離し不要である。なお `pulse_need_to_know` 理由コードは Knowledge Home と Morning Letter が使っているため、この ADR では名称を残す。理由は、他機能の画面表示を壊さずに安全に廃止を進めるためである。
4. **`recap-db` の `pulse_*` テーブルとビューを DROP する。** `pulse_generations`、`pulse_cluster_diagnostics`、`pulse_selection_log` および関連 3 ビューを `recap-migration-atlas` の新規マイグレーションで削除する。これらは派生物であり原典ではない。一方、`knowledge_events` に既存の `recap.evening_pulse_generated.v1` イベントが残っていても削除しない。projector が過去のこのイベントをどう扱うか（明示的に無視する分岐を残すかどうか）は、再射影が通ることを確かめて実装時に決める。理由は、追記型イベントログの不変条件を壊さず、不要な派生物の保管だけを終えるためである。
5. **3-day Recap、Topic Cards、Morning Letter は残す。** Topic Cards の埋め込み・継続判定・文検証の部品は [[001024]] が使う。理由は、読書中心のテーマページ生成に再利用できる資産を保つためである。
6. **残存している 7-day Recap の RPC・API・UI を同じ順序で削除する。** `GetSevenDayRecap`、`/recap?window=7` 切替UI、`/api/v1/generate/recaps/7days`、`/v1/generate/recaps/7days`、`/v1/recaps/7days` を呼び出し側から順に削除する（自動バッチは [[000184]] で既に停止済み）。理由は、15 日で 0 回の死んだ経路を同時に整理するためである。
7. **どこからもリンクされていないルートは、削除の候補として挙げるにとどめる。** 確認できた候補は `alt-frontend-sv/src/routes/eval-dashboard/+page.svelte`（および `+page.server.ts`）と `alt-frontend-sv/src/routes/(app)/settings/knowledge-home-admin/+page.server.ts` の 2 件である。URL を直接開いて使っているかどうかは計測できていない。R4 の実装時に持ち主に確かめてから削除する。理由は、リンクがないことは使われていないことの証拠にならないためである。
8. **[[000161]]、[[000162]]、[[000163]] を本 ADR で置き換える。** この 3 本は Decision 全体が Evening Pulse の実装・スキーマ・UI 拡張だけを対象としており、廃止により丸ごと効力を失うため `supersedes` に指定する。

### 検討した代替案

- **(a) 欠陥を直して残す**: 退けた。理由は決定項目 1 のとおり、利用実績がゼロの機能に修正費用を投じる価値が見合わないためである。
- **(b) 画面の導線だけ隠して生成は続ける**: 退けた。誰も見ない生成物のために `recap-worker` の計算資源と DB 容量を使い続けることになるためである。
- **(c) 生成物を保管・アーカイブしてから DROP する**: 退けた。Evening Pulse の出力は `recap_outputs` や記事原典から作られた派生物であり、再生成や参照の予定がないためである。

## Consequences

### Pros

- [[PM-2026-062]] のアクションアイテム 12 番 (b) の判断が確定し、使われていない機能の保守・監視・テスト負債を一掃できる。
- `recap-worker` のパイプラインから不要なステージとテーブル書き込みが消え、構成が簡潔になる。
- 呼び出し側から順に外すことで、rolling deploy 中の不整合を防げる。

### Cons / Tradeoffs

- `knowledge_events` に過去の `recap.evening_pulse_generated.v1` イベント行が残る。fold を外したあとも再射影が通ることを、実装時に確かめる必要がある。
- `today_digest_view.weekly_recap_available` の列名や `pulse_need_to_know` の理由コード名など、歴史的な名称の一部は他機能が使うため本 ADR 後も残る（改名は別判断とする）。
- [[PM-2026-062]] の 12 番 (a)「3 日 Recap 画面の既定表示を Topic Cards に切り替えるか」および 11 番の画面修正（廃止完了までの暫定扱い）の調整はこの ADR では決めない。
