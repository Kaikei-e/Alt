# ADR-000993: Knowledge Home と Your Trail を /feeds 起点に寄せてスリム化し、閲覧・既読状態を相互同期する

## Status

Accepted

## Date

2026-10-14

## Affected Services

- knowledge-sovereign (Go)
- alt-backend (Go)
- alt-frontend-sv (TypeScript / Svelte)
- knowledge-sovereign-db (PostgreSQL、本番データの手動クリーンアップおよび修復計画)

## Context

Knowledge Home (`/home`) と Your Trail (`/knowledge/trail`) が日常の読書導線で使われず、「無駄な機能」になっていた。2026-10-14 に本番の DB・ログとコードパスを調べ、原因は見た目ではなく次の構造にあると判断した。

- **二つの受信箱が分断されていた。** 日常の既読化は `/feeds`（alt-db の read_status）で行われるが、そこから knowledge-sovereign へは何も届かない。`/feeds` で読み終えた記事が `/home` では未読のまま残り、Trail にも足跡が残らなかった。
- **Home の why がほぼ全件同じだった。** 大半の item が `new_unread` と `summary_completed` だけを持ち、カードは理由のない時系列リストと区別がつかなかった。高信号の `tag_hotspot` は先頭 2 件の表示枠からあふれていた。
- **Trail spine が dismiss で埋まっていた。** episode 窓を `dismissed` の足跡が占め、path wear も dismiss で水増しされていた。
- **cluster branch が出なくなっていた。** 一度提案した target を候補クエリが除外しないため、上位 N 件が dedupe で毎回はじかれ、新しい cluster branch が出なくなっていた。why に引用する anchor も「直近の足跡」で固定されており、タグを実際には共有していない記事を根拠として示すことがあった。
- **read model に古いデータが溜まっていた。** `knowledge_home_items` に旧 projection version と負荷試験ユーザの行が残り、イベントが 15 分ないだけで freshness が `degraded` と判定されていた。

## Decision

**「A 案」を採用する。** `/feeds` を日常の読書導線の軸とし、Home と Trail はそこへ寄せて高信号の面に絞る。そのうえで閲覧と既読の状態を両方向に同期する。

初回実装は 2026-10-14 の一連のコミット（b1bebe655 / 8907d0bbd / 217f6cfda / c65a9f20a / 3b37a052e / 491a0083e / 0985ed720）で入り、同日に本番データのクリーンアップも行った。続いて 2026-10-15 に事後レビューで判明した不具合・契約違反・計画差分の追補修正と本番 DB の read-only 調査を実施した。

### knowledge-sovereign

- **Trail spine を engagement verb に限定する。** `GetTrailFootprints` と cluster 候補の導出は `EngagementVerbs`（read / asked / listened）だけを数える。`dismissed` は spine にも wear にも入れない。
- **cluster 候補を作り直す。** 既に `knowledge_trail_branches` にある target は `NOT EXISTS` で候補から外す。why の anchor は、実際にタグを共有している直近の engaged 記事から選ぶ（`AnchorItemKey` / `AnchorTitle` / `AnchorVerb`）。共有タグは `tagclean.CleanDisplay` を通し、空になった候補は提案しない。
- **tagclean の junk 語を広げる。** 汎用のメタタグ（ai / llm / api / 技術 / 開発 など）を junk 語に加え、Union-Find で巨大クラスタができるのを防ぐ。
- **Home の read model を整える。**
  - open で `new_unread` を再付与しない。
  - recall reason を `(Type, Description, SourceItemKey)` で重複排除する。
  - title が空の行は読み出しで除外する。
  - `ListDistinctUserIDs` は active version かつ nil UUID 以外に限る。
  - 未射影イベントが無い間は fresh と判定する。

### alt-backend

- `enrichItemsWithTagHotspots` は `tag_hotspot` を why の**先頭**に入れる。
- **閲覧・既読を相互に同期する。**
  - Home で記事を open（allowlist 対象の読書開始）または dismiss すると、`/feeds` 側でも既読にする（`MarkArticleAsRead`）。
  - `/feeds` で既読にすると、Home の該当 item を dismiss する。Trail の足跡は作らない。
  - お気に入りに登録すると open として記録する。
- 同期は既存のイベント（HomeItemOpened / HomeItemDismissed）と既存 RPC だけで行う。新しいイベント型も payload field も追加しない。

### alt-frontend-sv

- **KnowledgeCard を絞る。**
  - title を押すと in-place reader（`FeedDetailModal` を再利用）で開く。
  - source host を表示する。
  - `new_unread` / `summary_completed` の why バッジと「EXPLAIN WHY」トグルは出さない。
- **読書面からの open 記録。** `/feeds`、記事詳細、`/articles/[id]` で記事を開くと、Trail に `open` を記録する（`trackHomeActionClient`）。`/articles/[id]` は id が変わるたびに end branches を読み直す。
- **その他の Home / Trail の調整。**
  - lens を削除できるようにする。
  - Mobile の recall を一覧内で展開できるようにする。
  - footprint が 2 件以上ある episode は最初から展開して表示する。
- **Knowledge Home の見た目を Alt-Paper の語彙で統一する。** 基準は、既に一貫していた Your Trail の見た目に置く。
  - 書体の役割を固定する。display（Playfair）は見出しに、body（Source Sans 3）は本文・ボタン・リンクに使う。mono（IBM Plex Mono）は日付・件数・kicker・タグ・ソースといったメタ情報に限る。
  - ステータスバッジ（why / recall reason / summarizing / supersede / archived）は 1 つの仕様にそろえる。mono、大文字、字間あり、1px 罫で、色の 3 段階（emphasis / info / muted）はそのまま使う。タグは Trail の `fp-tag` と同じ見た目にする。
  - 箱の入れ子をやめる。recall rail は上端の 2px 罫と hairline 区切りの一覧にし、カード内の操作群は枠のない ghost ボタンにする。
  - モバイルの左右余白を 16px にそろえる。狭い画面では source と時刻を見出しの上に dateline として置く。
  - ロジック、DOM の testid、イベント送信は変えていない。

### 2026-10-15 追補修正（事後レビュー指摘の解消）

2026-10-14 の実装に対する事後レビューで検出された不具合・Rule 8 違反・`$effect` 契約違反・計画差分を以下のとおり修正した。

- **knowledge-sovereign**
  - `knowledge_trail_branches` の `ON CONFLICT (branch_key)` を先勝ち upsert に変更（`anchor_item_key` / `why_json` / `status` / `created_at` を上書きせず、`projection_version` のみ更新）。
  - cluster 候補 SQL で正規化・junk 語除外・Unicode 空白トリム・非 ASCII 句読点除去を `LIMIT` 前に適用し、junk 候補による上位枠の占有（ロックアウト）と空タイトル target による枠消費を防止。また anchor LATERAL 選択でも clean 共有タグを持つ engaged 足跡のみを最新順で選び、実 Postgres（pgテスト）で SQL を検証。
  - `knowledge-sovereign/CLAUDE.md` の誤記を修正（engagement verb 3 種、クラスタ提案の最小共有タグ数 1）。
- **alt-backend**
  - Rule 8 準拠（[[000928]] と同型の無言スキップ防止）: Home↔`/feeds` 同期 hook の nil ガードによる無言スキップを撤廃し、未配線時は起動および呼び出し時に fail-fast（panic）するよう統一。`FetchArticleByURL` 失敗時は URL 原文をログに出さず構造化エラーログを記録。
  - `open` 時の `/feeds` 既読化（`MarkArticleAsRead`）を明示的な allowlist（`source` が `"home_card"` / `"article_page"` / `"favorite"`）に限定し、`/feeds` 一覧展開やモバイルスワイプ面（[[000948]] の遅延既読フラッシュ + UNDO）の未読状態を破壊しないよう修正。不正 JSON や非オブジェクトの metadata は拒否。
  - Trail branch を `taken` にした際の BE 側 `open` 自動発行を廃止し、遷移先の読書面（`/articles/[id]`）の `open` 記録に一本化。
  - `alt-backend/CLAUDE.md` の誤記を修正。
- **alt-frontend-sv**
  - `open` の二重記録を解消: Home から `FeedDetailModal` を開く際は `trackCardOpen={false}` でカード側の `"home_card"` 記録のみに統一し、Mobile `FeedDetails` は `articleId` が確定したときのみ 1 回だけ `open` を送信（Inoreader ID へのフォールバックを廃止）。
  - `/articles/[id]` で 10/14 改修時に `ArticleVisit` と `+page.svelte` に `$effect` による再取得・訪問記録を入れていた契約違反を解消し、`onMount` + `afterNavigate`（および request token による stale 応答ガード）へ移行。
  - Home の「Your Trail」導線を削除し、in-place reader（`FeedDetailModal`）に end branches と URL エンコード済み `/articles/[id]` リンクを追加。
  - lens 削除に lens ID 単位のインライン確認 UI（フォーカス移動・アクセシブル名付き）を追加し、RPC 失敗時はエラーを再送出してトースト誤表示を防止。
  - `EpisodeCard` 既定展開に合わせて `tests/e2e/integration/knowledge-trail.spec.ts` を更新し、`trackHomeActionClient` の本番コード内 `MODE === "test"` 分岐を撤廃。

### 検討した代替案

- **B 案「現行の `/home` + Trail のまま配線とバグを直す」は却下した。** `/feeds` との分断が残る限り、Home と Trail は日常の読書から切り離されたままで、根本原因を解消できない。
- **act_outcome を fold するときに sovereign 側で read 足跡を書く案（計画 1.3）と BE 側で taken 時に `open` を自動発行する案は却下した。** sovereign 側での足跡生成は既存の不変条件「act outcome は footprint を増やさない」（`knowledge_trail_projector` のテスト）に反し、BE 側での `open` 自動発行は遷移先の `/articles/[id]` の `open` 記録と二重になるため、読書面からの `open` 記録に一本化した。

## Consequences

### Pros

- `/feeds` で読んだ記事が Home から消え、Trail に足跡として残る。2 つの受信箱が実質 1 つになる。
- Home のカードには理由のあるバッジだけが残り、`tag_hotspot` が見えるようになる。
- Trail spine から dismiss のノイズが消え、cluster branch の提案が clean タグ基準で再開する。why が引用する anchor は、実際に clean タグを共有する記事になる。
- Knowledge Home と Trail が同じ視覚語彙（書体の役割、バッジ、タグ、罫）で読めるようになる。
- 同期 hook の fail-fast 化、`open` allowlist、`open` 二重記録の解消、先勝ち upsert により、イベント汚染やスワイプ面の UNDO 破壊を防げる。

### Cons / Tradeoffs

2026-10-15 の追補修正完了時点で、残存する非ブロッキング事項とトレードオフは次のとおり。

- **knowledge-sovereign（単体テストと pg 統合テストの役割分担）**: 先勝ち upsert を検証する projector 単体テストはフェイク同士の比較であり、実 SQL の先勝ち挙動は pg 統合テスト（「最初の提案の値が残る」アサート）が担保している。
- **knowledge-sovereign（SQL タグ正規化の境界とコスト）**: 空白判定と `[[:alpha:]]` は DB ロケールに依存する（本番・テストとも `postgres:16-alpine` で同一挙動）。SQL 側では複数形の単数化を行わないため、単複ペアで共有タグ数が二重計上されうる。また候補クエリで行ごとに `regexp_replace` を 2 回呼ぶため CPU コストが増える可能性がある（未計測）。
- **alt-backend（既存 port の nil ガード）**: 今回のスコープ外である既存の `!= nil` ガード（`dismissPort` / `recallSignalPort` / `featureFlagPort` / `articleURLLookupPort` / `tagHotspotPort`）は残存している。
- **alt-frontend-sv（既存 `$effect` と lens 削除ロールバック粒度）**: `/articles/[id]` には以前からある `$effect` ベースの取得が 2 箇所（source URL 解決と本文の自動取得、今回スコープ外）残っている。また `useLens.remove()` のロールバックは配列全体のスナップショットを戻すため、2 件の削除が重なり先行分が失敗した場合にサーバ側で削除済みの lens が画面上に戻りうる。
- **本番の追記専用ログ**: 重複して発行された `trail.branch_proposed.v1` イベント 5 件は追記専用の `knowledge_events` に永久に残るが、先勝ち upsert により投影への影響はなくなる。
