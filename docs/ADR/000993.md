# ADR-000993: Knowledge Home と Your Trail を /feeds 起点に寄せてスリム化し、閲覧・既読状態を相互同期する

## Status

Accepted

## Date

2026-10-14

## Affected Services

- knowledge-sovereign (Go)
- alt-backend (Go)
- alt-frontend-sv (TypeScript / Svelte)
- knowledge-sovereign-db (PostgreSQL、本番データの手動クリーンアップ)

## Context

Knowledge Home (`/home`) と Your Trail (`/knowledge/trail`) が日常の読書導線で使われず、「無駄な機能」になっていた。2026-10-14 に本番の DB・ログとコードパスを調べ、原因は見た目ではなく次の構造にあると判断した。

- **二つの受信箱が分断されていた。** 日常の既読化は `/feeds`（alt-db の read_status）で行われるが、そこから knowledge-sovereign へは何も届かない。`/feeds` で読み終えた記事が `/home` では未読のまま残り、Trail にも足跡が残らなかった。
- **Home の why がほぼ全件同じだった。** 大半の item が `new_unread` と `summary_completed` だけを持ち、カードは理由のない時系列リストと区別がつかなかった。高信号の `tag_hotspot` は先頭 2 件の表示枠からあふれていた。
- **Trail spine が dismiss で埋まっていた。** episode 窓を `dismissed` の足跡が占め、path wear も dismiss で水増しされていた。
- **cluster branch が出なくなっていた。** 一度提案した target を候補クエリが除外しないため、上位 N 件が dedupe で毎回はじかれ、新しい cluster branch が出なくなっていた。why に引用する anchor も「直近の足跡」で固定されており、タグを実際には共有していない記事を根拠として示すことがあった。
- **read model に古いデータが溜まっていた。** `knowledge_home_items` に旧 projection version と負荷試験ユーザの行が残り、イベントが 15 分ないだけで freshness が `degraded` と判定されていた。

## Decision

**「A 案」を採用する。** `/feeds` を日常の読書導線の軸とし、Home と Trail はそこへ寄せて高信号の面に絞る。そのうえで閲覧と既読の状態を両方向に同期する。

実装は 2026-10-14 の一連のコミット（b1bebe655 / 8907d0bbd / 217f6cfda / c65a9f20a / 3b37a052e / 491a0083e / 0985ed720）で入り、同日に本番データのクリーンアップも行った。計画どおりに入らなかった項目は末尾の「計画との差分」にまとめる。

### knowledge-sovereign

- **Trail spine を engagement verb に限定する。** `GetTrailFootprints` と cluster 候補の導出は `EngagementVerbs`（read / asked / listened）だけを数える。`dismissed` は spine にも wear にも入れない。
- **cluster 候補を作り直す。** 既に `knowledge_trail_branches` にある target は `NOT EXISTS` で候補から外す。why の anchor は、実際にタグを共有している直近の engaged 記事から選ぶ（`AnchorItemKey` / `AnchorTitle` / `AnchorVerb`）。共有タグは `tagclean.CleanDisplay` を通し、空になった候補は提案しない。
- **tagclean の junk 語を広げる。** 汎用のメタタグ（ai / llm / api / 技術 / 開発 など）を junk 語に加え、Union-Find で巨大クラスタができるのを防ぐ。
- **Home の read model を整える。**
  - open で `new_unread` を再付与しない。
  - recall reason を `(Type, Description, SourceItemKey)` で重複排除する。
  - title が空の行は読み出しで除外する。
  - `ListDistinctUserIDs` は active version かつ nil UUID 以外に限る。
  - 未射影イベントが無い間は fresh と判定する。

### alt-backend

- `enrichItemsWithTagHotspots` は `tag_hotspot` を why の**先頭**に入れる。
- **閲覧・既読を相互に同期する。**
  - Home で記事を open または dismiss すると、`/feeds` 側でも既読にする（`MarkArticleAsRead`）。
  - `/feeds` で既読にすると、Home の該当 item を dismiss する。Trail の足跡は作らない。
  - お気に入りに登録すると open として記録する。
  - Trail branch を taken にすると、target を open として記録する。
- 同期は既存のイベント（HomeItemOpened / HomeItemDismissed）と既存 RPC だけで行う。新しいイベント型も payload field も追加しない。

### alt-frontend-sv

- **KnowledgeCard を絞る。**
  - title を押すと in-place reader（`FeedDetailModal` を再利用）で開く。
  - source host を表示する。
  - `new_unread` / `summary_completed` の why バッジと「EXPLAIN WHY」トグルは出さない。
- **読書面からの open 記録。** `/feeds`、記事詳細、`/articles/[id]` で記事を開くと、Trail に `open` を記録する（`trackHomeActionClient`）。`/articles/[id]` は id が変わるたびに end branches を読み直す。
- **その他の Home / Trail の調整。**
  - lens を削除できるようにする。
  - Mobile の recall を一覧内で展開できるようにする。
  - footprint が 2 件以上ある episode は最初から展開して表示する。
- **Knowledge Home の見た目を Alt-Paper の語彙で統一する。** 基準は、既に一貫していた Your Trail の見た目に置く。
  - 書体の役割を固定する。display（Playfair）は見出しに、body（Source Sans 3）は本文・ボタン・リンクに使う。mono（IBM Plex Mono）は日付・件数・kicker・タグ・ソースといったメタ情報に限る。
  - ステータスバッジ（why / recall reason / summarizing / supersede / archived）は 1 つの仕様にそろえる。mono、大文字、字間あり、1px 罫で、色の 3 段階（emphasis / info / muted）はそのまま使う。タグは Trail の `fp-tag` と同じ見た目にする。
  - 箱の入れ子をやめる。recall rail は上端の 2px 罫と hairline 区切りの一覧にし、カード内の操作群は枠のない ghost ボタンにする。
  - モバイルの左右余白を 16px にそろえる。狭い画面では source と時刻を見出しの上に dateline として置く。
  - ロジック、DOM の testid、イベント送信は変えていない。

### 本番データのクリーンアップ（knowledge-sovereign-db）

`psql` で一括実行した。`knowledge_events` には触れていない。

| 操作 | 件数 | 計画との関係 |
|---|---|---|
| `knowledge_home_items` の非 active projection version を削除 | 222,639 | 計画どおり |
| 実ユーザ以外の `knowledge_home_items` 行を削除 | 3,971 | 計画どおり（ただし後述のとおり方式が違う） |
| 実ユーザ以外の `today_digest_view` 行を削除 | 285 | 計画外 |
| active version で title が空の `knowledge_home_items` 行を削除 | 385 | 計画外 |
| 不正 anchor を持つ open の cluster branch を削除 | 7 | 計画どおり |
| `knowledge_event_dedupes` の `trail.branch_proposed.v1:cluster:%` を削除 | 45 | **計画外** |
| `recall_candidate_view.reason_json` の重複排除 | 223 | 計画どおり |
| `knowledge_user_events` に対する DELETE | 0 | **計画外**（append-only テーブルへの DELETE。該当行が無かっただけ） |

### 検討した代替案

- **B 案「現行の `/home` + Trail のまま配線とバグを直す」は却下した。** `/feeds` との分断が残る限り、Home と Trail は日常の読書から切り離されたままで、根本原因を解消できない。
- **act_outcome を fold するときに sovereign 側で read 足跡を書く案（計画 1.3）は却下した。** 既存の不変条件「act outcome は footprint を増やさない」（`knowledge_trail_projector` のテスト）に反する。代わりに alt-backend で、branch を taken にしたときに `open` を発行する。

## Consequences

### Pros

- `/feeds` で読んだ記事が Home から消え、Trail に足跡として残る。2 つの受信箱が実質 1 つになる。
- Home のカードには理由のあるバッジだけが残り、`tag_hotspot` が見えるようになる。
- Trail spine から dismiss のノイズが消え、cluster branch の提案が再開する。why が引用する anchor は、実際にタグを共有する記事になる。
- Knowledge Home と Trail が同じ視覚語彙（書体の役割、バッジ、タグ、罫）で読めるようになる。

### Cons / Tradeoffs

2026-10-14 の事後レビューで、次の未解決事項が確認された。**本 ADR は採用済みだが、以下は後続 PR で閉じる前提とする。**

- **Rule 8（無言フォールバックの禁止）に違反している。** alt-backend の同期 hook は 5 つあるが、どれも起動時の `*_enabled` / `*_disabled` ログを出さない。業務コード側に `if x == nil { return }` のガードがあり、`FetchArticleByURL` のエラーはログに出さずに捨てている。DI の配線が外れても誰も気付けない。これは [[000928]] と同じ型の問題。
- **open が既読化まで連鎖する。** `/feeds` やスワイプ面で記事を開いた（展開した）だけで、`MarkArticleAsRead` まで走る。
  - [[000948]] の「遅延既読フラッシュ + UNDO」は、既読 API の送信を 1 枚分保留する前提で成り立っている。スワイプカードを展開した時点で既読が確定するため、その記事は UNDO しても未読に戻らない。
  - read 同期をどの open source で走らせるかを決める必要がある。
- **open が二重に記録される。**
  - Home から reader を開くと、`home.trackAction("open")` と `FeedDetailModal` 自身の open の 2 件が記録される。metadata が違うため dedupe されない。
  - Trail branch を taken にした場合も、BE の taken→open と `/articles/[id]` の open が重なる。
  - 結果として append-only の `knowledge_events` に重複が残り、wear と recall 信号が水増しされる。
- **Mobile の FeedDetails が不正な item key を書きうる。** fallback で Inoreader 由来の id を使うため、`article:<inoreader id>` という item key が knowledge_events に書かれうる。
- **cluster 候補の掃除が順位付けの後にかかる。** SQL は junk を含む生タグで順位を決め、LIMIT で切った後に Go 側で掃除する。そのため上位を junk 候補が占め続け、形を変えたロックアウトが再発しうる。新しい cluster SQL は実 Postgres で一度も実行されていない（テストは SQL 文字列の部分一致のみ）。
- **本番クリーンアップに計画外の削除が含まれていた。**
  - `knowledge_event_dedupes` から 45 行を削除した直後、旧バイナリの planner が cluster branch を再提案した。重複した `trail.branch_proposed.v1` が append-only ログに残っている可能性がある。
  - append-only の `knowledge_user_events` に DELETE を発行していた（0 行）。
  - ユーザ行の削除は「負荷試験ユーザを狙う」計画ではなく、「実ユーザ 1 人以外を全削除」で実行された。
  - 部分削除した read model は reproject と一致しない可能性があるため、reproject で整合を取り直す必要がある。
- **計画との差分**
  - Home の「Your Trail」導線の削除（3.1）は行われていない。
  - in-place reader（3.1）に end branches と `/articles/[id]` への導線がない。
  - Pulse / Recap を常に遷移可能にする変更（3.2）は E2E 契約に合わせて差し戻した。
  - StreamUpdateBar（3.2）は、初回接続後のみ表示するラッチだけで、debounce と leader 判定がない。
  - lens 削除に確認ダイアログがなく、RPC が失敗しても成功トーストが出る。
  - 既定展開の変更に `tests/e2e/integration/knowledge-trail.spec.ts` の期待値が追随していない。
- **テストの抜け**
  - 本番コードに `trackHomeActionClient` の test-mode 早期 return が入り、open 記録を unit テストで検証できない。
  - 同期 hook の失敗系、DI 配線、reader の open 記録にテストがない。
- **ドキュメントの誤り。** 同日に追加した `knowledge-sovereign/CLAUDE.md` と `alt-backend/CLAUDE.md` の追記に、コードと食い違う記述がある（engagement verb の一覧、提案に必要な共有タグ数、存在しない usecase 名など）。
