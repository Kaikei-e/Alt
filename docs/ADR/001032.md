# ADR-001032: コード変更前の ADR 先行起票をハーネスで機械的に強制する

## Status

Accepted

## Date

2026-11-27

## Affected Services

- `scripts/altharness` (`internal/preflight`, `internal/guards/agy.go` — `PreToolUse` / `SessionStart` / `Stop` ゲート)
- `.claude/settings.json`, `.agents/hooks.json`, `.codex/hooks.json`, `.gitignore`（3 エージェント間のフックおよび worktree 継承配線）
- `.claude/skills/` および `.agents/skills/`（`alt-adr-writer`, `adr-preflight`, `tdd-workflow`, `plan-context-loader`, `grill-with-docs`）
- `CLAUDE.md`, `AGENTS.md`, `.agents/rules/rule-ledger.md`, `.agents/rules/task-packet.md`（共有ルールと台帳）

## Context

Alt では `docs/ADR/` を DocDag（`docdag.yaml`）で型付き有向非巡回グラフ（DAG）として管理し、[[001028]] で単一 Go バイナリ `scripts/altharness/alt-harness` へ全エージェントフックと品質ゲートを統一した。しかし実運用において、Claude Code・Antigravity CLI（`agy-cli`）・Codex が `docdag` で ADR を起票せずに直接コード実装を開始する傾向が継続していた。

現行ハーネス・フック・スキルの監査により、次の 4 つの構造的原因が判明した。

1. **無条件リトライを学習させる `adr-preflight` 受領証設計**: `scripts/altharness/internal/preflight/preflight.go` の `handlePreToolUse` は、初回編集ブロック（exit `2`）を返す**直前に**セッション受領証を書き込み、stderr に `"Receipt recorded for this session; retrying the same edit now succeeds."` と出力する。このため、エージェントは ADR を一切起票せずに同一編集を即リトライするだけで通過できる。
2. **スキル指示の逆転（事後起票の強制）**: `.claude/skills/alt-adr-writer/SKILL.md` が「実装・テスト green 後に `status: accepted` で書く」手順のみを記述しており、`docdag.yaml` の `status_values: [proposed, accepted, superseded, withdrawn]` および `docs/ADR/template.md` の既定値 `status: proposed` を活かした実装前起票と正面衝突していた。さらに `.claude/skills/grill-with-docs/SKILL.md` も ADR 省略を促す文言を含んでいた。
3. **`agy-cli` 側のスキル欠落と検証パリティ不足**: `.agents/skills/` には 13 スキル中 3 件しかシンボリックリンクされておらず、`alt-adr-writer`・`plan-context-loader`・`tdd-workflow`・`grill-with-docs` が `agy-cli` から発見不能であり、`.agents/skills/adr-preflight/SKILL.md` の相対リンクも切れていた。また `agy-hook pre-edit` は `preflight` の終了コード `2` のみを拒否し、他の非ゼロ終了コードで fail-open になる余地があった。
4. **worktree における Claude Code フック欠落**: `.gitignore` の `.claude/*` により `.claude/settings.json` が追跡対象外となっていたため、新規クローンや `.claude/worktrees/*` のサブエージェント実行環境では `preflight` を含む全 Claude フックが無効化されていた。

Alt 自身の不変条件である「規則台帳（`rule-ledger.md`）の `max_judgment_rules` ラチェットは判断規則を増やさず機械強制へ寄せる（H11）」「未配線やサイレント迂回を許容しない（[[000928]]）」「`docdag.yaml` の `proposed` / `accepted` ライフサイクルで未確定決定と現行契約（binding）を厳格に分離する」に基づき、散文ルールの追記ではなくハーネス構造レベルで ADR 先行を強制する。

なお設計の整理にあたり、先行事例として Lauren Tan（`@poteto`）氏による MIT ライセンスの Cursor プラグイン `pstack`（`https://github.com/cursor/plugins` 配下 `plugins/pstack/`、および AI Engineer CODE 2026 基調講演 *All Code Is Slop (Except Mine)*）における以下の実践原則をクリーンルームで参照・検証した。

- **Encode Lessons in Structure / `/correct` 5 階層**: 繰り返し無視される指示はドキュメント（最下層）に追記せず、構造・型・修正コマンドを明示する機械ゲート（上位層）へ昇格する。
- **Never Block on the Human（可逆作業の自律化）**: 未確定ドラフト（`status: proposed`）のような可逆な事前作業は人手待ちで止めず自律実行させ、既存 binding ADR の破壊・置換（`supersedes`）のみ人手承認を求める。
- **Prove It Works**: 動作確認・テスト通過の証拠を完了条件とし、未検証のまま確定（`accepted`）扱いにしない。
- **スキル可視性と直接パスフォールバック**: `cursor/plugins#527` で報告された通り `disable-model-invocation: true` でルーティング先スキルを隠すとホスト間のスキル呼び出しが破綻するため、ADR 関連スキルを可視のまま維持しフック出力に実ファイルパスを併記する。

## Decision

Claude Code・`agy-cli`・Codex の全 3 環境において、本番コード編集前に `docdag` で検証済みの ADR 起票（`status: proposed`）を機械的に必須化する。

1. **スキップ経路のない ADR 先行 `PreToolUse` ゲート（`alt-harness preflight`）**:
   - **免除対象は `docs/**`・`docdag.yaml`（コーパス自体）とテストファイルのみ**とする。テストファイル判定（`isTestRelpath`）は Alt の全言語規約（`*_test.go`、`test_*.py` / `*_test.py` / `conftest.py`、`*.test.*` / `*.spec.*` / `*_test.ts(x)`、`*_test.rs`、`*_test.sh` / `test-*.sh`、およびパス要素 `tests` / `test` / `__tests__` / `e2e` / `testdata` / `fixtures`）を対象とし、TDD の RED テスト先行作成を阻害しない一方、グラフ破損時（`docdag validate` 失敗）は fail-closed でブロックする。
   - **本番ファイル編集時の必須条件**: 現行作業ツリー（`git status --porcelain -uall -- docs/ADR` で削除以外の `docs/ADR/\d{6}\.md` かつ非空の通常ファイル）または非デフォルトブランチ上の差分（`HEAD` が `main`/`master` 以外のときの `<base>...HEAD` における `AMCR` の `docs/ADR/\d{6}\.md`）に有効な ADR が存在し、かつ `docdag validate` が通過すること。`main`/`master` 上の既コミット済み ADR は別タスクへの漏れ出しを防ぐため対象外とする。
   - **無条件リトライ受領証の廃止**: 有効な ADR が存在しない場合、`handlePreToolUse` は受領証を一切書き込まず終了コード `2` でブロックし続け、対象スコープの binding ADR 一覧と次に実行すべき厳密な 5 手順（`docdag context` → `docdag new "<title>" --dry-run --format json` → `docs/ADR/template.md` から `status: proposed` で作成 → `docdag validate --touching` → 再試行）およびガイドパス（`.agents/skills/alt-adr-writer/SKILL.md`）を提示する。`--skip` 等の迂回 CLI は設けない（壊れたツールチェーン専用の緊急停止スイッチ `ALT_ADR_PREFLIGHT=disabled` のみ既存どおり維持する）。
   - **有効な ADR 検知後の自動通過と削除時再ロック**: 有効な ADR が存在し `docdag validate` が通れば同一フィンガープリントに対する受領証を記録して即通過させ、二重ブロックを避ける。ADR が削除・破損された場合は `computeFingerprint` の変化で受領証が自動失効し、即座に再ブロックする。
2. **2 段階 ADR ライフサイクル（`proposed` → `accepted`）の統一**:
   - **Phase 1（実装前ドラフト）**: `alt-adr-writer` はデフォルトで実装前ドラフト（`status: proposed` / `## Status\n\nProposed`）をサポートし、`docdag new "<title>" --dry-run --format json` と `docs/ADR/template.md` から起票する。`docdag.yaml` の `status_drift` 規則により `supersedes:` frontmatter を付けると旧 ADR が `superseded` でない限り検証エラーとなるため、既存 binding ADR の置換を予定する場合は必ずユーザ合意を得たうえで、ドラフト段階では本文の `[[000NNN]]` 記述に留め、確定昇格時に `supersedes:` 追加と旧 ADR の `status: superseded` 更新を同一コミットで行う。
   - **Phase 2（実装・検証後の確定昇格）**: 対象サービスのテスト・リントがすべて green になった段階で実測結果・Consequences を反映し、`status: proposed` → `status: accepted` へ昇格させて `docdag validate --touching` および `docdag validate --immutable-since origin/main` を通過させる。
3. **3 環境パリティと worktree 継承の確立**:
   - `.gitignore` に `!.claude/settings.json` を追加して秘密情報を含まないフック設定を git 追跡対象とし、新規クローンおよび Claude Code worktree サブエージェントでも `preflight` ほか全フックが自動で効くようにする。
   - `.claude/settings.json` の `PostToolUse` に `docs/ADR/*.md`・`docdag.yaml` 編集時の即時 `docdag validate --touching` / `docdag lint --strict` 検証を追加する。
   - `scripts/altharness/internal/guards/agy.go` の `runAgyPreEdit` を任意の非ゼロ終了コードで fail-closed（`decision: "deny"`）へ引き締め、`runAgyStop` に `docs/ADR/`・`docdag.yaml` 未コミット変更時の `docdag validate` 検証を追加する。
   - `.agents/skills/` に `alt-adr-writer`・`plan-context-loader`・`tdd-workflow`・`grill-with-docs` のシンボリックリンクを追加し、`agy-cli`・Codex から発見可能かつ `adr-preflight` の相対リンクを修復する。
   - `SessionStart` 出力、`CLAUDE.md`・`AGENTS.md` の共有クリティカルルール（Rule 11: ADR First）、`rule-ledger.md`（`R-06` 更新、`max_judgment_rules: 6` 維持）、`task-packet.md`、`tdd-workflow`、`grill-with-docs` を本契約へ整合させる。

検討して却下した案:

- **軽微修正向けの `--skip <category> --reason "..."` 免除 CLI を設ける案**: 軽微修正の摩擦は減る一方、エージェントが安易に `--skip` へ逃げるインセンティブを残し「起票せずに実装する」再発余地を閉じ切れないため却下した。テストファイルと `docs/` のみ自動免除とし、本番コード変更には一貫して ADR を求める方が単純かつ堅牢である。
- **現行の 1 回保留受領証を維持し、プロンプト・スキル文面だけを強化する案**: 散文ルールのみではコンテキスト圧縮や自律実行ループで容易に無視されるため、規則台帳（H11）および `Encode Lessons in Structure` の原則に反するとして却下した。
- **実装前に直接 `status: accepted` で起票する案**: 未検証の計画が `docdag query --binding` の現行契約集合に混入し、「確定 ADR は動いた状態を記録する」という Alt の不変条件を崩すため却下した。

## Consequences

### Pros

- Claude Code・`agy-cli`・Codex および Claude Code worktree の全実行経路で、ADR 未起票のまま本番コードへ進む挙動を構造的に阻止できる。
- `proposed` → `accepted` の 2 段階運用により、`docdag` の binding 集合を未検証計画で汚染することなく、ADR 先行と TDD（テストファイル免除）を両立できる。
- `.agents/skills/` の補完と `.claude/settings.json` の追跡化により、ツール間のスキル・フック非対称性と worktree 盲点が解消される。
- `max_judgment_rules` ラチェット（6）を増やさず、`R-06` の機械強制強度を引き上げられる。

### Cons / Tradeoffs

- 小規模な本番コード修正（タイポ修正や軽微な設定調整など）であっても、`docs/ADR/NNNNNN.md` の起票または既存変更中 ADR への反映が必要になる。壊れたツールチェーンでの緊急時のみ `ALT_ADR_PREFLIGHT=disabled` を人手で設定して退避する。
- シェルコマンド経由の直接ファイル書込（`sed -i` やリダイレクト等）は `PreToolUse` 編集フックの対象外である制約は引き続き残る（ファイル編集ツールの使用を前提とする）。
- `.claude/settings.json` が git 追跡対象となるため、個人固有の許可設定やローカルパスは引き続き git 管理外の `.claude/settings.local.json` に分離して維持する必要がある。
