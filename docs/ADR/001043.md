# ADR-001043: 旧 Knowledge Home・Trail を /today・/knowledge へ統合し、モバイルとデスクトップの主導線を統一する

## Status

Accepted

## Date

2026-11-28

## Affected Services

- alt-frontend-sv (TypeScript / SvelteKit) — `/home`・`/knowledge/trail` の 303 リダイレクト統合、Mobile ボトムナビと Desktop サイドバーの統一、残存 `/home` リンクの更新、未使用 UI コンポーネント 3 点の撤去

## Context

[[001015]] の 15 日間本番計測（`GetKnowledgeHome` 13 回、`GetTrail` 7 回、`cluster` branch 45,055 本中採択 9 本）を受け、[[001022]] はモバイルの起動面を `/today` へ移した。しかし同 ADR 決定項目 6 でデスクトップのシェル変更を見送った結果、以下の分裂と空洞化が残存した。

- **モバイルとデスクトップの二重人格**: モバイルの起動面は `/today`（`Today / Swipe / Gallery / Search / Menu`）で `/home` と `/knowledge/trail` は Menu 奥に退避された一方、デスクトップ `Sidebar.svelte` は依然として最上位に `Knowledge Home (/home)` と `Your Trail (/knowledge/trail)` を置き、`/today` へのリンク自体が存在しない。
- **旧面の機能空洞化**: `/home` は固定定数スコア（`0.5/0.7/0.8/0.1`）の経過日数減衰と「開封 1 時間後にスコア `0.5` 固定で再提示する Recall」のみで動作しており、`/knowledge/trail` も `cluster` 停止後は同一記事への自己参照 `continuation` のみになっている。
- **残存リンクとデッドコード**: `dashboard`・`feeds/tag-verse`・`settings/feeds`・`articles/[id]`・`TagArticlesScreen` が `/home` へ遷移し続け、`WhyTypography.svelte`・`WhyPanel.svelte`・`MiniRecallPanel.svelte` は本番ルートから一切 import されないまま残置されている。
- **Themes（`/knowledge`）の到達性**: [[001022]] の Cons で R3 以降の判断に委ねていた「モバイルボトムナビへの Themes 昇格」が未決のままだった。

## Decision

1. **旧 `/home` と `/knowledge/trail` をサーバサイド 303 リダイレクトで統合する**:
   - `(app)/+layout.ts` が `ssr = false` のため、初回 HTTP リクエストで確実に HTTP 303 を返す `src/lib/server/redirect-resolver.ts`（`hooks.server.ts` 経由）に `/home` → `/today` および `/knowledge/trail` → `/knowledge` を登録する。
   - あわせてクライアントサイド遷移時のフォールバックとして `src/routes/(app)/home/+page.server.ts`（`/today` へ 303）と `src/routes/(app)/knowledge/trail/+page.server.ts`（`/knowledge` へ 303）を配置する。
   - これにより旧ブックマーク・PWA ショートカット・外部リンクを壊さずに新導線へ収束させる。運用者向けの `/admin/knowledge-home` は維持する。
2. **モバイルとデスクトップの主導線を「Today → 収集 → Themes」に統一する**:
   - **Mobile 5 タブ（`NAV_TABS`）**: `Today (/today)`・`Swipe (/feeds/swipe/visual-preview)`・`Gallery (/feeds/visual-preview)`・`Themes (/knowledge)`・`Menu (/menu)` に組み替え、`getActiveTabIndex` で `/knowledge` 配下をタブ 3（`Themes`）に割り当てる。`Search (/search)` は `MOBILE_MENU_SECTIONS` の `Browse` 先頭へ移し、`NAV_TABS` との重複をゼロに保つ。`Home (/home)` と `Trail (/knowledge/trail)` は `MOBILE_MENU_SECTIONS` から削除する。
   - **Desktop `Sidebar.svelte` 最上位（`main`）**: `Today (/today)`・`Themes (/knowledge)`・`Gallery (/feeds/visual-preview)`・`Search (/search)` に統一する。`Knowledge Home` と `Your Trail` を削除し、`Dashboard (/dashboard)` は `Recap` 配下または二次領域へ整理する（重複のない一貫構造にする）。
3. **残存する `/home`・`/knowledge/trail` リンクと遷移先を更新する**:
   - `dashboard/+page.svelte`、`feeds/tag-verse/+page.svelte`、`settings/feeds/+page.svelte`、`articles/[id]/+page.svelte`、`MobileTagArticlesScreen.svelte`、`DesktopTagArticlesScreen.svelte` の `/home` 参照を `/today` へ更新する。
   - `knowledge/+page.svelte` フッターの `/knowledge/trail` リンクを撤去する。
4. **本番未使用の認識論 UI 死蔵コンポーネント 3 点を削除する**:
   - 本番ルートからの import が 0 件の `WhyTypography.svelte`、`WhyPanel.svelte`、`MiniRecallPanel.svelte` およびそれらの単体テストを削除する。

### 既存 binding ADR の扱い

- **[[001022]]**: 決定項目 1（`/` → `/today`）・2（`/today` 新設）・4（Web Push）・5（常駐ボトムタブ）・7（英語表記）は維持しつつ、決定項目 3（`Search` タブを `Themes` に変更）および決定項目 6（デスクトップシェルの据え置き）を本 ADR で更新する。
- **[[000993]]・[[000949]]**: `/feeds` 既読同期および `GetItemBranches` 契約等のバックエンド基盤は維持しつつ、フロントエンドの独立面としての `/home`・`/knowledge/trail` は本 ADR で `/today`・`/knowledge` へ統合廃止する。

### 検討した代替案

- **旧 `/home` と `/knowledge/trail` をソフト退役（案内バナー表示のみ）にする**: 退けた。定数ランキング・死んだ 1 時間 Recall・自己参照 Trail の保守負債と URL ハイジャック（`AskSheet` の `history.replaceState`）が残り続け、デスクトップ利用者の迷いを解消できないため。
- **モバイルの `Search` タブを残し `Themes` を Menu に置き続ける**: 退けた。読んだ記事を知識として昇華する場である `/knowledge` がメニュー奥に埋もれたままでは日常の知識還流ループが閉じないため。

## Consequences

### Pros

- モバイルとデスクトップで「Today（今日読む）→ 収集（Swipe / Gallery）→ Themes（`/knowledge`）」のメンタルモデルが完全に一致する。
- 空洞化した旧 `/home`・`/knowledge/trail` と未使用 UI 3 点の保守負荷が消滅する。
- 303 リダイレクトにより旧 URL からのアクセスもエラーにならず安全に着地する。

### Cons / Tradeoffs

- モバイルのボトムタブから `Search` が 1 タップ遠くなる（`Menu` 内の `Browse` 先頭へ移動）。
- 旧 `/home`・`/knowledge/trail` 向けのバックエンド RPC や projector コード自体は安全のため本 ADR では削除せず、利用停止を確認した後の別 ADR で段階的に撤去する。
