# ADR-001005: alt-frontend-sv のブラウザ E2E を alt-frontend-sv.yml に一本化し本番イメージで実行する

## Status

Accepted

## Date

2026-11-10

## Affected Services

- `.github/workflows/alt-frontend-sv.yml`（本番イメージで E2E を実行するワークフローに作り直す）
- `.github/workflows/e2e-playwright.yml`（alt-frontend-sv スイートをマトリクスから外し、他のワークフロー定義だけの変更では起動しない）
- `e2e/playwright/suites.yaml`、`e2e/playwright/_lib/ci-matrix.py`（スイートの担当ワークフローを宣言する `workflow` フィールドと `--workflow` オプション）
- `e2e/playwright/alt-frontend-sv/run.sh`（Playwright イメージを環境変数で上書き可能にする。既定の挙動は変えない）
- alt-frontend-sv のモバイル UI 2 コンポーネント（アクセシブル名の修正）

## Context

alt-frontend-sv のブラウザ E2E スイートは、in-process のモックサーバ（Kratos / AuthHub / Backend）だけで完結し、compose の staging スタックを使わない。それなのに PR CI では 2 か所で同じ spec を走らせていた。

| 実行場所 | 相手 | プロジェクト | 起動条件 |
| --- | --- | --- | --- |
| `e2e-playwright.yml` | 本番イメージ | auth / desktop-chromium / mobile-chrome（3 分割） | docs 以外のすべての PR |
| `alt-frontend-sv.yml` | Playwright コンテナ内で `bun run build && node build` した Web サーバ | 上記 + a11y-desktop / a11y-mobile（3 分割） | `alt-frontend-sv/**` の変更 |

この重複には 3 つの問題があった。

- **関係のない PR でも重い**: `e2e-playwright.yml` にサービス単位の paths フィルタを入れないのは、共有配線（compose、fixture、上流パッケージ、proto）の回帰を取りこぼさないためである（[[001004]]）。しかし alt-frontend-sv スイートは共有配線を使わないので、この理由が当てはまらない。それでもバックエンドだけの PR で毎回、イメージビルドとシャード 3 本（各 2〜2.5 分）を払っていた。
- **責務の所在が曖昧**: フロントエンドの変更で、どちらの実行が何を保証しているのかが分かりにくかった。a11y は本番イメージで検査されていなかった。
- **ワークフロー定義だけの変更でも E2E が走る**: PR #301 は `dispatch-deploy.yaml` と runbook だけの変更だったが、docs-only の例外に当たらないため、E2E 全体が走った。

あわせて、本番イメージでの実行は e2e/playwright 共通のテスト依存を使うので、axe-core が 4.12.1（alt-frontend-sv 側の lockfile）から 4.14.0 に上がる。4.14 では `label-content-name-mismatch`（WCAG 2.5.3 Label in Name、レベル A）が既定で有効になった。その結果、モバイル UI の 2 か所で、表示テキストがアクセシブル名に含まれていないことが分かった（「Exclude source」ボタンの名前が「Exclude a feed source」、「Mark as Read」ボタンの名前が「Mark <title> as read」）。

## Decision

alt-frontend-sv のブラウザ E2E は `alt-frontend-sv.yml` だけが担い、本番イメージに対して実行する。

1. **本番イメージでの実行を `alt-frontend-sv.yml` に移す**: ジョブは plan → build → sharded → merge → verdict の順に流す。
   - plan は `ci-matrix.py --workflow alt-frontend-sv.yml` でシャードのマトリクスを出す。シャード数は `suites.yaml` だけが持つ。
   - build は `build-images.py` で本番イメージを 1 回だけビルドし、artifact でシャードへ渡す。
   - 各シャードは `e2e/playwright/alt-frontend-sv/run.sh` を実行する。`PROJECTS` で a11y-desktop / a11y-mobile を追加し、5 プロジェクトを回す。
   - Playwright のランナーイメージは digest で固定し、取得失敗は回数上限つきで再試行する。
   - blob レポートとアプリコンテナのログは、シャードごとに artifact として残す。
   - レポート統合の失敗は警告に留める。一方、ビルドかシャードが失敗・キャンセルされたら verdict で run を赤にする（[[001004]] と同じ規則）。
   - paths フィルタには、`run.sh` とテストが読むもの（`alt-frontend-sv/**`、`e2e/playwright/alt-frontend-sv/**`、`e2e/playwright/_lib/**`、`e2e/playwright` の package ファイル、`suites.yaml`、`merge.config.ts`、`services.yaml`）と自身を含める。
2. **スイートの登録は残し、担当ワークフローを宣言する**: `suites.yaml` の alt-frontend-sv エントリは残し、`workflow: alt-frontend-sv.yml` を付ける。
   - `ci-matrix.py` は、担当が `e2e-playwright.yml` 以外のスイートをマトリクスから外し、外したスイートを stderr に出す。
   - `workflow` の値が `.github/workflows/` 直下に実在するファイル名でなければ、exit 1 で失敗させる（書き間違いでスイートが黙って消えるのを防ぐ）。
   - `run.sh` はスイートの単一の入口のままにし、既定のプロジェクト構成も変えない。
3. **ソースからビルドしていた旧ジョブを廃止する**: 出荷するのは本番イメージなので、E2E はそれだけを対象にする。
4. **他のワークフロー定義だけの変更では横断 E2E を起動しない**: `e2e-playwright.yml` の起動条件を、すべてを含めたうえで docs-only の集合と `.github/workflows/**` を除き、自身だけを含め直す `paths` に変える。
5. **アクセシビリティの指摘は UI を直す**: アクセシブル名が表示テキストで始まるようにする（「Exclude source」は表示テキストそのもの、「Mark as Read: <title>」）。axe-core を古い版に固定して検査を外すことはしない。

### 却下した代替案

- **2 か所での実行を続ける**: 同じ spec を二度払うだけで、どちらが何を保証しているかも曖昧なまま残る。
- **横断 E2E 側に残し、`alt-frontend-sv.yml` の実行をやめる**: フロントエンドに関係のない PR でも毎回走り、a11y も本番イメージで検査されない。共有配線を使わないスイートを、共有配線の回帰を拾うための「フィルタなし」に乗せ続ける理由がない。
- **`suites.yaml` からエントリを削除する**: `build-images.py` とスイート配線の監査（`audit-suite-wiring.py`）がこの登録を前提にしている。
- **axe-core を 4.12.1 に固定する**: 実在する WCAG レベル A の不具合を隠すだけになる。

## Consequences

### Pros

- **実行が 1 回になる**: alt-frontend-sv の E2E は、フロントエンドとそのテスト基盤の変更に対してだけ、1 回走る。バックエンドだけの PR は、イメージビルドとシャード 3 本の分を払わなくてよくなる。
- **a11y も本番イメージで検査される**: 実際に出荷するイメージに対して a11y も検査されるようになり、モバイル UI の Label in Name 違反 2 件を直した。
- **ワークフロー定義だけの PR が軽くなる**: 横断 E2E を待たずに済む（ci-gate も早く返る）。
- **登録の誤りが CI で見える**: スイートの担当ワークフローとシャード数が `suites.yaml` だけで決まる。宣言の誤りは `ci-matrix.py` が exit 1 で止める。

### Cons / Tradeoffs

- **paths フィルタの網羅は人手頼み**: `alt-frontend-sv.yml` の paths フィルタは、`run.sh` とテストの依存を手で列挙している。workflow-safety-check の規則 11 が見るのは自身と reusable workflow だけなので、新しい依存を足したときの漏れは機械的には検出されない。
- **フロントエンドだけの PR でも横断 E2E は走る**: サービス単位のフィルタを入れない方針（[[001004]]）を維持するため、フロントエンドだけの変更でもバックエンド系スイートは走る。
- **ソースビルドの経路は CI で検査されない**: `bun run build && node build` の経路（ローカル開発時の `bun run test:e2e`）は、CI では検査されなくなる。
- **テスト依存の版が分かれる**: テスト依存の版が 2 つの lockfile（`alt-frontend-sv/bun.lock` と `e2e/playwright/package-lock.json`）に分かれる。ローカルの `bun run test:e2e` は axe-core 4.12.1 のままなので、CI（4.14.0）でだけ出る a11y 違反がありうる。
- **ワークフロー定義の変更は E2E を通らない**: `.github/workflows/` 配下の変更は、`e2e-playwright.yml` 自身を除いて E2E を起動しない。E2E が将来 `.github/` 配下のスクリプトや composite action を使うようになったら、それを含め直す必要がある。
