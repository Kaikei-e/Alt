# ADR-001041: Knowledge Home から開く記事リーダーで既存日本語要約を AI SUMMARY へ初期表示し Excerpt 重複を解消する

## Status

Accepted

## Date

2026-11-28

## Affected Services

- alt-frontend-sv — `src/lib/reader/`（`types.ts`、`reader-overlay.svelte.ts`、`mappers.ts`、`createArticleReader.svelte.ts`、`ArticleReaderOverlaySession.svelte`、`ArticleEditorialRail.svelte`）、`src/lib/hooks/useSummarize.svelte.ts`、`src/routes/(app)/home/+page.svelte`

## Context

[[001019]] で記事リーダーを `alt-frontend-sv/src/lib/reader/` に一本化し、[[000754]] のデスクトップ向け editorial rail を `ArticleEditorialRail.svelte` としてオーバーレイ（`ArticleReaderOverlaySession.svelte`）と単独記事ページ（`/articles/[id]`）で共有した。

しかし Knowledge Home（`/home`）からデスクトップ幅（1024px 以上）で記事を開き要約を表示すると、editorial rail 内の `Excerpt` と `AI SUMMARY` に **同一の日本語要約が二重表示される** 不具合が発生している。原因は次の 2 点の食い違いにある。

1. **`knowledge_home_items.summary_excerpt` の実体は日本語 AI 要約全文である**: [[000944]] 以降、`knowledge-sovereign` の `folds_article.go`（`buildSummaryVersionCreatedWrites`）は `SummaryVersionCreated` イベントの `summary_text` を切り詰めずにそのまま `summary_excerpt` に保存しており、RSS フィードの原文 description / excerpt は保持しない。
2. **Knowledge Home が旧 `FeedDetailModal` 時代の `RenderFeed` 変換シムを使い続けていた**: `alt-frontend-sv/src/routes/(app)/home/+page.svelte` の `toHomeRenderFeed` が `item.summaryExcerpt` を `RenderFeed.excerpt` および `RenderFeed.description` に詰めて `renderFeedToReaderItem` へ渡していたため、`ArticleEditorialRail.svelte` が日本語 AI 要約を `Excerpt` 見出しの下に描画していた。さらに `Summarize` を押すと、同じキャッシュ済み日本語要約が `AI SUMMARY` セクションにも描画され、同一内容が上下に重複した。

一方、`/feeds`・`/feeds/visual-preview`・`/feeds/favorites`・`/feeds/viewed`・`/feeds/search` では `RenderFeed.excerpt` に RSS 原文抜粋（`generateExcerptFromDescription`）が入るため、日本語の `AI SUMMARY` と役割が異なる。

## Decision

**Knowledge Home の既存日本語要約を `Excerpt` ではなく `AI SUMMARY` の初期値としてリーダーへ直接渡し、editorial rail 側でも `AI SUMMARY` と同一内容の `Excerpt` を抑止する案を採用する。**

具体的な設計は以下の通り。

1. **`ReaderArticleItem` に `initialSummary?: string | null` を追加する**:
   - `src/lib/reader/types.ts` の `ReaderArticleItem` に `initialSummary?: string | null` を定義し、`src/lib/reader/reader-overlay.svelte.ts` の `toPlainReaderItem` でシリアライズ対象に含める。
   - RSS 原文抜粋（`excerpt`）、本文取得失敗時の補助表示（`fallbackDescription`）、既存 AI 要約（`initialSummary`）の 3 役割を型レベルで分離する。
2. **Knowledge Home 専用のリーダー変換 `knowledgeHomeItemToReaderItem` を導入する**:
   - `src/lib/reader/mappers.ts` に `knowledgeHomeItemToReaderItem(item: KnowledgeHomeItemData): ReaderArticleItem` を追加し、`src/routes/(app)/home/+page.svelte` から旧 `toHomeRenderFeed` シムを除去する（ストリームカード・Recall 候補の双方に適用）。
   - `item.summaryState === "ready"` かつ `item.summaryExcerpt` が非空の場合のみ `initialSummary` に設定する。`excerpt` と `fallbackDescription` は `null` とし、Knowledge Home からの遷移では `Excerpt` セクションを表示しない。
3. **`useSummarize` と `createArticleReader` で初期要約をシード可能にする**:
   - `useSummarize` に `seed(initialSummary: string | null)` を追加し、空白を除いた文字列が与えられた場合に `summary` を設定して `buttonState` を `"success"` にする。これにより開いた直後から `AI SUMMARY`・音声読み上げ（`Play summary`）・再要約（`Re-summarize`）が利用可能になる。
   - `createArticleReader` に `getInitialSummary?: () => string | null | undefined` を追加し、初回マウントおよび記事切り替え（`urlChanged || idSwitched`）時のリセット直後に初期要約をシードする。同一記事の `Re-fetch` や `Re-summarize` 実行時には再シードしない。
   - `ArticleReaderOverlaySession.svelte` は `getInitialSummary: () => overlayState.article.initialSummary` を `createArticleReader` に渡す。
4. **`ArticleEditorialRail` に同一内容の重複抑止ガードを入れる**:
   - `/feeds` 等の RSS 原文抜粋を持つ面では `Excerpt` セクションを引き続き表示する。
   - ただし `excerpt` と `reader.summarizer.summary` が空白正規化後に完全一致する場合は `Excerpt` セクションを非表示とし、将来別経路から同じ要約が `excerpt` に入った場合も二重表示を構造的に防ぐ。

### 検討した代替案

- **(a) Knowledge Home から `excerpt` を外すだけで、`AI SUMMARY` は `Summarize` 押下時のみ取得する**: 退けた。Knowledge Home の一覧カードですでに完成済みの日本語要約を保持しているにもかかわらず、リーダーを開くと要約が消えて再度 `Summarize` 押下を要求するため体験が後退する。
- **(b) `Excerpt` 用に RSS 原文抜粋をバックエンドから追加取得して表示する**: 退けた。`knowledge_home_items` および `ArticleCreated` イベントは RSS 原文 description を持たず、バックエンド・イベント契約の拡張が必要になるうえ、日本語要約がすでにある Knowledge Home では原文抜粋を並べる価値が乏しい。
- **(c) 全画面の `ArticleEditorialRail` から `Excerpt` を一律削除、または要約表示中に常時非表示にする**: 退けた。`/feeds` 系の面では RSS 原文抜粋と日本語 AI 要約で情報が異なるため、他画面の挙動を変えずに Knowledge Home の誤マッピングと完全一致重複のみを解消する方針を選んだ。

## Consequences

### Pros

- Knowledge Home からデスクトップ・モバイルいずれで記事を開いても、既存の日本語要約が最初から `AI SUMMARY` として表示され、`Excerpt` との二重表示が解消される。
- 開いた直後から `Play summary`（音声読み上げ）と `Re-summarize`（強制再要約）が追加通信なしで使えるようになる。
- `home/+page.svelte` に残っていた `RenderFeed` 変換シム（`toHomeRenderFeed`）を除去でき、`ReaderArticleItem` の役割境界が明確になる。
- `/feeds` 等の RSS 原文抜粋表示を保ちつつ、editorial rail 側の重複抑止で同種の再発を防げる。

### Cons / Tradeoffs

- Knowledge Home からの遷移時に本文取得が進行中または失敗した場合、以前は `fallbackDescription` に同じ日本語要約が描画されていたが、以降は `AI SUMMARY` セクション（モバイルでは本文プレースホルダ直上、デスクトップでは右 rail）に表示が一本化される。
- 既存の日本語要約が表示された状態で `Re-summarize` を押すと `forceRefresh: true` で再生成が走る。キャッシュ再取得ではなく強制再要約となるが、画面上に最新投影の要約がすでに出ているため意図どおりの動作である。
