# ADR-000988: モデル・依存のライセンス許可リストを MIT / Apache-2.0 / PostgreSQL License に確定し、Gemma 例外の解消経路を明文化する

## Status

Accepted

## Date

2026-09-01

## Affected Services

- rag-db（pgvector / 将来の PostgreSQL 拡張の採用判断）
- news-creator（生成モデルの選定基準）
- rag-orchestrator / rerank-server / knowledge-embedder（embedding・reranker の選定基準）

## Context

これまでモデル・weights・依存のライセンス方針は「MIT / Apache 2.0 のみ」という運用者ローカルの
合意として存在していたが、[[000987]] の鮮度監査で 2 つの不整合が確定した。

1. 既に採用している PostgreSQL 拡張（pgvector / pgvectorscale / pg_textsearch / pg_bigm）は
   いずれも **PostgreSQL License** であり、SPDX 上 MIT でも Apache-2.0 でもない。字義どおりに
   適用すると既存スタックの中核が許可リスト外になってしまう。
2. 現行の生成モデル gemma4 系は **Gemma Terms**（独自規約）で配布されており、上記の
   許可リストの分類には入らない。

選定基準が暗黙のままだと、次のモデル・拡張の選定時に基準が場当たりになるか、逆に問題のない
permissive ライセンスまで機械的に弾かれる。

## Decision

**ライセンス許可リストを次の 3 つに確定する: MIT / Apache-2.0 / PostgreSQL License。**
これがモデル・weights・ライブラリ・DB 拡張・評価資材に共通で適用される全リストであり、
以下を明示的に除外する: AGPL / GPL / SSPL / Elastic License、CC-BY-SA / CC-BY-NC、
ベンダー独自規約（Gemma Terms・Llama Community License・NVIDIA Open Model License・
PLaMo コミュニティライセンス等）。

- **PostgreSQL License を許可に加える理由**: BSD 系の permissive ライセンスであり、
  MIT/Apache と実務上の義務が同等。PostgreSQL エコシステムの標準ライセンスであるため、
  これを除外すると pgvector を含む拡張が原理的に採用不能になる。
- **gemma4 の扱い**: 許可リストは**新規採用の選定基準**であり、既存採用分に遡及しない。
  gemma4 系は現行ベースラインとして継続し、[[000987]] のとおり新規候補は許可リスト準拠
  モデルのみから選定、eval で勝る準拠候補が出た時点で交代する。
- **評価データセットへの適用**: JQaRA / JMTEB / JGLUE 等の CC-BY-SA-4.0 データセットは
  取り込み・再配布しない（公開スコアの引用は可）。retrieval 品質評価は自前 golden set で行う。

**検討した代替案**:
- *「MIT / Apache のみ」を維持し pgvector 等を個別例外にする*: 例外リストが恒常的に増える
  構造であり、PostgreSQL License は内容的に例外扱いする理由がないため不採用。
- *BSD 系全般（BSD-2/3-Clause 等）まで広げる*: 現時点で必要な依存が存在しない。必要になった
  時点で個別 ADR で判断する方が許可リストの意味が保たれるため、今回は加えない。
- *gemma4 の即時退役*: 品質検証なしの交代は品質主軸（[[000987]]）と矛盾するため不採用。

## Consequences

### Pros

- 既存スタック（pgvector 等）と方針の食い違いが解消され、選定判断が許可リスト照合に還元される
- gemma4 の位置づけ（遡及なし・eval 交代方式）が明文化され、後続の選定で Gemma 系を
  なし崩しに増やす根拠として使えなくなる
- 評価資材までライセンス方針の適用範囲であることが明文化される

### Cons / Tradeoffs

- 日本語性能で有力な許可リスト外モデル（Llama 系 fine-tune・NVIDIA OML 系等）を品質評価の
  土俵に乗せる前に弾くため、品質面の機会損失がありうる
- gemma4 のベースライン継続は eval で準拠候補が勝つまで無期限に続きうる
