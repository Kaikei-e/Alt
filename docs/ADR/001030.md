# ADR-001030: news-creator の HybridPrioritySemaphore に Tauto スロット保存則モデルと適合テストオラクルを導入する

## Status

Accepted

## Date

2026-11-27

## Affected Services

- `news-creator` (Python: `HybridPrioritySemaphore` 適合テスト・ゴールデンベクタ配置および Phase 2 ハードニング対象)
- `specs` (`specs/tauto/hybrid-priority-semaphore/` 配下の形式仕様・機械検証済み定理・ベクタ出力ドライバ)

## Context

`news-creator/app/news_creator/gateway/hybrid_priority_semaphore.py`（896 行）は推論バックエンドの同時実行スロット（RT / BE 優先度制御・プリエンプション・エイジング・帯域保証）を司る中核コンポーネントであり、約 6 週間で 7 件の障害・改修に関与した（[[000243]]、および 8 日間で 6 件のポストモーテム `PM-2026-004`・`PM-2026-006`・`PM-2026-012` / [[000601]]・`PM-2026-013` / [[000606]]・`PM-2026-014` / [[000610]]・`PM-2026-015` / [[000612]]）。

プリエンプション連鎖による RT スロットの BE プール流出と `min(+1, cap)` での黙殺消滅（10 分間の推論停止・113.33 秒キュー滞留）、`slot_id` 未返却による所有権推論破綻、`be_slots=0` 構成での 109 回連続 `SLOT INVARIANT VIOLATION`（281 秒滞留）、`set_result()` 直後の `CancelledError` による 86 回連続 `SLOT INVARIANT VIOLATION`（最大 551.59 秒滞留）と、個別パッチで 1 つの漏れを塞ぐたびに隣接する状態遷移の隙間が露呈してきた（FP-17）。

なお、`PM-2026-012` / `PM-2026-014` / `PM-2026-015` で繰り返し持ち越されていた `Hypothesis` 導入アクションは、`Hypothesis` が **MPL-2.0** であり [[000988]] のライセンス許可リスト（MIT / Apache-2.0 / PostgreSQL License）に抵触するため採用できない。

本 ADR 策定前の全量コード監査および実実行再現により、現行実装（既存 86 テスト全通過、本番呼び出し元は `news-creator/app/news_creator/gateway/ollama_gateway.py` の 5 経路すべてが `slot_id` を明示渡し）にも以下 6 項目の残存ギャップが確認された。

1. **複数 in-transit スロット時の偽陽性（観測性）**: `_check_slot_invariant`（`hybrid_priority_semaphore.py:656-680`）が転送中スロットを 1 ビット `woke_up` でしか控除しないため、`total_slots >= 2` で同一イベントループターン内に 2 回連続 `release()` すると 2 スロットが in-transit になり、正常動作中に `SLOT INVARIANT VIOLATION` ERROR を誤発報する（実再現済み）。
2. **未知・二重 `slot_id` の `release()` による相互排除破綻（安全性）**: `_resolve_release_home_pool`（`:575-609`）が未知・既解放の `slot_id` に対して呼び出し側の `was_high_priority` から `home_pool` を推論して後続 waiter を起床させるため、`total_slots=1` でも `len(_acquired_slots) == 2` を実再現した。また waiter 不在時は `_return_slot_to_pool`（`:649-655`）の `min(avail + 1, cap)` が二重解放を黙殺し、逆に `be_slots=0` 側へ誤推論すると `min(0 + 1, 0) = 0` でスロットを黙殺消滅させる。
3. **旧 `release(slot_id=None)` と明示 `slot_id` 混在による RT スロット消失（安全性）**: `slot_id=None` 経路（`:585-604`）が最古の一致スロットを消去するため、転送済み RT スロットを持つ後発 BE が旧経路で解放すると別 BE の `slot_id` を奪い、後続の正規解放が `min()` で潰れて RT スロットが永久消失する（実再現済み）。本番 5 経路はすべて `slot_id` を渡しており旧経路は不要である。
4. **`rt_reserved_slots < 0` の検証欠落（安全性）**: `__init__`（`:105-110`）が下限 0 を検査しないため `(total_slots=2, rt_reserved_slots=-1)` で `_be_slots=3` が成立し、上限超過の 3 並列取得を許す（実再現済み）。
5. **LIFO モードでの昇格 BE 飢餓（活性）**: `rt_scheduling_mode="lifo"` では新規 RT が負の `-start_time` を積む（`:474-478`）のに対し、`_apply_aging` が昇格 BE を正の `+start_time` のまま `_rt_queue` に積む（`:821-825`）ため、後続 RT に恒久的に追い抜かれる（実再現済み）。
6. **その他残存事項**: `except asyncio.CancelledError` 内の `async with self._lock`（`:382`）での二重キャンセル時キュー掃除漏れ、`_release_slot_to_pool_or_waiter`（`:682-708`）での `_check_slot_invariant` と `_consecutive_rt_releases` リセット欠落、`check_leaks()`（`:298`）と `_preemption_threshold`（`:152`）の本番未接続、`queue_status()` の `accepting` 計算ずれ。

事前プロトタイプ（`Hihaheho/tauto` v0.1.0、9 `inductive enum` / 47 純粋 `fn` / **54 `pub theorem`**）では、`tauto --offline check --fresh --summary` が **`110 ok, 0 failed, 0 incomplete; 0 skipped; axioms: none`**（カーネル検証 `0.875s`、コールド wall-clock `6.78s`）で通過し、`tauto --offline run` の 6 シナリオ 49 ステップを本番 `HybridPrioritySemaphore` へ再生して全 49 ステップで状態一致と上記ギャップ 1（`python_invariant_error_logs=1`）の実検知を実証した。

## Decision

**[[001029]] で確定した Tauto 形式仕様基盤を用い、[[000601]]・[[000606]]・[[000610]]・[[000612]] が積み上げた `HybridPrioritySemaphore` の所有権・保存則契約を `specs/tauto/hybrid-priority-semaphore/` として形式化し、本番 Python ランタイム依存ゼロの適合テストオラクルを `news-creator` に導入する。**

本決定は [[000988]]（ライセンス許可リスト）および [[001029]]（配置規約・CI ゲート・撤退基準）を前提とし、既存 ADR を置換しない。

### 1. 形式モデルと機械証明する不変条件

`specs/tauto/hybrid-priority-semaphore/`（`src/` と `vectors/` 分離、[[001029]] 規約準拠）において、6 カウンタ所有権モデル（`rt/be` × `avail/held/in_transit`）＋キュー長・`guaranteed_be_ratio` に対し、任意の有限イベント列および無制限の `Nat` 設定について以下を **公理ゼロ・hole ゼロ** で証明する。

1. **プール別および全体スロット保存則**: 全遷移（即時取得・フォールバック取得・キュー上限拒否・waiter 起床解放・プール返却解放・不正解放拒否・`CompleteTransfer`・`CancelQueued`・`CancelInTransit` 回収・`PromoteBeToRt`）に対し `rt_avail + held_rt + in_transit_rt = rt_reserved` かつ `be_avail + held_be + in_transit_be = be_slots`（したがって `avail + held + in_transit = total_slots`）が保存される。
2. **`min(..., cap)` 無しでのプール上限保存**: 解放・回収時に `min()` で切り詰めずに `Succ(avail) <= cap` が常に成り立つことを証明する（`min()` が正当状態では死蔵コードであり、バグの黙殺にしかならないことを形式的に確定する）。
3. **同時実行上限とプール越境ゼロ**: `held_rt + held_be <= total_slots`（`total_slots = 1` での相互排除を含む）、および `be_slots = 0` / `rt_reserved = 0` フォールバック構成で存在しないプールのスロットが決して生成されないこと。
4. **未知・二重解放の厳格拒否**: `held_<pool> == 0` に対する解放は常に `RejectedInvalidRelease` の無操作となり、waiter 起床も架空スロット生成も起こさない。
5. **障害リプレイ定理**: `PM-2026-012` / `014` / `015`・複数同時 in-transit・`guaranteed_be_ratio`・`all_be` + `max_queue_depth` のカーネル簡約定理を固定する。

### 2. `pytest` 適合テストオラクルと `pytest-asyncio` との責務分担

- **ゴールデンベクタ**: `tauto --offline run` の出力を `news-creator/app/tests/gateway/testdata/hybrid_priority_semaphore_vectors.txt` へコミットし、`news-creator/app/tests/gateway/` の `pytest` 適合ハーネスが各ステップの 9 状態カウンタを本番 `HybridPrioritySemaphore` と突合する。`news-creator` の Docker イメージ・Python 依存・`news-creator.yml` は `tauto` に一切依存しない。
- **`pytest-asyncio` が引き続き担う境界**: 逐次純粋モデルでは表現できない以下の領域は、引き続き `news-creator` の `pytest-asyncio` スイートで担保する。
  - CPython `asyncio` イベントループの `await` 割り込み（例: `CancelInTransit` 内の `async with self._lock` がターンを譲り起床済み waiter が先に `_track_acquire()` する挙動）
  - `asyncio.Lock` 再入および `except asyncio.CancelledError` 内での二重キャンセル
  - `time.monotonic` ベースのエイジング浮動小数点計算・スイープ間引き・`heapq` FIFO/LIFO 順序
  - PEP 525 非同期ジェネレータ / `weakref.finalize`（[[000243]]）および `ollama_gateway.py` の `asyncio.wait(FIRST_COMPLETED)` プリエンプション競合
  - 活性（無限到着下の飢餓不在）

### 3. 段階的実装順序（Phase 1 / Phase 2）と PM アクション対応

1. **Phase 1（形式仕様 + 適合テスト追加、本番 Python 無変更）**: [[001029]] の基盤整備と合わせて `specs/tauto/hybrid-priority-semaphore/`・`testdata/hybrid_priority_semaphore_vectors.txt`・`pytest` 適合テストを追加する。
   - **FP-07 防止契約**: Phase 1 時点では本番 Python 実装をまだ改修しないため、正常解放系シナリオを必須 pass としつつ、Phase 2 対象の `SCENARIO_MULTI_IN_TRANSIT`（`SLOT INVARIANT VIOLATION` ログ 0 件検証）と `RejectedInvalidRelease` 検証は黙ってスキップせず `@pytest.mark.xfail(strict=True, reason="Phase 2 hardening")` で明示固定する。
   - Phase 1 完了により、`PM-2026-012` / `014` / `015` で未完了だった Hypothesis PBT 項目を [[000988]] 準拠の Tauto 形式証明＋適合テストオラクルで代替クローズし、本 ADR を `accepted` へ更新する。
2. **Phase 2（監査で実再現された残存ギャップのハードニング PR・別 PR、TDD 先行）**:
   - `_in_transit_rt` / `_in_transit_be` カウンタを明示追跡し `_check_slot_invariant` および `queue_status()` の複数 in-transit 偽陽性を解消する。
   - 未知・二重 `slot_id` を拒否し（waiter を起床させない）、旧 `release(slot_id=None)` フォールバックを廃止する（`PM-2026-015` の `slot_id` 必須化アクションをクローズ）。
   - `_return_slot_to_pool` の黙殺 `min(..., cap)` を明示的な不変条件エラーログ・アサートへ置き換える。
   - `__init__` に `rt_reserved_slots < 0` 検証を追加し、LIFO モードでの昇格 BE タイムスタンプ符号を是正する。
   - Phase 1 の `xfail(strict=True)` テストを必須 pass へ切り替える。
   - なお観測性・アラート側の未完了アクション（`PM-2026-015 D-1` の `SLOT INVARIANT VIOLATION` アラート配線や `total_slots==1` プリエンプション安全弁）は別 PR で独立管理する。
   - 本実装ブランチ（`feat/tauto-formal-specs`）では Phase 1（`specs/tauto/hybrid-priority-semaphore/`：98 `pub theorem`・`170 ok, 0 failed, 0 incomplete, 0 holes, 0 skipped, axioms: []`、11 シナリオ 94 ステップ適合オラクル）と Phase 2（`hybrid_priority_semaphore.py` の全 6 ギャップ解消と `xfail` 撤去・全 109 セマフォテスト必須 pass）を一括実装・検証済みのため、本 ADR を `accepted` とする。

### 4. 検討した代替案と却下理由

- **既存の `pytest` 単体テスト拡張のみで継続する案**: 既存 86 テスト全通過の状態でも、複数 in-transit 偽陽性や未知 `slot_id` による相互排除破綻など 6 項目のギャップを見落としており、点サンプルの追加だけでは全設定・全イベント列の保存則を保証できないため却下した。
- **ランタイム `_check_slot_invariant` の強化のみで対処する案**: 障害発生後の事後検知にしかならず、また `min(..., cap)` や 1 ビット `woke_up` のように検査実装自体に欠陥が混入しうるため単独案としては却下した（Phase 2 でランタイム検査も併用強化する）。
- **`Hypothesis` PBT を `news-creator` に導入する案**: `Hypothesis` は **MPL-2.0** であり [[000988]] に違反するため却下した。
- **`HybridPrioritySemaphore` 自体を Rust 書き直し + Kani 検証する案**: Python `asyncio` ゲートウェイ（`ollama_gateway.py`）にネイティブ拡張・FFI 境界と別言語ビルドを持ち込むコストが過大であり、無制限帰納法も得られないため却下した。

## Consequences

### Pros

- 過去 7 件の障害・改修を繰り返した `HybridPrioritySemaphore` のスロット保存則・プール上限・相互排除・ゼロ越境を、無制限の設定と任意長トレースに対して公理ゼロで機械証明できる。
- `news-creator` の本番コンテナイメージ・Python 依存・推論レイテンシに一切影響せず、既存の `uv run pytest` で適合回帰テストを常時実行できる。
- [[000988]] に抵触する `Hypothesis`（`MPL-2.0`）を入れずに `PM-2026-012` / `014` / `015` の検証アクションをクローズできる。
- Phase 1 の `xfail(strict=True)` 境界と Phase 2 のハードニング計画により、監査で実再現された相互排除破綻・偽陽性・LIFO 昇格飢餓を安全かつ段階的に塞げる。

### Cons / Tradeoffs

- 逐次純粋モデルでは CPython `asyncio` 割り込み・浮動小数点エイジング・PEP 525 / `weakref.finalize` を証明できないため、`pytest-asyncio` テストとの二層維持が必要になる。
- 仕様ファイルは約 2,100 行（カーネル検証 `0.875s`）の保守対象となり、セマフォの状態遷移変更時は `.taut` 仕様・証明・`testdata/` ベクタの同時更新が要る（[[001029]] の CI ゲートで強制）。
- Phase 2 で未知・二重 `slot_id` の許容フォールバックを廃止する際、旧挙動を前提とする一部ユニットテスト（`test_hybrid_priority_semaphore_branches.py:23-63`）の更新が必要になる。
