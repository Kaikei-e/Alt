# ADR-001044: 読了時マイクロ外化と Themes 共創ワークスペースを導入し、知識昇華と Augur 還流ループを構築する

## Status

Accepted

## Date

2026-11-28

## Affected Services

- proto — `proto/alt/reading/v1/reading.proto` と `proto/services/sovereign/v1/sovereign.proto` に記事アノテーション（抜粋・スタンス・1 行メモ）とテーマ共創キュレーションのメッセージ・RPC を追加
- knowledge-sovereign (Go / PostgreSQL) — マイグレーション `00038`（`reading_annotations`, `reading_theme_curations`）、4 種の新規イベントを `event-auth-policy.json`・`event_auth_interceptor.go`・`reading_projector` へ追加、読み出し RPC を実装
- alt-backend (Go) — Clean Architecture 準拠で Domain・Port・Gateway・Usecase・`ReadingService` Connect-RPC ハンドラおよび DI 配線（`*_enabled` 起動ログ付き）を追加
- alt-butterfly-facade (Go) — 既存 `alt.reading.v1.ReadingService` 公開許可リストでの透過転送を確認・検証
- news-creator (Python) — ユーザーによるテーマキュレーション・ハイライトを次版テーマ生成のステアリング入力（optional `user_steering`、改行フラット化によるプロンプト境界保護付き）として受け取れる拡張を追加
- alt-frontend-sv (TypeScript / SvelteKit) — 統合リーダー内 `ArticleCaptureBar`、共創型 `/knowledge/themes/[themeId]`、`/augur` からのテーマ還流、`/today` の軽量文脈想起セクションを実装

## Context

[[001015]]・[[001024]] は読んだ記事だけを原典とする `reading_sources` とテーマページ `/knowledge` を立ち上げ、「1.31 秒間隔の高速さばき」からの脱却に大きく前進した。しかし、[[001015]] の代替案 (c) でユーザー側のメモ・想起を退け、[[001024]] の Cons で「自分で構造を作る場合と機械が与えるテーマページを読む場合の学習効果の差は一次資料で確認できていない」と保留したため、以下の課題が残っている。

- **認知科学・実証研究が示す受動閲覧の限界**: 処理水準理論（Craik & Lockhart, 1972）、生成効果（Slamecka & Graf, 1978）、テスト効果・望ましい困難（Roediger & Karpicke, 2006; Bjork & Bjork, 2011）に加え、近年の大規模 RCT ではガードレール無しの AI 出力依存がメタ認知的怠惰（Fan et al., 2025, BJET）、AI 除去後の成績低下（Bastani et al., 2025, PNAS, -17%）、批判的思考の低下（Lee et al., 2025, CHI '25）、脳内結合性低下と想起不全（Kosmyna et al., 2025）を招くことが実証されている。
- **HCI 研究が示す混合主導（Mixed-Initiative）の有効性**: 読書中の低摩擦インライン摘み出し（Threddy, UIST 2022）、ユーザーが AI 合成を剪定・方向づけする共創ワークフロー（Synergi, UIST 2023）、記事単位ではなく問い・主張・根拠で構造化する Discourse Graphs（Chan et al., 2024）は、重いノート執筆を強いずに探索幅と理解定着を高める。
- **Alt 内部の断絶**: `/knowledge/themes/[themeId]` は完全読み取り専用で、ユーザーが `Key points` を取捨選択したり `Open questions` に答えや疑問を追加したりできない。さらに `Ask Augur` でユーザーが能動的に発した問いと回答がチャット履歴に孤立し、テーマや読書資産へ一切還流しない。

## Decision

1. **トリアージには一切入力を求めず、読書完了点と Themes だけに「マイクロ外化」を導入する**:
   - Swipe / Gallery の高速さばき（1.31 秒操作）は完全に無摩擦のまま維持する。
   - 統合記事リーダー（[[001019]] の `ArticleReaderBody`）の読了領域に `ArticleCaptureBar` を配置し、**1 タップ抜粋（本文選択テキストまたは任意スニペット）＋ 4 種の認識論スタンス（`surprise` / `question` / `contradiction` / `insight`）＋ 任意 1 行メモ（各最大 500 文字）** を記録できるようにする。
2. **追記型イベント 4 種と再射影可能な read model 2 表を `knowledge-sovereign` に追加する**:
   - 新規イベント（`alt-backend` の `allowed_events` に登録）:
     - `reading.annotation_created.v1` / `reading.annotation_deleted.v1`
     - `reading.theme_item_curated.v1` / `reading.theme_curation_removed.v1`
   - マイグレーション `00038_create_reading_annotations_and_curations.sql` で `reading_annotations` と `reading_theme_curations` を新設し、`reading_projector` がイベントペイロードのみから決定論的に fold する（reproject-safe）。
   - すべての書き込み・読み取りで JWT 由来 `user_id` による所有権境界をサーバ側（`event_auth_interceptor.go` のユーザー委譲検証を含む）で強制し、SQL は完全にパラメータ化する。削除済み行の `deleted_at` は再射影や重複イベントで復元されないよう `COALESCE` で単調保護する。フロントエンドのテキスト描画はすべて Svelte の自動エスケープを用い、`{@html}` は使用しない。
3. **`alt.reading.v1.ReadingService` と `services.sovereign.v1.KnowledgeSovereignService` を拡張する**:
   - 記事アノテーション: `SaveArticleAnnotation` / `DeleteArticleAnnotation` / `ListArticleAnnotations`（`article_ids` フィルタおよび直近一覧の両対応）
   - テーマキュレーション: `CurateThemeItem` / `RemoveThemeCuration` / `ListThemeCurations`（`pin_key_point`, `dismiss_key_point`, `add_question`, `resolve_question`, `add_seed_note`, `promote_augur_insight` の厳格な allow-list enum）
   - 既存の `ReadingService`（`VISIBILITY_PUBLIC`）に乗せるため、新規マイクロサービス・新規 DB・新規 mTLS 辺を一切増やさない。
4. **`/knowledge/themes/[themeId]` を人間共創ワークスペースへ昇格し、Augur 還流ループを閉じる**:
   - `Key points` 各行に 1 タップの **Pin**（上位固定・次版優先シード）と **Dismiss**（非表示・次版除外シード）を付与する。
   - `Open questions` 各行に **Ask Augur**（`/augur?q=...&themeId=...&themeTitle=...` へ文脈付き遷移）と **Resolve**（任意 1 行の結論メモ付き解決）を付与する。
   - テーマ画面内からユーザー自身の **Open question / Seed note** を直接追加でき、さらにテーマを構成する原典記事（`sources`）上でユーザーが記録した `reading_annotations` を **Your takeaways** セクションに自動集約して表示する。
   - `/augur` 側で `themeId` / `themeTitle` クエリを受理し、アシスタント回答に 1 タップの **Save insight to Theme** 操作（`promote_augur_insight` と `augur_conversation_id` を記録）を追加して、疑問→Augur 相談→テーマ定着の閉ループを完成させる。
5. **`/today` にユーザー自身の未解決の問い・気づきの軽量文脈想起を配置する**:
   - 廃止された旧 Recall Rail（開封 1 時間後・スコア `0.5` 固定）の代替として、`/today` の `Read today` キュー直下にユーザー自身の最新アノテーション（`question` / `contradiction` / `insight` 優先、最大 3 件）を静かに表示し、記事または Augur へ即座に戻れるようにする。
6. **`news-creator` に任意 `user_steering` 入力契約を実装し、次版テーマ生成への接続口を用意する**:
   - `news-creator` の `ThemeGenerateRequest` と `theme_page.jinja` にオプショナルな `user_steering`（ピン留め要点・除外要点・ユーザーの問いとメモ）を追加し、各行の改行フラット化と既存の出典照合不変条件を保ったまま次版のテーマ生成がユーザーの関心を反映できるようにする。`knowledge-sovereign` 側では `recap-worker` への `ListReadingAnnotations` / `ListReadingThemeCurations` 読取権限を先行許可し、`recap-worker`（Rust）の `ThemesPipeline` からの呼び出し配線は後続 PR として切り出す。

### 検討した代替案

- **専用の Markdown エディタや独立 PKM サービスを新設する**: 退けた。新規サービス・DB・mTLS 境界を増やすと配管負債が再燃し、モバイルでの 1 タップ読書体験とも乖離するため。
- **ブラウザ `localStorage` のみにメモを保存する**: 退けた。モバイルとデスクトップ間で知識が同期されず、テーマ生成パイプラインや追記ログからの再射影にも参加できないため。

## Consequences

### Pros

- 「読む（`/today`・Reader）→ 極小外化する（抜粋・スタンス・1 行メモ）→ つなげて育てる（共創 `/knowledge/themes` ＆ Augur 還流）→ 思い出す（`/today` 文脈想起）」という知識昇華ループが一貫して閉じる。
- 新規マイクロサービスや DB を増やさず、既存の `ReadingService`・`reading_projector`・append-first / reproject-safe 不変条件の上に乗る。
- [[001024]] の未解決論点（AI 生成の受動閲覧 vs ユーザー関与による構造化）に対し、低摩擦な混合主導設計で実証可能な基盤が整う。

### Cons / Tradeoffs

- 新規イベント 4 種と read model 2 表の追加に伴い、本番適用時は `knowledge-sovereign` のマイグレーション `00038` を先行実行する必要がある（`migrate → deploy`）。
- テキストフィールド（`excerpt` / `note`）を最大 500 文字で送るため、上流 WAF の誤検知がないか運用開始時に監視が必要である（制御文字除去・長さ制限・プレーンテキスト限定で緩和する）。
- `news-creator` の `user_steering` 受け口と `knowledge-sovereign` の読取権限は本 ADR で整備済みだが、`recap-worker`（Rust）の `ThemesPipeline` からこれらを取得・送信する配線は未着手であり、後続 PR で Pact 契約テストと併せて接続する。
- テーマ間の異分野ブリッジ（Swanson 型 $A \to B \to C$ / HippoRAG 2 的探索）と [[001023]] の記事末接続 UI の本配線は、本 ADR の共創基盤の上に乗る次段階として扱う。
