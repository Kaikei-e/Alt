# ADR-001002: news-creator の raw 生成呼び出しに Gemma 4 チャットテンプレートを必須化し、プレースホルダ出力を劣化として扱う

## Status

Proposed

## Date

2026-11-09

## Affected Services

- news-creator (Python): `OllamaGateway` の raw プロンプト受け入れ条件、`MorningLetterUsecase` のプロンプト構築・出力検証、`MorningLetterContent` スキーマ
- recap-worker (Rust): Morning Letter の `generated_at` をサーバ側で付与する
- alt-backend (Go): Morning Letter の時刻パース失敗を握りつぶさない

## Context

### 症状

Morning Letter（`morning_letters`、1 日 1 行で再生成は同じ行を上書き）は 2026-07-06 以降、126 日分中 122 日分で `lead`・`generated_at` とほぼすべての `bullets`（258 件中 256 件）が文字列 `"..."` だけになっていた。そのうち 113 日分は `is_degraded=false`、つまり成功として保存されていた。直近 30 件の非 fallback 行はすべて `"..."` で、1 回の生成は 1〜2 秒だった。2026-06 にも散発しており（2 件）、5 月から 7 月初旬までは実文が生成されていた。

### 原因

- `OllamaGateway.generate` は `"raw": True` を送る。コード上のコメントには「プロンプトは Gemma 4 のチャットテンプレート（`<|turn>` / `<turn|>`）を含んでいる前提」とある。Ollama の API ドキュメントでも、`raw` を true にするとプロンプトに書式が一切適用されず、テンプレート済みの完全なプロンプトを渡す場合に使うものとされている
- recap 要約とトピックカードの usecase は `wrap_gemma_prompt` で、クエリ展開と記事要約の usecase はプロンプト内に直接、テンプレートを付けている。`MorningLetterUsecase._build_prompt` だけが `morning_letter.jinja` を描画したまま渡していた（raw 化は 2026-04-03、テンプレートなしの Morning Letter プロンプトは 2026-04-07 から）
- Gemma 4 のターン区切りは `<|turn>` / `<turn|>` で、生成の開始は `<|turn>model\n` である（Google の Gemma 4 プロンプト書式ページと Hugging Face の `chat_template.jinja`）。Gemma 1〜3 の `<start_of_turn>` 系とは異なる

### 検証（同一入力の A/B）

使い捨てコンテナから同じ Ollama に直接、本番の daemon と同じ構成の入力（プロンプト約 2,400 トークン、`num_ctx` 12,288 なので切り詰めなし）を 2 回ずつ投げた。DB や他サービスへの書き込みはしていない。

| 条件 | 結果 |
|---|---|
| テンプレートなし・raw・JSON スキーマ指定（現行） | 2/2 回とも `"..."`（出力 82〜88 トークン、1.0〜1.8 秒） |
| `wrap_gemma_prompt` あり・raw・JSON スキーマ指定 | 2/2 回とも日本語の具体的なリードと箇条書き 8〜9 件（約 4 秒） |
| テンプレートなし・raw・形式指定なし | 2/2 回とも 1 トークン目でターン終了トークンを出して空応答 |
| テンプレートなし・raw=false・JSON スキーマ指定 | 思考チャネルで `num_predict` を使い切り、2 回とも未完 |

テンプレートがないと、モデルは開いたままのターンを閉じようとして終了トークンを最有力にする。JSON スキーマの文法制約が JSON 完成まで終了を禁じるため、文法上最短の `"..."` で各フィールドを埋めて抜ける。これが `"..."` の発生機構である。

5〜6 月に実文が出ていた理由と、2026-07-06 から常態化した理由は切り分けていない。テンプレートなしの状態は 4 月からあり、6 月には散発していた。常態化はその後の Ollama 更新とモデル差し替え（2026-07-08 以降、[[000947]]、[[000981]]）より前に始まっており、ランタイム更新との因果は確認できていない。

### 検知できなかった理由

- `MorningLetterContent` の各フィールドは `Field(min_length=1)` しか持たず、`"..."` は検証を通る
- `generated_at` を LLM に生成させていた。7 月以前から実在しない日時（過去年や未来日）が入っていた
- alt-backend は `generated_at` のパース失敗を無視し、`0001-01-01` として扱っていた
- 文法制約付きデコードは構文を保証するが、内容の質は保証しない。形式制約を強くすると推論性能が落ちるという報告もある（"Let Me Speak Freely?", arXiv:2408.02442）。Ollama の structured outputs ドキュメントも、スキーマをプロンプトにも書くことを推奨している

類似の先例として、raw プロンプトでモデルターンのヘッダの改行が落ちて空要約が出た [[PM-2026-059]] がある。

## Decision

news-creator が `raw: true` で Ollama を呼ぶときは、Gemma 4 のチャットテンプレートで包んだプロンプトだけを受け付けることを採用する。あわせて、Morning Letter の出力には内容の検証を設け、通らなければ理由付きの劣化として扱う。

1. `OllamaGateway.generate` は、raw 呼び出しのプロンプトが `<|turn>` で始まり `<|turn>model\n` で終わることを検査し、満たさなければ例外を送出する。gateway 側で自動的に包むことはしない
2. `MorningLetterUsecase` は、system 指示と user 入力を分けて `wrap_gemma_prompt` で包む。Ollama を呼ぶ全 usecase に「送信プロンプトがテンプレート済みである」ことを確かめる単体テストを置く
3. Morning Letter の出力検証に次を加える。検査に通らなければ再試行し、それでも通らなければ既存の抽出型 fallback に流して `is_degraded=true` と `degradation_reason`（例: `placeholder_output`）を記録する。無言で成功扱いにしない
   - 省略記号だけ・極端に短い文字列のフィールドを拒否する
   - セクション間で箇条書きが同一のものを拒否する
   - 日本語比率の下限を下回るものを拒否する
4. `generated_at` は LLM の出力スキーマから外し、recap-worker が保存時にサーバ時刻で付与する。alt-backend は時刻のパース失敗を握りつぶさず、エラーとして返す
5. Ollama 本体またはモデルを更新するときは、合成入力による Morning Letter / recap 要約の生成確認（プレースホルダや空応答が出ないこと）を更新手順に含める
6. news-creator → recap-worker のレスポンス形が変わる（`generated_at` の削除）ため、Pact の RED テストを先に入れる

### 検討した代替案

- **gateway で未テンプレートのプロンプトを自動的に包む**: 呼び出し側の意図が隠れ、二重に包む事故の余地が残る。[[000640]] のテンプレート移行の趣旨（プロンプトトークンを明示的に揃える）にも合わない。却下
- **`raw: false` にして Ollama のテンプレートに任せる**: A/B では思考チャネルで生成予算を使い切った。また、他の usecase と挙動が分かれる。却下
- **`min_length` を引き上げるだけ**: 文法制約の下では、`"......"` のような長いプレースホルダに変わるだけで解決しない。却下

## Consequences

### Pros

- テンプレートの付け忘れが、黙った品質崩壊ではなく呼び出し時の例外として表に出る
- Morning Letter の失敗が `is_degraded` と理由として見えるようになり、成功率を数えられる
- 実在しない `generated_at` が画面や時刻計算に入らなくなる

### Cons / Tradeoffs

- Morning Letter 1 回の生成時間が 1〜2 秒から約 4 秒に延びる（30 分ごとの再生成なので許容範囲）
- 出力検証の閾値が厳しすぎると、正当な短い出力も劣化扱いになる。閾値は運用で調整する
- すでに保存された `"..."` 行は書き換えない。過去分は使えないまま残る
- 5〜6 月に実文が出ていた理由と、7 月から常態化した理由は未切り分けのまま残る
- `generated_at` を LLM の出力から外すことは、[[000633]] で定めた Morning Letter の出力契約の部分的な変更になる
