# ADR-000985: state を持つコンポーネントを viewport 分岐の外に出し、augur と feed の二重実装を 1 本に畳む

## Status

Accepted

## Date

2026-08-28

## Affected Services

- alt-frontend-sv (SvelteKit / Svelte 5 Runes / TypeScript)

## Context

### 分岐がリアクティブになった瞬間、二重実装が実害に変わった

[[000984]] の修正により `{#if isDesktop()}` は初回評価で凍らず、実際に幅の変化へ追随して
切り替わるようになった。これ自体は正しい修正だが、副作用として「分岐の**中**に state を持つ
コンポーネントを置く」という既存の書き方が、そのまま remount ＝ state 消失を意味するように
なった。凍っている間は二重実装が共存できていた、というのが正確な因果である。

Alt の frontend は augur (チャット) と feed 系リスト (`/feeds`, `/feeds/favorites`,
`/feeds/viewed`, `/feeds/visual-preview`) の両方で、`{#if isDesktop()}` の両ブランチに
**同じ機能の別実装**を置いていた。会話スレッドもフィード一覧もそのコンポーネントのローカル
`$state` だったため、回転 (あるいは幅の変化) のたびに丸ごと作り直されていた。

### augur — 1 つの質問に 3 回課金していた

実ブラウザ (851 → 393 → 851) の probe:

```
PROBE-AUGUR-DESKTOP  {"streamCalls":1}
PROBE-AUGUR-MOBILE   {"streamCalls":2,"hasAnswer1":false}
PROBE-AUGUR-DESKTOP2 {"streamCalls":3,"hasAnswer1":false}
```

1 つの質問に対し `streamAugurChat` が 3 回呼ばれる。会話スレッドも毎回消える
(`hasAnswer1:false`)。`?q=` にまだ質問が残っているため、remount した側が同じ質問を
再送する構造だった。RAG のストリームは課金対象であり、これは「回転すると読者が 3 回払う」に
等しい。

### feeds — 既読にして消した記事が回転で戻ってくる

同じ probe 形式での実測:

- カード数 40 → 20 (積み上げたページが捨てられる)
- `scrollY` 2430 → 0 (旧実装が mount 時に `scrollTop = 0` していた)
- 回転ごとに fetch +1
- **既読にして消した記事が戻ってくる** — `removedUrls` が `FeedGrid` のローカル `$state`
  だったため、grid が作り直されると「消した」という事実ごと消えていた

### 規模 — モバイル側は FeedGrid を丸ごと再実装していた

- feeds: `FeedsClient`(562 行) / `ViewedFeedsClient`(356 行) / `favorites` のページ内直書き
  (約 130 行) が、いずれも `FeedGrid` の再実装だった
- augur: `AugurChat` と `ChatWindow` が同じ `streamAugurChat` を呼び、同じ fallback formatter を
  使い、同じガードを持つ別実装だった

### 統合は今回思いついた方針ではなく、記録済みの意図だった

- [[000714]] は「`ChatWindow` を `AugurChat` と同じインタフェースに揃える」という決定
- [[000674]] は Ask Augur の再設計を「同一コンセプトをモバイルに適用」と記述している
- [[000751]] はモバイル側の `onConversationIdChange` 欠落を Cons に to-do として残している

さらに `ChatWindow` は既に `$lib/components/desktop/augur/` から `ArticleScopeCard` を
import していた。desktop / mobile というディレクトリ境界は、この機能に関しては最初から擬制
だった。

## Decision

**データを持つコンポーネントを `{#if}` の外に出し、分岐は葉 (カードの見た目、ヘッダ、CSS
クラス) だけにする。** これを 1 つの原則として採用し、augur と feed 系の 2 箇所に適用した。

`{#if isDesktop()}` は mount / destroy であり、**ナビゲーション chrome のための構文**である。
state を持つ画面に使ってはならない。幅ごとに本当にレイアウトが違うなら CSS で表現し、
コンポーネントのインスタンスは生かしたままにする。この一段落は
`alt-frontend-sv/docs/DESIGN_LANGUAGE.md` にも同じ内容で追記した。

### 適用例 1 — augur (`e2f0865`)

`ChatWindow.svelte` (643 行) とそのテストを削除し、`AugurChat` に一本化する。見た目の差
(サイドバー付き 3 カラム vs 全画面、送信ボタンの語 vs 矢印、入力欄の行数と文字サイズ) は
すべて CSS に落とした。iOS の auto-zoom 対策でモバイルが持っていた `font-size: 1rem` は
768px 未満で維持している。

### 適用例 2 — feed 系リスト (`8b836f2`)

`FeedGrid` を `{#if}` の外に 1 つだけ置き、分岐を `cardRenderer` snippet とヘッダだけにする。
その結果 `gridClass` は全ページで CSS 1 本に落ちた (visual-preview は
`grid grid-cols-2 gap-2 md:gap-5 lg:grid-cols-3 xl:grid-cols-4` で各幅の列数・gap が旧実装と
一致することを確認)。

### 統合の前に「同じ機能の別実装か、意図的に別体験か」を判定した

これは畳む前に必ず通す関門である。同じに見えるものを機械的に寄せると、意図して分けた体験を
壊す。

- **augur**: 2 実装を 17 軸で読み比べ、「意図的に分けた 2 つの体験」ではなく「同じ機能の、
  片方が遅れた実装」と判定した。vault の 3 本 ([[000714]] / [[000674]] / [[000751]]) も同じ
  ことを言っている。→ 統合
- **feeds の `SearchFeedsClient`**: **FeedGrid ページではないと判定して残した。** offset
  カーソル・`SearchFeedItem`・valibot 検証と、`FeedGrid` とは別のパイプラインで動いている。
  代わりに同じ考え方を state にだけ適用し、検索セッションをルートへ持ち上げてクエリを
  desktop の検索欄と共有させた
- **未判定**: `feeds/tag-trail` / `recap/+page` / `recap/evening-pulse` / `articles/by-tag` は
  いずれも `{#if isDesktop()}` を持つが、上記の判定を通していないため今回は着手していない
  (Cons 参照)

### 検討した代替案

- **二重実装を残し、分岐だけ非リアクティブに戻す** — [[000984]] が直した「横向きの電話が
  desktop レイアウトに固まる」に戻る。症状を分岐の凍結で隠すだけで、二重メンテのコストは
  残る。却下
- **state を store に持ち上げ、コンポーネントは 2 本のまま残す** — remount による state 消失は
  止まるが、2 実装の差 (モバイルに届かない `onConversationIdChange`、citation の `kind` /
  `refId` 欠落、空カーソル正規化の欠落) はそのまま残り、次の機能追加も 2 箇所に書く必要が
  ある。ただしこの形は `SearchFeedsClient` のように**畳めないと判定したもの**には正しい解で、
  実際にそちらへは適用した
- **`FeedGrid` を desktop / mobile それぞれのラッパーで包む** — 分岐の位置が 1 段ずれるだけで、
  ラッパーが state を持てば同じ障害が再発する。却下

### 意図的に破棄した挙動と、その理由

以下は「消えた」のではなく「捨てると決めた」ものである。理由を残さないと次の人がバグとして
差し戻す。

- **モバイルの typewriter (10ms/文字) → throttle 済みチャンク (50ms)**。3 実装のうち 2 つ
  (`AugurChat` / `useAugurPane`) が既にこの形で、desktop の e2e もその形を assert している。
  加えて typewriter のタイマーキューは破棄時に止められておらず、実際に漏れていたのはこちら
  だった。**文字送りの感触が要るなら、fork として戻すのではなく全員ぶん 1 箇所で足すこと**
- **既読フィードの先読み** — unread RPC が権威なので二重ソースになる。モバイルで 1 リクエスト減
- **内部の `100dvh` スクロールコンテナ** — document スクロールへ寄せた (可読幅 42rem は CSS で
  維持)
- **`content-visibility: auto`** — リスト全体に付いており、リスト全体が画面外のときしか効かない
- **`scrollTop = 0` on mount** — remount が回転を意味するようになった今、これ自体がバグ

### 訂正された前提

着手時に渡された「独立バグ」のうち 2 件は事実と違った。修正前のコンポーネントにテストを
当てて反証している。

- **「`AugurChat` に `onDestroy` が無い」は誤り。** `onMount` が abort cleanup を返しており、
  Svelte が破棄時に実行する。ストリームの孤児化は起きていなかった。実際の害は逆で、
  **回転が生きたストリームを abort し、読者が既に支払った回答を捨てていた**。abort 自体は
  残しつつ、次に読む人が読み違えないよう明示的な `onDestroy` に移した
- **SvelteKit の `replaceState` も `$page.url` を更新しない。** `page.state` を設定して古い URL
  で `history.replaceState` を呼ぶだけで、`page.url` を代入するのは実ナビゲーションのみ。
  `?q=` はどちらでも残る。それでもルータの API に替えたのは、kit が生の `history.replaceState`
  に対して警告を出すようパッチしているため

### 統合で踏みかけた地雷

`ThreadEntry` は `href={cite.URL}` を生のまま束ねており、ARTICLE / SUMMARY 種別では
`href=""` (現在ページへのリンク) になり、sanitizer も通っていなかった。素朴に `ThreadEntry`
へ寄せていたら、モバイル側が持っていた `sanitizeHrefUrl` の保護を消していた。citation rail と
同じ `citationHref()` に揃え、リンク先が無いものはプレーンテキストで描くようにした。
**「畳む」は「良いほうに揃える」であって「先に書いたほうに寄せる」ではない。**

### 葉に落とさなかった 1 点

`/feeds` の `unreadOnly` だけは `isMobile()` を**非リアクティブに 1 回だけ**読んで決める。
回転で追随させるとデータソースが変わり、grid が list を捨てて再取得する — つまり今回直した
障害そのものになる。回転で `getAllFeeds` が呼ばれないことをテストで固定した。

## Consequences

### Pros

- **回転が読者に課金しなくなった。** augur は 1 質問 = 1 ストリームで固定 (851 → 393 → 851 で
  `streamCalls` が 1 のまま、スレッドも未送信の下書きも保持)
- **feeds は回転でカード数 20 のまま・fetch 1 回のまま・既読にして消した記事が戻ってこない。**
  grid の DOM ノード identity が往復を通して保たれることを `rotation-continuity.spec.ts` で
  固定した
- モバイルに `onConversationIdChange` が初めて届く ([[000751]] の to-do 消化)。リロードで会話を
  再開できる
- citation の `kind` / `refId` がモバイルにも渡り、ARTICLE 種別がリンクになる
- デスクトップのモーダル既読が初めて読み上げられる (`liveRegionMessage`。元は無言でカードが
  消えていた)
- 楽観的既読の失敗ロールバックが `FeedGridApi.restoreFeedByUrl` で可能になった。元は「全体
  refresh」しか戻す手段が無く、1 タップの取り消しに全ページを捨てていた
- `EmptyFeedState` / `EmptyViewedFeedsState` の landmark と導線が両幅に効く。デスクトップは
  "No dispatches on the wire" の一行で出口が無かった
- **既存バグが移植で解消**: `ViewedFeedsClient` には空カーソルの正規化が入っておらず、
  `each_key_duplicate` で無限ページングしていた。RED で発覚し、1 本に畳んだ側の実装が
  そのまま修正になった
- production 正味 **−495 行**、削除コンポーネント計 918 行。`gridClass` が全ページで CSS 1 本に
  落ち、以後のレイアウト変更が 1 箇所で済む

### Cons / Tradeoffs

- `AugurChat` はもう desktop 専用ではないのに `src/lib/components/desktop/augur/` にある。
  ディレクトリ名が嘘をついている状態で、移動は別 PR
- `augur/[conversationId]` に `augur-page` の html ロックが無い (既存バグ)。`/augur` にはあるが
  会話ページには無く、iOS の bounce 抑止が効かない
- モバイル augur に Playwright カバレッジが無い (`tests/e2e/mobile/` に augur ディレクトリが
  無い)。回帰は unit と実ブラウザ手動 probe に依存している
- **feeds の `scrollY` は完全一致にできない** (600 → 往復後 1216)。タイルが「幅の半分の 16:9」
  なので幅が広がると文書が実際に伸び、Chrome はピクセルではなく割合で復元する。リフローその
  もので grid の再生成とは別問題 (旧実装は 0 にリセットしていた)。テストは「先頭に飛ばされ
  ない」の `>= 600` で固定した。詳細は `8b836f2` を参照
- `VirtualFeedList.svelte` (33 行) が誰からも参照されていない孤児として残っている
- `feeds/tag-trail` / `recap/+page` / `recap/evening-pulse` / `articles/by-tag` は
  `{#if isDesktop()}` を持ったまま**未判定・未着手**。「同じ機能の別実装か、意図的に別体験か」
  の判定を通していないため、今回の原則が適用済みだと誤解しないこと
- typewriter を捨てたので、文字送りの体感が必要という声が出たら 1 箇所 (`AugurChat` の
  throttle) に足す作業が発生する。fork で戻すのは禁止
- `/feeds` の `unreadOnly` を非リアクティブに読む判断により、「モバイルで開いてから横向きに
  しても unread のまま」という挙動が残る。データソースの切り替えより継続性を優先した結果
