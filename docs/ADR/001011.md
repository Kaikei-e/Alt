# ADR-001011: View 列順序・sparse-checkout・atlas.sum 追跡の三つの CI 不変ルールを現行契約として再確定する

## Status

Accepted

本 ADR は [[000877]] の決定を現行の拘束力ある契約（binding record）として引き継ぐ。[[000940]] の frontmatter にある [[000877]] への `supersedes` 辺は、一括 frontmatter 修復作業によって誤って付与されたものであり、[[000940]] 本来の決定を反映していない。確定済み ADR は append-only 規約の対象であるため [[000940]] 側の辺はグラフ上に残したまま、本 ADR により契約を再確定する。

## Date

2026-11-15

## Affected Services

- knowledge-sovereign — `knowledge-sovereign/migrations/atlas.sum` の git 追跡と `compose/sovereign.yaml` の `:ro` マウント、`.github/workflows/knowledge-sovereign.yaml` の複数ディレクトリ `sparse-checkout` および `pgtest` 統合テストで不変ルールを強制する
- alt-backend — `.github/workflows/backend-go.yaml` の複数ディレクトリ `sparse-checkout`（`observability` / `compose` / `migrations-atlas` / `e2e/fixtures`）と `pgtest` 統合テストで不変ルールを強制する
- migrations-atlas — `migrations-atlas/migrations/atlas.sum` の git 追跡と `compose/core.yaml` の `:ro` マウント、`CREATE OR REPLACE VIEW` を含むマイグレーション定義に適用する
- rag-migration-atlas — `rag-migration-atlas/migrations/atlas.sum` の git 追跡と `compose/rag.yaml` の `:ro` マウントで不変ルールを強制する
- recap-migration-atlas / acolyte-migration-atlas / pre-processor-migration-atlas — Rule 3 はすべての migrator に適用される。3 つとも `atlas.sum` を git で追跡している
- ci-cd — Rule 2 の適用先は `.github/workflows/` 配下の `sparse-checkout` 指定である

## Context

### 誤った supersede による現行契約の脱落

2026-10-24 に実施された 979 件の ADR に対する一括 frontmatter 修復コミットにおいて、Knowledge Loop から Knowledge Trail への移行と旧 read 表層（[[000929]] / [[000930]] / [[000933]] / [[000937]] / [[000938]] / [[000939]]）の retire を定めた [[000940]] の `supersedes` リストが 6 件から 60 件へ拡張された。これにより 54 件の ADR が `accepted` から `superseded` へ反転した。

[[000877]] は CI/CD および DB マイグレーションの一般的な不変ルールを定めた ADR であり、Knowledge Loop の read 表層 retire とは無関係であるにもかかわらず、上記 54 件に含まれて `superseded` 扱いとなった。その結果、[[000877]] は `docdag query --binding` の出力から脱落し、編集前の ADR ブリーフ（`adr-preflight`）にも表示されなくなった。

CI は `docdag validate --immutable-since` で、確定済み（`accepted` / `superseded`）ADR の書き換えを `immutable_violation` として報告する。vault の規約は、意味を変えない編集を「意図してレビューする例外」として認めているが、通常の PR はこの finding をゼロに保つ。[[000940]] の `supersedes` から `000877` を外す訂正は、[[000877]] の status と本文の Status 節の書き戻しを伴い、訂正の経緯が ADR として残らない。そこで現行のコードベース実態を再検証したうえで、有効な契約を新規 ADR として再確定する。

### 元の 3 ルールが必要になった障害背景（[[000877]] より）

2026-05-01〜02 のデプロイサイクルにおいて、独立した三つの障害が連鎖して CI とデプロイを停止させたことが原契機である。

1. **`CREATE OR REPLACE VIEW` の列順序変更（PG 42P16）**: `knowledge-sovereign/migrations/00018_add_knowledge_loop_visibility_lifecycle.sql` でビューに新列を追加した際、当初は既存列の間に挿入しようとした。PostgreSQL は `CREATE OR REPLACE VIEW` 実行時に SELECT リストの位置でカラム名を照合するため、位置ずれを既存列の改名とみなしてエラー `42P16: cannot change name of view column` で失敗し、マイグレーションコンテナが停止した。
2. **CI の `sparse-checkout` 欠落**: 当時 `alt-backend` のテストがリポジトリルート起点で共有ディレクトリ（`proto/`）を読み込んでいた一方、CI ワークフローの `sparse-checkout` が `alt-backend` のみをチェックアウトしていたため、ローカルでは通るのに CI 上で `go test ./...` が失敗した。
3. **`atlas.sum` の `.gitignore` 除外**: 当時 `migrations-atlas/migrations/atlas.sum` がルート `.gitignore` に記載され、`rag-migration-atlas` も独自の `.gitignore` で `migrations/atlas.sum` を除外していた。migrator コンテナは `/migrations` を `:ro`（read-only）でバインドマウントするため、チェックアウト時に `atlas.sum` が存在しないとコンテナ内で `atlas migrate hash` による生成もできず、`read-only file system` でマイグレーションが失敗した。

## Decision

View 列順序・`sparse-checkout`・`atlas.sum` 追跡の三つの CI/マイグレーション不変ルールを現行契約として再確定する。

### Rule 1: `CREATE OR REPLACE VIEW` に新列を追加するときは SELECT リスト末尾にのみ追加する

PostgreSQL の `CREATE OR REPLACE VIEW` は SELECT リストの位置で既存カラム名を照合するため、既存列の間に新列を割り込ませたり列順を並べ替えたりすると `42P16: cannot change name of view column` で失敗する。既存のビューを `CREATE OR REPLACE VIEW` で更新して列を追加する場合は、**常に SELECT リストの末尾に追加する**。論理的な表示順や並び替えが必要な場合は、アプリケーション層または別の新規ビューで対処し、置換ビューで既存列の位置を変更しない。

- **現行の適用箇所**: `migrations-atlas/migrations/20250812001200_create_integrity_check.sql:159`（`migration_dashboard`）、`recap-migration-atlas/migrations/20260131000000_add_evening_pulse_tables.sql:120,138,156`（`pulse_latest_generations` / `pulse_quality_stats` / `pulse_syndication_stats`）をはじめとする各サービスの SQL マイグレーション全般。
- **現行の検証手段**: `CREATE OR REPLACE VIEW` の列順のみを静的検査する専用 lint は存在しないが、`.github/workflows/backend-go.yaml:131`（`alt-backend/app/test_utils/pgtest/pgtest.go:201-250`）および `.github/workflows/knowledge-sovereign.yaml:77`（`knowledge-sovereign/app/test_utils/pgtest/pgtest.go:190-239`）が実 PostgreSQL に対して全 Atlas マイグレーションを先頭から適用するため、42P16 違反は統合テストで検出される。

### Rule 2: CI の `sparse-checkout` には参照するすべてのディレクトリを含める

GitHub Actions でサービス単体のテストやビルドを実行する際、`actions/checkout` の `sparse-checkout` には、コードやテストがリポジトリルート起点で参照するすべてのディレクトリ（`compose`、`observability`、`migrations-atlas`、`e2e/fixtures`、`kratos`、`scripts`、`docs/features/*` 等）を明示的に列挙しなければならない。

- **現行の強制箇所**:
  - `.github/workflows/backend-go.yaml:77-80`（`alt-backend`, `observability`, `compose`）— `alt-backend/app/orchestrator/gateway/admin_metrics_gateway/allowlist_test.go:251`（`TestAllowlist_AvailabilityJobsMatchPrometheusScrapeConfig`）および `alt-backend/app/config/compose_image_proxy_wiring_test.go:131`（`TestComposeAltBackendImageProxyIsExplicitlyWired`）の参照先を供給し、不在時は fail する設計でガードしている。
  - `.github/workflows/backend-go.yaml:107-110`（`alt-backend`, `migrations-atlas`, `e2e/fixtures`）— `pgtest` 統合テスト用のマイグレーション履歴と DB 初期化フィクスチャを供給する。
  - `.github/workflows/knowledge-sovereign.yaml:45-47`（`knowledge-sovereign`, `docs/features/knowledge-loop`）。
  - `.github/workflows/altctl-go.yaml:35-39`（`altctl`, `compose`, `kratos`, `pki-agent/scripts`）。
  - `.github/workflows/news-creator.yml:38-40`（`news-creator`, `compose`）、`.github/workflows/recap-subworker.yml:38-40`（`recap-subworker`, `compose`）、`.github/workflows/proto-contract.yaml:667-672`（`recap-worker`, `compose`, `scripts`, `recap-migration-atlas`）。

### Rule 3: migrator の `atlas.sum` は必ず git 追跡対象にする

本番および統合テストの Atlas migrator コンテナは `/migrations` を read-only（`:ro`）でバインドマウントして動作するため、実行時に `atlas.sum` を自動生成できない。すべての migrator において `atlas.sum` は **git 追跡対象（コミット済み）** でなければならず、ルート `.gitignore` および各サービス配下の `.gitignore` に `atlas.sum` を追加してはならない。マイグレーション SQL を追加・変更した際は、ローカルで `atlas migrate hash`（または `Makefile` のハッシュ再生成ターゲット）を実行し、更新された `atlas.sum` を同時にコミットする。

- **現行の強制箇所**:
  - git 追跡状況（`git ls-files "*atlas.sum*"`）: `acolyte-migration-atlas/migrations/atlas.sum`、`knowledge-sovereign/migrations/atlas.sum`、`migrations-atlas/migrations/atlas.sum`、`pre-processor-migration-atlas/migrations/atlas.sum`、`rag-migration-atlas/migrations/atlas.sum`、`recap-migration-atlas/migrations/atlas.sum` の全 6 migrator で追跡済み。
  - `.gitignore`（ルート）に `atlas.sum` の除外指定はなく、`rag-migration-atlas/.gitignore` も削除済みのまま再作成されていない。
  - `:ro` バインドマウント箇所: `compose/core.yaml:938`（`migrations-atlas/migrations`）、`compose/rag.yaml:93`（`rag-migration-atlas/migrations`）、`compose/sovereign.yaml:88`（`knowledge-sovereign/migrations`）、`compose/recap.yaml:94`（`recap-migration-atlas/migrations`）、`compose/acolyte.yaml:98`（`acolyte-migration-atlas/migrations`）、および統合テストの `alt-backend/app/test_utils/pgtest/pgtest.go:214`・`knowledge-sovereign/app/test_utils/pgtest/pgtest.go:203`。
  - ハッシュ再生成の導線: `Makefile:125-131,147-154,167-176`、`knowledge-sovereign/docker/scripts/hash.sh:28`、`pre-processor-migration-atlas/docker/scripts/hash.sh:33`。

### 引き継がない事項

[[000877]] に含まれていた以下の事項は、現行コードベースで対象が廃止・置換済みであるため本 ADR には引き継がない。

1. **`knowledge_loop_entries_public` ビュー固有の修正（[[000877]] Context バグ 1・Rule 1 修正記述）**: `knowledge-sovereign/migrations/00018_add_knowledge_loop_visibility_lifecycle.sql:57` で対処された `knowledge_loop_entries_public` ビューは、[[000940]] に伴う `knowledge-sovereign/migrations/00028_drop_knowledge_loop_projections.sql:17`（`DROP VIEW IF EXISTS knowledge_loop_entries_public;`）で削除済みである。Rule 1 の一般原則のみを引き継ぐ。また、[[000859]] で言及された Knowledge Loop 向けのビュー静的スキャンテスト（`invariants_canonical_test.go`）も現存しない。
2. **`backend-go.yaml` の `proto/` sparse-checkout と `TestTransitionPolicyConformance`（[[000877]] Context バグ 2・Rule 2 修正記述）**: `alt-backend/app/handler/knowledge_loop/transition_policy_test.go` および `proto/alt/knowledge/loop/v1/loop_transition_policy.json` は Knowledge Loop retire により削除済みであり、現在の `.github/workflows/backend-go.yaml:77-80` の `sparse-checkout` に `proto` は含まれていない（現在は `observability` / `compose` / `migrations-atlas` / `e2e/fixtures` を指定している）。Rule 2 の一般原則のみを引き継ぐ。
3. **E2E hurl テスト（`22-surface-planner-cron`）の副次バグ修正（[[000877]] Context 末尾）**: `e2e/hurl/` スイート自体が Playwright へ移行済み（`.github/workflows/e2e-playwright.yml:3`、`e2e/_lib/reclaim-network-pool.test.sh:20`）であり、当該 hurl テストは存在しない（なお `ListKnowledgeEvents` RPC 自体は `knowledge-sovereign/app/handler/rpc_events.go:29` に現存する）。
4. **[[000877]] の `depends-on` 対象 ADR と staging compose の高速 tick 調整**: [[000877]] の `depends-on` に列挙されていた 6 件（`000853`, `000859`, `000861`, `000873`, `000874`, `000876`）はいずれも `status: superseded` であり、再確定する 3 ルールはいずれもそれらを前提としないため `depends-on` は引き継がない。`compose/compose.staging.yaml:377-380` の projector tick 設定も Trail/Home 向けに更新済みであるため引き継がない。

### 検討した代替案と却下理由

1. **[[000940]] の `supersedes` リストと [[000877]] の本文を直接編集して復元する** — 却下。`docdag validate --immutable-since` が `immutable_violation` を出す。vault の規約は意味を変えない編集を意図してレビューする例外として認めており、この訂正はその例外に当たりうる。それでも例外として通すと、訂正の経緯が ADR として残らず、通常の PR で finding をゼロに保つ運用を一度崩すことになる。訂正そのものを決定として記録できる新規 ADR を選んだ。
2. **誤分類のまま放置する** — 却下。依然として有効で CI/デプロイを直接守っている 3 つの不変ルールが `docdag query --binding` および編集前 ADR ブリーフから脱落したままになり、再発防止の強制力を失う。
3. **[[000877]] と [[000895]] を単一の ADR にまとめて再確定する** — 却下。両者は主題（CI/マイグレーション基盤規約 vs. Inoreader トークン・サイレント停止検知）も影響サービスも全く異なり、1 本に混ぜると `affected_services` と `adr-preflight` の粒度が崩れる（[[000895]] は [[001012]] で個別に扱う）。

## Consequences

### Pros

- 三つの不変ルールが `accepted` かつ binding な現行契約として DocDag グラフに復帰し、`docdag query --binding` および `adr-preflight` の編集前ブリーフに再掲される。
- Knowledge Loop / Hurl 時代に固有だった無効な記述を「引き継がない事項」として分離し、現行コードベースのパスと一致した検証可能な契約になる。
- append-only 規約を破らずに履歴と現行契約の整合性を回復できる。

### Cons / Tradeoffs

- 誤った `supersedes` 辺（[[000940]] → [[000877]]）自体は append-only 規約上グラフ内に残存する。
- `docdag resolve 000877` を実行すると、[[000940]] と [[001011]] の両方が返される。
- 3 ルールに関する記述が [[000877]] と本 ADR の 2 ファイルに重複して存在する。
- `atlas.sum` の手動更新コストおよび `CREATE OR REPLACE VIEW` 列順序の専用静的 lint 不在（現状は `pgtest` 統合テストでの間接検出に依存）は引き続き残る。
