# ADR-000975: Recap 一示唆カード実験を baseline 付き時系列観測として再定義し、専用 interaction イベントで判定する

## Status

Proposed

本 ADR は [[000971]] を完全置換する。[[000971]] の「4サイクル ≈ 12日」「EmitTrailOutcome と同じ計測」「形式仮説の因果採択」は実装根拠にしない。

## Date

2026-08-11

## Affected Services

- recap-worker (Rust) — 一示唆カード出力
- alt-frontend-sv (TypeScript) — 着地 UI と計測
- knowledge-sovereign (Go) — interaction イベント受領
- alt-backend (Go) — 受信用 RPC / BFF

## Context

### 1. 形式仮説を最安で試す方向は維持する

運用者は 3 日窓 Recap を読んでいない。NNG の 1997 / 2008 研究は「長文より scan 可能な形式を先に試す」順序を質的に支持するが、個人ダイジェストの効果量や閾値の根拠にはならない。フル文書を即廃止せず並走する方針は維持する。

### 2. [[000971]] の実験設計が実装と方法論に合っていなかった

1. **生成頻度の誤解。** 3 日 Recap は `DailyCadence`（JST 02:00）の日次バッチであり、「3 日に1回」ではない。
2. **Trail 語彙汚染。** `EmitTrailOutcome` / `trail.act_outcome.v1` は taken branch 専用。Recap に流用すると語彙最小契約を破る。
3. **baseline なしの4点。** 交差も比較器もない単一アームでは「形式仮説の採択」を因果主張できない。正式な N-of-1 / SCED でもない。
4. **除外が事後裁量。** 異常週除外を事前に operational 定義していない。

### 3. 中間成果の機械読者化は別問題として残す

クラスタ / ジャンル / 重複排除済み文集合の planner 入力化は [[000977]] 側の候補生成で扱い、本 ADR は人間向け形式実験に閉じる。

## Decision

**Recap の人間向け出力を「フル文書 + 一示唆カード」の並走で検証する。実験は「事前登録付き単一ユーザー時系列プロダクト観測」と呼び、baseline 7 配達の後に intervention 14 配達を行い、専用イベント `recap.interaction.v1` だけで判定する。**

### D1. 配達単位と期間（事前固定）

- **配達** = その日の日次バッチが生成し `recap_ready` を enqueue した1回。
- **Baseline:** 現行 `/recap` フル文書着地のまま **7 配達**。
- **Intervention:** 一示唆カード先行着地 **14 配達**。
- 新奇性バッファ: intervention の先頭 **2 配達**は感度分析で除外可（事前宣言。主要解析からは外し、生データは残す）。
- 必要観測数: baseline 有効 ≥5、intervention 有効 ≥10。割ったら判定を延長し、延長上限はさらに 7 配達。

### D2. 出力と着地

- フル文書生成は継続（アーカイブ / grounding 資産）。
- 一示唆カード: 「最重要の示唆1つ（3文以内）＋未回収の問い1つ」。一画面に収まらない量を禁止。
- `recap_ready` の kind / payload / トリガー性は変更しない。変更するのはタップ後の着地のみ（カード先、フル文書リンク併置）。

### D3. 計測イベント（Trail 非汚染）

- 単一 event type: `recap.interaction.v1`
  - payload: `{ job_id, action: card_shown|doc_opened|doc_dwell|question_navigated, dwell_ms?, surface, client_event_id, occurred_at }`
- dwell 計時は Page Visibility の visible-time 手法だけを流用する。`EmitTrailOutcome` RPC と `trail.act_outcome.v1` は **禁止**。
- dedupe_key = `recap.interaction.v1:<job_id>:<action>:<client_event_id>`
- retention: 実験比較のため **21 日超**を保証する（hot 7日面へ落とさない。sovereign append log または明示 retention class）。
- 目的外: このイベントを Trail / Home projector の入力にしない（実験観測専用）。
- CDC RED: FE/BFF → backend → sovereign の append 契約を producer GREEN より先に置く。

### D4. 主要アウトカムと判定規則（事前固定）

- **主要指標（1つ）:** 通知経由でカードに接触した配達のうち、visible dwell ≥30s を伴う文書遷移率。
- 判定:
  1. baseline / intervention とも接触ゼロ → 上流（通知・生活動線）再診断。[[000974]] のバッジ効果と合わせて見る。
  2. 接触あり、かつ intervention の主要指標が baseline に対し実質改善しない → **形式を暫定第一候補**とする。フル文書は生成継続し UI 上はアーカイブ格下げを次 ADR で設計する。「因果採択確定」とは書かない。
  3. intervention で meaningful dwell 付き文書遷移が安定して残る → 形式単独仮説を棄却し、構造仮説の検証 ADR を起こす。
- 補助指標（判定をひっくり返さない）: 問いからの検索 / Augur 遷移、カード表示回数、文書遷移の有無。

### D5. 除外・欠測（事前リスト）

除外候補（暦で事前宣言）: 渡航日、終日オフライン、意図的な通知無効日。  
除外理由と日付を実験ログに残す。除外後に D1 の下限を割ったら延長規則を適用し、なお不足なら「判定不能」で終了する（都合の良い部分採択を禁止）。

### 検討した代替案と却下理由

**(a) [[000971]] の4サイクル因果採択を維持 — 却下。**  
実装頻度と方法論の両方に反する。

**(b) Trail act_outcome の再利用 — 却下。**  
語彙最小・branch closure 契約を壊す。

**(c) フル文書即廃止 — 却下。**  
不可逆に近く、形式仮説未検証。

**(d) 通知本文に示唆を載せる — 却下。**  
トリガー原則変更と変数増加を同時に起こす。rich preview は [[000977]] でも初期出荷外。

## Consequences

### Pros

- 実験単位が日次実装と一致し、n の定義が壊れていない。
- Trail 契約を汚染せずに計測できる。
- どの結果でも次の一手（暫定形式 / 構造仮説 / 上流再診断 / 判定不能）が事前に決まる。

### Cons / Tradeoffs

- baseline + intervention で最短約3週間かかり、[[000971]] より長い。
- 単一ユーザーのため生活ノイズは残る。統計的検定は主張しない。
- カード品質（示唆内容）と形式がなお交絡しうる。判定文言を「暫定第一候補」に落とすことで過剰主張を抑える。
- recap-worker 最終段が一時的に二形態になる。
