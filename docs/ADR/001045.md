# ADR-001045: 変更差分リントゲート（lint-changed）を Stop フックと単一バイナリへ統合し、未検査の lint 違反のまま終了することを機械的に防ぐ

## Status

Accepted

## Date

2026-11-28

## Affected Services

- `scripts/altharness` (Go 単一バイナリ) — `lint-changed` サブコマンド追加、`agy-hook stop` への統合、`post-edit` フォーマッタのプロジェクトルート解決修正、`lang go` のピン留め一致 `PATH` ツール再利用と明示的オフラインオプション追加
- `.agents/hooks.json`, `.claude/settings.json`, `.codex/hooks.json`, `.agents/rules/rule-ledger.md` — 3 環境（Antigravity / Claude Code / Codex）の Stop フック配線と規則台帳 `R-46` 登録

## Context

PR #418 の CI 実行時、97 件以上のチェックが通過した一方で `Backend Go Tests / quality`（`./scripts/lint/run.sh alt-backend/app` → `golangci-lint`）のみが、新規テストファイル内の未使用ヘルパ型・メソッド 3 件（`unused`）により失敗した。

このすり抜けをハーネス構造の観点で分析した結果、以下の 3 点が重なっていたことが判明した。

1. **エージェント終了時の Stop フックに差分リント検査が存在しない**:
   - `scripts/altharness/internal/guards/agy.go` の `runAgyStop` は `check_layers.sh --changed` と `docdag validate` のみを検証しており、変更された Go / Python / TypeScript・Svelte ファイルに対する静的リント（`golangci-lint` / `ruff` / `biome`）を強制していなかった。
   - `.claude/settings.json` および `.codex/hooks.json` にも変更差分リントの Stop フックが未配線であり、完了前リントは `AGENTS.md` の文章ルール頼みになっていた。
2. **`agy-hook post-edit` のフォーマッタがリポジトリルートを作業ディレクトリにしていた**:
   - `defaultAgyFormatFile` が `.py`・`.ts`/`.svelte` に対して `cmd.Dir = repoRoot` のまま `uv run --no-sync ruff format` や `npx --no-install biome format` を呼んでいたため、`pyproject.toml` や `package.json` がサブディレクトリ（`news-creator/app`, `alt-frontend-sv` 等）にあるファイルで自動整形が空振りしていた。
3. **オフライン／サンドボックス環境で `./scripts/lint/run.sh <go-target>` がローカルのピン留め一致バイナリを使えない**:
   - `scripts/altharness/internal/lang/gosh.go` の `ensureGoTool` はキャッシュ `~/.cache/alt-lint/<goVer>/` にバイナリが無い場合、ローカル `PATH` に同一ピン留めバージョン（`v2.14.0`）の `golangci-lint` が既に存在しても即座にネットワーク経由の `go install` を試みて失敗する。また `govulncheck` がオンライン DB 照会を必須とするため、ネットワーク遮断サンドボックスでは Go 品質ゲート全体が完走できない。

## Decision

[[001028]] の純 Go 標準ライブラリ単一バイナリ方針、[[001032]] の 3 環境パリティ方針、および [[001039]] の強制ラダー（`ARCH → CHECK → VERIFY → LEDGER`）と Proven-to-Fail 原則に従い、文章ルールの追記ではなく **決定論的な `CHECK` ゲート** として以下を導入する。

### 強制ラダー選定根拠（Higher-Rung Rejection）

- **`ARCH` を使わなかった理由**: Go コンパイラは `*_test.go` 内の未使用 unexported 型・メソッドやスタイル／品質 lint 規則をコンパイルエラーにせず、Python・TypeScript の静的 lint 違反も型境界だけでは排除できないため、構造制約（`ARCH`）単独では防げない。
- **採用段: `CHECK`（Stop フック＋単一バイナリ差分リントゲート）**: エージェントがターンを終了する境界で変更モジュールのみを数秒で静的検査し、違反があれば終了を拒否して修正ループへ戻す。

### 具体的な変更

1. **`alt-harness lint-changed` サブコマンドの新設（`scripts/altharness/internal/guards/lint_changed.go`）**:
   - `git status --porcelain` から変更・未追跡ファイル（削除済み・`stopped-using-k8s/`・生成ファイル `gen/` / `*.pb.go` を除外）を収集し、言語ごとの所有プロジェクトルート単位で高速リントを実行する。
   - **Go**: 最寄りの `go.mod` 配下の変更パッケージディレクトリのみに対し、リポジトリルートの `.golangci.yml` を使って `golangci-lint run --config <root>/.golangci.yml ./<pkg>...` を実行する（キャッシュ済みピン留め版 → `PATH` の順で解決し、ツール欠落時は fail-closed で失敗させる）。`internal/lint/run.go` でルート `.golangci.yml` 対象外と定義されている `scripts/altharness` 自身については、`go vet` と `golangci-lint run --no-config --default=none --enable=unused,ineffassign --new-from-rev=HEAD` で新規違反を検知する。
   - **Python**: 最寄りの `pyproject.toml` を作業ディレクトリにして `uv run --no-sync ruff check` と `ruff format --check` を変更 `.py` ファイルのみに実行する。
   - **TypeScript / Svelte**: 最寄りの `package.json` を作業ディレクトリにして `node_modules/.bin/biome check`（または `bunx biome check`）を変更 `.ts/.tsx/.svelte` ファイルのみに実行する。
   - `--hook` モード（Claude Code / Codex の Stop フック向け）では、標準入力の `stop_hook_active: true` 時は無限ループ防止のため許可（exit 0）し、通常終了時に違反があれば詳細を stderr へ出力して exit 2 でブロックする。
2. **3 環境の Stop フック配線と `selfcheck` 検証**:
   - `agy-hook stop`（`scripts/altharness/internal/guards/agy.go`）に `agyRunChangedLintFn` を組み込み、層検査・`docdag validate` の直後に `lint-changed` を実行し、失敗時は `{"decision":"continue","reason":...}` を返す。`.agents/hooks.json` の Stop タイムアウトを 60 秒へ余裕を持たせる。
   - `.claude/settings.json` および `.codex/hooks.json` に `Stop` フックとして `alt-harness lint-changed --hook` を配線する。
   - `selfcheck` の既知コマンド一覧に `lint-changed` を追加し、`.agents/rules/rule-ledger.md` に `R-46` として登録する（`max_judgment_rules` は増やさない）。
3. **`defaultAgyFormatFile` のプロジェクトルート解決修正**:
   - `.go` は `gofmt -s -w`、`.py` は最寄り `pyproject.toml` ディレクトリで `uv run --no-sync ruff format --quiet`、`.ts/.tsx/.svelte` は最寄り `package.json` ディレクトリでローカル `node_modules/.bin/biome`（フォールバック `npx --no-install biome`）を実行するよう修正する。
4. **`ensureGoTool` のピン留め一致 `PATH` 再利用と明示的オフラインオプション（`scripts/altharness/internal/lang/gosh.go`）**:
   - キャッシュ未命中時、`PATH` 上の同名バイナリのバージョン出力がピン留め版（例: `golangci-lint` `v2.14.0`）と**厳密一致する場合のみ**再利用する。バージョン不一致時は引き続き拒否し、未ピン留めドリフトを許さない。
   - オフライン環境向けの明示的オプトインとして `ALT_LINT_SKIP_GOVULNCHECK=1` 指定時のみ `govulncheck` を `SKIP (ALT_LINT_SKIP_GOVULNCHECK=1)` として明示ログ出力のうえ通過可能にする（既定は従来どおり必須、CI では一切設定しない）。

### 検討した代替案

- **Stop フックで `./scripts/lint/run.sh <target>`（全パッケージ＋`govulncheck`）を毎回実行する**: 退けた。`alt-backend/app` 全 367 パッケージ走査とオンライン DB 照会は 1〜2 分を要し、フックタイムアウトおよびオフラインサンドボックス制約に抵触するため。変更パッケージ限定なら 1〜3 秒で同一 `.golangci.yml` の全ルールを検査できる。
- **`AGENTS.md` に「`golangci-lint` を必ず実行すること」と文章注意書きを追加する**: 退けた。文章ルールは既に存在していたにもかかわらずすり抜けた実績があり、[[001039]] の `ARCH → CHECK → VERIFY → LEDGER` 原則に反するため。

## Consequences

### Pros

- 未使用シンボル（`unused`）・`ruff`・`biome` 違反を残したままエージェントが作業完了を宣言することを、3 環境（Antigravity / Claude Code / Codex）の Stop 境界で機械的に阻止できる。
- 変更パッケージ限定実行により、Stop フックのオーバーヘッドを数秒以内に抑えつつ CI と同一の `.golangci.yml` ルールを適用できる。
- `post-edit` フォーマッタのサブディレクトリ解決バグが解消し、Python / Svelte・TS 編集直後のフォーマット漏れが減る。
- オフラインサンドボックスでも、ピン留め一致のローカル `golangci-lint` を使って Go 品質ゲートを再現できる。

### Cons / Tradeoffs

- 変更ファイルとは別パッケージに影響するクロス-パッケージ破壊（例: 別パッケージの未使用シンボル化）は変更パッケージ限定チェックだけでは検知できないため、最終確認としての `./scripts/lint/run.sh <target>` や CI 全量走査は引き続き必要である。
- Stop フックの実行時間が最大数秒増える（クリーン作業ツリー時は `git status` のみで即時返却するため影響はほぼゼロ）。
