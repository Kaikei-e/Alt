# ADR-000950: BFF の依存クラス別 circuit breaker と MarkAsRead 後の未読投影キャッシュ invalidation を導入する

## Status

Accepted

## Date

2026-07-24

## Affected Services

- alt-butterfly-facade (Go)
- alt-frontend-sv (TypeScript / SvelteKit)

## Context

Web UI の既読（Connect `FeedService/MarkAsRead`）が間欠的に「効かない」報告があった。
12h 観測では:

- plecto 上 MarkAsRead **108×200 / 13×503 (~11%)**。503 は BFF の
  `Service temporarily unavailable due to circuit breaker`（1–5ms 即拒否）。
  backend には未到達。
- 到達した MarkAsRead は backend / ClickHouse とも **ERROR 0**、`read_status` 書き込み成功。
- BFF はプロセス全体で **単一** circuit breaker を共有していたため、
  `ArticleService/FetchArticleContent` 等の外部 I/O 失敗が既読 RPC を巻き込んでいた。
- [[000582]] で `GetUnreadFeeds` / `GetAllFeeds` を TTL 10s、`GetUnreadCount` を 15s
  キャッシュしたが、mutation 成功後の **active invalidation は無く**、
  200 直後の再取得で未読が戻る read-your-writes 破れがあり得た。
- [[000624]] / PM-2026-019 で FE の広い invalidate cascade はレイテンシ悪化のため削減済み。
  今回も FE cascade 復活は採用しない。

## Decision

1. **依存クラス別 circuit breaker（opt-in、mutation / projection 分離）**
   - **Critical mutation**: Critical Feed Mutation（`MarkAsRead` / `MarkAsUnread`）専用 breaker。
   - **Unread projection**: Unread Projection Read（`GetUnreadFeeds` / `GetUnreadCount` / `GetAllFeeds`）専用 breaker。
   - **Non-critical（default）**: 未分類を含むその他すべて。
   - Article fetch で non-critical が open しても mutation / projection は通す。
   - GetAllFeeds 嵐で projection が open しても MarkAsRead は通す（共有 critical バケットの再発を避ける）。
   - 注: これは「依存クラス別 bulkhead」であり、RPC 単位の完全な per-dependency CB ではない。

2. **BFF write-side active invalidation**
   - Critical Feed Mutation が backend **2xx** のあと、当該 user の
     Unread Projection endpoints を bodyHash 横断で削除（`DeleteByUserAndEndpoints`）。
   - 同時に user cache epoch を bump し、in-flight の GetUnreadFeeds が
     `SetIfEpoch` で stale 結果を再格納しないようにする。
   - TTL は [[000582]] の safety net として維持。FE の TanStack unread cascade は戻さない
     （[[000624]] 維持）。

3. **FE 失敗 UX（一覧系のみ）**
   - MarkAsRead 失敗時はカードを残し、ユーザー向けエラーを表示。自動リトライなし。
   - スワイプ deferred commit はスコープ外。

### Rejected alternatives

| 案 | 却下理由 |
|----|----------|
| mutation だけ CB 対象外 | 未読一覧も同じ CB で死ぬと RYW 検証・一覧自体が落ちる |
| mutation 時にキャッシュ全 `Clear()` | 他ユーザー／無関係エントリまで巻き込み、再取得嵐に近い |
| FE invalidate cascade 復活 | PM-2019 / [[000624]] の再発リスク |

## Consequences

### Pros

- 外部記事 fetch 障害が既読を巻き込まない。
- MarkAsRead 成功直後の未読一覧が BFF キャッシュ由来で戻らない。
- 失敗がユーザーに見え、カードが消えたままサーバ未反映、という齟齬を減らせる。

### Cons / Tradeoffs

- mutation breaker が open すると既読だけ 503（projection は別予算）。
- projection breaker が open すると未読一覧だけ 503（MarkAsRead は通る）。
- 未分類 endpoint は non-critical のため、新規の「本当は critical」な RPC は明示登録が必要。
- mutation ごとの prefix 走査はキャッシュサイズに比例（現状単一ユーザ・小規模 LRU では許容）。
- non-critical は依然メガバケット（FetchArticleContent と Stream が共有）。完全な per-RPC CB ではない。
