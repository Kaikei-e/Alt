# ADR-000956: alt-backend の E2E を Hurl から Playwright へ全面移行し、網羅性と CI 速度を同時に引き上げる

## Status

Accepted

## Date

2026-08-05

## Context

[[000778]] は [[000766]] の共通 dispatch 規約に沿って `e2e/hurl/alt-backend/`
を第 5 増分として追加した。以後 25 本の `.hurl` (1,119 行) が alt-backend の
REST / Connect-RPC 契約を守ってきた。その判断は当時正しかった。ここで論点に
なるのは Hurl そのものではなく、**alt-backend の表面積が Hurl の表現力を超えた**
という事実である。

移行の直接の動機は 3 つある。

### 1. 「存在すればよい」アサーションが 9 箇所に堆積していた

Hurl は 1 行 1 JSONPath でしか語れない。その結果、返り値の形を主張したい場面が
軒並み `jsonpath "$" exists` に退行していた。これは `null` でも `[]` でも `{}` でも
**エラーエンベロープでも通る**。`25-feeds-stats.hurl` の 3 エンドポイントは、
統計値がすべて 0 になっても、`{}` を返すようになっても緑だった。

### 2. ファイル間の暗黙の順序依存が並列化の天井になっていた

`10-register` → `11-list` → `13-delete` は同じ行を共有する 1 本の鎖であり、
`13` は `$[0].id` — その時たまたま先頭にあった feed — を削除していた。
`--jobs 4` がファイル単位でしか効かないのはこの鎖のためで、テスト単位の並列化も
シャーディングも構造的に不可能だった。

### 3. ミドルウェア設定という層が丸ごと無検証だった

`routes.go` は CSP / HSTS / nosniff、2MB body limit とその `/stream` skipper、
gzip の `/metrics` 除外、CORS allow-headers、そして DoS protection
(100 req/min・burst 200・**block 5 分**) を手で組んでいる。いずれも
「消しても機能は動くが、消えたことに誰も気づかない」種類の設定であり、
Hurl suite はそのどれ 1 つにも触れていなかった。

なお alt-frontend-sv は既に Playwright を採用しており、
`e2e/playwright/alt-frontend-sv/run.sh` が [[000766]] の dispatch 規約を
Hurl から Playwright へ拡張済みである。本 ADR は新しい規約を作るのではなく、
**既にある 2 つ目の枠にもう 1 サービスを載せる**。

## Decision

**`e2e/hurl/alt-backend/` を削除し、`e2e/playwright/alt-backend/` に
API 専用 Playwright suite を新設する。** dispatch 契約
(`bash e2e/<framework>/<svc>/run.sh`) は変更しない。

### D1. ブラウザを起動しない Playwright

どの spec も `page` / `browser` / `context` を触らない。HTTP のみなので
Playwright はブラウザを一切起動せず、`PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` で
`node:22-bookworm-slim` (約 150MB) に載る。Playwright 公式イメージ (約 1.7GB) を
引かないことがこの suite の cold-start コストの大半を消す。

### D2. 隔離は teardown ではなく命名で行う

worker ごとに他が使わない URL prefix で RSS feed を 3 本 seed し、変更を伴う
テストは自分の行を先に登録する。アサーションは包含
(「自分の 3 URL がリストにある」) であり、基数 (「3 行以上ある」) ではない。
これにより `fullyParallel` が安全になり、Hurl suite が構造的に持てなかった
「テスト単位の並列化」が成立する。

### D3. worker ごとに `X-Real-IP` を分ける

alt-backend の DoS middleware は `trustForwardedHeaders=true` (常に nginx の
背後に置かれる前提) で client IP ごとに token bucket を持ち、**枯渇した IP を
5 分ブロックする**。6 worker が runner container の単一 source address を
共有すると、1 つの bucket を途中で枯らして suite 全体が 5 分の穴に落ちる。

これは limiter の回避ではなく **本番の再現**である。本番ではブラウザ 1 台ごとに
X-Real-IP が異なる。単一 bucket を共有していた側が非現実的だった。
limiter 自体は専用アドレスを使う `tests/rate-limit.spec.ts` で意図的に検証する。

### D4. レスポンスエンベロープは Zod スキーマで一括検証する

`jsonpath "$" exists` の代替として、封筒全体を 1 手で検証する。すべての
object schema は `passthrough()` — alt-backend が約束するフィールドへの契約であり、
追加を禁じるものではない。

### D5. Connect-RPC の登録を配線ゲートとして使う

`SetupConnectHandlers` が載せる 9 サービスのうち、Hurl が触れていたのは 1 つ。
新 suite は各サービスが **401** (auth interceptor が走った = handler が載っている)
を返すことを主張する。**404** (path が何にも解決しない = 登録されていない) との
区別が、CLAUDE.md rule 8 が言う「DI が配線を忘れた」と「意図的に無効」を
境界で見分ける唯一の手段である。

### D6. CI は build 1 回 + 4 shard + blob merge

images を build job で 1 度だけ焼いて artifact で配り、4 shard が load する。
各 shard は blob を出し、`merge-reports` が 1 つの HTML + JUnit に畳む。
`fullyParallel` によりシャードはファイル単位ではなくテスト単位で割れるため、
実測で 49 / 49 / 50 / 46 と均等に分かれる。

### D7. 既知バグは「現在の挙動」として pin し続ける

Hurl suite が記録していた既知バグ (deps-stub の route drift 3 件、
scraping-domains の GET/PATCH 不整合) は、理由のコメントごと移送した。
加えて移行中に発見した **augur 2 経路の認証欠落** も同じ形式で pin した
(下記 Consequences)。いずれも「あるべき挙動」ではなく「現在の挙動」を pin する。
修正が入ればテストが落ちる — それが意図した信号である。

## Consequences

### 得たもの

- **spec 25 本 / テスト約 207 件**。Hurl の 25 ファイル・約 120 リクエストから、
  同じ契約を保ったまま網羅面を拡張した。
- **新規に検証対象になった面**: CSRF の 2 つの拒否分岐と除外リスト、
  security headers 一式、2MB body limit とその `/stream` skipper、
  DoS rate limiting と per-IP スコープと whitelist bypass、
  Connect-RPC 9 サービス中 8 つの登録、`/v1/feeds/summarize/stream`
  (Hurl が明示的に除外していた)、`/v1/admin/scraping-domains/:id/refresh-robots`
  (アサーション皆無だった)、auth 境界の route group ごとの検証、
  cursor の追跡、ETag / `If-None-Match` の 304 分岐、OPML の round-trip。
- **失敗時の情報量**。status 不一致は body を添えて落ち、失敗テストは
  request/response の trace を残す。

### 初回 CI 実行が明らかにしたこと

本 suite の初回 CI で 211 件中 14 件が落ちた。**14 件すべてが「Hurl suite の
記述どおりに書いたアサーション」と「実際の API」の食い違い**であり、
インフラ（build → 4 shard → blob merge）は初回から通っている。

落ちた 14 件は「テストのバグ」として直したのではなく、**API の実挙動を
pin し直した**。特に次の 2 つは Hurl では原理的に見えなかった:

1. **cursor の封筒が 3 エンドポイントで揃っていない。** `21-feeds-fetch-cursor.hurl`
   の冒頭は「3 つは同じ封筒を共有する」と書いているが、`/fetch/cursor` は
   `{data, has_more, next_cursor?}`、`/fetch/viewed/cursor` と
   `/fetch/favorites/cursor` は `has_more` を持たない。Hurl が後者 2 つに
   `jsonpath "$" exists` しか書いていなかったため、差は不可視だった。

2. **pagination 検証も揃っていない。** ValidationMiddleware は
   `strings.Contains(path, "/feeds/fetch/cursor")` で照合するので
   `/feeds/fetch/viewed/cursor` にはマッチしない。unread だけが上限 1000 で
   拒否され、他 2 つは 100 に暗黙 clamp して 200 を返す。

そのほか、`DELETE /v1/rss-feed-link/:id` が `user_feed_subscriptions` を
削除する一方で `/list` はユーザ非スコープの全件であること（CRUD の対に
見えて対ではない）、malformed UUID / 空 `feed_url` / 非 OPML アップロードが
いずれも 400 ではなく 500 になること、などを pin した。一覧は
`e2e/playwright/alt-backend/README.md` の「Found by this suite」にある。

### 発見した問題（本 PR では修正しない）

**`GET /v1/rag/context` と `POST /sse/v1/rag/answer` に認証がない。**
`RegisterAugurRoutes(e, v1, container)` は `g.GET("/rag/context", …)` を素の
`/v1` group に、`e.POST("/sse/v1/rag/answer", …)` を root の Echo instance に
登録しており、`routes.go` の他のすべての `/v1` group と違って
`authMiddleware.RequireAuth()` を通していない。JWT なし・tenant scope なしで
RAG orchestrator に到達する。

Hurl suite は両方に JWT を付けて呼んでおり negative を撮っていなかったため、
これは今まで見えていなかった。**生きているエンドポイントの利用者を変えるのは
プロダクトの判断であり、テスト suite の判断ではない**ので、本 ADR は
現状を `tests/augur-rag.spec.ts` に pin するに留める。`RequireAuth` 配下に
移した時点でその 2 テストが落ちる — その時に削除して
`tests/auth.spec.ts` の `PROTECTED_ROUTES` に移す。

### 失うもの・負債

- **Hurl と Playwright の 2 フレームワークが e2e/ に並存する。** 他 9 サービスは
  Hurl のままであり、`e2e/hurl/_lib/` (slice 描画・network pool 回収・PKI 発行) は
  両者が共有する。`_lib` は framework 非依存だがディレクトリ名がそう言っていない。
  他サービスを移す判断が出るまではこの非対称を許容する。
- **依存インストールが 2 コンテナに割れる。** staging network は
  `internal: true` で egress がないため、`npm ci` は default bridge の別
  コンテナで実行し bind mount 経由で workspace に置く。run.sh の中で最も
  説明を要する部分であり、コメントで理由を明記している。
- **`node_modules` が workspace に落ちる。** `e2e/.gitignore` に追加済み。

### 移行によって削除したもの

- `e2e/hurl/alt-backend/` (25 `.hurl` + README + run.sh)
- `e2e/fixtures/alt-backend/{register-feed-1,2,3}.json`, `sample-feeds.opml`
  — 新 suite は worker ごとに固有 URL を生成するため固定 fixture は使わない
- `e2e/hurl/alt-backend/run.sh` が生成していた `LOOP_TX_*` 18 変数
  — 参照していた `.hurl` は既に削除済みで、run.sh 側だけが残っていた
