# ADR-000977: Trail Pull-only に限定 Beacon 例外を追加し、関所通過 branch を local-day 予算付き trigger 通知で配送する

## Status

Proposed

本 ADR は [[000973]] を完全置換する。Trail 正準契約の改訂なしに Beacon を実装してはならない。本 ADR の Decision は core-concept への carve-out 追記と一体で成立する。[[000976]] の関所 green 前に Beacon を出荷しない。

## Date

2026-08-11

## Affected Services

- Trail 正準契約（core-concept / implementation-plan / wiki）
- knowledge-sovereign (Go)
- alt-data-hub (Go)
- alt-backend (Go)
- alt-frontend-sv (TypeScript)
- alt-harvester (Go) — Echo が同じ budget を使う

## Context

### 1. [[000973]] が正本と衝突していた

`knowledge-trail-core-concept.md` §C5 は配送を navigation load + 明示 refresh に限定し、§G は「配信層そのものを持たない」と書く。Web Push は SSE による画面ライブ更新ではないが、Trail branch の自発配送層であり、黙って許容できない。ユーザ選択により **品質ゲート済み・予算付き・trigger-only の限定例外**を正本へ追加する。

### 2. 合算予算が未決だった

[[000970]] / [[000974]] の Echo（朝夕最大2）と Beacon（最大1）を足すと local day 最大3通になる。ユーザはこの合算を明示的に採択した。予算 owner と timezone、予算超過時の端末結果を固定しないと、遅延再試行が生活時間外に漏れる。

### 3. 実装ギャップ

- `AppendKnowledgeEventIfNew` は内部 commit 済みで、後続 outbox INSERT は dual-write になる。
- data-hub fan-out は未知 kind を `ELSE FALSE` で沈黙させる。
- 現行 `corroborated` はタグ数であり、[[000976]] の grounded confidence と同じではない。
- rich preview はロック画面原則の変更であり、初期仮説としては時期尚早。

## Decision

**Trail 正準の Pull-only に、opt-in・[[000976]] 関所通過・trigger-only・画面自動更新なしの Web Push Beacon だけを限定例外として追加する。`trail_branch_proposed` を user-local calendar day あたり最大1件配送し、Echo と合わせて同日最大3件とする。予算は data-hub が atomic に所有する。rich preview は初期出荷しない。**

### D1. 正準契約 carve-out（必須）

`knowledge-trail-core-concept.md` を次の趣旨で更新する（本文は同 commit で反映）。

- §C5 / §G: SSE / WebSocket / 自発ポーリングによる **画面更新**は引き続き禁止。
- 例外: `trail_branch_proposed` Web Push は、明示 opt-in・関所通過・trigger payload・patch-exit 着地・予算内、に限り許可する。通知は Trail ページを自動更新しない。
- 原則11（patch-exit 少数精鋭）を維持。branch inbox は作らない。

### D2. 選抜ゲート（配送）

- [[000976]] の `confidence_basis_version = v2_source_grounded` かつ `confidence = corroborated`
- `relation_kind ∈ { contradiction, continuation }`（contradiction 優先）
- user-local day あたり業務事実 **最大1 branch**
- 候補なし / 関所不通過 / 予算超過は enqueue しない。沈黙は正常（分類カウンタ必須）
- contradiction が未実装の間は continuation のみでよいが、feature-state を loud に出す

### D3. Transactional outbox（sovereign）

- 新 API: `AppendBranchProposedAndNotify`（単一 Tx）
  1. `knowledge_events` + dedupe
  2. 選抜通過かつ appended のときだけ `notification_outbox`
  3. Commit
- relay: pre-processor 同型（batch 50 / lease / full-jitter / max 8 / TTL 24h / loud `notification_outbox_relay_enabled`）
- dedupe_key（業務事実）= `trail_branch:` + branch_key
- projector は outbox に触れない（reproject で再通知しない）
- CDC RED: sovereign → data-hub Enqueue（kind / budget fields）を GREEN より先

### D4. 通知予算（data-hub が owner）

- clock: **user-local calendar day**（TZ は profile / JWT。欠落は fail-closed）
- global cap: **3** / local day
- kind quota: `recall_echo_ready` ≤2、`trail_branch_proposed` ≤1
- Enqueue トランザクション内で kind quota と global cap を原子的に判定・消費する
- 超過時の応答: terminal **`SUPPRESSED_BUDGET`**（再試行しない。遅延再送で枠をまたがない）
- Echo（[[000974]]）も同一 API を使う。Beacon 実装前に budget API を先行させてもよい

### D5. payload・prefs・UI

- 既定 payload: kind / url（patch-exit）/ count のみ。定型 notificationCopy。
- **rich preview は初期出荷しない**（オプトイン UI も作らない）。価値計測後の別 ADR。
- `push_subscriptions.trail_branch_proposed BOOLEAN NOT NULL DEFAULT FALSE`（明示 opt-in）
- proto field 番号計画（両 proto 同時）:
  - 5 = `recall_echo_ready`（[[000974]]）
  - 6 = `trail_branch_proposed`
- fan-out CASE を同じ変更で更新。未知 kind は **エラーまたは明示 reject**（silent zero 禁止）
- notificationclick 着地: 該当記事の patch-exit（`GetItemBranches`）

### D6. 監視

- planner カウンタ: 候補数 / emit / 予算超過 / 関所不通過 / 候補なし / gate_unavailable
- push 側: `SUPPRESSED_BUDGET` / sent / dead / expired
- ゼロ配送日が「候補なし・関所不通過・予算超過」に分類されている限り正常

### D7. 誤差還流

- 通知経由の dismiss_reason / dwell を [[000976]] LLM 段のプロンプト文脈に正例・反例として注入する経路を、関所 green 後の follow-up PR で配線する（本 ADR の出荷ブロッカーにはしないが、CDC 対象）。

### D8. 実装 wave

1. Trail core-concept / wiki carve-out
2. data-hub budget schema + Enqueue 契約 CDC RED（Echo/Beacon 共通）
3. sovereign AppendBranchProposedAndNotify + outbox/relay
4. prefs/proto/fan-out（field 5/6）
5. E2E: opt-in → 関所通過 branch 1件 → patch-exit。予算3で4通目が SUPPRESSED_BUDGET

### 検討した代替案と却下理由

**(a) Pull-only を維持し Beacon 廃止 — 却下。** ユーザは限定例外を選択。  
**(b) Home 通知として再分類 — 却下。** branch の why/evidence は Trail 成果物であり、patch-exit 着地と一体。  
**(c) rolling 24h 最大2 — 却下。** ユーザは local-day 最大3を選択。  
**(d) rich preview 初期 ON/トグル — 却下。** 原則変更を初期に持ち込まない。  
**(e) projector 発火 — 却下。** reproject 再発火。  
**(f) UTC day — 却下。** JST 境界ずれを避ける。

## Consequences

### Pros

- 正本と ADR の二重真が消える。
- Echo と Beacon の合算が atomic に制御される。
- 関所 + 予算 + opt-in の三重で通知許可を焼きにくい。
- silent fan-out zero と dual-write を設計段階で潰す。

### Cons / Tradeoffs

- local-day 最大3は割り込みとして多い日がありうる。D6 と設定 UI で観測・抑制する。
- TZ 欠落時 fail-closed は配送機会を落とす。
- rich preview なしではロック画面の情報量が薄い（意図的）。
- sovereign に relay 常駐責務が残る。
