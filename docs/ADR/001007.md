# ADR-001007: Tag Verse を Alt-Paper の instanced WebGL シーンに作り直し、tag cloud を stale-while-revalidate で返す

## Status

Accepted

## Date

2026-11-10

## Affected Services

- alt-frontend-sv: Tag Verse (`/feeds/tag-verse`) のシーン・ラベル・画面外枠・詳細パネルを作り直し、3D シーンを動的 import に分離
- alt-backend: `FetchTagCloudUsecase` のキャッシュを stale-while-revalidate + `singleflight` に変更（`cmd/backend` が読む面）

## Context

Tag Verse は記事タグを 3D 空間に配置するデスクトップ専用の画面で、[[000349]] で導入され、[[000351]] で WebGPU 化、[[000377]] / [[000385]] で性能対策を重ねてきた。2026-11 時点で次の問題が残っていた。

**デザイン言語の不一致。** 他の主要画面は Alt-Paper（紙色の背景・インクの文字色・セリフ見出し・細い罫線・ブラーやグローなし）に揃ったが（[[000674]]、[[000678]] ほか）、Tag Verse だけが黒背景・シアンとオレンジの発光・星空・ブルームの宇宙テーマのままだった。オーバーレイ文字は `text-white/30`（黒地で約 3.3:1）で、WCAG 1.4.3 の 4.5:1 を満たしていなかった。

**描画コスト。** コードを読んで確認した構造は次のとおり。

- タグ 300 個それぞれが独立した `TagAsteroid` コンポーネントで、メッシュ・`SphereGeometry`・`MeshStandardMaterial` をタグごとに持つ（ドローコール約 300）。色は 5 段階しかないのに、マテリアルは共有されていなかった。
- タグごとに `useTask` が 1 本、計 300 本が毎フレーム走る。Threlte の `useTask` は既定で `autoInvalidate: true` なので、`renderMode` が `on-demand` でも描画ループが止まらない。
- ラベルは `@threlte/extras` の `<HTML occlude={true}>` で、表示中のラベルごとに毎フレーム、シーン全体へのレイキャストが走る（前面のラベル約 160 本 × 300 メッシュ）。
- TSL の `RenderPipeline` + `BloomNode` が全画面ブルームを毎フレーム実行し、`dpr` は上限なし。
- `WebGPURenderer` の破棄順序に起因するクラッシュ回避コードが 3 箇所に残っていた（[[000350]]、[[000355]]、[[000372]]）。

**バンドル。** `+page.svelte` が `TagVerseScreen` を静的 import しており、three.js・`three/webgpu`・`three/tsl` を含むルートのエントリ chunk が 1.87 MB（gzip 504 KB）だった。モバイルで到着した場合も、`/home` へリダイレクトされる前にこれを丸ごと読み込んでいた。

**詳細パネルの通信。** `HUDArticlesTab` / `HUDRecapsTab` は `onMount` と `$effect` の両方でロードを呼ぶため、開くたびに同じ RPC が 2 本飛んでいた。非アクティブなタブはアンマウントされるので、タブを切り替えるたびに再取得も起きていた。

**バックエンドのコールドパス。** `FetchTagCloudUsecase` の結果はプロセス内メモリに 30 分キャッシュされる。[[000385]] のキャッシュウォーマーは、[[000954]] のバイナリ分割で harvester 側のプロセスに移ったため、`cmd/backend` のキャッシュに届かなくなり無効化されている。その結果、TTL が切れた後の最初の読み手が、alt-data-hub への 2 本の RPC（タグ集計と共起）とレイアウト計算を同期的に待っていた（[[000385]] の計測で共起 418 ms + レイアウト 28〜65 ms）。利用者が少なく、訪問間隔が TTL を超えることが多いため、ほぼ毎回コールドになる。同時に来たコールドの読み手も、それぞれ独立に再計算していた。

## Decision

**Tag Verse を Alt-Paper の WebGL シーンとして作り直し、tag cloud の読み出しを stale-while-revalidate にする。** 3D でタグを空間的に探索するという Tag Verse の役割は維持し、見た目と描画方式を置き換える。

### シーン（alt-frontend-sv）

- **レンダラ**: Threlte 既定の `<Canvas>`（WebGLRenderer）を使う。`renderMode` は `on-demand`、`dpr` は `[1, 2]` でクランプ、`toneMapping` は `NoToneMapping`（インクの色をそのまま出すため）。`WebGPURenderer`、`forceWebGL`、破棄回避コード、ブルーム、星空は削除する。
- **ノード**: 全タグを 1 本の `THREE.InstancedMesh`（共有の `SphereGeometry` と `MeshBasicMaterial`）で描く。インスタンスごとに行列と色を持ち、変化したインスタンスだけを更新してから `invalidate()` する。ポインタ判定は `InstancedMesh` のレイキャストが返す `instanceId` で行う。ホバー中と選択中のノードはアクセント色にし、1.15 倍に拡大する。インスタンス数はノード数から決める。
- **配色**: 色はマウント時に、キャンバスのコンテナから CSS 変数（`--app-bg` / `--text-primary` / `--interactive-text`）を読んで決める。ノードの 5 段階（しきい値は [[000362]] を踏襲）は、インク色を紙色に段階的に混ぜて作る。どの段も紙色に対して 3:1（WCAG 1.4.11）以上であることをテストで固定する。色を解釈できない場合や、コントラストが不足するテーマでは、Alt-Paper の値に戻す。
- **奥行きの表現**: 背景と同じ紙色の線形 `Fog` を使う。霧の範囲はカメラから注視点までの距離 d に追従させ、near = d − 0.2R、far = d + 1.6R とする（R は雲の半径）。範囲をワールド座標で固定すると、ズームアウト時に全ノードが紙色に溶けるため。
- **ラベル**: WebGL キャンバスの上に 2D `<canvas>` を 1 枚重ね（`pointer-events: none`、`aria-hidden`）、`renderStage` 上の 1 本のタスクで描く。このタスクは `autoInvalidate: false` で、フレームが実際に描かれるときだけ動く。描画手順は次のとおり。
  - 各ノードのアンカーを画面座標に投影する。
  - 選択中 → ホバー中 → 記事数の多い順に、一様グリッドの衝突判定で貪欲に配置する。
  - 紙色で縁取りしてから文字を描く。
  - 不透明度は three の霧と同じ `smoothstep` で計算し、ラベルがノードと同じ曲線で消えるようにする。
- **カメラ**: タグを選ぶと約 600 ms の ease-out で寄る。この間だけ `useTask` が動く。`prefers-reduced-motion` のときは即座に切り替える。自動回転は既定でオフにし、トグルで有効にする。

### 画面外枠（alt-frontend-sv）

- 上部バー（タイトル、タグ数・記事数、Rotate、Reset view）、左の検索付きタグ一覧、右の詳細パネルを Alt-Paper のトークンで構成する。2 本線のマストヘッドは使わない。
- タグ一覧を、キーボードとスクリーンリーダーで全タグに到達する経路にする。キャンバスに描いたラベルは支援技術から見えないため。
- 詳細パネルの振る舞い:
  - タブは WAI-ARIA のパターンに従う。
  - 開いたら見出しにフォーカスを移し、閉じたら元の要素に戻す。
  - Escape で閉じる。ただし IME の変換中とフォーム要素内の Escape は無視する。
  - タブの内容はタグごとに 1 回だけ取得し、一度開いたタブはマウントしたまま保持する。
  - ページングは、リクエストの連番で古い応答を捨てる。
- `TagVerseScreen` はマウント時に、`fetchTagCloud` と `import("./TagVerseScene.svelte")` を並列に開始する。three.js はこの動的 import 経由でしか読み込まれない。
- `gpuCapability` は WebGL2 の可否だけを判定し、判定に使ったコンテキストを `WEBGL_lose_context` で解放する。

### tag cloud キャッシュ（alt-backend）

`FetchTagCloudUsecase` を次のように変える。

- 30 分以内のエントリは、そのまま返す（fresh）。
- 30 分〜24 時間のエントリは、古いまま即座に返し、裏で再計算を 1 本だけ走らせる（stale）。再計算中かどうかのフラグは mutex 下で立て、失敗しても panic しても必ず下ろす。
- エントリがない、limit が違う、24 時間より古い場合は、同期的に計算する（miss）。
- 同期計算・`Refresh`・裏の再計算は、limit をキーに `golang.org/x/sync/singleflight` で 1 本にまとめる。共有する計算は `context.WithoutCancel` + 30 秒のタイムアウトで実行し、最初の呼び出し元が切断しても、合流した他の呼び出し元を巻き込まない。
- 裏の再計算での panic は recover し、Error ログに出す。HTTP ハンドラの外の goroutine なので、recover しないとプロセスごと落ちる。
- キャッシュのログに `cache_state`（`fresh` / `stale` / `miss` / `refresh`）を付ける。

### 検討して却下した案

- **WebGPU とブルームを残し、インスタンス化だけ行う**: ブルームと発光は Alt-Paper と相容れない。WebGPU にしてから破棄順序の不具合が 3 件の ADR に及んでいた。300 個の単色球と 2D ラベルという規模では、WebGPU を使う利点もない。
- **`@threlte/extras` の `<InstancedMesh>` / `<Instance>`**: 親メッシュのレイキャストを無効化し（`raycast={() => null}`）、`<Instance>` ごとに `PositionMesh` で判定する。全インスタンスの行列も `useTask` で毎フレームコピーする。インスタンス単位の当たり判定を 1 回のレイキャストで得られる、素の `THREE.InstancedMesh` を選んだ。
- **troika の `Text` / `BatchedText` でラベルを 3D 化**: `Text` はラベルごとにメッシュになる。`BatchedText` は 1 ドローコールにまとまるが、WebGL2 前提で、衝突判定による間引きは別に要る。新しい依存も増える。画面座標で衝突判定する 2D canvas のほうが、編集的な縁取り文字も素直に描ける。
- **`<HTML>` オーバーレイに `autoRender` を付けて残す**: ラベルごとの DOM と遮蔽レイキャストが根本のコストで、残る。
- **3D をやめて 2D のグラフにする**: Tag Verse の役割（空間的な探索）を変えてしまう。今回の対象外。
- **バックエンドのウォーマーを `cmd/backend` 内で定期実行する**: 誰も見ていない間も 24 分ごとに計算が走る。stale-while-revalidate なら、読み手の待ち時間をなくしつつ、計算を読まれたときだけに抑えられる。
- **キャッシュを共有ストアに移す**: 1 つの読み取りモデルのために新しいインフラ依存を足すことになり、見合わない。プロセス内キャッシュ + stale-while-revalidate で、コールドになるのはプロセス起動直後の 1 回だけになる。

## Consequences

### Pros

- tag-verse ルートのエントリ chunk が 1.87 MB（gzip 504 KB）から 24 KB になった。three.js は遅延 chunk の 809 KB（gzip 209 KB）に分かれ、モバイルで到着した場合は読み込まれない。WebGPU と TSL を外した分、three.js の chunk 自体も半分以下になった。
- ドローコールは約 300 からノード用の 1 本（と 2D キャンバス 1 枚）になった。カメラが止まっている間は描画しない。毎フレームの JS 処理（タスク 300 本、ラベルの遮蔽レイキャスト、ブルーム）がなくなった。
- 他の画面と同じ Alt-Paper の見た目になり、文字のコントラストは 4.5:1、ノードは 3:1 をテストで保証している。
- キーボード、スクリーンリーダー、`prefers-reduced-motion`、IME 入力中の操作で、Tag Verse を使えるようになった。
- 詳細パネルの RPC が、開くたびに 2 本から 1 本になり、タブ切り替えでの再取得がなくなった。
- tag cloud の読み手は、プロセス起動直後の 1 回を除き、キャッシュ済みの応答を受け取る。同時に来たコールドの読み手は 1 回の計算に合流する。
- [[000350]] / [[000355]] / [[000372]] の破棄回避コードが不要になり、削除した。

### Cons / Tradeoffs

- 長く使われなかった後の最初の表示では、最大 24 時間前のタグ集計を見せる（裏で更新され、次の表示から新しくなる）。タグの記事数はゆっくり変わる値なので許容する。プロセス再起動直後の 1 回目は従来どおり同期計算になる。
- 共有した計算は呼び出し元のキャンセルから切り離されるため、全員が切断しても最大 30 秒は計算を続ける。
- 裏の再計算での panic は recover して Error ログに出すため、プロセスは落ちない。panic を見逃さないには、ログでの監視が前提になる。
- ラベルはキャンバスに描くので、支援技術からは見えない。代替はタグ一覧が担う。
- 配色はマウント時に 1 回だけ CSS 変数から読む。画面を開いたままテーマを変えても、再マウントするまで反映されない。
- 既知の小さな挙動が 2 つある。Reset view の後に同じタグを選び直してもカメラが寄らない。自動回転中はポインタの下からノードが外れてもホバー表示が残る。
- 執筆時点で、ブラウザでの見た目確認と、スタックに対する Playwright（`tests/e2e/desktop/feeds/tag-verse.spec.ts`）は未実施。
