# ADR-001027: ハーネス検査器を Go の並列ランナーへ移し、同じ検査を落とさずメタゲートを短くする

## Status

Accepted

## Date

2026-11-23

## Affected Services

`scripts/` の lint / agent-harness / corpus 入口と、それを呼ぶ CI。外部リンタ（`golangci-lint`、`ruff`、`ast-grep`、`buf` など）の採用そのものは変えない。

## Context

`./scripts/lint/run.sh repo` と `./scripts/lint/run.sh harness` は、抑制ラチェット、生成コード、正本同期、作業ツリー衛生、コーパス、タスクパケットを直列に実行していた。同じ読み取り専用検査が両方のゲートに登録され、`sync_go_canonical.py` は `rglob("*.go")` で依存ディレクトリまで降り、`proto.sh` の `buf breaking` は毎回 GitHub 上の `main` を参照していた。検査項目を削ると捕捉率（失敗コーパス `C-01`..`C-22`、規則台帳の `max_judgment_rules`）が下がる。必要なのは実装言語と実行モデルの変更である。

入口（`scripts/lint/run.sh`、各 `*.py` / `*.sh`、フック）は CI・Makefile・エージェントが固定パスで呼ぶ。パスは残し、中身を Go にする。

## Decision

検査器の実装を `scripts/altharness`（モジュール `alt/scripts/altharness`）に置く。

- ゲートは有界ワーカープールで読み取り専用ステップを並列に走らせる。各ステップはタイムアウトを持ち、終了コードと出力はカタログ順に出す。成功結果だけを `HEAD` と作業ツリー指紋でキャッシュし、失敗はキャッシュしない。コマンドのないステップは成功にしない。
- 0 件スキャン、欠落ツール、リポジトリ外パス、シンボリックリンク脱出は非ゼロ終了のままにする。
- `scripts/altharness` は検査器自身であり、`run.sh --list` のサービス対象に含めない。
- Go 正本の孤児探索は git 作業ツリーでは `git ls-files` を使い、git でないフィクスチャだけ枝刈り付きの走査に戻す。
- `buf breaking` の比較先は `.git#branch=origin/main,subdir=proto` とする。
- 既存パスは Go バイナリを `exec` する薄いラッパにする。外部リンタはこれまで通りサブプロセスで呼ぶ。
- 規則台帳の `max_judgment_rules` は引き下げない限り据え置く（現行は 6）。

検討して却下した案: Bash の直列ゲートを残して Python 検査器だけを Go にする。メタゲートの重複と直列実行が残る。もう一つは検査ステップを削除して時間だけを稼ぐ案。捕捉率を下げるので却下した。

## Consequences

- 同じ検査を、`repo` と `harness` の両方を続けて走らせたときに二度実行しない（同一引数は一度、または成功キャッシュ）。並列度の上限は `ALT_HARNESS_WORKERS`（既定は最大 6）。
- `go test -race` を検査器自身の回帰に使う。
- ラッパ経由の CLI は従来の終了コードと診断文を維持する。差分がある場合は失敗を成功に倒さない方向だけを許す。
- 外部ツールのバージョン固定（`buf` 1.48.0 など）は各言語ランナーに残る。ツールが PATH に無いときは成功扱いにしない。
- `scripts/altharness/bin/` は生成物であり git に入れない。
