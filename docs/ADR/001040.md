# ADR-001040: LOOP-04 敵対的レビューで検出した既存不具合（altctl・news-creator・search-indexer・auth-hub・recap-subworker）を是正する

## Status

Accepted

## Date

2026-11-28

## Affected Services

- `altctl` (Go): バックアップ検証・リストアのパス封じ込め（`internal/migrate`）、`.env`・シークレット生成の symlink 遮断と権限保証（`internal/setup`）、および `internal/config` の C-02 単体テスト補完
- `news-creator` (Python): `OllamaGateway.chat_stream` の上流ストリーム `aclosing` 保証
- `search-indexer` (Go): `driver/backend_api` の nil Protobuf タイムスタンプ安全変換
- `auth-hub` (Go): `config` の `<KEY>_FILE` 読込・空ファイルエラーに対する fail-fast 化および必須設定値検証強化
- `recap-subworker` (Python): `learning_machine/scripts/pseudo_label.py` の Python 3.14 `argparse` ヘルプ文字列 `%` エスケープ修正

## Context

[[001039]] で導入した LOOP-04 敵対的最終レビュー（異系統モデル監査、`auto_applied: false` 契約）において、実コードベースの重点 7 項目（`F-01`〜`F-07`）を実テスト・再現コマンドで駆動検証した結果、ハーネス PR 内では自動修正せず独立した TDD 修正対象として保全された既存プロダクト不具合が特定された（`docs/review/loop-04-adversarial-review-report.json`、`docs/review/harness-loop-01-07-implementation-slides-2026-11-28.md`）。

1. **`REV-05`（`F-04` / `altctl`）**: `altctl/internal/migrate/manifest.go` の `resolveUnderBase` が字句的な `filepath.Join`/`filepath.Rel` 検査のみを行い、`os.OpenRoot(backupDir)` や symlink 解決を行わないため、`backupDir` 内の symlink（例: `volumes/db.dump -> 外部ファイル`）が `Manifest.Verify` を通過し `Migrator.Restore` へ流入していた（`TestReproSymlinkEscape` で `exit_code=1` 再現済み）。
2. **`REV-06`（`F-04` / `altctl`）**: `altctl/internal/setup/envfile.go` の `CreateEnvFile` が `os.Stat` + `os.WriteFile` を使用していたため、dangling `.env` symlink が `force=false` でも素通りして `projectRoot` 外にファイルを作成し、live `.env` symlink は `force=true` で外部ファイルを上書きしていた。さらに既存 `0o644` の `.env` を `--force` で上書きしても `Chmod(0o600)` されず権限が残存していた（`TestReproEnvSymlink` で `exit_code=1` 再現済み）。
3. **`REV-08`（`F-06` / `news-creator`）**: `news-creator/app/news_creator/gateway/ollama_gateway.py` の `chat_stream` が `_build_streaming_generator`（`generate_stream`）と異なり `self.stream_driver.chat_stream(payload)` を `async with aclosing(...)` で包まず直列反復していたため、クライアント切断時に HIGH PRIORITY セマフォ枠が解放される一方、上流ストリームが開いたまま残留していた（`test_chat_stream_closes_driver_before_releasing_slot` で `exit_code=1` 再現済み）。
4. **`REV-03`（`F-02` / `search-indexer`）**: `search-indexer/app/driver/backend_api/client.go` の `GetDeletedArticles` と `toDriverArticle` が `GetDeletedAt().AsTime()` および `GetCreatedAt().AsTime()` を nil 検査なしで呼び出しており、nil タイムスタンプがゼロ値 `time.Time{}` ではなく Unix エポック `1970-01-01T00:00:00Z`（`IsZero() == false`）へ変換されていた。
5. **`REV-04`（`F-03` / `auth-hub`）**: `auth-hub/config/config.go` の `getEnv` が `<KEY>_FILE` 指定時の `readConfigFile` エラーを無視して通常環境変数やデフォルト値（例: `http://kratos:4433`）へ黙ってフォールバックしており、起動時 fail-fast 契約（`CLAUDE.md` Rule 9）に反していた。
6. **`REV-09`（`F-07` / `recap-subworker`）**: `recap-subworker/recap_subworker/learning_machine/scripts/pseudo_label.py` の `--accept_top_percent` 引数ヘルプ文字列に未エスケープの `P%` が含まれており、Python 3.14 の `argparse._check_help` により実行のたびに `ValueError: badly formed help string` で即クラッシュしていた。
7. **`REV-01`（`F-01` / `altctl`）**: `altctl/internal/config` に `C-02`（`!errors.As(err, &configFileNotFoundError)`）を直接固定するパッケージ単体テストが存在しなかった。
8. **異系統モデル再監査（Round-1）で追加検出した双子不具合 2 件**:
   - **`AUD-01`（`F-04` / `altctl`）**: `altctl/internal/setup/secrets.go` の `GenerateSecrets` も `REV-06` と同じ `os.Stat` + `os.WriteFile` + パス指定 `os.Chmod(0o644)` パターンを使用しており、dangling/live symlink 経由で `secrets/` 外のファイル作成・上書き・権限緩和が可能だった（`TestReproSecretsSymlinkEscape` で `exit_code=1` 再現）。
   - **`AUD-02`（`F-03` / `auth-hub`）**: `<KEY>_FILE` が 0 バイトまたは空白のみのファイルを指す場合、`getEnv` が `("", nil)` を返し、さらに `Config.Validate()` が `KratosAdminURL`・`BackendTokenIssuer`・`BackendTokenAudience` および空白のみの値を検証していなかったため、`iss=""` / `aud=""` / `admin=""` のまま起動が成功していた（`TestReproEmptyFileEnvClobbersClaims` で `exit_code=1` 再現）。

## Decision

上記すべての既存不具合およびテスト欠落を、各サービスの独立した TDD 修正（RED 再現テスト → GREEN 実装 → リント・型検査・異系統モデル 2 ラウンド敵対的再監査）として一括是正し、LOOP-04 の重点 7 項目（`F-01`〜`F-07`）すべてを実テスト・実行証明つきで `safe` へ昇格させる方針を採用する。

1. **`altctl` パス封じ込めと `.env` / `secrets` 生成ハードニング（`REV-05`, `REV-06`, `AUD-01`, `REV-01`）**:
   - `altctl/internal/migrate`: `Manifest.Verify` を `os.OpenRoot(backupDir)` ベースの単一ファイルハンドル検証（成分ごとの `root.Lstat` による symlink・非通常ファイル拒否 + `root.Open` 後の `f.Stat` / SHA-256 算出による TOCTOU 解消）へ移行した。`resolveUnderBase` も `os.OpenRoot`・成分ごとの `Lstat`・`filepath.EvalSymlinks` 境界検証で symlink 脱出および非通常ファイルを拒否し、`Migrator.Restore` ではコンテナ停止前に全対象ボリュームを事前検証したうえで `restoreVolume` でも再検証する。`Restore` / `VerifyBackup` / `GetBackupSummary` / `ListBackups` の `manifest.json` 読込も `loadManifestInDir`（`os.OpenRoot`）経由に統一した。
   - `altctl/internal/setup`: `CreateEnvFile` および `GenerateSecrets`（`ensureEd25519KeyPair` を含む）を `os.OpenRoot` ベースへ書き換え、単一ファイル名検証・`root.Lstat` による dangling/live symlink および非通常ファイルの無条件拒否・`root.OpenFile`（新規作成時は `O_EXCL`）・オープン済み fd に対する `f.Chmod`（`.env` は `0o600`、`secrets/*` は現行運用契約の `0o644`）を徹底した。
   - `altctl/internal/config`: `config_test.go` を追加し、未存在時の既定値フォールバックと不正 YAML / 明示不存在パス時のエラー返却（`C-02`）を固定した。
   - 却下した代替案: 字句的な `filepath.EvalSymlinks` 単独チェックは dangling symlink や open 前の TOCTOU を防げないため不採用とした。
2. **`news-creator` `chat_stream` 上流ストリーム解放保証（`REV-08`）**:
   - `OllamaGateway.chat_stream` 内の `_stream()` で `self.stream_driver.chat_stream(payload)` を `async with aclosing(stream_iterator):` で包み、クライアント切断・`aclose()`・`athrow()`・`CancelledError`・例外時に上流ストリームが確実にクローズされた**後**に `finally` で HIGH PRIORITY セマフォ枠が解放される順序（`["driver_closed", "slot_released"]`）を保証した。
   - 却下した代替案: 手動 `finally: await stream.aclose()` は `CORPUS C-07` で記録されたとおりキャンセル例外との競合でクリーンアップ漏れや SSE ハングを招くため不採用とした。
3. **`search-indexer` nil タイムスタンプのゼロ値正規化（`REV-03`）**:
   - `search-indexer/app/driver/backend_api/client.go` に `timestampOrZero(ts *timestamppb.Timestamp) time.Time` を導入し、`GetDeletedArticles` と `toDriverArticle` で nil タイムスタンプを `1970-01-01T00:00:00Z` ではなく `time.Time{}` へ正規化した。
   - 却下した代替案: nil タイムスタンプでエラー終了させる案は、既存の `published_at` 未設定記事フォールバックや欠損メタデータ耐性を破壊するため、先行実装（`pre-processor/app/repository/backend_api_article.go`）と揃えたゼロ値正規化を採用した。
4. **`auth-hub` `<KEY>_FILE` および必須設定値の fail-fast 化（`REV-04`, `AUD-02`）**:
   - `auth-hub/config/config.go` の `getEnv` を `(string, error)` 返却へ改め、`<KEY>_FILE` が設定されている場合は `readConfigFile` 失敗または空白・0 バイトファイルを即座に `Load()` エラー（`read <KEY>_FILE: ...`、秘密値本体は含めない）として返す。併せて `Config.Validate()` で `KratosURL`・`KratosAdminURL`・`Port`・`BackendTokenIssuer`・`BackendTokenAudience`・`CSRFSecret`・`InternalAuthSecret` の空・空白のみ値をすべて拒否する。
   - 却下した代替案: 警告ログのみ出して既定値へフォールバックする案は `CLAUDE.md` Rule 9（Fail-fast startup config）に反するため不採用とした。
5. **`recap-subworker` `pseudo_label.py` Python 3.14 `argparse` 修正（`REV-09`）**:
   - `--accept_top_percent` のヘルプ文字列 `P%` を `P%%` にエスケープし、Python 3.14 での無条件 `ValueError` クラッシュを解消した（同サービス内 264 ファイル・全 40 箇所の `add_argument(help=...)` を AST 検査し他に未エスケープ `%` がないことも確認済み）。

## Consequences

### Pros

- `altctl` のバックアップ検証・リストアおよび `.env` / `secrets` 初期化における symlink 脱出（CWE-59）と `--force` 上書き時の権限緩和を構造的に排除できた（`altctl` 全 12 パッケージ `-race` 通過、`./scripts/lint/run.sh altctl` 0 issues）。
- `news-creator` のチャットストリーミングでクライアント切断時の上流接続リークとセマフォ枠の早すぎる解放が解消され、同時実行数の不変条件が守られる（対象 445 テスト通過、`ruff` / `bandit` / `pyrefly` 0 errors）。
- `search-indexer` で欠損タイムスタンプが `1970-01-01` として誤解釈される不具合を防ぎ、`IsZero()` 契約が一貫した（`search-indexer/app` 全 20 パッケージ `-race` 通過、`./scripts/lint/run.sh search-indexer/app` 0 issues）。
- `auth-hub` の全 `<KEY>_FILE` 経路と必須設定値が起動時 fail-fast に統一され、空ファイルや誤設定の黙認起動を防げる（`auth-hub` 全 13 パッケージ `-race` および `TestEffectiveConfigGolden` 通過、`./scripts/lint/run.sh auth-hub` 0 issues）。
- `recap-subworker` の `pseudo_label.py` が Python 3.14 上で引数パースおよび `--help` 表示まで正常動作するようになった（23 ユニット・不変条件テスト通過、`ruff` / `pyrefly` 0 errors）。
- 異系統モデル敵対的再監査（Round-1 → Round-2）を経て `F-01`〜`F-07` 全 7 項目の `safe` 判定と `exit_code == 0` 実行証明を確定した。

### Cons / Tradeoffs

- `auth-hub` で存在しない・空の `<KEY>_FILE` を残したまま通常環境変数や既定値に頼っていた設定があれば起動時に即時失敗するようになる（fail-fast 原則上、意図した挙動である）。
- `altctl` のバックアップディレクトリや `secrets/` 配下に symlink を手動配置する非標準運用は拒否されるようになる。
- 本変更を稼働環境へ反映する際は、各コンパイル済みサービス（`altctl` / `search-indexer` / `auth-hub`）および Python コンテナ（`news-creator` / `recap-subworker`）の通常リビルドが必要になる。
