# ADR-001040: LOOP-04 敵対的レビューで検出した既存不具合（altctl・news-creator・search-indexer・auth-hub・recap-subworker）を是正する

## Status

Proposed

## Date

2026-11-28

## Affected Services

- `altctl` (Go): バックアップ検証・リストアのパス封じ込め（`internal/migrate`）、`.env` 生成の symlink 遮断と権限保証（`internal/setup`）、および `internal/config` の C-02 単体テスト補完
- `news-creator` (Python): `OllamaGateway.chat_stream` の上流ストリーム `aclosing` 保証
- `search-indexer` (Go): `driver/backend_api` の nil Protobuf タイムスタンプ安全変換
- `auth-hub` (Go): `config` の `<KEY>_FILE` 読込エラーに対する fail-fast 化
- `recap-subworker` (Python): `learning_machine/scripts/pseudo_label.py` の Python 3.14 `argparse` ヘルプ文字列 `%` エスケープ修正

## Context

[[001039]] で導入した LOOP-04 敵対的最終レビュー（異系統モデル監査、`auto_applied: false` 契約）において、実コードベースの重点 7 項目（`F-01`〜`F-07`）を実テスト・再現コマンドで駆動検証した結果、ハーネス PR 内では自動修正せず独立した TDD 修正対象として保全された既存プロダクト不具合が特定された（`docs/review/loop-04-adversarial-review-report.json`、`docs/review/harness-loop-01-07-implementation-slides-2026-11-28.md`）。

1. **`REV-05`（`F-04` / `altctl`）**: `altctl/internal/migrate/manifest.go` の `resolveUnderBase` が字句的な `filepath.Join`/`filepath.Rel` 検査のみを行い、`os.OpenRoot(backupDir)` や symlink 解決を行わないため、`backupDir` 内の symlink（例: `volumes/db.dump -> 外部ファイル`）が `Manifest.Verify` を通過し `Migrator.Restore` へ流入する（`TestReproSymlinkEscape` で `exit_code=1` 再現済み）。
2. **`REV-06`（`F-04` / `altctl`）**: `altctl/internal/setup/envfile.go` の `CreateEnvFile` が `os.Stat` + `os.WriteFile` を使用しているため、dangling `.env` symlink が `force=false` でも素通りして `projectRoot` 外にファイルを作成し、live `.env` symlink は `force=true` で外部ファイルを上書きする。さらに既存 `0o644` の `.env` を `--force` で上書きしても `Chmod(0o600)` されず権限が残存する（`TestReproEnvSymlink` で `exit_code=1` 再現済み）。
3. **`REV-08`（`F-06` / `news-creator`）**: `news-creator/app/news_creator/gateway/ollama_gateway.py` の `chat_stream` が `_build_streaming_generator`（`generate_stream`）と異なり `self.stream_driver.chat_stream(payload)` を `async with aclosing(...)` で包まず直列反復しているため、クライアント切断時に HIGH PRIORITY セマフォ枠が解放される一方、上流ストリームが開いたまま残留する（`test_chat_stream_closes_driver_before_releasing_slot` で `exit_code=1` 再現済み）。
4. **`REV-03`（`F-02` / `search-indexer`）**: `search-indexer/app/driver/backend_api/client.go` の `GetDeletedArticles` と `toDriverArticle` が `GetDeletedAt().AsTime()` および `GetCreatedAt().AsTime()` を nil 検査なしで呼び出しており、nil タイムスタンプがゼロ値 `time.Time{}` ではなく Unix エポック `1970-01-01T00:00:00Z`（`IsZero() == false`）へ変換される。
5. **`REV-04`（`F-03` / `auth-hub`）**: `auth-hub/config/config.go` の `getEnv` が `<KEY>_FILE` 指定時の `readConfigFile` エラーを無視して通常環境変数やデフォルト値（例: `http://kratos:4433`）へ黙ってフォールバックしており、起動時 fail-fast 契約（`CLAUDE.md` Rule 9）に反する。
6. **`REV-09`（`F-07` / `recap-subworker`）**: `recap-subworker/recap_subworker/learning_machine/scripts/pseudo_label.py` の `--accept_top_percent` 引数ヘルプ文字列に未エスケープの `P%` が含まれており、Python 3.14 の `argparse._check_help` により実行のたびに `ValueError: badly formed help string` で即クラッシュする。
7. **`REV-01`（`F-01` / `altctl`）**: `altctl/internal/config` に `C-02`（`!errors.As(err, &configFileNotFoundError)`）を直接固定するパッケージ単体テストが存在しない。

## Decision

上記すべての既存不具合およびテスト欠落を、各サービスの独立した TDD 修正（RED 再現テスト → GREEN 実装 → リント・型検査・異系統モデル再監査）として一括是正し、LOOP-04 の重点項目 `F-04`・`F-06` を含む全 7 項目の安全性を実テスト・実行証明で再確定する方針を採用する。

1. **`altctl` パス封じ込めと `.env` 生成ハードニング（`REV-05`, `REV-06`, `REV-01`）**:
   - `altctl/internal/migrate`: `Manifest.Verify` を `os.OpenRoot(backupDir)` ベースの単一ファイルハンドル検証（`Lstat` による symlink 拒否 + `Open` 後の `Stat` / SHA-256 算出による TOCTOU 解消）へ移行する。`resolveUnderBase` も `os.OpenRoot` と `EvalSymlinks` 境界検証で symlink 脱出および非通常ファイルを拒否し、`Restore` / `VerifyBackup` / `GetBackupSummary` の `manifest.json` 読込も `os.OpenRoot(backupDir)` 経由に統一する。
   - `altctl/internal/setup`: `CreateEnvFile` を `os.OpenRoot(projectRoot)` ベースへ書き換え、`.env` が symlink（dangling / live 問わず）または非通常ファイルの場合は `force` の有無にかかわらず拒否する。書込は `root.OpenFile`（`!force` 時は `O_EXCL`）と `Chmod(fsperm.SecretFile)`（`0o600`）で権限を強制し、`.env.example` の読込も `root` 内に封じ込める。
   - `altctl/internal/config`: `config_test.go` を追加し、未存在時の既定値フォールバックと不正 YAML 時のエラー返却（`C-02`）を固定する。
   - 却下した代替案: 字句的な `filepath.EvalSymlinks` 単独チェックは dangling symlink や open 前の TOCTOU を防げないため不採用とした。
2. **`news-creator` `chat_stream` 上流ストリーム解放保証（`REV-08`）**:
   - `OllamaGateway.chat_stream` 内の `_stream()` で `self.stream_driver.chat_stream(payload)` を `async with aclosing(stream_iterator):` で包み、クライアント切断・例外時に上流 Ollama ストリームが確実にクローズされた**後**に `finally` で HIGH PRIORITY セマフォ枠が解放される順序を保証する。
   - 却下した代替案: 手動 `finally: await stream.aclose()` は `CORPUS C-07` で記録されたとおりキャンセル例外との競合でクリーンアップ漏れや SSE ハングを招くため不採用とした。
3. **`search-indexer` nil タイムスタンプのゼロ値正規化（`REV-03`）**:
   - `search-indexer/app/driver/backend_api/client.go` に `timestampOrZero(ts *timestamppb.Timestamp) time.Time` を導入し、`GetDeletedArticles` と `toDriverArticle` で nil タイムスタンプを `1970-01-01T00:00:00Z` ではなく `time.Time{}` へ正規化する。
   - 却下した代替案: nil タイムスタンプでエラー終了させる案は、既存の `published_at` 未設定記事フォールバックや欠損メタデータ耐性を破壊するため、先行実装（`pre-processor/app/repository/backend_api_article.go`）と揃えたゼロ値正規化を採用した。
4. **`auth-hub` `<KEY>_FILE` の fail-fast 化（`REV-04`）**:
   - `auth-hub/config/config.go` の `getEnv` を `(string, error)` 返却へ改め、`<KEY>_FILE` が設定されている場合は `readConfigFile` の失敗（不在・権限不足・`..`・symlink 脱出）を即座に `Load()` エラーとして返す。通常環境変数やデフォルト値への黙ったフォールバックを禁止する（エラー文言に秘密値本体を含めない）。
   - 却下した代替案: 警告ログのみ出して既定値へフォールバックする案は `CLAUDE.md` Rule 9（Fail-fast startup config）に反するため不採用とした。
5. **`recap-subworker` `pseudo_label.py` Python 3.14 `argparse` 修正（`REV-09`）**:
   - `--accept_top_percent` のヘルプ文字列 `P%` を `P%%` にエスケープし、Python 3.14 での無条件 `ValueError` クラッシュを解消する。

## Consequences

### Pros

- `altctl` のバックアップ検証・リストアおよび `.env` 初期化における symlink 脱出（CWE-59）と `--force` 上書き時の権限緩和を構造的に排除できる。
- `news-creator` のチャットストリーミングでクライアント切断時の上流接続リークとセマフォ枠の早すぎる解放が解消され、GPU 同時実行数の不変条件が守られる。
- `search-indexer` で欠損タイムスタンプが `1970-01-01` として誤解釈される不具合を防ぎ、`IsZero()` 契約が一貫する。
- `auth-hub` の全 `<KEY>_FILE` 経路が起動時 fail-fast に統一され、誤設定の黙認起動を防げる。
- `recap-subworker` の `pseudo_label.py` が Python 3.14 上で引数パースおよび `--help` 表示まで正常動作するようになる。

### Cons / Tradeoffs

- `auth-hub` で存在しない `<KEY>_FILE` を残したまま通常環境変数や既定値に頼っていた設定があれば、起動時に即時失敗するようになる（ただし fail-fast 原則上、意図した振る舞いである）。
- `altctl` のバックアップディレクトリ内に外部参照 symlink を手動配置する非標準運用は拒否されるようになる。
