# ADR-001020: Swipe の左を「流す」、右を「今日読む」に割り当て、Keep スタンプとカードの要約ボタンを外す

## Status

Accepted

## Date

2026-11-18

## Affected Services

- alt-frontend-sv — `SwipeFeedScreen.svelte`、`VisualPreviewCard.svelte`、`dispatch-session.svelte.ts`、および関連テストの更新

## Context

[[001015]] の R2（Swipe の左右と「今日読む」）に対応する決定である。2026-11-17 時点の本番データを読み取り専用で計測したところ、既読操作の間隔は中央値 1.31 秒、Swipe カードの Keep スタンプからのお気に入り追加は 90 日で 0 件、要約の利用は 15 日で 10 回であった。持ち主は 2026-11-18 に「左が流す、右が今日読むに蓄積」と定め、Keep スタンプとカード上の要約ボタンを外し、要約をリーダーの中だけにする方針を決定した。

現状の実装には次の課題がある。

- `src/lib/components/mobile/feeds/swipe/SwipeFeedScreen.svelte` の `handleDismiss(_direction: number)`（366 行目）は、カード側から渡される方向引数（`SwipeFeedCard.svelte` 625 行目および `VisualPreviewCard.svelte` 560 行目の `-1` / `1`）を捨てており、左右どちらへ払っても同じ既読処理になる。
- `src/lib/components/mobile/feeds/swipe/dispatch-session.svelte.ts` は `pending` に単一のリンク文字列（`string | null`）のみを保持し、次の `dismiss()`・`pagehide`・unmount・最後のカード消費時に無条件で `markRead` を確定送信する。操作種別を持たないため、既読化以外の遅延操作を扱えない。
- `SwipeFeedCard.svelte`（643-659 行目）と `VisualPreviewCard.svelte`（600-616 行目）には Keep スタンプ（`data-testid="keep-stamp"`、`registerFavoriteFeedClient`）が置かれ、フッターには `Article` と `Summary` の 2 ボタンが置かれている。スワイプ以外の操作手段（ボタン）でカードを払う手段は無い。

## Decision

[[000948]] の全項目を下記のとおり引き継ぎまたは置き換えることで、本 ADR は [[000948]] を置き換える。

1. **左スワイプを「流す」にする**: 左へ払うと「流す」として記事を既読にする。現状と同じく `dispatch-session.svelte.ts` で 1 件分だけ確定送信を遅延させ、UNDO できるようにする。理由は、誤スワイプの回復余地を残しつつ、読まない記事を素早く処理するためである。
2. **右スワイプを「今日読む」にする**: 右へ払うと「今日読む」キューへ積む（[[001021]]）。この操作では既読にしない。こちらも 1 件分だけ確定送信を遅延させ、UNDO できるようにする。理由は、読むと決めた記事を未読のまま残しつつ、誤って右に払った場合も 1 手戻せるようにするためである。
3. **向きと操作種別の保持**: `SwipeFeedScreen.svelte` の `handleDismiss`（366 行目）で向き引数を受け取り、左（`-1`）を `pass`、右（`1`）を `queue` に割り当てる。`dispatch-session.svelte.ts` の保留スロットにはリンクに加えて操作種別（`pass` / `queue`）を持たせ、確定時に種別に応じた送信を行う。理由は、既存の single-slot 遅延送信と UNDO の仕組みを壊さずに 2 種類の操作を扱うためである。
4. **上限到達時の即時戻し**: 「今日読む」キューが上限（[[001021]] の 7 本）に達している状態で右へ払ったときは、保留バッファに入れずカードを山へ戻し、その場で上限に達したことを知らせる。理由は、遅延フラッシュ後に失敗しても持ち主が気づけないためである。
5. **Keep スタンプの削除**: カード右上の Keep スタンプ（`data-testid="keep-stamp"`）を外す。お気に入りの機能そのもの（一覧画面と `registerFavoriteFeedClient` の保存先）はこの ADR では削除しない。理由は、90 日で追加 0 件と使われておらず、振り分け判断を「流す」と「今日読む」の 2 択に絞るためである。
6. **カード上の要約ボタン削除**: カード上の要約ボタン（`Summary`）およびカード内の要約表示・読み上げコントロールを外し、要約は [[001019]] のリーダーの中だけにする。理由は、要約が 15 日で 10 回しか使われておらず、カード上の要約が本文を読む代わりになってしまうためである。
7. **タップで単一リーダーを開く**: カード内の本文展開リーダーを外し、カードをタップして [[001019]] のリーダーを重ね表示で開く。理由は、リーダーを 1 本に統一して滞在と読了を計測するためである。
8. **ドラッグ時のラベル表示とボタン代替手段**: カードを引いている間は、向きに応じたラベル（`Pass` / `Read today`）を表示する。また、スワイプ以外の操作手段（ボタン）でも `Pass` と `Read today` を実行できるようにする。理由は、軌跡に頼る操作には単一のポインタでの代替手段が必要であるためである（WCAG 2.5.1）。
9. **英語の UI 文言**: 方向ラベルや代替ボタンを含む UI の文言は英語にする。理由は、既存画面の言語規約と揃えるためである。

### ADR-000948 の Decision 各項目の扱い

- **1. ボトムナビ非表示（没入モード）**: **引き継ぐ**。`/feeds/swipe/*` を `isImmersiveRoute()` で判定し、ナビと予約 padding を外す原則を維持する（`/feeds/swipe` の統合遷移は [[001019]] による）。
- **2. Dispatch header**: **引き継ぐ**。カード外上部に編集部風ミニヘッダー（Menu / kicker / セッションカウンタ / UNDO / Filter）を常設し、セッション操作のみを置く規則を維持する。
- **3. Keep stamp**: **置き換える**。本 ADR の決定 5 により外す。
- **4. Reading actions の 2 大ボタン化**: **置き換える**。フッターを Article / Summary のみとし左右方向の意味付けを退けた決定を、本 ADR の決定 1・2・6・7・8（カード内リーダーと Summary を外し、左右スワイプに意味を与え、代替ボタンを置く）で置き換える。[[000948]] が意味付けを退けた理由は、「どちらに投げても既読」という慣れを壊し、意図しない保存を量産することだった。この懸念は残る。本 ADR は次の 4 点で受け止める。右は既読を書かないので、誤って右に払っても記事は失われない。積む先は期限のないお気に入りではなく、上限 7 本・期限 48 時間のキュー（[[001021]]）なので、意図しない項目は自然に消える。払っている間に向きのラベルを出す。左右とも UNDO できる。意図しない右払いがどれだけ起きるかは、UNDO と手動の取り外しの回数で確かめる。
- **5. UNDO + 遅延既読フラッシュ**: **置き換える**。single-slot バッファと UNDO 深度 1 の仕組みを維持したうえで、本 ADR の決定 1・2・3（操作種別 `pass` / `queue` を持つ保留操作への拡張）で置き換える。

### 検討した代替案

- **(a) 右スワイプをお気に入り（Keep）のままにする**: 退けた。90 日で 0 件と使われておらず、お気に入りには期限が無いため積んだ記事が滞留するためである。
- **(b) 右スワイプを「リーダーを開く」にする**: 退けた。開く操作はカードのタップで足りるためである。
- **(c) 上下のスワイプを追加して操作を増やす**: 退けた。「流す」と「今日読む」の 2 つの操作で足り、上下のスワイプはカード内の縦スクロールと衝突するためである。

## Consequences

### Pros

- Swipe 面が「流す」と「今日読む」の 2 択の振り分け画面として単純になり、読みたい記事だけが未読のまま残る。
- 90 日 0 件の Keep スタンプとカード内要約・本文展開を削ることで、画面の情報量と重複実装が減る。
- スワイプに加えてボタン操作でも払えるようになり、単一ポインタでの操作性（WCAG 2.5.1）を満たす。

### Cons / Tradeoffs

- 「今日読む」上限（7 本）到達時にカード戻しを行うため、遅延中の `queue` 保留分（最大 1 件）を含めた残枠計算の仕様と、上限到達時の通知メッセージの具体文言・見せ方は実装時に詰める必要がある。
- 左右どちらに払っても既読になる現状の操作に慣れているため、切り替えの直後は意図しない右払いが起きうる。
- 非スワイプボタンの配置位置（フッターかカード周辺か）と、カードタップ領域とタイトルの外部リンクの押し分けは、この ADR では決めていない。
- `DispatchHeader` のセッションカウンタ（`№ N`）が `pass` のみを数えるか `queue` も含めるかは、この ADR では決めていない。
- `SwipeFeedScreen.svelte.test.ts`・`VisualPreviewCard.svelte.spec.ts`・`dispatch-session.svelte.test.ts` および関連 E2E テストの期待値を書き換える必要がある。
