# ADR-001042: 失敗プレースホルダ要約の Knowledge Home 汚染を防ぎ、要約削除時に投影を同期する

## Status

Accepted

## Date

2026-11-28

## Affected Services

- pre-processor (Go) — `article_summarizer.go` の `savePlaceholder` および `summarize_queue_worker.go` の短文・長文プレースホルダ保存に `SkipVersioning: true` を設定し、失敗定型文の `SummaryVersionCreated` 発行を止める
- alt-backend / alt-data-hub (Go) — `SaveArticleSummary` に失敗定型文の多層防御ガードを追加し、`DeleteArticleSummary` で `SummaryRetracted` イベントを発行する
- knowledge-sovereign (Go) — `SummaryRetracted` イベントを `event-auth-policy.json` と `knowledge_home_projector` に登録し、`ClearKnowledgeHomeItemSummary` で対象行の要約・`supersede_state`・スコア・`summary_state` を再射影安全に巻き戻す

## Context

Knowledge Home 周辺の品質検証で、要約パイプラインと `knowledge-sovereign` 投影の間に 2 件の構造的汚染バグを確認した。

1. **失敗プレースホルダ要約が `summary_state = "ready"` かつ高スコア `0.8` で浮上する**:
   - `pre-processor/app/service/article_summarizer.go` の `savePlaceholder` は、本文が短すぎる・長すぎる記事に対して `"本文が短すぎるため要約できませんでした。"` 等の定型文を `article_summaries` に保存して再処理ループを防いでいる。
   - しかし `summary.SkipVersioning` を立てずに `DataHubService.SaveArticleSummary` を呼ぶため、`alt-data-hub` が通常の要約完了と同じく `summary_versions` と `SummaryVersionCreated` を発行し、`knowledge_home_projector`（[[000944]]）が `summary_state = "ready"`・`why: summary_completed`・`score = 0.8`（未要約記事の `0.5` より高優先）で投影していた。
2. **低品質要約の削除が `knowledge-sovereign` に伝わらない**:
   - `pre-processor` の `quality_checker` が低スコア（`< 7`）の要約を `DataHubService.DeleteArticleSummary` で削除しても、`alt-backend/app/dataplane/connect/datahubapi/article_summary_handler.go` は `alt-db` から削除するだけで `knowledge-sovereign` へイベントを送らない。
   - `UpsertKnowledgeHomeItem` はマージ安全設計（`COALESCE(NULLIF(...))` と `summary_state = GREATEST(...)`）のため、仮に空文字で再 upsert しても `ready` 状態や壊れた抜粋を巻き戻せない。

## Decision

1. **`pre-processor` のプレースホルダ保存で `SkipVersioning: true` を明示する**:
   - `pre-processor/app/service/article_summarizer.go` の `savePlaceholder` および `summarize_queue_worker.go` の `PlaceholderTooShort` / `PlaceholderTooLong` 保存で `SkipVersioning: true` を設定し、`DataHubService.SaveArticleSummary` に既存の `SUMMARY_VERSIONING_SKIP` を渡す。これにより `article_summaries` への処理済みマーカー保存を維持しつつ、`summary_versions` と `knowledge_events` への誤発行を止める。
2. **`alt-data-hub` の `SaveArticleSummary` に失敗定型文ガードを多層防御として置く**:
   - `alt-backend/app/dataplane/connect/datahubapi/article_summary_handler.go` でも既知のプレースホルダ失敗文言を判定し、古いクライアントや別経路から届いた場合も `createSummaryVersionUsecase.Execute` をスキップする。
3. **追記型の `SummaryRetracted` イベントを新設し、`DeleteArticleSummary` から発行する**:
   - `alt-backend/app/domain/knowledge_event.go` に `EventSummaryRetracted = "SummaryRetracted"` を定義し、`knowledge-sovereign/config/event-auth-policy.json` の `alt-data-hub`（および `alt-backend`）の `allowed_events` に追加する。
   - `DeleteArticleSummary` が `alt-db` からの削除に成功した後、`getArticleByID` で所有 `user_id`（および `tenant_id`）を解決できる場合に `AppendKnowledgeEvent` で `SummaryRetracted`（payload: `article_id`, `reason: "quality_deleted"`）を発行する。依存ポート未配線時は警告ログを明示出力する。
4. **`knowledge-sovereign` に `ClearKnowledgeHomeItemSummary` と `foldSummaryRetracted` を実装する**:
   - `sovereign_db` に記事単位で `summary_excerpt = ''`・`summary_state = 'pending'`・`supersede_state = ''`・タグ有無に応じた未閲覧スコア巻き戻し（タグあり `<= 0.7`、タグなし `<= 0.5`）かつ `why_json` から `summary_completed` を除去する専用パッチクエリ `ClearKnowledgeHomeItemSummary` を追加する。
   - `knowledge_home_projector` の `foldEvent` で `SummaryRetracted` を処理し、イベントログからの全量再射影でも同一結果が再現される（reproject-safe）ようにする。

### 検討した代替案

- **既存の `SummarySuperseded` を流用する**: 退けた。`foldSummarySuperseded` は置換後の要約が存在する前提で `supersede_state` のみを立て、`summary_excerpt` や `summary_state = 'ready'` を消去しないため、削除同期の要件を満たさない。
- **`UpsertKnowledgeHomeItem` の `GREATEST` を緩める**: 退けた。通常の順不同イベント再生で `pending` が `ready` を上書きする退行を防ぐための重要な不変条件であり、明示的な取消イベント専用のパッチメソッドに分離する方が安全である。

## Consequences

### Pros

- 要約不可のプレースホルダ文言が「要約完了（高スコア `0.8`）」として Knowledge Home や後続の要約参照を汚染しなくなる。
- `quality_checker` による低品質要約の削除がイベント経由で `knowledge_home_items` に反映され、`alt-db` と `knowledge-sovereign` の乖離が解消する。
- append-first と reproject-safe の不変条件を保ったまま取消を表現できる。

### Cons / Tradeoffs

- 本 ADR 適用前に既に発行された過去のプレースホルダ `SummaryVersionCreated` イベント自体は追記ログに残るため、既存行の掃除には後続のクリーンアップまたは再要約が必要になる。
- `DeleteArticleSummary` の RPC 契約には `user_id` が含まれないため、記事行が既に削除済みのケースでは `SummaryRetracted` をスキップする（警告ログを記録する）。
