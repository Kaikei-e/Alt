# ADR-001022: モバイルの起動面を /today にし、ボトムナビを Today / Swipe / Gallery / Search / Menu に組み替える

## Status

Accepted

## Date

2026-11-18

## Affected Services

- alt-frontend-sv — `/` のリダイレクト先変更、`/today` ルートの新設、`NAV_TABS`・`MOBILE_MENU_SECTIONS`・`getActiveTabIndex` の組み替え
- alt-harvester — `today_entrance_ready` 通知の遷移先 URL を `/home` から `/today` へ変更

## Context

[[001015]] で定めた段階 R2 として、モバイルの起動面とボトムナビを「読む・読ませる」中心の構成へ組み替える。

現状のコードは次の状態にある。

- `alt-frontend-sv/src/routes/+page.server.ts` は認証済みセッションに対して `/` から `/home` へ 303 リダイレクトを返している（`alt-frontend-sv/src/lib/server/redirect-resolver.ts` は旧 `/desktop/*`・`/mobile/*` パスの安全ネットのみを担当し、`/` は扱わない）。
- `alt-frontend-sv/static/manifest.webmanifest` は `id` と `start_url` のいずれも `"/"` を指定している。
- `alt-frontend-sv/src/routes/(app)/` 配下に `/today` ルートは存在しない。
- `alt-frontend-sv/src/lib/config/navigation.ts` の `NAV_TABS` は、[[000716]] で統合された後に [[000903]] と [[000940]] を経て、現在は `Home` (`/home`)、`Trail` (`/knowledge/trail`)、`Search` (`/search`)、`Augur` (`/augur`)、`Menu` (`/menu`) の 5 タブになっている。Swipe (`/feeds/swipe/visual-preview`) と Gallery (`/feeds/visual-preview`) は `MOBILE_MENU_SECTIONS` の `Browse` に置かれている。
- `alt-backend/app/orchestrator/job/today_entrance_notifier.go`（`alt-harvester`）の `today_entrance_ready` 通知は、遷移先定数 `todayEntranceNavigate` を `"/home"` に設定している。

2026-11-17 時点の本番データを読み取り専用で計測した結果（直近 15 日の RPC 呼び出し回数）、`GetKnowledgeHome` は 13 回、`GetTrail` は 7 回、`StreamChat`（Augur）は 0 回であり、毎日使われているのは Gallery と Swipe だけである。

## Decision

1. **`/` は `/today` へ 303 で遷移させる。** 遷移先の変更は `alt-frontend-sv/src/routes/+page.server.ts` の 1 箇所で行う。同じルートのフォールバック表示（`+page.svelte`）のリンクも `/today` に合わせる。`alt-frontend-sv/static/manifest.webmanifest` の `start_url` と `id` は `"/"` のまま変えない。理由は、インストール済み PWA の同一性を維持したまま、サーバー側のリダイレクト変更だけで起動面を切り替えられるためである。
2. **`/today` を新設する。** `alt-frontend-sv/src/routes/(app)/today/` を新設し、画面上部に「今日読む」キュー（[[001021]]）を表示する。キューが空のときは Swipe (`/feeds/swipe/visual-preview`) と Gallery (`/feeds/visual-preview`) への入口を出す。理由は、ユーザーが読むと決めた記事へ迷わず戻れる起動面を設けるためである。
3. **ボトムナビを Today / Swipe / Gallery / Search / Menu に組み替える。** R2 で `alt-frontend-sv/src/lib/config/navigation.ts` の `NAV_TABS` を `Today` (`/today`)、`Swipe` (`/feeds/swipe/visual-preview`)、`Gallery` (`/feeds/visual-preview`)、`Search` (`/search`)、`Menu` (`/menu`) に組み替える。あわせて `alt-frontend-sv/src/lib/components/mobile/bottom-nav.ts` の `getActiveTabIndex` を新タブ構成に合わせて更新する。現在タブにある `Home` (`/home`)、`Trail` (`/knowledge/trail`)、`Augur` (`/augur`) は削除せず `MOBILE_MENU_SECTIONS`（Menu）に移す。`Swipe` と `Gallery` は `NAV_TABS` との `href` 重複を防ぐため Menu から外す。なお、R3 で `Search` タブをテーマページの面（Knowledge）に替えるかどうかは R3 の利用実績を見て決め、この ADR では決めない。理由は、毎日使う面と「今日読む」の入口を 1 タップに置きつつ、既存面への導線も Menu に残すためである。
4. **Web Push の `today_entrance_ready` の遷移先を `/today` にする。** `alt-backend/app/orchestrator/job/today_entrance_notifier.go` の `todayEntranceNavigate` を現状の `"/home"` から `"/today"` に変更し、対応するテストと Pact 契約を更新する。理由は、通知をタップした利用者を新しい起動面へ直接着地させるためである。
5. **ボトムタブバーを常に出す方針（[[000716]]）は引き継ぐ。** モバイルでは `ResponsiveLayout.svelte` によるボトムタブバーの常駐表示を引き継ぐ。ただし、Swipe 面の没入表示（非表示の例外）は [[001020]] に従う（[[000948]] の没入モードを引き継いだもの）。理由は、ナビゲーションの一貫性を保ちつつ、スワイプ時の誤タップを防ぐためである。
6. **デスクトップのシェルはこの ADR では変えない。** `Sidebar.svelte` を中心とするデスクトップのナビゲーションは現状のまま残す。理由は、[[001015]] の方針どおりモバイルから先に作り直すためである。
7. **UI の文言は英語（`Today` / `Read today`）とする。** ナビゲーションのタブ名とキューの見出しを既存の英語表記（Search / Menu 等）と揃える。理由は、既存モバイル UI と表記を統一するためである。

### [[000627]] の Decision 各項目の扱い

[[000627]] の Decision には、この ADR が扱わない項目が含まれる。そのため [[000627]] 全体は置き換えず、一部を改める関係（`depends-on`）にする。各項目の扱いは次のとおり。

- **全体方針（Knowledge Home 中心のシェルと 5 タブ bottom navigation）**: 5 タブの bottom navigation は [[000716]] を経て引き継ぐ。中心の面を Knowledge Home とする点は `/today` に改める。
- **1. MobileBottomNav**: 5 タブの構成を `Today / Swipe / Gallery / Search / Menu` に改める。safe-area 対応と `getActiveTabIndex` のパス優先判定の枠組みは引き継ぐ（pill インジケータと `HIDE_PATHS` は既に [[000628]]・[[000716]] で置換済み）。
- **2. ResponsiveLayout 統合**: `ResponsiveLayout.svelte` に `MobileBottomNav` を統合し `<main>` に下余白を取る構造を引き継ぐ。
- **3. ランディング redirect 変更**: `/` の遷移先を `/home` から `/today` に改める。同じ項目にある `dashboard/+page.svelte` と `settings/feeds/+page.svelte` の `/home` への遷移は変えない。[[000627]] の決定のまま残る。
- **4. FloatingMenu → MobileMoreSheet 降格**: 既に [[000639]]・[[000716]] で Menu タブへ置換・廃止済みであり、この ADR は Menu タブの構造を引き継ぐ。
- **5. Knowledge Home モバイルブランチ再構築**: `(app)/home/+page.svelte` の内部のモバイル構成は変えない。[[000627]] の決定のまま残る。
- **6. デザイン言語の強化**: Alt-Paper のモバイル向けタイポグラフィと CSS トークンの仕様は変えない。[[000627]] の決定のまま残る。
- **7. Redirect 負債解消**: `feeds/tag-verse/+page.svelte`・`dashboard/+page.svelte`・`settings/feeds/+page.svelte` の `/home` 向けの導線は変えない。[[000627]] の決定のまま残る。

### 検討した代替案

- **(a) 起動面を Swipe にする**: 退けた。読むと決めて「今日読む」に置いた記事へ戻るための専用の場所がなくなり、「読ませる」目的を果たせないためである。
- **(b) Home を起動面のまま残し「今日読む」のカードを足す**: 退けた。2026-11-17 時点の本番データ計測で Home は 15 日で 13 回しか開かれておらず、使われていない面を起点に残すと日常導線が散るためである。
- **(c) manifest の `start_url` を `/today` に変える**: 退けた。サーバー側の 303 リダイレクト 1 箇所で起動面の切り替えは完結し、manifest 変更はブラウザ側の更新反映時期に左右されるためである。

## Consequences

### Pros

- アプリ起動時と `today_entrance_ready` 通知タップ時の着地先が `/today` に統一される。
- 日常利用が集中している Swipe と Gallery を 1 タップで開けるようになる。
- `manifest.webmanifest` の `id` と `start_url` を維持するため、インストール済み PWA の挙動が壊れない。

### Cons / Tradeoffs

- `dashboard/+page.svelte`、`feeds/tag-verse/+page.svelte`、`settings/feeds/+page.svelte`、`+page.svelte` のフォールバックリンクには `/home` への導線が残る（整理の時期はこの ADR では決めていない）。
- R3 で `Search` タブをテーマページ（Knowledge）へ替えるかどうかは、この ADR では決めず R3 で判断する。
- `today_entrance_ready` の URL 変更に伴い、`alt-harvester` と `alt-data-hub` 間の Pact 契約とテストの更新が必要になる。
