# ADR-000987: Augur RAG パイプラインを品質主軸で全面刷新し、モデル世代交代を eval ゲートに固定する

## Status

Accepted

## Date

2026-09-01

## Affected Services

- rag-orchestrator (Go) — retrieval 5 段の再設計、chunker v10、rebuild エンジン、観測性
- rerank-server (Python) — モデル選択の設定化と推論予算の導出
- rag-db (PostgreSQL 18 + pgvector) — セキュリティ patch と vector 向けチューニング
- news-creator — 生成モデル候補の Modelfile 定義（ベースライン `gemma4-e4b-12k` は不変）

## Context

Ask Augur の品質不満（取りこぼし・的外れ引用・浅い回答・鮮度）を実測調査した結果、単一の
大障害と複数の無言欠陥に収束した。

- **embedding 全損**: 2026-08-02 のマイグレーションが `rag_chunks.embedding` を全消去したが、
  対応する backfill が一度も実行されなかった。調査時点でベクトル検索可能な文書は全 57,058 件中
  1,105 件（1.94%）のみで、約 1 ヶ月間 BM25 単独で稼働していた。エラーは一切出ず
  （NULL は `ORDER BY distance` で `NULLS LAST` に沈むだけ）、検知手段も存在しなかった。
  破壊側（マイグレーション）は毎デプロイ自動実行される一方、復旧側は追跡外のローカル
  スクリプトだったという非対称が根本原因。PM-2026-018 と完全に同型の再発である。
- **rerank が実質無効**: `RERANK_TOP_K=10` が「cross-encoder への入力上限」として実装されて
  おり、融合済み候補（最大 243 件を観測）を検索スコア順に 10 件へ切ってから rerank していた。
  11 位以下の正解を引き上げることが原理的に不可能で、コメント「Rerank 50 candidates to top 10」
  と実装が矛盾していた。
- **スコア空間の混線**: BM25 生スコアが [0,1] 較正済み前提の `RelevanceGate` 閾値で判定され、
  Fallback Rate 16.7%→58.3% の悪化として記録済み・未修正だった
  (docs/review/augur-fallback-rate-regression-analysis-2026-04-11.md)。
- **無言欠陥群**: `related_citations` が全 84 turn で空（nil クエリベクトルで pgvector アームが
  SQL から脱落 + 引用タイトル連結の AND 検索）、fallback 回答の非永続化（最悪の回答だけ履歴から
  消える）、agentic tool chat の 422（`content` の omitempty）、`tag_search` 恒常 0 件（架空の
  user_id フィルタ）、article-scoped intent が planner の語彙に存在せず常に上書きされ strategy が
  死にコード化（記事指定 7 会話中 5 件で対象記事を引用できず）。
- **観測の空白**: TTFT / 成功率メトリクスは 5 本のポストモーテムで再発行され全て OPEN のまま。
  全インシデントの検知手段がユーザ報告だった。
- **eval の形骸化**: golden set 12 件・ベースライン Pass 0%、CI 未接続。さらに committed の
  eval 資材に実記事タイトル・実会話クエリが混入しており、public リポジトリの情報衛生に反していた。

最新化の前提として 2026-09-01 に候補モデル・依存の鮮度監査を一次ソース（HF モデルカード /
LICENSE 実物 / GitHub releases / PyPI）で実施し、ライセンス方針（モデル・weights は MIT /
Apache-2.0 のみ）で全候補を篩った。現行生成モデルの Gemma 系ライセンスは方針と矛盾している。

## Decision

**品質（検索・回答品質）を主軸とし、既知バグを新設計の仕様として消滅させる全面刷新を採用する。
モデルの最終選定は本 ADR では行わず、golden set 上の A/B eval に委ねる。**

1. **eval ゲート**: golden set を 52 件（committed・完全合成）+ 実データ由来ケース
   （`eval/testdata/golden_cases.local.json`、gitignore、DB から read-only 生成器で再現可能）に
   分離。段階別メトリクス（Recall@K / nDCG@10 / MRR、rerank delta、citation recall）と
   プロファイル指定の A/B 実行・差分レポートを実装。**committed 資材に本番由来の記事 ID・
   タイトル・クエリを置くことを禁止**し、既存の混入（baseline レポート等）は削除した。
   CC-BY-SA の公開評価データセット（JQaRA / JMTEB 等）はライセンス方針に抵触するため
   自前 golden set のみを用いる。
2. **モデル候補（2026-09-01 検証、ライセンスは LICENSE 実物確認）**:
   - embedding: `bge-m3`（MIT、現行・対照）vs `cl-nagoya/ruri-v3-310m`（Apache-2.0、
     JMTEB 77.24）。Qwen3-Embedding-0.6B は日本語 Retrieval で 9pt 劣後のため降格。
     次元が 1024 以外のモデルが勝った場合、rag-db 列型の変更は**別 ADR を必要とする**。
   - reranker: 現行 `bge-reranker-v2-m3`（JQaRA 0.673）に対し `japanese-bge-reranker-v2-m3-v1`
     (MIT, 0.6918) / `japanese-reranker-base-v2` (MIT, 0.7845) /
     **`cl-nagoya/ruri-v3-reranker-310m` (Apache-2.0, 0.8688、第一候補)**。
     rerank-server は `RERANK_MODEL` で切替可能にし、ModernBERT 系の ONNX int8 export が
     現行依存 pin（optimum-onnx 0.1.0 / transformers &lt;4.58）で成立することを検証済み。
   - 生成: `gemma4-e4b-12k`（ベースライン残留。Gemma 系は新規候補から除外し、eval で敗れた
     場合のみ交代＝ライセンス矛盾の解消）vs `qwen3.5:4b`（Apache-2.0、Ollama 公式）vs
     `sarashina2.2-3b`（MIT、日本語実測値あり）vs `granite4.2:3b`（Apache-2.0）。
     Modelfile は定義のみで pull / 切替はしない。
3. **retrieval 再設計**: `SearchResult` / `ContextItem` に **ScoreKind**（vector / bm25 / rrf /
   rerank）を導入し、`RelevanceGate` と品質判定は較正済み空間（rerank）のみを閾値判定する。
   rerank は「融合候補 → cross-encoder（上限 `RERANK_MAX_CANDIDATES`=40、サーバ側予算
   10s ÷ 250ms/候補から導出）→ TopK 切り詰め」の順に修正。BM25 検索は並列化し、拡張クエリにも
   hybrid 検索を対称適用、ベクトル検索は 2 往復を単一 CTE に統合。timeout はサーバ 10s <
   クライアント 12s（compose）< Go 既定 15s の順序をコードとテストで固定。
4. **chunker v10 + 一回限りの全再構築**: 文境界を CJK 対応（v9 は日本語で文境界を検出できず
   固定長切断していた）、文境界オーバーラップ 0.15、merge-forward、設定を含むバージョン刻印。
   再構築は target（chunker × embedder バージョン）をパラメータとする専用 CLI
   （`rebuild enqueue` / `rebuild run`）で行い、冪等再開・無言 no-op の loud 検出・進捗 ETA を
   持つ。状態は rag-db にのみ置く（ローカルファイルのカーソルを廃止）。応急 backfill は行わず、
   新チャンカー + eval で選定したモデルによる 1 回の再構築に集約する（GPU 常駐 embedding の
   実測回帰に基づく見積りは全量で約 8 時間）。[[000620]] の HNSW DROP/REINDEX は現行の
   律速（埋め込み）では割に合わないため採らない。
5. **無言障害の根絶（rule 8）**: related_citations のエンコーダ配線と全空経路の loud 化、
   fallback 回答の永続化（`citations` JSONB の封筒形、マイグレーション不要）、agentic 422 の
   `content` 必須化、`tag_search` の user_id フィルタ除去、article-scoped intent の pin と
   `CandidateArticleIDs` 伝搬、Ollama の全ゼロ embedding 応答（上流の open バグ）を拒否する
   縮退ベクトルガード。
6. **観測性**: TTFT / ストリーム所要 / 回答経路別成功・fallback / rerank fallback / キャッシュ /
   **embedding カバレッジ（chunker × embedder バージョン別 gauge、target 自動追随）** の
   11 系列と、9 本のアラート（カバレッジ低下・fallback 率・TTFT p95・sampler 停止）を追加。
   本障害クラス（無音のコーパス劣化）を構造的に可視化する。
7. **基盤**: rag-db を `postgres:18.6`（28 CVE 修正）+ pgvector 0.8.6 に pin し、
   `shared_buffers` 1GB / `maintenance_work_mem` 1GB / `hnsw.ef_search` 100 /
   `hnsw.iterative_scan = relaxed_order` を conf 既定にする（従来は ef_search 40 が Stage1 の
   LIMIT を無言に切っていた）。rag-orchestrator の mem_limit は 128m → 512m。

**検討して不採用にした代替案**:
- *修理先行（世代交代は後）*: 再埋め込みの二重払いを避けるため不採用。既知バグは新設計の
  仕様として消す方針を採った。
- *応急 backfill（現行モデルで即復旧）*: 再構築 1 回の原則を優先し不採用。復旧は新スタックの
  再構築に集約する。
- *生成のリモート併用*: [[000943]] のローカル完結・劣化契約を維持。sovereignty を優先。
- *Ollama の版上げ・KV cache q8_0*: 前者は有効な変更が無く（17 日差）、後者は本ホストでの
  実測（生成 21% 低速化）に反するため不採用。
- *GraphRAG / 多段 agentic hop / 長コンテキストでの検索代替 / HyDE / vLLM / pgvectorscale /
  VectorChord・pg_search (AGPL)*: 規模・レイテンシ・ライセンスの不適合で不採用。
  Meilisearch BM25 + RRF (k=60) は 2026 年時点でも標準構成のため変更しない。
- *eval ハーネスの DeepEval 移行*: 段階別メトリクスと A/B 差分を持つ自前 Go ハーネスを
  構築済みのため不採用（依存追加に見合わない）。

## Consequences

### Pros

- 品質改善が golden set 上の数値で検証可能になり、モデル世代交代が「eval で勝った場合のみ」
  という再現可能な手続きに固定される。
- 既知の品質バグ（rerank 窓・スコア空間・article-scoped・無言 fallback 群）が新設計の仕様と
  テストで固定され、同型再発が構造的に困難になる。
- embedding カバレッジの gauge とアラートにより、本件のような無音のコーパス劣化が最大
  2 時間で検知される（従来は検知手段ゼロ）。
- 公開リポジトリの eval 資材から本番データが排除され、実データはローカル生成器で再現可能。
- lint 指摘は main 比で 36 件純減。全変更が `go test -race` / pytest / promtool green。

### Cons / Tradeoffs

- 再構築が完了するまで本番のベクトル検索は縮退（BM25 単独 + 新 rerank 窓）のまま。
  再構築バッチ（約 8 時間）と各モデルの pull はデプロイ判断として別途承認が必要。
- embedding 次元が 1024 以外のモデルが eval で勝った場合、列型変更の別 ADR と追加
  マイグレーションが必要になる。
- `buildOptions` がモデル名の部分文字列でサンプリング設定を分岐する暗黙結合が残る
  （候補タグ名が制約を受ける。既知の負債として記録）。
- optimum-onnx の transformers 上限 pin により、rerank-server は transformers のセキュリティ
  床を上げられない（上流 unresolved。export 専用イメージへの分割が将来の解法）。
- ライセンス方針の文言「MIT / Apache-2.0 のみ」は pgvector / pgvectorscale / pg_textsearch
  （PostgreSQL License）を字義上排除してしまう。方針側の明文修正が未決。
- 過去に commit された実データ（旧 baseline レポート等）は git 履歴に残存しており、本 ADR の
  範囲では削除していない（履歴の扱いは別判断）。

## Deploy-model 整合性セルフチェック

- 新設 compose service なし（既存 service の env / conf / image tag 変更のみ）
- one-shot init container なし。rebuild は CLI（`docker compose run`）として人間が起動する
- 新設名前付き volume なし
- **rolling 互換**として pass
