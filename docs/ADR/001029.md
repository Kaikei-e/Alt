# ADR-001029: 形式仕様ツールチェーンとして Tauto を本番非依存で導入し、配置規約・CI ゲート・撤退基準を確定する

## Status

Accepted

## Date

2026-11-27

## Affected Services

- `specs` (新設 `specs/tauto/` 配下の Tauto 形式仕様・機械検証済み定理・ベクタ出力ドライバ規約)
- `scripts` (`scripts/lint/tauto.sh`、`scripts/lint/canary_ledger.toml`、`scripts/altharness` のカナリア・生成物ドリフト検査・直叩き禁止、`.agents/rules/rule-ledger.md`)
- `ci-cd` (`Makefile` の `install-tauto`、`.github/workflows/formal-specs.yaml`、既存ワークフローの `specs/**` パス除外、`.dockerignore`・`.gitignore`)

## Context

Alt の障害記録（`docs/postmortems/`）と失敗パターン体系（FP-01〜FP-19）のうち、DI 配線漏れ・契約ドリフト・Compose / PKI / マイグレーション運用は既存の `alt-harness`・Pact・DocDag・kisage で機械的に捕捉できている。一方、複数サービスに点在する**純粋状態機械・資源保存則・ABA 防止・欠番放棄**といった中核不変条件では、個別ケースの単体テストだけでは境界の相互作用を取り切れず、パッチを重ねるたびに隣接バグが露呈する傾向がある（具体適用先の詳細は後続の個別 ADR で定義する）。

この層に機械検証済みの形式仕様と決定論的適合テストオラクルを導入するにあたり、Alt 固有の 5 つの制約を満たす共通ツールチェーンと CI ガバナンスを先に確定する必要がある。

1. **ライセンス制約（[[000988]]）**: Alt の依存許可リストは MIT / Apache-2.0 / PostgreSQL License に限定される。過去のポストモーテムで検討されていた `Hypothesis`（Python）および `go.sum` 残存の `rapid`（Go）はいずれも **MPL-2.0** であり、新規導入は [[000988]] に抵触する。
2. **本番ランタイム・安定版 Rust からの隔離**: Alt の主力バックエンドは Go / Python であり、Rust サービス 4 本（`plecto` / `recap-worker` / `rask-log-aggregator` / `rask-log-forwarder`）はすべて安定版 `rust-version = "1.99.1"` に固定されている。形式検証ツールチェーンは本番コンテナ・ランタイム・安定版 Rust ビルドに一切影響させてはならない。
3. **`sparse-checkout` および `ci-gate` との整合（[[001004]]・[[001011]]）**: 各サービスの CI ジョブは `sparse-checkout` で必要ディレクトリだけを取得するため、サービス側の通常テスト（`pytest` / `go test`）は形式検証バイナリに依存せず完結させる必要がある。また無関係な PR のビルドやデプロイを遅延させないパス限定トリガが必須である。
4. **ハーネス統一とサイレントパス防止（[[001028]]・R-13・R-22・R-25）**: Alt の品質ゲートは単一 Go バイナリ `scripts/altharness/alt-harness` と `scripts/lint/canary_ledger.toml`（現行 45 ターゲット）・生成物整合チェック（`internal/generated/diff.go`）・規則台帳（`max_judgment_rules = 6`）で統治されている。
5. **事前実測で判明した `Hihaheho/tauto` v0.1.0 の CLI 制約**: ローカルビルドした [Hihaheho/tauto](https://github.com/Hihaheho/tauto)（`v0.1.0`、**Apache-2.0 OR MIT**）で以下を実測確認した。ゲート設計でこれらをすべて塞ぐ必要がある。
   - tote 名は **`[a-z][a-z0-9-]*`（アンダースコア `_` 不可）** が強制され、`_` を含むと `tauto init` / `tauto check` が終了コード 1 で失敗する。
   - `tauto --offline proof-status --json <空ディレクトリ>` は **終了コード 0**（`files: 0, ok: 0`）を返す（R-13 / C-21 サイレントパス）。
   - `pub axiom ...` を含むファイルでも `proof-status --json` と `tauto lint --json` は **終了コード 0** を返す（JSON 内 `axioms` 配列検査が必須）。
   - tote ディレクトリ名と `Tauto.eure` の `package.name` が不一致でも `proof-status` は終了コード 0 になる一方 `check` は終了コード 1 で失敗するため、**`check` と `proof-status --json` の両方**が必須。
   - `tauto fmt --check` はディレクトリ引数を受け付けず（`EISDIR`）、ソート済み `*.taut` ファイル列を渡す必要がある。
   - tote 内別ディレクトリ（`vectors/emit.taut` 等）から `src/` を参照する場合は相対文字列 import（`import "../src/<file>.taut" { ... }`）を使い、明示シンボル一覧 `{ ... }` を付けないと `tauto lint --json` が `import-list` 違反で失敗する。

## Decision

**Alt のオフライン形式仕様・適合テストオラクル基盤として [Hihaheho/tauto](https://github.com/Hihaheho/tauto)（`Apache-2.0 OR MIT`）を本番ランタイム依存ゼロで採用し、リポジトリ配置規約・サプライチェーン固定・`alt-harness` / CI ゲート・撤退基準を確定する。**

本決定は [[000988]]・[[001004]]・[[001011]]・[[001028]] を前提・拡張とし、既存 ADR を置換しない。個別サービスへのモデル適用と証明対象の定義は、本 ADR に依存するサービス別の後続 ADR に分離する。

### 1. リポジトリ配置規約と本番ランタイム非依存境界

- **形式仕様の配置**: リポジトリ直下に `specs/tauto/<tote>/` を新設する。`tauto` の識別子制約（`[a-z][a-z0-9-]*`・アンダースコア不可）に従い、ディレクトリ名と `Tauto.eure` の `package.name` をハイフン区切りで一致させる（将来別ツールへ移行する場合も `specs/<tool>/` で衝突しない）。
- **純粋証明部とベクタ出力ドライバの分離**: 各 tote 内は以下 2 ディレクトリに分離する。
  - `src/`: 純粋 `inductive enum`・純粋 `fn`・`pub theorem` のみを置き、`proof-status` で `skipped == 0` を強制する。
  - `vectors/`: `import "../src/<file>.taut" { ... }` の明示リスト相対 import と `perform show` を用いて決定論的適合ベクタを出力するドライバを置く。
- **サービス非侵入の配置理由**: `<service>/spec/` のようにサービス配下へ置かないことで、証明のみの編集が Compose ビルドコンテキスト・`docker-build.yaml`・`dispatch-deploy.yaml`・対象サービス CI を不要発火させることを防ぐ。
- **適合テストベクタの配置（[[001011]] 準拠）**: `tauto --offline run` が生成するプレーンテキストのゴールデンベクタを、各消費サービスの `testdata/` 配下へコミットする（先頭行に `# Code generated by tauto 0.1.0 from specs/tauto/<tote>; DO NOT EDIT.` を付与し、再生成は Makefile / シェル経由で行う — `guard-scope` が `DO NOT EDIT` ファイルの直接編集を遮断するため）。これにより各サービスの通常 `pytest` / `go test`・`sparse-checkout`（[[001011]]）・本番 Docker イメージは `tauto` バイナリおよび専用 Rust ツールチェーン（`1.100.0`）に一切依存しない。

### 2. ツールチェーン固定と安定版 Rust（`1.99.1`）からの完全隔離

- **サプライチェーンとライセンス（[[000988]] 準拠）**: `Hihaheho/tauto`（`Apache-2.0 OR MIT`）は許可リスト内。取得元は GitHub・`static.rust-lang.org`・`crates.io`（`--locked`）のみとし中国インフラを経由しない。
- **`Makefile` の `install-tauto`**: `install-lkal` / `install-kisage` と同型で追加し、`KISAGE_PURE_GOALS`（`.env` 非読込リスト）へ登録する。40 桁 commit SHA（`TAUTO_COMMIT ?= a6bb593f85e6dcc5ef53ba7a28c43d1f65f410a6`）・`TAUTO_VERSION ?= 0.1.0`・`TAUTO_RUST_TOOLCHAIN ?= 1.100.0`（上流 `rust-toolchain.toml` の `channel = "1.100"` に整合）を固定し、`mktemp -d` 内で `RUSTUP_TOOLCHAIN=$(TAUTO_RUST_TOOLCHAIN) cargo build --locked --release -p tauto-cli --bin tauto` を実行して `$(HOME)/.local/bin/tauto` へ原子配置する（オフライン用 `TAUTO_SRC_DIR` も併設）。
- **安定版 Rust（`1.99.1`）隔離ルール**:
  - Alt リポジトリ配下に `tauto` 用の `rust-toolchain.toml` や `Cargo.toml` を一切置かず、`rustup default` も変更しない。
  - CI ではコンパイル済み `tauto` バイナリ（約 80 MB）のみを `actions/cache`（キー: `tauto-${{ runner.os }}-${{ runner.arch }}-<TAUTO_COMMIT>-<TAUTO_RUST_TOOLCHAIN>`）でキャッシュし、キャッシュヒット時は専用 Rust ツールチェーン自体をインストールしない（`target/` はキャッシュせず [[001004]] のキャッシュ予算を守る）。未キャッシュ時の導入は `if [ ! -x "$HOME/.local/bin/tauto" ]; then make install-tauto; fi` とし、ワークフロー YAML 内の `run:` ブロックで `tauto` コマンドを直叩きしない。

### 3. 統一 lint ゲート・`alt-harness` 統合・パス限定 CI（[[001028]]・[[001004]] 準拠）

- **単一エントリポイント `./scripts/lint/run.sh tauto`**: 名前付きターゲット `scripts/lint/tauto.sh`（実体は `scripts/altharness/internal/lang/tauto.go`）を追加し、以下を fail-fast かつゼロサイレントパスで検証する。
  1. `tauto --version` 一致確認（未導入時は即 exit 1）。
  2. `alt-harness canary tauto-canary`（`mktemp -d` 上で偽定理→exit 1、hole `?h`→exit 3 かつ `lint` exit 1、公理混入→JSON `axioms` 非空をカナリア実証、R-13 / R-25）。
  3. `specs/tauto/*/Tauto.eure` の検出件数 `>= 1` および各 tote の `src/*.taut` 件数 `>= 1` を強制（空ディレクトリ exit 0 封殺）。
  4. 各 tote に対し `tauto fmt --check <sorted *.taut>`、`tauto lint --json`（空配列 `[]`）、`tauto --offline check --summary --timeout 60 <tote>`、`tauto --offline proof-status --json <tote>/src`（`files > 0 && ok > 0 && failed == 0 && holes == 0 && incomplete == 0 && skipped == 0 && len(axioms) == 0 && externs == 0 && len(unread) == 0`）。
  5. `tauto --offline run <tote>/vectors/emit.taut` の出力とコミット済み `testdata/*_vectors.txt` の `diff -u`（ベクタドリフト検出）。
- **`alt-harness` 同期更新点**:
  - `scripts/lint/canary_ledger.toml` に `[targets."tauto"]`（ターゲット数 45 → 46）を追加し、`tauto-canary` を `scripts/altharness/internal/canary/ledger.go`（`validCanaryCommands`）と `scripts/altharness/internal/canary/audit.go`（`auditCommandNames`）の双方へ登録する。
  - `scripts/altharness/internal/generated/diff.go` に `.taut` ソース変更と `testdata/*_vectors.txt` の対応マッチャを追加する（R-22: 仕様未変更でのベクタ手編集を全 PR の `repo` / `harness` ゲートでブロック。`regen.go` には `tauto` 実行を入れず、非関連 PR に `tauto` バイナリを要求しない）。
  - `scripts/altharness/internal/workflow/shell.go` の `directLintTools` に `"tauto"` を追加し、CI ワークフロー YAML からの `tauto` 直叩きを禁止して `./scripts/lint/run.sh tauto` 経由を強制する。
  - `.agents/rules/rule-ledger.md` に機械強制された `R-45` を追加し（`max_judgment_rules = 6` を維持、新規 `判断` ルールを増やさない；`R-35`〜`R-44` は [[001037]]・[[001039]] が先行取得済みのため `R-45` を採番）、`.gitignore` に `specs/tauto/**/.tauto/` を追加して `alt-harness hygiene`（R-10）を維持する。
- **パス限定ワークフロー（`.github/workflows/formal-specs.yaml`）**:
  - `specs/tauto/**`、各適用 ADR が定めるモデル対象実装・テストファイル、`scripts/lint/**`、`scripts/altharness/**`、`Makefile`、自身を `paths:` に限定し、`ci-gate`（[[001004]]）経由で該当 PR のみを自動ゲートする。週次 `schedule` と `workflow_dispatch` でランナー更新によるビルド劣化を早期検知する。
  - `.github/workflows/docker-build.yaml`・`.github/workflows/dispatch-deploy.yaml` に `paths-ignore: ['specs/**']`、`.github/workflows/e2e-playwright.yml` に `'!specs/**'`、`.dockerignore` に `specs/` を追加する。

### 4. 検討した代替ツールと却下理由

選定は Alt 自身の 5 要件（① 任意の数値・イベント列に対する無制限帰納法証明、② 公理ゼロ JSON ゲート、③ 証明済み純粋関数からの決定論的適合ベクタ直接出力、④ [[000988]] ライセンス適合、⑤ オフライン単一バイナリ CI 実行と AI 対話証明ループ）を基準に評価した。

| 候補 | 公式リポジトリ・確認済みライセンス | 性質 | 評価・却下/補完位置づけ |
|---|---|---|---|
| **Tauto（採用）** | `github.com/Hihaheho/tauto`（`Apache-2.0 OR MIT`） | 依存型カーネル証明（無制限帰納法）＋内蔵 VM/evaluator によるベクタ出力＋JSON 証明支援 CLI | 5 要件をすべて満たし、単一キャッシュ済みバイナリで高速にオフライン検査できる。実験的 `0.1.0` リスクは固定 commit・パス限定 CI・撤退基準で封じ込める。 |
| **TLA+ / TLC** | `github.com/tlaplus/tlaplus`（`MIT`） | 時相論理＋有限状態明示モデル検査（JVM / TLC）、証明は TLAPS | 並行インターリービングや活性検証に強いが、TLC は有界検査であり無制限帰納法には別途 TLAPS が要る。JVM 依存と適合ベクタ抽出の接着コストが高いため主系には採らず、並行活性検証が必要な場合の補完候補とする。 |
| **Quint** | `github.com/quint-co/quint`（`Apache-2.0`） | 型付き実行可能 TLA 仕様言語・シミュレータ・Apalache 記号検査（`Apache-2.0`、JVM+Z3）・ITF JSON トレース | ライセンス適合・MBT トレース出力が優秀だが、無制限帰納法ではなく有界/確率検証。Tauto 撤退時の **有界状態機械向け第 1 フォールバック** と位置づける。 |
| **Lean 4** | `github.com/leanprover/lean4`（`Apache-2.0`） | 成熟した依存型定理証明支援系＋ネイティブ実行評価器 | ライセンス適合・成熟度では Tauto を上回る一方、CI に `elan` + Lake 構築が要り小規模モデルに対する運用重量が重い。Tauto 撤退時の **無制限帰納法向け第 1 フォールバック** と位置づける。 |
| **Hypothesis + `rapid` のみ（PBT 単独）** | `github.com/HypothesisWorks/hypothesis`（**`MPL-2.0`**）、`github.com/flyingmutant/rapid`（**`MPL-2.0`**、既存 `go.sum` に残存） | 実 Python / Go コードへのランダム化プロパティテスト | **`Hypothesis` の新規導入は `MPL-2.0` であり [[000988]] に違反する**。また有限サンプリングであり全入力証明にならない。 |
| **Kani** | `github.com/model-checking/kani`（`Apache-2.0 OR MIT`） | CBMC ベースの Rust 向けビット精密有界モデル検査器 | Go / Python サービスへ直接適用できず無制限帰納法も得られない（将来の Rust サービス検証候補に留める）。 |

### 5. 撤退基準とゼロダウンタイム撤回経路

以下のいずれかに該当した場合、後継 ADR で Tauto を撤退・移行する。

1. **ツールチェーン腐敗**: 固定した Rust `1.100.0` が GitHub `ubuntu-latest` 上でビルド不能となり 30 日以内に上流修正が無い、または上流が 6 ヶ月停止し Alt の更新を阻害した場合。
2. **健全性欠陥**: 偽の定理が公理ゼロで `tauto check` を通過する、または `proof-status --json` が失敗・hole・公理を黙殺する欠陥が判明した場合。
3. **保守コスト過大**: 連続する 2 本のモデル関連 PR で、証明更新コストが実装＋テスト変更コストの 3 倍を超過した場合、または `formal-specs.yaml` のインフラ起因フレーク率が 30 日間で 10% を超えた場合。
4. **破壊的仕様変更**: 上流アップグレードで既存 `.taut` 仕様の 50% 超の書き直しが必要になった場合。

**撤回経路（1 PR・本番影響ゼロ）**: コミット済みの `testdata/*_vectors.txt` は通常のプレーンテキスト回帰フィクスチャとしてそのまま各サービスのテストで生き残る。`.github/workflows/formal-specs.yaml`・`scripts/lint/tauto.sh`・`Makefile` / `scripts/altharness` / `canary_ledger.toml` の Tauto 項目を削除して本 ADR を supersede するだけで即撤回でき、必要に応じて **Lean 4** または **Quint** へ移行する。

本基盤は `Makefile`（`install-tauto` / `tauto-vectors`）・`scripts/lint/tauto.sh`・`scripts/altharness`（`lang/tauto.go`・`canary/tauto.go`・`generated/diff.go`・`workflow/shell.go`）・`scripts/lint/canary_ledger.toml`（46 ターゲット）・`.agents/rules/rule-ledger.md`（`R-45`）・`.github/workflows/formal-specs.yaml` として実装され、`./scripts/lint/run.sh tauto`・`repo`・`harness` および敵対的監査を通過したため `accepted` とした。

## Consequences

### Pros

- [[000988]]（MIT / Apache-2.0 / PostgreSQL License）準拠のまま、本番コンテナ・ランタイム・安定版 Rust `1.99.1` サービスへ一切影響させずに機械検証済み形式仕様基盤を導入できる。
- `tauto proof-status --json`・`tauto-canary`・`generated/diff.go` を [[001028]] の `alt-harness` と [[001004]] の `ci-gate` に統合することで、空ディレクトリ通過・公理混入・ベクタ手編集によるサイレントパス（FP-07 / R-13 / R-22）を機械的に封じられる。
- 基盤判断を個別サービスの仕様適用（[[001030]]・[[001031]]）から分離したことで、将来の追加適用やツール撤退時の影響範囲を `docdag query 001029 --ancestors` で明快に追跡できる。

### Cons / Tradeoffs

- **実験的ツールチェーン依存（`v0.1.0` + 固定 Rust `1.100.0`）**: `tauto` は未安定リリースであり、キャッシュミス時のソースビルド（約 3 分）と専用 Rust ツールチェーン `1.100.0` の維持リスクを負う（§5 の撤退基準で上限を管理する）。
- **モデルと実装の乖離リスク**: `tauto` は `.taut` の純粋関数のみを証明し、Go / Python / SQL 実装を直接型検査しない。乖離防止は有限の適合ベクタと `diff -u` / `generated/diff.go` に依存する。
- **ハーネス保守項目の増加**: `canary_ledger.toml`（45 → 46 ターゲット）・`lang/tauto.go`・`tauto-canary`・`generated/diff.go`・`rule-ledger.md`（`R-45`）の維持が加わる。
