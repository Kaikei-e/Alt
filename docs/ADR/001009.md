# ADR-001009: tag-generator のノイズタグを入力整形・品詞・ストップワードの各層で発生源から止める

## Status

Accepted

## Date

2026-11-12

## Affected Services

- tag-generator: 入力の整形（`input_sanitizer`）、英語の抽出（`english_extractor`）、日本語の抽出（`japanese_extractor`、`hybrid_extractor`）、タグの検証（`tag_validator`）、ストップワードの読み込み（`model_manager`）、イメージのビルド（`Dockerfile.tag-generator`）

## Context

Tag Verse（[[001008]]）の上位タグに、明らかなノイズが多数混ざっていた。

| 種類 | 例（記事数） |
|---|---|
| 機能語・伝聞動詞 | like（2,568）、said（1,793）、would |
| 年・数字だけの語 | 2026（2,579）、0、10 |
| URL・HTML の断片 | https、nbsp、amp |
| 日本語の時刻表現 | 午前 |

タグ名のブロックリストで隠すのではなく、どの層を通り抜けたのかを突き止めた。原因の確認では、UniDic（fugashi）と、KeyBERT 0.9.0 のソースを照合した。

- **英語の機能語**: KeyBERT の経路に、プロジェクトのストップワードが渡されていなかった。そのため scikit-learn の既定リストだけが効き、like と said が通った。KeyBERT を使わないフォールバックのトークナイザのリストには、would などの助動詞が無かった。さらに、ストップワードの資源が見つからないと警告を出して空集合で続行していた。
- **日本語の数詞・助数詞・副詞可能名詞**: UniDic は、数詞（2026）、助数詞（件、年）、副詞可能名詞（午前、同日）にも `pos1 = 名詞` を返す。抽出側は `pos1.startswith("名詞")` を満たす語をすべて受け入れていた。設定にあった `名詞-数詞` のようなハイフン付きの品詞名は、UniDic の出力とは一度も一致していなかった。
- **日本語の既定経路（`use_japanese_semantic=True`）**: KeyBERT 0.9.0 は、`vectorizer` が渡されると語彙を `vectorizer.fit(docs)` で作り、`candidates` を使わない（docstring にも "This is not used if you passed a `vectorizer`" とある）。その analyzer がすべての名詞を通しており、KeyBERT の出力も検証せずにタグへ追加していた。
- **URL・HTML の断片**: `SanitizationConfig.strip_urls` は定義されていたが、どこからも読まれていなかった。また `nh3.clean` が `&nbsp;` や `&amp;` を再エスケープするため、実体参照がそのままトークナイザに渡っていた。

## Decision

ノイズの種類ごとに、それが入り込む層で止める。タグ名のブロックリストには頼らない。

- **入力の整形**: インラインの URL を既定で取り除く（`strip_urls=True`）。HTML の実体参照は、`nh3` で掃除したあとに 1 回だけ復号する。整形後のテキストはトークン化の入力専用とし、その旨を docstring とテストで固定する。
- **英語**:
  - KeyBERT の stop words は、scikit-learn の `ENGLISH_STOP_WORDS` とプロジェクトのリストの和集合にする。
  - scikit-learn は dev 依存グループに入っておらず、import できない場合に別の経路へ切り替えるとサイレントフォールバックになる。そこで、318 語のリストを正確に同梱する。
  - プロジェクトのリストに足すのは閉じた語類（助動詞、機能語、伝聞動詞）に限る。話題を表す動名詞（reporting、making など）は入れない。
  - 2 文字の単語は、元の文で全大文字のとき（AI）か、数字を含むとき（5G）だけ残す。
  - 重複判定で同じ語とみなすのは複数形（s / es）だけにする。market と marketing、stream と streaming は別のタグとして残る。
- **日本語**:
  - 単一トークンの候補からは、数詞・助数詞可能・副詞可能（および助動詞語幹）を除外する。これは頻度経路と KeyBERT の analyzer の両方に適用する。
  - 複合語では、内側の数詞や助数詞を残す（二酸化炭素、5G通信、2026年問題）。複合語を捨てるのは、話題を表す名詞を含まない場合と、全体が「数字＋助数詞」の場合（2026年、午前10時）だけである。
  - KeyBERT の出力は、候補集合、ストップワード、`is_valid_japanese_tag` の 3 つで検証してから使う。
  - 時刻を表す語のストップワードは、品詞では除けない語（夜間など）だけを残す。
- **検証**: 数字だけの語と年を拒否する。URL・HTML の断片はタグ全体が一致する場合だけ拒否する。部分一致だと「net neutrality」「HTTP API」まで落とすためである。
- **fail-fast**:
  - ストップワードの資源が欠けている場合は `ModelLoadError` で止める。
  - イメージのビルド時に、`nltk.data.find` で NLTK の `stopwords` と `punkt_tab` が揃っていることを確かめる。`nltk.download` は失敗しても False を返すだけなので、ビルドの時点で落とさないと、壊れたイメージが起動後に 503 を返し続けることになる。

### 検討して却下した案

- **タグ名のブロックリスト**: 観測された語しか止められず、同じ種類の新しい語（数字や URL の断片）を取りこぼす。
- **tag cloud の SQL や UI 側でノイズを除外する**: タグは Tag Verse 以外（Knowledge Home、検索、Recap）でも使われるため、表示側だけで隠しても誤ったタグは残り続ける。
- **scikit-learn を import できなければ同梱リストへ切り替える**: サイレントフォールバックになり、どちらのリストが効いているのかが実行環境ごとに変わる。
- **KeyBERT の既定経路で複合語を出せるようにする**（vectorizer が候補そのものを返す形にする）: タグの粒度が変わり、「二酸化炭素の排出削減」のような長い句がタグになる。ノイズ除去とは別の判断なので、この ADR の範囲外とした。

## Consequences

### Pros

- 新しく付くタグから、機能語、年や数字、URL・HTML の断片、時刻表現が消える。既定の日本語経路を、KeyBERT と同じく vectorizer から語彙を作るテストダブルで通して確認した。この経路で 午前 / 2026 / 10 / 件 / 同日 がタグになる件数は 0 だった。現行のコードでは、10 タグすべてがノイズになる文書もあった。
- 二酸化炭素、二要素認証、5G通信、3Dプリンター、2026年問題などの複合語と、AI、5G、C++、GPT-4 などの短い技術語は残る。
- 資源の欠落は、起動時またはビルド時に表に出る。

### Cons / Tradeoffs

- **保存済みのタグは変わらない。** tag cloud は全期間で集計し、再タグ付けの経路（`UpsertArticleTags`）はリンクを追加するだけで古いものを消さない。そのため、既存のノイズは画面に残る。是正方法は、次のいずれかを別途決める必要がある。
  - 置き換え型の再タグ付けを実装し、[[000399]] の版管理に沿って全記事を付け直す
  - 投影テーブルから SQL で削除する
  - tag cloud の集計期間を絞る
- **日本語の既定経路は単一形態素しか出せない。** KeyBERT の語彙が analyzer の出力になるためで、この変更以前からの制約である。「生成AI」は「生成」と「AI」に分かれ、複合語は頻度経路からしか出ない。
- 複数形による重複判定は、new と news、arm と arms をまとめてしまう。
- 小文字で書かれたプログラミング言語名の go は、ストップワードと 2 文字の規則で落ちる。
- 整形後のテキストは、エンコードされたマークアップが復号された形になる。トークン化の入力専用である。
- ストップワードを fail-fast にしたので、イメージのビルドで NLTK データの取得に失敗すると、そのビルドは失敗する。
