# ADR-001019: 記事リーダーを 1 本に統合し、URL 付きの重ね表示で開き、既読のきっかけを「開いた」から「読んだ」に変える

## Status

Accepted

## Date

2026-11-18

## Affected Services

- alt-frontend-sv — `src/lib/reader/` の新設、各面のリーダー呼び出し置換、`/feeds/swipe` 削除と遷移設定
- alt-backend — `TrackHomeActionUsecase` の `open` 起因の既読同期削除

## Context

[[001015]] の R1（リーダーの一本化）に対応する決定である。2026-11-17 時点の本番データを読み取り専用で計測したところ、既読操作の間隔は中央値 1.31 秒であり、日常利用は Gallery（`/feeds/visual-preview`）と Swipe（`/feeds/swipe/visual-preview`）に限られる。

現状の `alt-frontend-sv` には記事本文を読み込む実装が 7 箇所に分かれており、滞在計測や読了判定を 1 箇所で扱えない。

- Gallery と各一覧のモーダル（`src/lib/components/desktop/feeds/FeedDetailModal.svelte`）: `/feeds/visual-preview`、`/feeds`、`/home`、`/feeds/favorites`、`/feeds/search`、`/feeds/viewed` で共有される。本文取得に `getFeedContentOnTheFlyClient`、表示に `RenderFeedDetails`、要約に `streamSummarizeWithAbortAdapter`、読み上げに `createSummarySpeech`、記事末に `ArticleEndBranches` を持つ。
- Swipe 通常カード（`src/lib/components/mobile/feeds/swipe/SwipeFeedCard.svelte`）: `/feeds/swipe` で使われる。本文取得に `requestContent` または `getFeedContentOnTheFlyClient`、表示にカード内 `{@html}`、要約に `streamSummarizeWithAbortAdapter` と `summarizeArticleClient` を持つ。
- Swipe Visual Preview カード（`src/lib/components/mobile/feeds/swipe/VisualPreviewCard.svelte`）: `/feeds/swipe/visual-preview` で使われる。本文取得に `requestContent` または `getFeedContentOnTheFlyClient`、表示にカード内 `{@html}`、要約に `streamSummarizeWithAbortAdapter` と `summarizeArticleClient`、読み上げに `createSummarySpeech` を持つ。
- 独立記事ページ（`src/routes/(app)/articles/[id]/+page.svelte`）: URL と題名解決（`45-96` 行）、リトライ付き本文取得 `fetchContent` と自動取得（`98-317` 行）、要約 `useSummarize`（`121, 284-292` 行）、`RenderFeedDetails` と `ArticleEndBranches`（`516-529` 行）、デスクトップ用 rail（`537-562` 行）を持つ。読み上げは無い。
- モバイル下部シート（`src/lib/components/mobile/FeedDetails.svelte`）: `FeedCard.svelte`、`/feeds/viewed`（`MorgueClipping.svelte`）、`/feeds/favorites`（`ClippingsEntry.svelte`）から使われ、`getArticleSummaryClient` と `getFeedContentOnTheFlyClient`、`RenderFeedDetails`、`streamSummarizeWithAbortAdapter` を持つ。
- Desktop Tag Trail パネル（`src/lib/components/desktop/articles/ArticleDetailPanel.svelte`）: `getFeedContentOnTheFlyClient`、`RenderFeedDetails`、`useSummarize` を持つ。
- モバイル検索結果展開（`src/lib/components/mobile/search/SearchResultItem.svelte`）: `getFeedContentOnTheFlyClient`、`RenderFeedDetails`、`getArticleSummaryClient` を持つ。

要約は `useSummarize`（2 箇所）と `streamSummarizeWithAbortAdapter` 直呼び（4 箇所）と `getArticleSummaryClient`（1 箇所）に分散している。読み上げ（`createSummarySpeech`）は `FeedDetailModal` と `VisualPreviewCard` に重複し、`/articles/[id]` には無い。なお [[000917]] が導入した `TtsPlaybackStore` や `TtsMiniPlayer` 等のコンポーネントは過去の整理で既に撤去済みである。

SvelteKit の版は `3.0.1` であり、`src/routes/(app)/augur/+page.svelte` で `goto(..., { shallow: true })` が使われているほか、`ResponsiveLayout.svelte` や `useTrailOutcome.svelte.ts` に `shallow` 判定が備わっている。一方、`/feeds/swipe` ルートと `src/lib/server/redirect-resolver.ts` の `/mobile/feeds/swipe` から `/feeds/swipe` への転送が残存している。

また `alt-backend/app/orchestrator/usecase/track_home_action_usecase/usecase.go`（`openMarkReadAllowedSources`）は、`open` アクション時に `source` が `""`・`"feed_detail_modal"`・`"mobile_feed_details"` の場合に `MarkArticleAsRead` を実行している。[[000994]] 本文は `"home_card"`・`"article_page"`・`"favorite"` に限ると記しているが、実装および `usecase_test.go` と食い違っている。

## Decision

1. **単一リーダーの抽出**: `src/routes/(app)/articles/[id]/+page.svelte` を母体にして、`alt-frontend-sv/src/lib/reader/` を新設し、記事リーダーを 1 本に統合する。本文の取得、要約、読み上げ、滞在の計測、記事末の表示をこの中に置く。理由は、現状 7 箇所に分かれた本文読み込みとリトライ・表示処理を集約し、滞在と末尾到達を 1 箇所で正確に測るためである。
2. **URL 付きの重ね表示**: Gallery や Swipe からは、SvelteKit の shallow routing（`$app/navigation` の `pushState` / `replaceState` または `goto(..., { shallow: true })` と `page.state`）を用い、URL を `/articles/<article_id>` に変えつつ下の面を破棄しない重ね表示で開く。ブラウザの戻る操作では、元のスクロール位置と Swipe のカード山に戻る。リロード、URL 共有、通知から直接開いたときは単独の記事ページ（`/articles/[id]`）として描画する。理由は、通常遷移では Swipe の山や Gallery の一覧位置が失われ、URL の無いモーダルでは共有やリロード復元ができないためである。
3. **文脈の受け渡しと機能の集約**: 次の記事へ進む操作、要約、読み上げは新設するリーダーの中に置く。読み上げは [[000992]] の決定を引き継ぎ、現状コードに残る `createSummarySpeech` を基盤にする。[[000917]] が導入した mini-player などの構成要素は撤去済みであり、この ADR では復活させない。どの面から開いたかと前後の記事リストは、文脈としてリーダーに渡す。理由は、面ごとの重複操作と読み上げ実装の分裂をなくすためである。
4. **開始イベントの送信**: リーダーが開いたときに `reading.opened.v1` を送信する（[[001018]]）。理由は、読書セッションの起点をすべての導線で統一するためである。
5. **既読化の契機変更**: 記事を既読にするきっかけを「開いた」から「読んだ」（[[001018]] の定義: 末尾到達または本文の長さに見合う滞在）に変える。`TrackHomeActionUsecase` の `openMarkReadAllowedSources`（実装の事実は `""`・`"feed_detail_modal"`・`"mobile_feed_details"` であり、[[000994]] の記述とは異なる）による `open` 起因のサーバ側既読同期は、R1 の最後に外す。Swipe で払ったときの既読化は [[001020]] で扱う。理由は、記事を開いただけで既読にすると、流し見や途中離脱と読了を区別できなくなるためである。
6. **面ごとの段階的切り替え**: 切り替えは、リーダーの抽出 → Gallery（`/feeds/visual-preview`）→ Swipe（`/feeds/swipe/visual-preview`）→ 残りの面（`/feeds`、`/home`、`/feeds/favorites`、`/feeds/viewed`、`/feeds/search`、`/feeds/tag-trail`）→ 旧実装の削除の順に進める。旧実装を残したまま次の段階へ進まない。合わせて Swipe のカード内リーダーと `/feeds/swipe` ルートを削除し、`/feeds/swipe` および `redirect-resolver.ts` の `/mobile/feeds/swipe` を `/feeds/swipe/visual-preview` へ遷移させる。理由は、新旧リーダーの並存による二重保守を防ぐためである。
7. **デスクトップ詳細構成の維持**: デスクトップの記事詳細画面の 2 カラム構成（[[000754]] の editorial rail）は、この ADR では変えず、リーダーの本体を共有するにとどめる。理由は、R1 の変更範囲をリーダー統一に絞るためである。
8. **記事末領域の確保**: リーダーの記事末尾に、[[001023]] のつながり表示を差し込む領域を用意する。この ADR の段階では枠の確保にとどめる。理由は、R3 で記事末の接続表示を後から無理なく組み込むためである。

### 検討した代替案

- **(a) 面ごとのリーダーを残して計測だけ足す**: 退けた。本文取得や要約と同様に、滞在計測と既読化の規則が 7 箇所に分かれて保守不能になるためである。
- **(b) URL を持たないモーダルで開く**: 退けた。戻る操作で期待どおりに閉じられず、URL の共有やリロード後の復元もできないためである。
- **(c) 常にページ遷移で開く**: 退けた。Gallery の無限スクロール位置と Swipe のカード山が遷移のたびに失われるためである。

## Consequences

### Pros

- 記事本文の取得・要約・読み上げ・滞在計測・末尾表示が 1 本のリーダーに集約される。
- URL 付きの重ね表示により、日常面の状態を保ったまま共有・戻る・リロード復元が成立する。
- 「開いた」ではなく「読んだ」で既読化するため、既読操作の信号が実際の読書行動と一致する。

### Cons / Tradeoffs

- `useSummarize`・`createSummarySpeech`・`RenderFeedDetails` を `src/lib/reader/` に統合するかフックとして残すかの内部構造と、重ね表示時のデスクトップ rail（[[000754]]）の見た目詳細は、この ADR では決めていない。
- 既読条件（滞在秒数と末尾到達のしきい値）の具体値は [[001018]] に委ねるため、単体では既読化タイミングを調整できない。
- R1 の移行途中では、Gallery・Swipe 以外の残存面が旧実装を呼ぶ期間が生じる。完了条件として全旧実装の削除を強制する。
- `SearchResultItem` のように `getArticleSummaryClient` のみを使う面を、新リーダーのストリーミング要約へ寄せるかそのまま閉じるかは、残りの面の切り替え時に判断する。
