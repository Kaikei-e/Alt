# ADR-000978: 14 本の pki-agent ワークロード sidecar を subject-scoped の in-process enrollment に置き換え dual-writer と unsafe な cross-revision を禁止する

## Status

Accepted

本 ADR はリポジトリ契約の GREEN を記録する。ホストへの cutover / rollback は行っていない。[[000747]] を置換しない。pki-agent バイナリと fail-closed な leaf ライフサイクルは残り、変わるのは実行場所（sidecar → 親プロセス）と provisioner の粒度である。

本 ADR は [[000774]] と [[000969]] を **supersede しない**。ADR 全体ではなく、次の条項だけを置き換える。

- **[[000774]]** — obsolete: pki-agent reverse-proxy sidecar の再導入、`PROXY_*`、netns Pattern B。残る: `validate_mtls_url_schemes`、`https://…:9443` URL、allowed-peers（現行は親の `MTLS_ALLOWED_PEERS`）。
- **[[000969]]** — obsolete: `pki-agent` scrape job、14 sidecar `:9510`、Pattern A vs B の DNS 補正。残る: Alertmanager + Pushover 配送。現行 scrape は 14 親 `:9110` の `pki_enrollment_*` と `absent()`。
- **[[000748]]** — nginx TLS sidecar 退役は維持。inbound TLS は親プロセス。proxy-mode を pki-agent に戻さない。

## Date

2026-08-19

## Affected Services

- pki-agent（tooling / bootstrap。compose ワークロードではない）
- compose/pki.yaml（step-ca / step-ca-bootstrap のみ）
- 14 east-west parents: alt-backend, alt-harvester, alt-data-hub, alt-notifier, alt-butterfly-facade, auth-hub, pre-processor, search-indexer, tag-generator, recap-worker, acolyte-orchestrator, recap-subworker, news-creator, rag-orchestrator
- observability（Prometheus scrape / pki-agent-alerts）
- pki-agent-recovery runbook

## Context

[[000747]] は compose 埋め込み shell の cert-init / cert-renewer を専用 Go サイドカー `pki-agent` に移した。その後の障害列（[[PM-2026-028]]〜[[PM-2026-034]]、[[PM-2026-054]]）は、sidecar が親と別プロセス・別 netns である限り再発するクラスだった。

- **Pattern B**（`network_mode: service:<親>`）は親 `--force-recreate` で netns が幽霊化し、inbound TLS が消える（[[000748]] [[000774]] [[000782]] [[000802]]）。Wave 4 受け入れテストは禁止トポロジが 0 件であることを pin する。
- 共有 `pki-agent` JWK provisioner は 1 侵害で任意 CN を偽造できる（[[000747]] F-001）。14 subject はそれぞれ `pki-agent-<subject>` を持つ。
- sidecar と親が同じ cert volume を書く **dual writer** は、in-process 移行の途中状態そのものが障害になる。混在 fleet は禁止。
- 旧イメージは `PKI_ENROLLMENT` を無視する。新 compose は sidecar が無い。この組み合わせは cert writer がゼロになり、平文フォールバックも無いので **unsafe**。
- 運用面では sidecar 14 本が accidental OSU を膨らませていた。最終カットオーバー後の会計は declared 91→77、long-running 77→63、accidental OSU 30→16、sidecar 14→0。init-edge allowlist は 22 のまま（親は引き続き `step-ca-bootstrap` を待つ）。

受け入れゲート（compose config / Wave 4 acceptance / subject-scoped provisioner / recovery runbook / observability-validate）はリポジトリ上で GREEN。シークレットバイトはリポジトリに無い。

## Decision

**east-west の leaf 発行と更新は、14 親プロセスの in-process enrollment が独占する。pki-agent ワークロード sidecar は 0 本とする。subject-scoped JWK、fail-fast、private `:9110`、zero dual-writer、cross-revision の deploy/rollback ロックを契約にする。**

### D1. 実行場所

最終 compose（現行リポジトリ）は各親に `PKI_ENROLLMENT=enabled` を明示する。空文字 `PKI_ENROLLMENT=""` は garbage として fail-fast する（Rule 9）。「Disabled」を本番 compose の未設定から推論しない。

過渡期（image-first mixed-mode。sidecar 時代の compose がまだ leaf を書く間）だけ、未設定（かつ `PKI_ENROLLMENT_FILE` も未設定）はコードに書いた **明示の一時デフォルト** として disabled になる。これは「欠けているから disabled」という沈黙推論ではない。新イメージを atomic compose cutover より先に載せても dual-writer にならず、かつ起動で落ちないための移行互換である。最終 compose 切替後は `enabled` が必須。この一時デフォルトを外して未設定も fail-fast にするのはホスト cutover 後の follow-up ADR であり、本 ADR の範囲外。

親イメージは `bootstrap.StartEnrollment`（または言語相当）を配線し、`/certs/svc-cert.pem` と `/certs/svc-key.pem` の唯一の writer になる。`pre_start` が `/certs` を親 uid:gid・mode 0750 に chown する（world-writable 禁止）。

旧 Pattern B 親（tag-generator / acolyte-orchestrator / recap-subworker / news-creator）は inbound TLS を親プロセスで終端する。`PROXY_LISTEN` / `PROXY_UPSTREAM` は置かない。`PEER_IDENTITY_TRUSTED` は off。`:9443` をホストへ publish しない。

### D2. subject-scoped JWK

- provisioner 名は `pki-agent-<CERT_SUBJECT>`。共有名 `pki-agent` は workload から禁止。
- パスワードは `secrets/pki-agent-<subject>-jwk.txt` → `/run/secrets/pki-agent-<subject>-jwk`。compose `secrets.file:` は欠落で fail-fast。
- `step_ca_root_password` は step-ca / bootstrap 専用。workload 親には載せない。
- `CERT_SUBJECT` は compose サービス名と一致。`CERT_SANS` は `<subject>,localhost`。
- bootstrap スクリプトは SUBJECTS ごとに JWK を足し、共有 `step ca provisioner add pki-agent` を実行しない。

### D3. private ops `:9110`

親は ops / metrics を `:9110`（Rust は `0.0.0.0:9110`）で bind し、ホストへ publish しない。Prometheus は 14 親の `:9110/metrics` を scrape する。`pki-agent*:9510` job は置かない。欠落は `absent()` で page する。

### D4. zero dual-writer

compose に `pki-agent-*` ワークロードを再宣言しない。残存コンテナは project=`alt` かつ service が `pki-agent-` で始まるものだけ stop+rm し、`docker ps` が 0 件になってから親を `up` する。`docker compose up --remove-orphans` は orphan 削除と親 recreate の順序を保証しないので leftover 掃除に使わない。Prometheus の pki-agent scrape は leftover 検知に使わない（job が無い）。

### D5. deploy / rollback ロック

| 方向 | 順序 | 違反時 |
|---|---|---|
| Forward | 新イメージ + 14 JWK ファイル + 14 subject-scoped provisioner を **compose より先に** | 旧 binary は enroll せず、sidecar も無い → writer ゼロ |
| Rollback | sidecar 時代の compose / sidecar を **旧イメージより先に**戻す。restore のあと leftover sweep を走らせない | 新 compose のまま旧 binary が走り enroll しない |

平文フォールバックと `InsecureSkipVerify` は採用しない。TLS は fail-closed。

### 検討した代替案

| 案 | 却下理由 |
|---|---|
| Pattern B sidecar を残す | netns orphan が `--force-recreate` のたびに再発する。inbound TLS を親に置けば cascade 自体が不要 |
| 混在 fleet（一部 sidecar / 一部 in-process） | 同一 volume の dual writer。障害面が二つに増える |
| 共有 JWK provisioner | [[000747]] F-001 のまま。1 漏洩で任意 CN |
| 発行失敗時に cleartext へ落とす | mTLS 不変条件を壊す。欠落は起動失敗が正しい |
| `depends_on.restart` / cascade スクリプトで sidecar を追従させる | force-recreate では発火しない（[[000782]]）。tombstone 化した `scripts/cascade-pki-sidecars.sh` を復活させない |

## Consequences

### Pros

- netns 共有 sidecar という障害クラスが構成から消える。親の `--force-recreate` に cascade は不要。
- provisioner 侵害の blast radius が 1 subject に閉じる。
- accidental OSU が 14 本減り、cert writer が 1 プロセス 1 volume になる。
- 欠落 JWK / 未配線 enrollment は起動時に fail-fast し、「disabled のつもり」と「DI 忘れ」が区別できる。

### Cons / Tradeoffs

- **リポジトリ GREEN ≠ ホスト cutover。** 本 ADR はデプロイしていない。オペレータ前提は (1) ホスト上の 14 JWK ファイル（repo に置かない、mode 0400）、(2) live step-ca への subject-scoped provisioner（`pki-agent/scripts/bootstrap-pki-provisioner.sh` は冪等）、(3) in-process enrollment を含む新イメージ、の三点が compose 適用より先にあること。シークレットを commit しない。
- 旧イメージと新 compose の交差は unsafe。deploy tooling が順序を破ると writer ゼロになる。
- leftover sidecar の掃除をオペレータが手順どおりやらないと dual-writer 窓が残る。
- pki-agent イメージは tooling として残るため、「サービスが消えた」と誤解すると bootstrap が止まって見える。責務は enrollment ではなく CA 側の provisioner / allowlist。
- Pattern B 親は inbound TLS 実装が言語ごとに親へ移った。hot-reload の対称性（サーバとクライアント）は [[000773]] のまま各親の責務。

## Deploy-model 整合性セルフチェック

sidecar を新設しない。enrollment は親イメージの起動経路にあり、rolling `up --no-deps <parent>` でも `pre_start` chown と in-process enroll が走る。`service_completed_successfully` の sibling init に cert を預けない。

- [x] 新設 compose service が `depends_on` で他 service を gate するか？ — 新設なし。削除した `pki-agent-*` への `depends_on` も無い。既存の `step-ca-bootstrap`（`restart: "no"` oneshot）待ちは従来どおり
- [x] 新設 compose service に `restart: "no"` の one-shot init container を含むか？ — 含まない。cert ディレクトリの chown は親の `pre_start`
- [x] 新設名前付き volume を populate する責務はどこにあるか？ — 既存 cert volume。writer は親プロセス。host 前提は 14 JWK + provisioner + 新イメージ（runbook に明文化）
- rolling 互換（cert ライフサイクルを rolling 非互換の sibling init に置かない）
