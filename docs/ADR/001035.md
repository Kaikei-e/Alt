# ADR-001035: ADR 参照時の docdag 利用をシェル初回保留ガードとスキル手順で定着させる

## Status

Accepted

## Date

2026-11-27

## Affected Services

- `scripts/altharness` (`internal/guards`, `internal/preflight`, `internal/selfcheck`, `cmd/alt-harness`)
- `.claude/settings.json`, `.codex/hooks.json`, `.agents/hooks.json`（3 エージェントの `PreToolUse` シェルフック配線）
- `.claude/skills/alt-adr-writer/` および `.agents/skills/alt-adr-writer`（`SKILL.md`, `references/frontmatter-and-validation.md`）
- `.agents/rules/rule-ledger.md`（`R-06` 強制手段・由来）

## Context

[[001032]] により本番コード変更前の ADR 先行起票は機械的に強制されたが、ADR を**読む**段階においてエージェントが `docdag context` を使わずシェルの `grep` / `rg` / `sed` / `cat` 等へ流れる問題が残っていた。

実運用では、`SessionStart` で「managed docs には `docdag` を使う」案内を出していても数十ターン後には効果が薄れ、実際に `depends-on` に列挙した 3 本の ADR を題名だけで選び依存先の `Decision` を読まなかった結果、[[000685]]（`Critic heuristic-first を品質チューニング段階へ進める` — LLM critic は引き続き補助的な最終手段に留める）との関係を新 ADR に書き落とす実害が発生した。また `docdag context <id> --section <見出し>` で任意の見出し（例: `Consequences`）を引けることが認知されておらず、「`Decision` 冒頭しか取れない」という誤認から `grep` / `sed` へ流れていた。

Alt の規則台帳（`rule-ledger.md` H11）および [[001032]] の方針どおり、長セッションで揮発する散文の注意書きに頼らず、**シェルで ADR を直接読んだ瞬間に 1 回だけ保留して具体コマンドを提示する機械ガード**と、**`depends-on` / `supersedes` の辺を張る前に依存先の `Decision` を 1 本ずつ読むスキル手順**を組み合わせる必要がある。ただし、`docdag` では表現できない本文全文の横断検索や全文精読を完全に塞ぐべきではないため、Read / Grep / Glob ツールは対象外とし、シェル側の保留もセッション内初回のみとする。

## Decision

ADR 参照時の `docdag` 利用を定着させるため、以下の 2 つの変更を採用する。

1. **`alt-adr-writer` に「辺を張る前の依存先 Decision 確認」手順を追加する**:
   - `.claude/skills/alt-adr-writer/SKILL.md`（`.agents/skills/alt-adr-writer` はシンボリックリンクで対称維持）の Phase 1（`--draft`）frontmatter 作成手順および §2.2 に、`depends-on` / `supersedes` に記載する各 ID は題名や他者の要約だけを根拠に選ばず、必ず 1 本ずつ `docdag context <id>`（必要に応じて `--section Consequences` 等）で `Decision` を読んでから記載し、新 ADR の内容と緊張関係がある場合は `## Context` または `## Decision` に明記する条件を追加する。
   - `.claude/skills/alt-adr-writer/references/frontmatter-and-validation.md` の `depends-on` 行にも同一条件を 1 文で追記する。
2. **シェル経由の ADR 読込を初回だけ保留するガード `alt-harness guard-adr-read` を追加する**:
   - **検知対象**: シェルコマンド（`Bash` / `run_command` / `shell`）において、`grep` / `egrep` / `fgrep` / `rg` / `sed` / `awk` / `gawk` / `mawk` / `cat` / `head` / `tail` / `less` が、`docs/ADR/\d{6}\.md`（相対パス・絶対パス・`.claude/worktrees/<name>/docs/ADR/...`・`cd docs/ADR && ...` 後の相対指定を含む）、`docs/ADR/` ディレクトリ全体、または `docs/ADR/` 配下の glob（例: `0009*.md`、`*.md`）を読む場合。パイプ・`&&` / `;` 後段およびコマンド置換（`$(...)` / バッククォート）内も既存の `guards/shell.go` 解析器で走査する。
   - **誤検知防止（非検知）**: `docdag` 自身の実行、`git diff` / `git log` / `git show` / `git add` / `git mv` 等の git 経由操作、番号付きでない `docs/ADR/template.md` / `README.md` / `index.md`、検索パターン位置引数、`docs/ADR/` 以外のパスは検知しない。また Read / Grep / Glob ツールは範囲外とし一切阻害しない。
   - **初回保留とセッション受領証**: `preflight` と同じ状態ディレクトリ（`ALT_ADR_PREFLIGHT_STATE_DIR` / `XDG_STATE_HOME` / `~/.local/state/alt-adr-preflight`）およびセッション識別（`session_id` / `conversationId`、欠落時は既存 `preflight`/`agy-hook` と同様に `"default"` へフォールバック）を用い、同一セッションの 1 回目のみ保留して受領証を記録し、2 回目以降は通過させる。`SessionStart` の受領証消去でセッション開始・圧縮時に自動リセットされる。壊れた入力（不正 JSON・欠落コマンド・受領証書込不能）は既存シェルガード（`guard-ops` / `guard-exec`）と揃えて fail-closed とする。
   - **案内文**: 検知した ADR 番号が特定できた場合はその番号を埋めた `docdag context <id>`、`docdag context <id> --section Consequences`、`docdag resolve <id> --fields id,title,status`、`docdag query --binding --where ... --fields ...` を提示し、ディレクトリ/glob 検索で番号を特定できない場合は横断検索中心のコマンド例を提示する。あわせて「保留はセッション内 1 回のみで、理由を確認すれば同一コマンドの再実行で通過する」旨を明記する。
   - **3 環境配線と `selfcheck` 必須化**: Claude Code（`.claude/settings.json` の `PreToolUse` `Bash` + `"onFailure": "block"`）、Codex（`.codex/hooks.json` の `PreToolUse` `Bash`）、`agy-cli`（`.agents/hooks.json` の `PreToolUse` `run_command|Bash|shell` に `alt-harness agy-hook pre-adr-read`）の 3 環境すべてに登録する。`alt-harness selfcheck`（H4）の必須フック検査および実リポジトリ件数検証に組み込み、3 環境のうち一部だけ欠落した状態を機械的に落とす。
   - **`SessionStart` での `--section` 例示補完**: `Prefer docdag over Glob/Grep/Read ...` のメッセージ本体は外部バイナリ `docdag prime`（外部 DocDag プラグインから起動）が出力しているため外部プラグインには触れず、リポジトリ側の `alt-harness preflight --hook` の `SessionStart` 出力に `docdag context <id> --section Consequences` の例示を追加して全 3 環境で起動時に見えるようにする。

検討して却下した案:

- **2 回目以降も恒久ブロックする案**: 複数 ADR の本文横断語句検索など `docdag` が直接サポートしない用途まで完全に塞いでしまい、回避行動を誘発するため却下した。初回保留で具体コマンドを想起させ、必要時は再実行で通すバランスを採る。
- **Read / Grep / Glob ツールにもガードを広げる案**: 置換先 ADR 執筆時など ADR 全文の精読が必要な場面で摩擦が大きいため、今回はシェル経由の読込のみを対象とした。
- **`agy-cli` で既存の `agy-hook pre-shell` に内包し `.agents/hooks.json` のエントリを増やさない案**: 3 環境のフック定義ファイル単位で欠落を `selfcheck` 検証・件数可視化する要件を満たせないため、独立ハンドラ `agy-hook pre-adr-read` として登録する方式を採った。

## Consequences

### Pros

- 長セッションの後半でもシェルで ADR を直読みした瞬間に具体的な `docdag context <id>` / `--section` / `resolve` / `query` コマンドが提示され、`docdag` の定着率が高まる。
- `alt-adr-writer` のチェック手順により、題名推測による `depends-on` / `supersedes` の誤配線や既存決定との緊張関係の見落としを起票段階で防げる。
- 3 環境（Claude Code / Codex / `agy-cli`）すべてが `selfcheck` H4 で監視されるため、片側だけの設定漏れを CI・起動時に即検出できる。

### Cons / Tradeoffs

- 静的シェル解析の複雑化・過検知を避けるため、シェル変数展開経由のパス（`p=docs/ADR/000979.md; cat "$p"`）、`find docs/ADR -exec cat {} +`、`python3 -c` 等のスクリプト内ファイル読込は意図的に検知対象外としている。
- 未知の値を取るオプションフラグ（コマンド固有の非標準フラグ）の直後に ADR パスが現れるような特殊な引数並びでは、フラグ値とファイル引数の判別がずれる可能性がある。
- 外部バイナリ `docdag prime` が標準出力に出す `Prefer docdag over Glob/Grep/Read ...` ブロック自体には手を入れていないため、`--section Consequences` の例示はリポジトリ側 `SessionStart` 出力（`adr_preflight_enabled` 行）と初回保留時の案内文から供給される。
