# ADR-001038: Knowledge Home Admin UI のモバイル・PWA レスポンシブレイアウトを修正する

## Status

Accepted

## Date

2026-11-27

## Affected Services

- alt-frontend-sv (SvelteKit 3 / Svelte 5 / TailwindCSS v4)

## Context

`/admin/knowledge-home`（Knowledge Home Operations 画面）はモバイルメニュー（`MOBILE_MENU_SECTIONS` の Admin セクション）から管理者ユーザが直接遷移できる経路として公開されており、PWA（`display: standalone`、`viewport-fit=cover`）上からも利用される。

一方で、`[[000629]]` で System Observability タブおよび実 SLI パネルを導入した時点では「Desktop UI のみを対象とし、Mobile 対応は含めない」というスコープだったため、ページ本体と配下コンポーネントの多くがデスクトップ幅前提の固定レイアウトのまま残っていた。モバイル実幅（375px〜393px）および PWA 環境で以下のレイアウト破綻が発生している:

1. **ページヘッダとアクションバーの横溢れ**: `+page.svelte` の `.ops-header-top` が `flex-wrap` なしの横並び、`.ops-actions` が `flex-shrink: 0` 固定となっており、タイトル・2 つの操作ボタン・`urlBackfillResult` サマリー・更新時刻が 1 行に並んでビューポート外へ大きく溢れる。
2. **タブナビゲーションの横溢れ**: `AdminTabNavigation.svelte` の 7 タブ（Overview / SLO / System / Reproject / Storage / Audit / Observability）に `overflow-x: auto` や `white-space: nowrap` がなく、375px 幅で右端から溢れてタブが操作不能・視認不能になる。
3. **CSS Grid / Flex の `min-width: auto` によるテーブル膨張**: `BackfillJobsTable`・`ReprojectRunsTable`・`StorageStatsPanel`・`SnapshotListPanel`・`RetentionStatusPanel`・`RetentionRunResultPanel` を包む `.panel` およびグリッド子要素に `min-width: 0` が指定されていないため、内側の `.table-container`（`overflow-x: auto`）が効かず、テーブル最小幅がページ全体を押し広げる。また `ResponsiveLayout` の `<main>` も `md:flex-1` に `min-w-0` がない。
4. **狭い 2 列カードでのテキスト溢れ**: `AdminMetricCard` に `min-width: 0` と折り返し制御がなく、`StorageStatsPanel` の長いテーブル名（`recall_candidate_view` 等）と `partitioned` バッジ、あるいは時刻・バージョン文字列がカード幅を突き破る。
5. **パネルヘッダ・メタ情報・フォームの未折り返しと iOS PWA ズーム**: `RetentionStatusPanel` / `SLOSummaryPanel` / `SnapshotListPanel` のヘッダ、`ProjectorPipelinePanel` / `RecallPipelinePanel` / `SovereignMutationPanel` のパーセンタイル行、`AuditResultPanel` のメタ情報が折り返さない。`ReprojectActions` と `AuditActions` の `<input>` は `width: 100%; min-width: 0` が欠落し、さらに `.field-mono` の `font-size: 0.8rem` が iOS Safari PWA でフォーカス時の自動ズームを引き起こす。`DiffSummaryPanel` の `.diff-dist` はモバイルでも 2 列固定のまま残る。
6. **Observability タブの固定列幅とタッチ非対応**: `[[000704]]` の `ServiceHealthTable` が `grid-template-columns: 14rem 10rem 1fr`（最小 416px 超）を固定指定し、`MetricRow` が `minmax(7rem, auto) 150px 1fr` を固定指定しているため、375px 幅で大幅に横溢れする。また Grafana リンクが `:hover` 依存（`opacity: 0`）でタッチ端末から見えない。
7. **PWA safe-area-inset の欠落**: `viewport-fit=cover` の standalone PWA で `.ops-page` に `env(safe-area-inset-top)` / `left` / `right` が考慮されていない。

## Decision

`[[000984]]` および `[[000985]]` の原則（viewport 分岐でコンポーネントツリーを二重化せず、単一ツリー内で CSS ベースのレスポンシブ表現を行う、ブレークポイントは `48rem` 基準）に従い、`/admin/knowledge-home` と配下の `knowledge-home-admin/` コンポーネント群を CSS ファーストでモバイル・PWA 対応に修正することを採用する。

具体的な変更内容:

1. **ページシェルと PWA セーフエリア (`+page.svelte`, `ResponsiveLayout.svelte`)**:
   - `.ops-page` に `width: 100%; box-sizing: border-box; min-width: 0;` を設定し、`@media (max-width: 48rem)` で余白を縮小しつつ `env(safe-area-inset-top / left / right, 0px)` を反映する。
   - `.ops-header-top` をモバイルで縦積みに切り替え、`.ops-actions` を `flex-wrap: wrap; min-width: 0` にしてアクションボタン・結果サマリー・ステータス表示が折り返して収まるようにする。
   - ページ内グリッド要素および `ResponsiveLayout` の `<main>` に `min-w-0` / `min-width: 0` を徹底し、子テーブルや長い文字列がページ幅を押し広げないようにする。
2. **水平スクロール可能なタブバー (`AdminTabNavigation.svelte`)**:
   - `.tab-bar` に `overflow-x: auto; max-width: 100%; -webkit-overflow-scrolling: touch; overscroll-behavior-x: contain;` を付与し、`.tab-item` を `flex-shrink: 0; white-space: nowrap` としつつモバイルではタップ領域（`min-height: 2.75rem`）を確保する。既存の `<button>` ロール契約は維持する。
3. **カード・テーブル・パネルヘッダ・フォームのモバイル適応**:
   - `AdminMetricCard` に `min-width: 0`、ラベルの `flex-wrap: wrap` + `overflow-wrap: anywhere`、モバイル時の値フォントサイズ縮小を適用する。
   - 全データテーブルパネルで `.panel` と `.table-container` に `min-width: 0; max-width: 100%` とタッチ慣性スクロールを設定し、セルが極端に潰れないよう `white-space: nowrap` を整える。
   - 全パネルヘッダ・パーセンタイル行・メタ情報に `flex-wrap: wrap` を適用し、`DiffSummaryPanel` の `.diff-dist` をモバイルで 1 列化する。
   - `ReprojectActions` と `AuditActions` の入力欄に `width: 100%; min-width: 0; box-sizing: border-box` を設定し、モバイル幅では 1 列積み・`font-size: 1rem`（16px）を維持して iOS PWA のフォーカス自動ズームを防ぐ。
4. **Observability タブのレスポンシブ化 (`ObservabilityPanel` / `MetricRow` / `ServiceHealthTable` / `DegradedBanner`)**:
   - `ServiceHealthTable` の固定 `14rem 10rem 1fr` をモバイル幅で `minmax(0, 1fr) auto` + Note 行折り返し（`grid-column: 1 / -1`）に切り替える。
   - `MetricRow` の 3 列グリッドをモバイル幅で 2 段レイアウト（上段: 値 + スパークライン、下段: 全幅シリーズダイジェスト）に切り替え、`@media (hover: none)` では Grafana リンクを常時視認可能にする。
5. **回帰防止テストの追加**:
   - モバイル幅（375px / Pixel 5）で全 7 タブの横溢れゼロ・全要素ビューポート内収容・タブ切替・テーブル内スクロール・フォーム入力サイズ・確認ダイアログ表示を検証する Playwright モバイル E2E テストおよび Vitest Browser コンポーネントテストを追加する。

### 検討した代替案

- **代替案 A: `{#if isMobile()}` でモバイル専用 Admin コンポーネントツリーを新設する**
  - 却下理由: `[[000984]]` / `[[000985]]` に反し、ポーリング・アクション実行・タブ状態を持つ Admin コンポーネントが端末回転時に再マウント・状態破棄されるうえ、7 タブ分の二重保守コストが発生する。
- **代替案 B: ページ全体や親コンテナに `overflow-x: hidden` だけを設定して横スクロールを隠す**
  - 却下理由: 画面外に溢れたタブ・ボタン・テーブルが切り捨てられて操作不能になるだけで、根本的な UI 破綻が解消しない。

## Consequences

### Pros

- モバイルブラウザおよび iOS / Android の standalone PWA 上で `/admin/knowledge-home` の全 7 タブが横溢れ・切り捨て・自動ズームなしで閲覧・操作できる（375px 実測で `AdminTabNavigation` 620px → 375px 内、`AdminMetricCard` 347px/165px 列 → 165px 内、`DiffSummaryPanel` 680px → 375px 内、Observability `ServiceHealthTable`/`MetricRow` 481px → 375px 内、`ReprojectActions` 入力フォント 12.8px → 16px に解消）。
- `[[000984]]` / `[[000985]]` の単一 `<main>`・単一ツリー原則を維持しているため、縦横回転時にもタブ選択やフォーム入力・ポーリング状態が維持される。
- デスクトップ幅（`> 48rem`）のレイアウトおよび既存のデスクトップ E2E セレクタ契約（`getByRole("button", ...)` 等）を壊さない（Playwright desktop-chromium 11/11 + mobile-chrome 1/1、Vitest Browser 24/24、server unit 2051/2051 すべて green）。
- Playwright モバイル E2E と Vitest Browser テストにより、今後のコンポーネント追加時のモバイル横溢れ回帰を機械的に検知できる。

### Cons / Tradeoffs

- データ密度の高い運用テーブル（Backfill Jobs / Reproject Runs / Snapshots / Retention）はモバイルでは `.table-container` 内の横スクロールによる閲覧となる（カード変換は行わず列構造と既存テストとの一貫性を優先した）。
- タブバーが 7 項目あるため、375px 幅では右側のタブへ到達するためにタブバー自体の横スワイプが必要となる。
