# ADR-000998: altctl の read-only mTLS エッジ検査で ADR-000995 の Alt 側範囲を確定する

## Status

Accepted

## Date

2026-11-07

## Affected Services

- altctl (Go) — `altctl mtls validate` / `altctl mtls observe` を新設（`altctl/cmd/mtls.go`, `altctl/internal/mtlsedge/`）
- pre-processor (Go) — 検査対象エッジの caller。コード変更なし
- news-creator (Python) — 検査対象エッジの receiver。コード変更なし
- scripts (`scripts/kisage-env.py`) — `verify` の `/mtls_allowlists` 投影検査に重複 peer の拒否を追加

## Context

[[000995]] は `pre-processor -> news-creator` の単一 mTLS エッジについて、「チェックポイント準備 → 本番変更前の候補検証 → 排他ロック下のコミット → デプロイ → 稼働観測 → 確定または補償復旧」の 6 段階ゲートを、既存の `scripts/deploy.sh` / `c2quay` 入口に段階導入すると提案した。実装に着手した結果、次の事実が判明した。

1. **入口の前提が現状と合わない。** `scripts/deploy.sh` は運用者が選びうるデプロイ手段の一つにすぎない。特定の入口にゲートを統合しても、その入口を使わない運用には効かない。さらに、保護コミット・デプロイ・補償復旧の各段はデプロイを実行する主体自身の commit / rollback と重なり、Alt 側に持たせると [[000995]] D6(d) が避けた dual-writer を別の形で招く。
2. **当初のプローブ方式は実イメージで動かない。** pre-processor の実行イメージは `gcr.io/distroless/static-debian12:nonroot` で、curl・シェル・openssl を含まない。`docker exec <pre-processor> curl …` は exit 126/127 で必ず失敗する。
3. **`docker inspect` のコンテナ側に `RepoDigests` は無い。** コンテナの `.Image` はイメージ ID（config digest）であり、`<repo>@sha256:<manifest digest>` と比較するには `docker image inspect` で解決する必要がある。
4. **D7.1 の投影検査は既に存在した。** `scripts/kisage-env.py verify`（`verify_declaration`）が `/mtls_allowlists` のキー集合と peer 集合を `deploy/host-prereqs.yaml` の `env_allowlists` と双方向に突き合わせ、CI（`compose-audit` の kisage-env-invariant ジョブ）で実行されている。重複 peer だけが集合比較をすり抜けていた。
5. **caller が実際に読む変数は ADR 記載と異なる。** pre-processor の news-creator クライアントは `MTLS_ENFORCE`、`MTLS_CERT_FILE` / `MTLS_KEY_FILE` / `MTLS_CA_FILE`、`NEWS_CREATOR_MTLS_SERVER_NAME`（未設定時 `news-creator`）を `pre-processor/app/bootstrap/wire.go` で、`NEWS_CREATOR_HOST` を `pre-processor/app/config/load.go` で読み、`NEWS_CREATOR_CLIENT_*` は読まない。さらに両サービスの PKI 設定（pre-processor の `internal/pki/config.go`、news-creator の `news_creator/infra/pki/config.py`）は一部のキーを `<KEY>_FILE` 優先で読む。両サービスとも `env_file: ../.env` を読み込むため、候補 `.env` に `_FILE` 変数を差し込むと、subject・SAN・証明書の出力先が、検査対象のキーとは別の経路で変わってしまう。

## Decision

**ADR-000995 の Alt 側の実装範囲を、運用者が任意のデプロイ手段に組み込める read-only の検査コマンド `altctl mtls validate` と `altctl mtls observe` に限定する。保護コミット・デプロイ・補償復旧の段は Alt の範囲外とし、デプロイを実行する主体の責務とする。**

### D1. `altctl mtls validate --env-file <candidate>`（本番変更前の候補検証）

- **環境凍結**: `compose/compose.yaml` から `include:` グラフを辿って到達する全 compose ファイルの YAML scalar を走査し、補間される変数名（`${A}`, `${A:-${B}}` の入れ子, `${A:?msg}`, `$A`。`$$` はエスケープとして除外）を収集する。その変数が altctl 自身の環境に存在すれば（空値を含む）compose を実行する前に変数名を挙げて失敗する。子プロセスに渡すのは `DOCKER_HOST` / `DOCKER_CONTEXT` / `DOCKER_CONFIG` / `PATH` / `HOME` と `COMPOSE_PROJECT_NAME=alt` だけとする。
- **隔離描画**: 0700 の一時ディレクトリにプロジェクト直下のエントリを symlink し、`compose/` の中身はバイト単位でコピーし、候補 `.env` を 0600 で置いて `compose/.env -> ../.env` を作る。`docker compose -f <stage>/compose/compose.yaml --env-file <stage>/.env -p alt config --format json` の出力はメモリ上でのみ扱い、終了時に一時ディレクトリを削除する。稼働中の `.env`・compose・`.kisage/` には一切書き込まない。
- **エッジ意味検査**（validate / observe 共通）: caller の `MTLS_ENFORCE=true`、証明書・鍵・CA のパスが `/certs/svc-cert.pem` / `/certs/svc-key.pem` / `/trust/ca-bundle.pem`、`NEWS_CREATOR_HOST` が `https://news-creator:9443`（path / query / userinfo / fragment なし）、実効 SNI が receiver の `CERT_SANS` の要素、caller の `CERT_SUBJECT` が `pre-processor` であり receiver の `MTLS_ALLOWED_PEERS` の要素（完全一致）であること、caller に `CERT_SUBJECT_FILE` / `CERT_PATH_FILE` / `KEY_PATH_FILE` が存在しないこと、receiver の `INBOUND_MTLS=true` と `PEER_IDENTITY_STRICT=true`、receiver に `CERT_SANS_FILE` / `CERT_SUBJECT_FILE` / `CERT_PATH_FILE` / `KEY_PATH_FILE` が存在しないこと。SNI と subject は caller と同じく trim しない。
- compose が「variable is not set」を出した場合は変数名で失敗し、それ以外の compose 失敗は stderr を出さずに `compose_config_failed` とする。

### D2. `altctl mtls observe [--expect-caller-image …] [--expect-receiver-image …]`（稼働観測）

- compose ラベル（`com.docker.compose.project=alt`, `…service=<svc>`）と `status=running` で各サービスの稼働コンテナがちょうど 1 つあることを確認し、なければ `not_observed` とする。
- コンテナの `.Image` を `docker image inspect` で `RepoDigests` に解決する。RepoDigest が無ければ失敗とする。期待値を指定した場合は完全一致で比較する。
- 稼働中のプロジェクトを `docker compose -f <project>/compose/compose.yaml --env-file <project>/.env -p alt config` で描画し、エッジ関連キーについてコンテナの `.Config.Env` との差分（ホストは収束したがコンテナが再作成されていない状態）を検出する。そのうえでコンテナの実効 env に D1 の意味検査をかける。
- **プローブ**: caller コンテナの `.Mounts` から `/certs` と `/trust` の volume を特定し、`docker run --rm --pull never --network container:<caller> --user 65532:65532` で両 volume を読み取り専用でマウントした使い捨てコンテナを起動する。receiver イメージに入っている curl を使い、caller の証明書で非免除パス `GET https://news-creator:9443/queue/status` を呼ぶ。curl 成功で pass、HTTP エラー（exit 22）や TLS 失敗で fail、`docker run` 自体の失敗（125–127）で `not_observed` とする。これで [[000995]] D7.2 のプローブ方式を確定する。

### D3. 出力と終了コード

- `--json` は [[000995]] D4 を基にした縮小版（`schema_version`, `edge`, `docker_context`, `tool_versions.docker_compose`, `elapsed_ms`, `rollout_succeeded`, `stages.{candidate_validate|live_observation}`）を出す。D4 との違いは次のとおり。`elapsed_ms` を追加した。各 stage に `reasons` を、`live_observation` に `env_drift_keys` と `probe` を追加した。`candidate_env_sha256` はトップレベルではなく `stages.candidate_validate` の下に置いた。artifact ID・世代・コミット関連の項目は範囲外の段に属するため持たない。含めるのは変数名・理由 ID・公開イメージの digest・候補ファイルの SHA-256 だけで、env の値・compose 出力・inspect 出力・プローブ出力は出さない。観測できなかった事実は推測値で埋めず `not_observed` とし、`not_observed` は pass に数えない。
- 終了コードは 0 = pass、1 = 検査失敗または未観測（読めない `--env-file`、`compose/compose.yaml` 不在、cobra のフラグエラーを含む）、2 = 用法エラー（`--env-file` なし、`--dry-run`、不正な `--expect-*`）、3 = docker 到達不可、4 = 設定エラー（`--project-dir` 不在、`.altctl.yaml` 不正）とする。

### D4. D7.1 の扱い

`/mtls_allowlists` の投影検査は既存の `kisage-env.py verify` を唯一の実装とし、重複 peer を拒否する分岐とその CLI テストを追加する。`scripts/check-env-overrides.py` に二重実装は置かない。

### D5. ADR-000995 との対応

| ADR-000995 | 本 ADR での扱い |
|---|---|
| 環境固定（Stage 1 の一部） | validate / observe の環境凍結 |
| 本番変更前の候補検証（Stage 2） | `altctl mtls validate` |
| 稼働観測（Stage 5） | `altctl mtls observe` |
| チェックポイント・保護コミット・デプロイ・補償復旧（Stage 1 の残り, 3, 4, 6） | Alt の範囲外。デプロイを実行する主体の責務 |
| D5 シナリオ 1〜3（stale override / shell override / 非対称 allowlist） | validate のテストで検証 |
| D5 シナリオ 4（stale container image/env） | observe のテストで検証（検知まで。補償復旧の発火は範囲外） |
| D5 シナリオ 5〜6（並行変更 / 切替と補償往復） | 範囲外 |
| `scripts/deploy.sh` への統合（Phase 2） | 行わない |

### 検討した代替案

- **(a) [[000995]] どおり 6 段階ゲートを `scripts/deploy.sh` に統合する — 却下。** 単一の入口に付けても他のデプロイ手段には効かず、commit / rollback をデプロイ実行主体と二重に持つことになる。
- **(b) 6 段階すべてを altctl の変更系コマンドとして実装する — 却下。** altctl が `.env` のコミットとロールアウトとロールバックを担うと、デプロイ実行主体と並ぶ書き手が増える。read-only の部品に留めれば、どのデプロイ手段にも前後の検査として組み込める。
- **(c) `docker exec` で pre-processor 内から curl する — 却下。** distroless イメージに curl が無い。
- **(d) `scripts/check-env-overrides.py` に D7.1 専用の lint を新設する — 却下。** `kisage-env.py verify` と重複し、差分が乖離する。

### 受入確認

- Go テスト（`go test -race ./cmd/... ./internal/mtlsedge/...` と altctl 全体）、`scripts/tests/test-kisage-env.py` が green。
- 独立レビューで 100 以上の変異（ステージングでの live `-f` / live `.env` の解決、子プロセス env の拡張、各意味規則の無効化、部分一致への置換、`not_observed` の pass 扱い、実 executor の env 継承など）を複数回のレビューで注入した。検出されなかった変異はその都度テストを追加し、等価変異（`extractIncludePaths` の `node.Decode(&m)` のエラー握りつぶし。yaml.v3 が先に拒否するため挙動が変わらない）を除いて最終的にすべて検出されることを確認した。
- 合成 `.env` による実 `docker compose config` での validate は pass し、秘密値の出力と一時ディレクトリの残留がないことを確認した。
- 稼働中のデプロイ（`compose/.env` を置かず、プロジェクト直下の `.env` だけを持つ配置）に対する observe の初回実行では、プローブ pass と両イメージの RepoDigest 解決を確認した。一方で、この配置では compose が補間用の `.env` を見つけられず描画が失敗することが判明した。`--env-file <project>/.env` を明示する形に改めた後の再実行では、digest 解決・env ドリフトなし・意味検査・プローブがすべて pass し `rollout_succeeded: true`（elapsed 約 0.5 秒）となった。

## Consequences

### Pros

- 本番の `.env` を書き換える前に、候補が caller / receiver の実際に読む値でエッジを壊さないことを、秘密値を出さずに確認できる。
- ロールアウト後に、イメージ digest・コンテナ再作成漏れ・caller 証明書による非免除パスの mTLS 疎通を 1 コマンドで観測できる。
- read-only で常駐物も増やさないため、[[000979]] の OSU 予算と rolling deploy モデルに影響しない。

### Cons / Tradeoffs

- 保護コミット・補償復旧（[[000995]] の Stage 3・4・6 とシナリオ 5・6）は Alt では検証しない。デプロイ実行主体の側でこれらを担わない限り、ADR-000995 の当初意図は完全には満たされない。
- プローブは caller の netns と証明書を使うが、TLS クライアントは curl であり、pre-processor の Go クライアント自身の TLS 設定（SNI 等）は実通信では検査しない。その部分は意味検査に依存する。
- 環境凍結は compose が補間する変数（例: `IMAGE_TAG`）をシェルから渡す運用を拒否する。そうした値は `.env` に置く必要がある。また子プロセスに `DOCKER_TLS_VERIFY` / `DOCKER_CERT_PATH` を渡さないため、TLS 保護されたリモート daemon は docker context 経由でのみ扱える。
- 対象は単一エッジに固定されている。他エッジへの展開はエッジ定義の一般化を要する。
