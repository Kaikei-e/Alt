# ADR-000976: 日本語評価で選定した凍結判別器を専用 claim-verifier に焼き込み、原文 grounding を通った why だけを Trail branch に emit する

## Status

Proposed

本 ADR は [[000972]] を完全置換する。英語ベンチ数字の無条件外挿、Bespoke-MiniCheck-7B（CC BY-NC）候補化、`corroborated` 意味の黙った破壊、原文 RPC「新設」誤記は実装根拠にしない。

## Date

2026-08-11

## Affected Services

- claim-verifier (Python, 新設)
- knowledge-sovereign (Go)
- news-creator (Python)
- alt-data-hub (Go)
- compose / pki
- evaluation/

## Context

### 1. 方向性は Trail と整合する

現行 why はタグ共起のテンプレートであり、意味レベルの空洞がある。原文（`articles.content`）で証拠を終端し、関所未通過なら emit しない（沈黙）は、Trail §C4 の precision 優先と整合する。

### 2. [[000972]] が不足していた科学・運用境界

1. MiniCheck の GPT-4 同等 / 400× / 4〜10pt は英語 LLM-AggreFact・コスト換算の条件付き結果。著者は非英語を未評価としている。
2. Bespoke-MiniCheck-7B は CC BY-NC 4.0 で、Alt の MIT / Apache-2.0 only に反する。
3. 判別器は bit-exact 決定論ではない（threshold / digest / runtime / chunk）。
4. 現行 `corroborated` は共有タグ ≥2。D4 の「異ドメイン原文 ≥2」は破壊的再定義だった。
5. `GetArticleContentByID` は既にあり、不足は sovereign peer 配線である。

### 3. 専用サービスを採る理由

ユーザは verifier を専用サービスに置くことを選択した。GPU/CPU を news-creator から独立してスケジューリングでき、生成 LLM と検証器の DI 境界を物理的に分けられる。配置比較（news-creator 同居 / recap-evaluator 拡張）は Cons に残す。

## Decision

**証拠の連鎖を記事原文で終端し、日本語評価ゲートを通過した MIT/Apache-2.0 の凍結判別モデルだけを専用 claim-verifier に焼き込む。why の全事実文が関所を通った branch のみを emit する。confidence は `confidence_basis_version` 付きで決定論側が算出し、生成 LLM の自己申告を禁止する。**

### D1. 真実の階層

- **原文** (`articles.content`): 唯一の grounding 文書。既存 `GetArticleContentByID` で読む。
- **要約・タグ**: 選抜文脈には使えるが、事実主張の根拠にしない。
- **LLM 出力**: 関所通過まで存在しないものとして扱う（emit しない）。

### D2. 三段パイプライン

1. **候補生成（既存 planner）**
2. **解釈（news-creator Ollama）** — 原文抜粋 + spine 文脈で why を執筆。「発見メカニズムの再記述」禁止。anchored why（足跡参照）は維持。
3. **関所（claim-verifier）** — why を文分割し、各事実文を evidence 記事原文で判定。1文でも unsupported なら branch 全体を出さない。

検証結果（model digest / threshold / chunk policy / per-claim verdict）は `trail.branch_proposed.v1` payload に含め、projector が live content を再読しなくても再投影できる形にする。

### D3. claim-verifier サービス

- Connect-RPC: `VerifyClaims(claims[], article_refs[]) → verdicts[]`
- 重みはイメージ焼き込み。実行時ネットワーク取得なし。
- **ライセンス:** MIT / Apache-2.0 のみ。Bespoke-MiniCheck-7B（CC BY-NC）は候補外。
- 候補モデル（評価で選定）: MiniCheck-FT5 / MiniCheck-RoBERTa / MiniCheck-DeBERTa、mDeBERTa-v3 多言語 NLI、日本語 DeBERTa+JNLI 系。
- 起動時: model digest と threshold を loud log。未設定は exit 非ゼロ。
- sovereign 未接続時: `claim_verifier_enabled=false` loud log + planner は branch emit を停止（silent pass 禁止）。

### D4. 日本語評価ゲート（モデル選定の前提）

- corpus: 最低 **300** claim–document 対。article / time / source で split。Alt 実記事 why と公開日本語 factual consistency 資源を別バケット。
- adversarial buckets: 引用虚偽、時間矛盾、転載・syndication、prompt injection を各最低件数で持つ。
- **出荷条件（事前固定、すべて必須）:**
  - precision@emit ≥ 0.95
  - false-emit rate ≤ 0.05 **かつ** 検証なし対照比で相対 ≥50% 減
  - supported recall ≥ 0.70
  - 各 adversarial bucket の FPR ≤ 0.02
  - domain-independence probe（転載ペアで多重確証が出ない率）≥ 0.90
- BAcc は参考指標であり単独合格にしない。
- threshold / chunk_size は dev のみで選び、test は一度きり。結果は `evaluation/` にコミット。

### D5. confidence 契約（破壊的上書きをしない）

- 既存タグ数ヒューリスティックの `corroborated` 意味は **残さない**。移行期間は `confidence_basis_version` で区別する。
  - `v1_tag_overlap`（現行・historical）
  - `v2_source_grounded`（本 ADR）:  
    - `corroborated`: 関所通過の支持記事が **独立ソース** 2本以上（登録局 / 配信系統の独立性判定を含む。ドメイン文字列一致だけでは足りない）  
    - `plausible`: 関所通過の支持が1本  
    - 事実主張が関所を通らない → emit しない（`speculative` で出さない）  
    - `speculative` は事実主張を含まない inquiry のみ
- 生成 LLM に confidence を出させない。

### D6. 配線・資源

- sovereign → data-hub: mTLS client、`DATAHUB_ALLOWED_PEERS` に `knowledge-sovereign`、CDC RED。
- sovereign → claim-verifier: 同上。
- **CPU-first:** 初期ベンチは CPU。GPU 昇格は D4 合格後、VRAM 争奪が news-creator 夜間バッチを壊さないことを runbook で確認してから。
- 出荷順序: in-app BranchCard が先。通知露出は [[000977]]。

### D7. 実装 wave

1. corpus + harness RED（合格閾値をテストとして固定）
2. モデル比較 GREEN → digest/threshold 固定
3. claim-verifier サービス + compose/pki
4. sovereign peer + CDC RED（content read / VerifyClaims）
5. planner 置換 + confidence_basis_version + E2E（偽 why が surface しない）

### 検討した代替案と却下理由

**(a) 要約 grounding — 却下。** 要約は LLM 生成物（Maynez; FRANK/XSum 92% は条件付き）。  
**(b) LLM self-critique — 却下。** 検証者と被検証者の同一生成系。  
**(c) クラウド検証 API — 却下。** ゼロクラウド。  
**(d) news-creator / recap-evaluator 同居 — 却下（本決定）。** ユーザ選択により専用サービス。将来の統合は別判断。  
**(e) Bespoke-7B — 却下。** CC BY-NC。

## Consequences

### Pros

- why が意味レベルに上がり、幻覚は関所を抜けないと出荷されない。
- 日本語・ライセンス・confidence 移行・配線が数値と契約で固定される。
- Beacon（[[000977]]）はこの関所の上にしか建たない。

### Cons / Tradeoffs

- 評価セット作成と不合格時の遅延が大きい。
- 新サービス分の運用面積が増える。
- 判別器誤りは消えない。最終防衛は dismiss_reason / dwell。
- `confidence_basis_version` 移行中は UI / 分析が二世代を扱う。
