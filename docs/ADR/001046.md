# ADR-001046: 変更差分リントへの抑制ラチェット統合と Rust flaky-hunt・決定論的ジッター検証の導入

## Status

Accepted

## Date

2026-11-28

## Affected Services

- `scripts/altharness` (Go 単一バイナリ) — `lint-changed` への `CHECK-02` 抑制ラチェット（削除ファイル検知含む）統合、および `flaky-hunt`（`VERIFY-05`）の Rust（`Cargo.toml` / `cargo test`）対応
- `scripts/lint/ratchet/suppressions.toml`, `.agents/rules/rule-ledger.md` — `alt-frontend-sv` の `ts_biome_ignore` 下限更新（`21 → 19`）と規則台帳更新
- `rask-log-forwarder/app` (Rust) — `RetryManager::calculate_delay_with_rng` の決定論的 RNG 注入シーム追加と、`test_retry_with_jitter` のシード固定化による確率的フレイキー解消

## Context

PR #418 の CI 実行時、全 172 チェックのうち 169 件（`Alt Frontend SV Tests` 全 3 シャード含む）が通過した一方、以下の 2 種類の根本原因により 3 ジョブ（`workflow-safety-lint`、`agent-harness/harness`、`Rask Log Forwarder Tests`）が失敗した。

1. **抑制ラチェット（`CHECK-02`）の下限更新漏れがローカル Stop フックをすり抜けた**（`workflow-safety-lint` / `agent-harness/harness`）:
   - 旧 `/knowledge/trail` 専用 E2E スペック（`biome-ignore` 2 件を含む）を削除した結果、`alt-frontend-sv` の `ts_biome_ignore` が `21 → 19` へ減少した。
   - [[001045]] で導入した `alt-harness lint-changed` は `listDirtyFiles` で削除ファイル（`D`）をスキップし、かつインプロセスの `internal/ratchet`（`CHECK-02`）を実行していなかったため、ローカルの Stop フックでは検知されず CI で初めて失敗した。
2. **`rask-log-forwarder` のジッター単体テストが 1/200 の確率で衝突して失敗する**（`Rask Log Forwarder Tests`）:
   - `rask-log-forwarder/app/src/reliability/retry.rs` の `apply_jitter` はグローバルな `rand::rng()` を直接呼び出し、ミリ秒切り捨て後に `[100ms, 299ms]` の 200 値（`base_delay=100ms, attempt=1` 時）を返す。
   - 決定論的 RNG 注入シームが無いため、`tests/reliability/test_retry_mechanism.rs:52` は非決定論的に 2 回呼んで `assert_ne!(delay1, delay2)` を検査しており、`224ms == 224ms` のように `p = 1/200 (0.5%)` で CI をランダムに落とす構造になっていた（`tests/retry_integration_test.rs` も 5 サンプル採取で確率を薄めているだけで本質は未解決だった）。
   - さらに `VERIFY-05` の `alt-harness flaky-hunt`（[[001037]]）は Go と Python のみ対応しており、Rust サービス（`Cargo.toml`）の不安定テストを同じ再現・証拠保存パイプラインで捕捉できなかった。

## Decision

Alt の純 Go 単一バイナリ方針（[[001028]]）、`VERIFY-05` 不安定テスト再現原則（[[001037]]）、および `ARCH → CHECK → VERIFY → LEDGER` の強制ラダーと Proven-to-Fail 原則（[[001039]]・[[001045]]・`docs/review/ハーネス追加施策 — poteto 方式の適用.md`）に従い、以下を実装する。

### 強制ラダー選定根拠（Higher-Rung Rejection）

1. **リトライジッターのフレイキー解消 — 採用段: `ARCH`（決定論的 RNG 注入シーム）＋ `VERIFY`（`flaky-hunt` Rust 対応）**:
   - グローバル `rand::rng()` のみに依存していた設計を改め、テスト側からシード固定 RNG を注入できる正規 API `RetryManager::calculate_delay_with_rng<R: Rng + ?Sized>(&self, attempt: u32, rng: &mut R) -> Duration` を導入する。既存の `calculate_delay` は `&mut rand::rng()` へ委譲し、本番挙動と公開 API 互換性を完全に維持する。
   - 修正前に `alt-harness flaky-hunt` の Rust ランナーで `test_retry_with_jitter` の実際の衝突失敗を再現してから、テストをシード固定 RNG による決定論的検証へ置き換える（`VERIFY-05`）。
2. **抑制ラチェット更新漏れの再発防止 — 採用段: `CHECK`（`lint-changed` への `internal/ratchet` 統合）**:
   - **`ARCH` を使わなかった理由**: ファイル削除や編集によるリポジトリ全体のインライン抑制件数変動（`biome-ignore` / `# noqa` / `#[allow]` / `nolint` / `#nosec`）は単一モジュールの型・コンパイラ境界では表現できず、`scripts/lint/ratchet/suppressions.toml` との横断照合が必要である。
   - **採用段: `CHECK`**: `lint-changed` の変更収集で削除ファイル（`D`）を含むソース変更・ラチェット変更を検知し、同一バイナリ内の `internal/ratchet` をインプロセス実行して増加・未更新の減少の双方を Stop フック境界で即時ブロックする。

### 具体的な変更

1. **`alt-harness lint-changed` への `CHECK-02` ラチェット統合（`scripts/altharness/internal/guards/lint_changed.go`）**:
   - `listDirtyFiles` が既存ファイル一覧に加えて削除ファイルを含むラチェット対象変更の有無を返すよう拡張する。
   - リポジトリに `scripts/lint/ratchet/suppressions.toml` が存在し、対象ソースファイルまたは `suppressions.toml` 自体に変更（追加・編集・リネーム・削除）がある場合、`ratchet.Run` をインプロセス実行し、不一致なら `lint-changed` および 3 環境（Antigravity / Claude Code / Codex）の Stop フックを失敗させる。
   - `lint_changed_test.go` に PR #418 と同一事象（`biome-ignore` を含む `.ts` ファイルの削除 → `ratchet.decrease-update-required` で FAIL → `ratchet --update` 後に PASS、および追加 → `ratchet.increase` で FAIL）の Proven-to-Fail テストを追加する。
2. **`alt-harness flaky-hunt` の Rust 対応（`scripts/altharness/internal/flakyhunt/`）**:
   - `--lang auto|go|python|rust` をサポートし、`Cargo.toml` から `"rust"` を自動検出する。
   - `rust_runner.go` で `cargo test` を指定ラウンド数反復実行し、通常出力（`test <name> ... FAILED`）・`--quiet` 出力（`<name> --- FAILED`）・`panicked at`・0 テスト通過（anti-FP-01）を抽出して `.harness/evidence/flaky-hunt/<module>/report.json` およびラウンド失敗ログへ記録する。
   - `flakyhunt_test.go` に Rust 自動検出・通常/`--quiet` 失敗抽出・正常通過 `#[should_panic]` 無視・0 テスト拒否の単体テストを追加する。
3. **`rask-log-forwarder/app` の決定論的ジッター設計とテスト修正**:
   - `src/reliability/retry.rs` に `calculate_delay_with_rng`（および内部 `apply_jitter_with_rng`）を追加し、`calculate_delay` をその薄い委譲にする。
   - `tests/reliability/test_retry_mechanism.rs` および `tests/retry_integration_test.rs` の非決定論的な `assert_ne!` / 確率的サンプリングを、`StdRng::seed_from_u64` を用いた決定論的テスト（`[100ms, 300ms)` 範囲不変条件・分散確認・同一シード再生の一致・既定 `calculate_delay` の範囲検証）へ置き換える。
4. **抑制ラチェット台帳と規則台帳の更新**:
   - `./scripts/altharness/alt-harness ratchet --update` により `scripts/lint/ratchet/suppressions.toml` の `alt-frontend-sv.ts_biome_ignore` を `21 → 19` へ更新する。
   - `.agents/rules/rule-ledger.md` の `R-24`・`R-38`・`R-46` に `lint-changed` でのラチェット検証および `flaky-hunt` の Rust 対応を反映する（`max_judgment_rules` は増やさない）。

### 検討した代替案

- **`test_retry_with_jitter` のサンプル数を増やす（例: 2 回 → 20 回）だけで済ませる**: 退けた。非決定論的テストを残す対症療法であり、乱数注入シームが無い設計上の欠陥を放置することになるため、`ARCH` 優先原則に反する。
- **`AGENTS.md` に「ファイル削除後は `alt-harness ratchet --update` を実行すること」と文章ルールを足す**: 退けた。文章ルールは忘れられる柔らかい制約であり、`lint-changed`（Stop フック）へインプロセス統合すれば約 2 秒で毎回機械強制できる。

## Consequences

### Pros

- ファイル削除を含むインライン抑制数の増減が Stop フック境界で即時検出され、PR 後の `workflow-safety-lint` / `agent-harness/harness` 差し戻しを防げる。
- `rask-log-forwarder` のリトライジッター検証が完全決定論的になり、0.5% 確率の CI フレイキーが構造的に根絶される。
- `alt-harness flaky-hunt`（`VERIFY-05`）が Go・Python に加えて Rust サービスでも同一スキーマの再現・証拠保存を提供できる。

### Cons / Tradeoffs

- ソース変更があるターンの Stop フック実行時間が抑制ラチェット走査分（約 2 秒）増加するが、クリーン作業ツリー時は従来どおり即時終了する。
