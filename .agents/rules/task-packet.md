# Agent Task Packet & GUARD-01 Rules

- **GUARD-01 (No Dangerous Bulk Autofix)**: Never run logic-mutating bulk autofix commands (`golangci-lint --fix`, `cargo clippy --fix`, `cargo fix`, `ruff check --unsafe-fixes`, `biome check --write --unsafe`). Fix targeted lint findings explicitly and re-verify via `./scripts/lint/run.sh <target>`.
- **Foreground Execution Only**: Never run verification or build commands in the background (`&`, `nohup`). Execute every command synchronously in the foreground and observe its exit status.
- **Work-Bounded Scope (Never Time-Bounded)**: Bound agent work by `allowed_paths`, `max_files` (recommended ≤ 10, hard cap 25), `max_functions` (recommended ≤ 3, hard cap 20), and explicit `allowed_rules` (wildcards `*` and `ALL` are forbidden). Do not run repo-wide builds or `./scripts/lint/run.sh all` when `forbid_repo_wide_test_build: true`. Stop and emit a handoff when bounded work completes or hits its cap.
- **Mandatory Three-Item Hand-off**: Every handoff must explicitly report:
  1. Modified files with added/deleted line counts and modified function count.
  2. Potential runtime behavior impact (`has_change`, checked dimensions such as `timeout`, `error_message`, `permissions`, `type_conversion`, `default_value`, `control_flow`, and an explicit confirmation summary even when unchanged).
  3. Change rationale (write `"変更なし"` explicitly when unchanged; never leave blank or use placeholders like `TBD`, `N/A`, or `-`) plus deterministic verification command and exit code.
- **LOOP-02 (Measured Verification Budget)**: Every TaskPacket must record `execution_policy.measured` (`duration_s`, `exit_code`, `at_commit`, optional `command_sha256`) via `./scripts/altharness/alt-harness packet measure <packet>` (optionally `--turn-limit-s <sec>` deriving budget as `turn_limit / 5`) before dispatch; unmeasured packets (`UNMEASURED_VERIFICATION_COMMAND`), over-budget commands (`VERIFICATION_BUDGET_EXCEEDED`), and stale hashes (`STALE_MEASURED_COMMAND`) are rejected.
- **LOOP-01 & VERIFY-01 Verification Gates**: Validate packets with `validate-packet <path>`, verify handoffs against real git diff, AST modified function count, CHECK-01 screener, lint-fix guards, and host command re-execution via `verify-handoff <handoff> --packet <packet> --base-commit <sha>`, verify test-first commit order via `verify-sequence --base-commit <sha> --test-command "<cmd>"`, and run `./scripts/verify/host-final-check.sh --target <target>` (with optional `--go-test-dir` / `--py-test-dir` / `--random-seed` for randomized-order host tests) for final host confirmation. Canonical spec: `docs/best_practices/agent-task-packet-standard.md`.
- **LOOP-03 / LOOP-04 / LOOP-05 / LOOP-06 / LOOP-07 Operational Loops**: Maintain append-only `.harness/runs/<branch>/decisions.tsv` via `alt-harness harness-run init|log|validate|status|parallelism --apply`; run adversarial multi-model reviews with `alt-harness loop-review brief|validate|record|check-coverage`; validate and compare packet template changes with `alt-harness loop-eval validate|stage|grade|compare --record`; promote 2-strike recurring failure classes via `alt-harness loop-correct scan|validate|record|scaffold-corpus`.
- **Governing ADR Citation in Worker Briefs**: Every subagent or swarm worker brief that edits production code must cite the governing `docs/ADR/NNNNNN.md` ID on line 1 (e.g., `Governing ADR: docs/ADR/001032.md (status: proposed)`), so workers inherit the active ADR context without drafting duplicate ADRs.
